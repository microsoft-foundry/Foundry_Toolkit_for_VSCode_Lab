# మాడ్యూల్ 8 - సమస్యలు పరిష్కారం

ఈ మాడ్యూల్ సాధారణ సమస్యల కోసం సూచన గైడ్. దీన్ని బుక్‌మార్క్ చేసుకోండి మరియు ఏదైనా దోషం వస్తే తిరిగి రా.

---

## 1. అనుమతి దోషాలు

### 1.1 `agents/write` అనుమతి నిరాకరించబడింది

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**మూల కారణం:** **ప్రాజెక్ట్** స్థాయిలో `Azure AI User` పాత్ర తప్పిపోయింది. ఇది #1 వర్క్‌షాప్ లో ఒక ప్రధాన ఎర్రర్.

**పరిష్కారం:**
1. [portal.azure.com](https://portal.azure.com) ను తెరువు.
2. మీ Foundry **ప్రాజెక్ట్** పేరును శోధించండి → ఫలితంగా వచ్చిన **"Microsoft Foundry project"** (పేరెంట్ ఖాతా కాదు) టైప్ పై క్లిక్ చేయండి.
3. **Access control (IAM)** → **+ Add** → **Add role assignment**.
4. పాత్ర: **Azure AI User** → తర్వాత.
5. సభ్యులు: మీతోను ఎంపిక చేసుకోండి → సమీక్షించి కేటాయించండి → సమీక్షించి కేటాయించండి.
6. **1–2 నిమిషాలు వేచి ఉండు** → మళ్ళీ ప్రయత్నించండి.

> **ఏందుకు Owner/Contributor సరిపోదు:** ఈ పాత్రలు *నిర్వహణ* చర్యలను మాత్రమే ఇస్తాయి. ఏజెంట్ ఆపరేషన్లు `agents/write` *డేటా చర్య* అవసరం, ఇది `Azure AI User`, `Azure AI Developer`, లేదా `Azure AI Owner` లో మాత్రమే ఉంటుంది. దయచేసి [Foundry RBAC docs](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) ని చూడండి.

### 1.2 ప్రొవిజనింగ్ సమయంలో `AuthorizationFailed`

**పరిష్కారం:** మీ అడ్మిన్‌కి రిసోర్స్ గ్రూప్ పై **Contributor** కేటాయించమని అడగండి, లేక వారు ప్రాజెక్ట్ సృష్టించి మీరు అందులో **Azure AI User** గా అంగీకరించనివ్వండి.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# "నమోదు చేసింది" వరకు అయిన వరకు వేచి ఉండండి
```

## 2. డాకర్ దోషాలు

> డాకర్ **ఐచ్చికం** మాత్రమే. ఇవి డాకర్ డెస్క్టాప్ ఇన్స్టాల్ చేసి ఎక్స్‌టెన్షన్ లోకల్ బిల్డ్ చేయడానికి ప్రయత్నించినప్పుడు వర్తించును.

### 2.1 డాకర్ డీమోన్ నడుస్తున్న లేదు

**పరిష్కారం:** డాకర్ డెస్క్టాప్ ప్రారంభించండి → "running" స్థితి కోసం వేచి ఉండండి → `docker info` తో ధృవీకరించండి → మళ్ళీ ప్రయత్నించండి.

### 2.2 డిపెండెన్సీ దోషాలతో బిల్డ్ విఫలమవుతుంది

**పరిష్కారం:** `requirements.txt` వ్యాకరణం సరి చూడండి, ముందుగా లోకల్ గా పరీక్షించండి: `pip install -r requirements.txt`.

### 2.3 ప్లాట్‌ఫారమ్ అసమ్మతి (ఆపిల్ సిలికాన్)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. ఆథెంటికేషన్ దోషాలు

### 3.1 `DefaultAzureCredential` విఫలం

**పరిష్కారం (క్రమంలో ప్రయత్నించండి):**
1. `az login` (మళ్ళీ సంతకం)
2. `az account set --subscription "<id>"` (సరిగా సబ్‌స్క్రిప్షన్ సెట్ చేయండి)
3. VS కోడ్ → ఖాతాలు → సైన్ అవుట్ → మళ్ళీ సైన్ ఇన్ అవ్వండి
4. ధృవీకరించండి: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 లోకల్‌లో టోకెన్ పనిచేస్తుంది కానీ హోస్ట్‌డ్‌లో కాదు

**అంచనా:** హోస్ట్‌డ్ ఏజెంట్లు సిస్టమ్ నిర్వహించబడిన ఐడెంటిటీ ఉపయోగిస్తాయి, మీ క్రెడెన్షియల్ కాదు. హోస్ట్‌డ్ ఏజెంట్ ఆథ్ లోపాలు వస్తే:
- `agent.yaml` లో `AZURE_AI_PROJECT_ENDPOINT` సరిగా ఉందా అని ధృవీకరించండి
- ప్రాజెక్ట్ యొక్క నిర్వహించిన ఐడెంటిటీకి మోడల్ యాక్సెస్ ఉందా అని తనిఖీ చేయండి

## 4. మోడల్ దోషాలు

### 4.1 మోడల్ డిప్లాయ్మెంట్ కనబడలేదు

**పరిష్కారం:** పేరు **కేస్-సెంసిటివ్**. `.env` లో `AZURE_AI_MODEL_DEPLOYMENT_NAME` ను ఫౌండ్రీ sidebar → Models లోని నిజమైన పేరుతో పోల్చండి.

### 4.2 అనుకోని మోడల్ అవుట్పుట్

**పరిష్కారం:** `main.py` లో `AGENT_INSTRUCTIONS` ను సమీక్షించండి (కట్ అయినదా చూడండి?). వేరే మోడల్ ప్రయత్నించండి (`gpt-4.1` vs `gpt-4.1-mini`).

## 5. డిప్లాయ్మెంట్ దోషాలు

### 5.1 ACR_PULL అనధికారికంగా ఉంది

**పరిష్కారం:** Azure Portal → Container Registry → Access control (IAM) → Foundry ప్రాజెక్ట్ నిర్వహించిన ఐడెంటిటీకి **AcrPull** పాత్ర జోడించండి.

### 5.2 ఏజెంట్ ప్రారంభం విఫలం (అది "Pending" లేదా "Failed" ఉండటం)

సైడ్‌బార్ లో కంటైనర్ లాగ్స్ తనిఖీ చేయండి. సాధారణ కారణాలు:

| లాగ్ సందేశం | పరిష్కారం |
|-------------|-----|
| `ModuleNotFoundError` | మిస్సింగ్ ప్యాకేజ్ `requirements.txt` కి జతచేయండి, మళ్ళీ డిప్లాయ్ చేయండి |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | `agent.yaml` లో `environment_variables` కింద env var జోడించండి |
| `Address already in use` | ఒకే ఒక ప్రాసెస్ మాత్రమే పోర్ట్ 8088 ను బైండ్ చేశాడో చూసుకోండి |

### 5.3 డిప్లాయ్మెంట్ సమయం పూర్తికాకుండా పోయింది

**పరిష్కారం:** ఇంటర్నెట్ కనెక్షన్ తనిఖీ చేయండి. మొదటి డిప్లాయ్ >100MB డేటాను పంపుతుంది. ప్రాక్సీ వైపు ఉన్నారా? డాకర్ డెస్క్టాప్ ప్రాక్సీ సెట్టింగ్స్ సర్చికండి.

## 6. పాత్ B - Foundry లోకల్

### 6.1 Foundry లోకల్ మొదలుకాగలదు కాదేమో

| సమస్య | పరిష్కారం |
|-------|-----|
| `foundry: command not found` | మళ్లీ ఇన్‌స్టాల్ చేయండి: `winget install Microsoft.FoundryLocal` |
| సమర్థవంతమైన వనరులు తక్కువగా ఉన్నాయి | Foundry Local కు సుమారు 4GB RAM ఖాళీ కావాలి. ఇతర యాప్స్ మూసివేయండి. |
| మోడల్ డౌన్లోడ్ విఫలమవుతుంది | డిస్క్ స్థలాన్ని తనిఖీ చేయండి (మోడల్స్ 2–8 GB ఉంటాయి). మళ్ళీ ప్రయత్నించండి: `foundry local models pull <name>` |

### 6.2 Foundry లోకల్ మోడల్ దోషాలు

| సమస్య | పరిష్కారం |
|-------|-----|
| స్లో ప్రతిస్పందనలు | అందుబాటులో ఉన్న CPU మెతడు ఆధారంగా ప్రదేశిక మోడల్స్ నడుస్తాయి GPU లేకపోతే. ఓవర్తించండి. |
| తక్కువ నాణ్యత అవుట్పుట్ | మీ హార్డ్‌వేర్ అనుమతిస్తే పెద్ద మోడల్ ప్రయత్నించండి. `phi-4-mini` ఒక మంచి సమతుల్యత. |
| కనెక్షన్ తిరస్కరించబడింది | Foundry Local నడుస్తోందా అన్నది ధృవీకరించండి: `foundry local status`. అవసరమైతే రీస్టార్ట్ చేయండి. |

## 7. দ্রুত సూచన: RBAC పాత్రలు

| పాత్ర | పరిధి | ఇస్తోంది |
|------|-------|--------|
| **Azure AI User** | ప్రాజెక్ట్ | డేటా చర్యలు: `agents/write`, `agents/read` |
| **Azure AI Developer** | ప్రాజెక్ట్/ఖాతా | డేటా చర్యలతో పాటు ప్రాజెక్ట్ సృష్టి |
| **Azure AI Owner** | ఖాతా | పూర్తి యాక్సెస్ + పాత్ర నిర్వహణ |
| **Contributor** | సబ్‌స్క్రిప్షన్/ఆర్.జీ | నిర్వహణ చర్యలు మాత్రమే (**డేటా చర్యలు లేవు**) |
| **Owner** | సబ్‌స్క్రిప్షన్/ఆర్.జీ | నిర్వహణ + పాత్ర కేటాయింపు (**డేటా చర్యలు లేవు**) |
