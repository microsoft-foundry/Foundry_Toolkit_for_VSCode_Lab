## Шта сте направили

**Оцењивач погодности резимеа за посао** - мулти-агентски хостовани ток рада који:
- Прима резиме и опис посла преко HTTP (`POST /responses`)
- Покреће четири специјализована агента у секвенцијалном ланцу - сваки агент преноси податке које његов наследник захтева
- Враћа оцену погодности (0–100 са разложеном анализом), листу недостајућих вештина и сертификата, и персонализовани пут учења са стварним Microsoft Learn линковима за сваки пропуст
- Позива Microsoft Learn MCP сервер (`https://learn.microsoft.com/api/mcp`) да преузме званичне ресурсе за учење за сваки идентификовани јаз у вештинама
- Покреће се као један контејнеризовани хостовани агент у Microsoft Foundry Agent Service

## Кључни концепти које сте научили

| Концепт | Шта сте вежбали |
|---------|-------------------|
| **Оркестрација мулти-агената** | `WorkflowBuilder` секвенцијални ланац са `add_edge()` |
| **Специјализација агената** | Четири фокусирана агента боља од једног агента опште намене |
| **Образац Content Router** | ResumeParser делује и као рутер - чува текст опис посла у `[JOB DESCRIPTION PASS-THROUGH]` секцији да би агенти у даљем ланцу имали приступ (потребно јер `context_mode="last_agent"` значи да само `start_executor` види необрађену корисничку поруку) |
| **Образац Content Relay** | JD Agent прослеђује `[PARSED RESUME PASS-THROUGH]` даље да би MatchingAgent добио оба профила; избегава дупли тригер са OR-семантиком који фан-ин графови узрокују |
| **Интеграција MCP алата** | `@tool` + `streamable_http_client` позива спољашњи MCP сервер |
| **Животни циклус Hosted Agent-а** | Scaffold → Конфигуриши → Локално тестирај → Имплементирај → Верификуј у облаку |
| **`context_mode="last_agent"`** | Свако извршење види само излаз свог директног претходника |
| **Foundry Toolkit ток рада** | Scaffold wizard, Agent Inspector, Workflow Visualizer, једним кликом деплој |

### Идеје за проширење овог тока рада

- **Додајте 5. агента** - Тренер за интервјуе који генерише вероватна питања за интервју на основу извештаја о јазовима
- **Додајте Bing алат за утемељење** - Нека JD Agent претражује сличне огласе за посао да обогати захтеве
- **Повежите са базом резимеа** - Повлачите профиле кандидата из базе преко прилагођеног `@tool`
- **Испробајте различите моделе** - Упоредите квалитет и латенцију излаза `gpt-4.1` и `gpt-4.1-mini`
- **Евалуирајте са Foundry** - Користите функцију Evaluations да оцењујете извештаје погодности у односу на златни скуп података

### За кориснике пута Б: Надоградите на облачно имплементирање

Када будете спремни за имплементацију у облак:
1. Набавите Azure претплату ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. Завршите [Lab 01, Module 01](../../lab01-single-agent/docs/01-setup.md) (направите пројекат, имплементирајте модел, доделите RBAC)

4. Наставите из [Module 06 - Deploy to Foundry](06-deploy-to-foundry.md)

## Очистите ресурсе (опционо)

Ако желите да уклоните Azure ресурсе направљене током овог радионичарског рада:

### Опција 1: Обришите resource group (уклања све)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### Опција 2: Обришите само hosted агент

1. Отворите [ai.azure.com](https://ai.azure.com) → ваш пројекат → **Build** → **Agents**.
2. Нађите **PersonalCareerCopilot** → кликните **Delete**.

### Опција 3: Обришите имплементацију модела

1. У Foundry sidebar-у проширите ваш пројекат → **Models**.
2. Кликните десним тастером на имплементацију модела → **Delete**.

> **Напомена о трошковима:** Hosted агенти наплаћују трошкове само док раде. Ако зауставите или обришете агента, нема даљих трошкова. Имплементација модела може наплаћивати мали износ за резервисани капацитет - обришите је ако сте завршили.
