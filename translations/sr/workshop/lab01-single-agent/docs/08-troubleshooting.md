# Модул 8 - Решавање проблема

Овај модул је водич за честе проблеме. Обележите га и вратите се када нешто крене по злу.

---

## 1. Грешке дозвола

### 1.1 `agents/write` одбијен приступ

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**Узрок:** Недостаје `Azure AI User` улога на нивоу **пројекта**. Ово је најчешћа грешка на радионици.

**Решење:**
1. Отворите [portal.azure.com](https://portal.azure.com).
2. Потражите име вашег Foundry **пројекта** → кликните на резултат типа **"Microsoft Foundry project"** (НЕ главни налог).
3. **Контрола приступа (IAM)** → **+ Додај** → **Додај доделу улоге**.
4. Улога: **Azure AI User** → Даље.
5. Чланови: Изаберите себе → Преглед + додели → Преглед + додели.
6. **Сачекајте 1–2 минута** → покушајте поново.

> **Зашто Owner/Contributor није довољно:** Ове улоге омогућавају само *управљачке* акције. Операције агента захтевају `agents/write` *data action*, која је доступна само у `Azure AI User`, `Azure AI Developer` или `Azure AI Owner`. Погледајте [Foundry RBAC документацију](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` током провизије

**Решење:** Замолите администратора да вам додели улогу **Contributor** на групи ресурса, или нека он направи пројекат за вас и додели вам **Azure AI User** на њему.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Wait until: "Registered"
```

## 2. Docker грешке

> Docker је **опционо**. Ове грешке важе само ако је Docker Desktop инсталиран и екстензија покушава локалну израду.

### 2.1 Docker демон није покренут

**Решење:** Покрените Docker Desktop → сачекајте да статус буде "running" → проверите са `docker info` → покушајте поново.

### 2.2 Израда неуспешна због грешака у зависностима

**Решење:** Проверите правопис `requirements.txt`, прво тестирајте локално: `pip install -r requirements.txt`.

### 2.3 Неусклађеност платформе (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. Аутентификационе грешке

### 3.1 `DefaultAzureCredential` не успева

**Решење (пробајте редом):**
1. `az login` (понављена аутентификација)
2. `az account set --subscription "<id>"` (тачна претплата)
3. VS Code → Налози → Одјави се → Пријави се поново
4. Потврдите: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 Токен ради локално али не и на хостованом

**Очекује се:** Хостовани агенти користе системски управљани идентитет, не ваше акредитације. Ако хостовани агент добија грешке у аутентификацији:
- Потврдите да `AZURE_AI_MODEL_DEPLOYMENT_NAME` у `agent.yaml` резолује на име вашег распоређивања модела (`FOUNDRY_PROJECT_ENDPOINT` се убацује од стране Foundry у тренутку извршења - немојте га декларисати у `agent.yaml`)
- Проверите да ли пројектни управљани идентитет има приступ моделу

## 4. Грешке модела

### 4.1 Распоређивање модела није пронађено

**Решење:** Име је **осетљиво на величину слова**. Упоредите `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` са тачним именом у Foundry бочној траци → Models.

### 4.2 Неочекиван излаз модела

**Решење:** Прегледајте `AGENT_INSTRUCTIONS` у `main.py` (да ли је скучен). Испробајте други модел (`gpt-4.1` против `gpt-4.1-mini`).

---

## 5. Грешке распоређивања

### 5.1 Непоједначен приступ извлачењу из ACR-а

**Решење:** Azure Portal → Container Registry → Контрола приступа (IAM) → Додајте улогу **AcrPull** управљаном идентитету Foundry пројекта.

### 5.2 Агент не успева да се покрене (остаје "Pending" или "Failed")

Проверите логове контејнера у бочној траци. Чести узроци:

| Порука лога | Решење |
|-------------|-----|
| `ModuleNotFoundError` | Додајте недостајући пакет у `requirements.txt`, поново распореди |
| `ValueError: Missing required environment variables` | Потврдите да је `AZURE_AI_MODEL_DEPLOYMENT_NAME` деклараисан у `agent.yaml` под `environment_variables` и има вредност, затим поново распореди. `FOUNDRY_PROJECT_ENDPOINT` се убацује од стране Foundry у тренутку извршења |
| `Address already in use` | Уверите се да само један процес користи порт 8088 |

### 5.3 Време распоређивања истиче

**Решење:** Проверите интернет везу. Прво распоређивање вуче >100MB. Сте иза проксија? Подесите прокси за Docker Desktop.

## 6. Путања Б - Foundry Local

### 6.1 Foundry Local се не покреће

| Проблем | Решење |
|-------|-----|
| `foundry: command not found` | Поново инсталирајте: `winget install Microsoft.FoundryLocal` |
| Недовољно ресурса | Foundry Local захтева ~4GB слободне RAM меморије. Затворите друге апликације. |
| Преузимање модела не успева | Проверите слободан простор на диску (модели су 2–8 GB). Покушајте поново: `foundry local models pull <name>` |

### 6.2 грешке модела у Foundry Local

| Проблем | Решење |
|-------|-----|
| Спори одговори | Очекује се - локални модели раде на CPU-у ако немате GPU. Будите стрпљиви. |
| Лош квалитет излазa | Покушајте већи модел ако вам хардвер то дозвољава. `phi-4-mini` је добар баланс. |
| Веза одбијена | Потврдите да Foundry Local ради: `foundry local status`. Поново покрените ако је потребно. |

## 7. Брзи преглед: RBAC улоге

| Улога | Обим | Омогућава |
|------|-------|--------|
| **Azure AI User** | Пројекат | Акције над подацима: `agents/write`, `agents/read` |
| **Azure AI Developer** | Пројекат/Налог | Акције над подацима + креирање пројекта |
| **Azure AI Owner** | Налог | Потпун приступ + управљање улогама |
| **Contributor** | Претплата/ГР | Само управљачке акције (**без** акција над подацима) |
| **Owner** | Претплата/ГР | Управљање + додела улога (**без** акција над подацима) |
