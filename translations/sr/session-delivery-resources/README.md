# Како одржати ову сесију

Хвала што ћете одржати ову сесију!

Пре одржавања радионице, молимо вас да:

1. Прочитате овај документ и све укључене ресурсе у целости.
2. Погледате снимање одржавања сесије и прођу радионице од почетка до краја.
3. Прођете кроз оба практична лабораторијска рада од почетка до краја на свом рачунару **бар једном** пре догађаја.
4. Потврдите свој Microsoft Foundry пројекат, поставке модела и квоте.
5. Обратите се одржавачу ако нешто није јасно.

## Почетак рада

Ова радионица учи програмере како да конструишу, тестирају и распоређују AI агенте у **Microsoft Foundry Agent Service** као **Hosted Agents** у потпуности из VS Code-а, користећи екстензију **Microsoft Foundry Toolkit**.

Радионица је подељена у више секција које укључују слајдове, **2 уживо демо приказа**, и **2 практична лабораторијска рада**.

### Предуслови за тренере

Пре него што одржите сесију, уверите се да имате:

- **Azure претплату** са дозволом за прављење ресурса (Власник или Доприносилац на ресурној групи).
- Приступ **Microsoft Foundry пројекту** у [региону који подржава хостоване агенте](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability).
- Квоту за **gpt-4.1** (или **gpt-4.1-mini**) у вашем Foundry пројекту.
- Следећи алати инсталирани:
  - [Visual Studio Code](https://code.visualstudio.com/)
  - [Microsoft Foundry Toolkit extension](https://marketplace.visualstudio.com/items?itemName=ms-windows-ai-studio.windows-ai-studio)
  - [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli)
  - [Azure Developer CLI (`azd`)](https://learn.microsoft.com/azure/developer/azure-developer-cli/install-azd)
  - [Docker Desktop](https://www.docker.com/) (Опционо)
  - Python 3.12 или новији

Покрените [Hosted agents quickstart with `azd`](https://learn.microsoft.com/azure/foundry/agents/quickstarts/quickstart-hosted-agent?pivots=azd) бар једном пре одржавања како бисте имали познато добар Foundry пројекат, распоред модела и Azure Container Registry на који ћете се ослонити у случају да се неко заглави.

## Демонстрације

У оквиру изведбе укључена су два уживо демо приказа. Одвојите по 10 минута за сваки.

| Демо | Лабораторија | Датотеке | Шта показати                              |
|------|-------------|-----------|----------------------------------------|
| Извршни агент   | Лаб 01      | [`workshop/lab01-single-agent/agent/`](../../../workshop/lab01-single-agent/agent) | Један хостовани агент; преведи технички жаргон у извршни резиме |
| Resume to Job Fit Evaluator | Лаб 02      | [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot) | Оркестрација са 4 агента; оцењује усаглашеност резимеа и посла и генерише препоруку |

### Демо 1: Извршни агент

Самостални агент у [`workshop/lab01-single-agent/agent/`](../../../workshop/lab01-single-agent/agent). Користите ово као 10-минутни демо пре Лаб 01.

1. Отворите [`workshop/lab01-single-agent/agent/main.py`](../../../workshop/lab01-single-agent/agent/main.py) и прођите кроз дефиницију агента (системски упит, модел, оквир).
2. Притисните `F5` да покренете **Agent Inspector** локално.
3. Налепите пример упита из [README](../README.md#see-it-in-action) и прикажите одговор у виду извршног резимеа.
4. Прикажите [`workshop/lab01-single-agent/agent/agent.yaml`](../../../workshop/lab01-single-agent/agent/agent.yaml) и [`workshop/lab01-single-agent/agent/Dockerfile`](../../../workshop/lab01-single-agent/agent/Dockerfile) да објасните артефакте распоређивања.
5. Демонстрирајте ток распоређивања (Docker build, ACR push, креирање хостованог агента) без чекања на завршетак.

### Демо 2: Resume to Job Fit Evaluator

Четвороагентски радни ток у [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot). Користите ово као 10-минутни демо пре Лаб 02.

1. Отворите [`PersonalCareerCopilot/main.py`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/main.py) и прикажите како су четворица агената повезана у секвенцијалну оркестрацију.
2. Притисните `F5` да покренете **Agent Inspector** за вишеважни радни ток.
3. Налепите кратак опис посла и пример резимеа у Инспекторов ћаскав.
4. Прођите кроз четвороагентски ланац: трансформатор резимеа, извукац захтева посла, оцењивач усаглашености и писац препорука.
5. Истакните како излаз сваког подагента постаје контекст следећег агента, наглашавајући образац предаје.
6. Прикажите [`PersonalCareerCopilot/agent.yaml`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/agent.yaml) како бисте упоредили са једноагентским еквивалентом из Демо 1.

## Савети за одржавање

- **Рано поставите очекивања.** Хостовани агенти су у прегледу - унапред помените регионалне ограничења и квоте да учесници не би били изненађени током лабораторије.
- **Прво покрените предуслове.** Обе лабораторије укључују `Validate prerequisites` VS Code задатак - нека учесници то покрену пре него што почну да пишу код.
- **Држите Agent Inspector видљивим.** Већина "аха" момената догађа се када учесници виде локални `/responses` петљу како се пали.
- **Имајте резервни пројекат.** Ако негде учесников Foundry пројекат достигне квоту, поделите унапред припремљени пројекат за корак распоређивања да не би блокирали простор.
- **Спаривајте учеснике.** Лаб 02 (вишеважни) је значајно лакши када учесници могу разговарати о оркестрацији са партнером.
- **Користите docs модуле као контролне тачке.** Свaка `docs/` фасцикла лабораторије подељена је у нумерисане модуле - користите их као природне тачке за паузу.
- **Унапред повуците базни Docker слику** на заједничким рачунарима за лабораторије да бисте избегли ограничења брзине регистра.

## Решавање проблема током извођења

| Симптом                                           | Прво што треба пробати                                                                                       |
|--------------------------------------------------|-------------------------------------------------------------------------------------------------------------|
| Agent Inspector не може да се повеже              | Потврдите да је порт `8088` слободан и да је задатак `Run Agent HTTP Server` покренут.                  |
| Debugger не може да се прикачи                   | Проверите да је порт `5679` слободан; поново покрените VS Code ако је `debugpy` већ заузет. |
| `azd up` не успева са општим аутх грешком | Покрените `az login` и `azd auth login`, уверите се да је изабран прави тенаnт.                      |
| Извођење се заглави на ACR push                   | Проверите да ли Docker Desktop ради и да корисник има `AcrPush` на регистру.                          |
| Модел враћа 404 / deployment-not-found            | Име развоја модела у `agent.yaml` мора да одговара развоју у Foundry пројекту.                          |
| Hosted agent заглављен у `Provisioning`          | Потврдите да регија пројекта [подржава hosted агенте](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability) и да има доступну квоту.       |
| Playground враћа 401                               | Поново аутентификујте Foundry екстензију кроз VS Code траку активности.                                       |

За детаљније смернице, свака лабораторија садржи свој `08-troubleshooting.md` документ - упутите учеснике тамо:

- Лабораторија 01: [`workshop/lab01-single-agent/docs/08-troubleshooting.md`](../workshop/lab01-single-agent/docs/08-troubleshooting.md)
- Лабораторија 02: [`workshop/lab02-multi-agent/docs/08-troubleshooting.md`](../workshop/lab02-multi-agent/docs/08-troubleshooting.md)

## Прилагођавање ове сесије

Добродошли сте да прилагодите радионицу својој публици. Честе варијације:

- **За публику из Backend-а:** проведите више времена на `agent.yaml`, Docker-у и ACR-у; скратите playground демонстрацију.
- **За публику Citizen-developera:** останите у Foundry екстензији за скелетонирање; смањите CLI кораке.
- **Једна трака, 60 минута:** изведите само увод, демонстрацију и Лаб 01.
- **Само радионица (без слајдова) формат:** отвори оба лаба README и користи их као примарни сценарио.

Ако проширујете лабове, молимо вас да измене вратите путем PR-а како би други предавачи имали користи.
