# यस सत्र कसरी प्रस्तुत गर्ने

यो सत्र प्रस्तुत गर्नु भएकोमा धन्यवाद!

कार्यशाला प्रस्तुत गर्नु अघि, कृपया:

1. यो दस्तावेज र यसमा समावेश भएका सबै स्रोतहरू पूर्णरुपमा पढ्नुहोस्।
2. सत्र प्रस्तुतिको रेकर्डिङ र कार्यशालाको अन्त्यदेखि अन्तसम्मको कभरिङ हेर्नुहोस्।
3. दुबै व्यावहारिक प्रयोगशाला आफ्नै मेसिनमा **कम्तीमा एक पटक** पुरै परिक्रमा गर्नुहोस्।
4. आफ्नो Microsoft Foundry परियोजना, मोडेल परिनियोजनहरू, र कोटा जाँच गर्नुहोस्।
5. यदि केही अस्पष्ट छ भने मर्मतकर्तासँग सम्पर्क गर्नुहोस्।

### प्रशिक्षक पूर्व आवश्यकताहरू

प्रस्तुत गर्नु अघि, सुनिश्चित गर्नुहोस् कि तपाईंसँग:

- संसाधनहरू सिर्जना गर्न अनुमति भएको **Azure सदस्यता** (Resource Group मा Owner वा Contributor)।
- [होस्ट गरिएको एजेन्ट समर्थन गर्ने क्षेत्र](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability) मा रहेको **Microsoft Foundry परियोजनामा** पहुँच।
- Foundry परियोजनामा **gpt-4.1** (वा **gpt-4.1-mini**) को कोटा।
- तलका उपकरणहरू इन्स्टल गरिएको छ:
  - [Visual Studio Code](https://code.visualstudio.com/)
  - [Microsoft Foundry Toolkit एक्सटेन्सन](https://marketplace.visualstudio.com/items?itemName=ms-windows-ai-studio.windows-ai-studio)
  - [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli)
  - [Azure Developer CLI (`azd`)](https://learn.microsoft.com/azure/developer/azure-developer-cli/install-azd)
  - [Docker Desktop](https://www.docker.com/) (वैकल्पिक)
  - Python 3.10 वा त्यसपछि

प्रस्तुत गर्नु अघि कम्तीमा एक पटक [Hosted agents छिटो शुरुवात `azd` सँग](https://learn.microsoft.com/azure/foundry/agents/quickstarts/quickstart-hosted-agent?pivots=azd) चलाउनुहोस् ताकि तपाईंसँग एक प्रमाणित Foundry परियोजना, मोडेल परिनियोजन, र Azure Container Registry सन्दर्भको लागि उपलब्ध होस् यदि सिक्ने व्यक्ति अड्किए।

1. [`PersonalCareerCopilot/main.py`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/main.py) खोल्नुहोस् र चार एजेन्टहरू कसरी क्रमशः संयोजन गरिएको छ देखाउनुहोस्।
2. बहु-एजेन्ट कार्यप्रवाहका लागि **Agent Inspector** सुरु गर्न `F5` थिच्नुहोस्।

## प्रस्तुति सल्लाहहरू

- **पहिले नै अपेक्षा निर्धारण गर्नुहोस्।** होस्ट गरिएको एजेन्टहरू प्रिभ्युमा छन् - क्षेत्र सीमाहरू र कोटाको कुरा सुरुमा बताउनुहोस् ताकि सहभागीहरू प्रयोगशालाको बीचमा अचम्मित नहुन्।
- **पहिले पूर्व आवश्यकताहरूको परीक्षण गर्नुहोस्।** दुबै प्रयोगशालाले `Validate prerequisites` नामक VS Code टास्क पठाउँछन् - सहभागीहरूले कुनै पनि कोड लेख्नु अघि यसलाई चलाउन लगाउनुहोस्।
- **Agent Inspector देखिने गरि राख्नुहोस्।** धेरै "आहा" क्षणहरू तब हुन्छन् जब सिक्नेहरूले स्थानीय `/responses` राउन्ड-ट्रिप हाइलाइट देख्छन्।
- **ब्याकअप परियोजना राख्नुहोस्।** यदि कुनै सिक्ने व्यक्तिको Foundry परियोजनाले कोटा पुर्यायो भने, कोठा रोक्ने सट्टा परिनियोजन चरणका लागि एक पहिले नै प्रावधान गरिएको परियोजना साझा गर्नुहोस्।
- **सहभागीहरूलाई जोडीमा राख्नुहोस्।** प्रयोगशाला 02 (बहु-एजेन्ट) सिक्नेहरूले साझेदारसँग छलफल गर्दा अर्थपूर्ण रूपमा सजिलो हुन्छ।
- **कागजात मोड्युलहरूलाई जाँच बिन्दुका रूपमा प्रयोग गर्नुहोस्।** हरेक प्रयोगशालाको `docs/` फोल्डर ८ अंकित मोड्युलहरूमा विभाजित छ - तीलाई प्राकृतिक विराम बिन्दुका रूपमा प्रयोग गर्नुहोस्।
- साझा प्रयोगशाला मेसिनहरूमा आधार Docker इमेज **पहिले खिच्नुहोस्** ताकि रजिस्ट्री दर सीमाहरूबाट बच्न सकियोस्।

## यो सत्र अनुकूलन गर्दै

तपाईं आफ्नो दर्शकहरुका लागि कार्यशाला अनुकूलन गर्न स्वतन्त्र हुनुहुन्छ। सामान्य भिन्नताहरू:

- **ब्याकएन्ड दर्शकहरू:** `agent.yaml`, Docker, र ACR मा बढी समय बिताउनुहोस्; प्राङ्गण डेमोलाई छोट्याउनुहोस्।
- **नागरिक-विकासकर्ता दर्शकहरू:** Foundry विस्तार UI मा स्क्याफोल्डिङका लागि रहनुहोस्; CLI चरणहरू घटाउनुहोस्।
- **एकल-ट्र्याक ६०-मिनेट स्लॉट:** मात्र परिचय, डेमो, र ल्याब ०१ मात्र प्रस्तुत गर्नुहोस्।
- **वर्कशप मात्र (स्लाइड बिना) फारम्याट:** दुबै ल्याबको रिडमीहरू खोल्नुहोस् र तिनीहरूलाई प्राथमिक स्क्रिप्टको रूपमा प्रयोग गर्नुहोस्।

यदि तपाईंले ल्याबहरू विस्तार गर्नुभयो भने, कृपया परिवर्तनहरू PR मार्फत फिर्ता योगदान दिनुहोस् ताकि अन्य प्रशिक्षकहरूलाई फाइदा पुग्ला।
