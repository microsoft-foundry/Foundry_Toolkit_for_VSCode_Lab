# मोड्युल ८ - समस्या समाधान

यो मोड्युल सामान्य समस्याहरूको लागि एक संदर्भ मार्गदर्शक हो। यसलाई बुकमार्क गर्नुहोस् र केही गलत हुँदा फर्केर आउनुहोस्।

---

## १. अनुमति त्रुटिहरू

### १.१ `agents/write` अनुमति अस्वीकृत

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**मूल कारण:** `Azure AI User` भूमिका **प्रोजेक्ट** स्तरमा हराइरहेको छ। यो #1 कार्यशाला त्रुटि हो।

**समाधान:**
1. [portal.azure.com](https://portal.azure.com) खोल्नुहोस्।
2. आफ्नो Foundry **प्रोजेक्ट** नाम खोज्नुहोस् → प्रकारको परिणाममा क्लिक गर्नुहोस् **"Microsoft Foundry project"** (अभिभावक खातामा होइन)।
3. **Access control (IAM)** → **+ Add** → **Add role assignment** मा जानुहोस्।
4. भूमिका: **Azure AI User** → अर्को।
5. सदस्यहरू: आफैलाई चयन गर्नुहोस् → समीक्षा + असाइन → समीक्षा + असाइन।
6. **1–2 मिनेट पर्खनुहोस्** → पुनः प्रयास गर्नुहोस्।

> **किन Owner/Contributor पर्याप्त छैन:** यी भूमिकाहरूले केवल *प्रबन्धन* कार्यहरू दिनेछन्। एजेन्ट अपरेसनहरूले `agents/write` *डेटा कार्य* आवश्यक पर्छ, जुन केवल `Azure AI User`, `Azure AI Developer`, वा `Azure AI Owner` मा हुन्छ। हेर्नुहोस् [Foundry RBAC डकुमेन्टहरू](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry)।

### 1.2 `AuthorizationFailed` प्रोभिजनिङको समयमा

**समाधान:** तपाइँको एडमिनलाई स्रोत समूहमा **Contributor** नियुक्त गर्न भन्नुहोस्, वा उनीहरूलाई तपाईंको लागि प्रोजेक्ट सिर्जना गर्न र तपाईंलाई त्यहाँ **Azure AI User** दिन भन्नुहोस्।

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Wait until: "Registered"
```

## 2. Docker त्रुटिहरू

> Docker **वैकल्पिक** छ। यी तब मात्र लागू हुन्छन् जब Docker Desktop स्थापना गरिएको छ र विस्तारले स्थानीय निर्माण प्रयास गर्छ।

### 2.1 Docker daemon चलिरहेको छैन

**समाधान:** Docker Desktop सुरु गर्नुहोस् → "running" स्थिति को पर्खनुहोस् → `docker info` सँग प्रमाणित गर्नुहोस् → पुनः प्रयास गर्नुहोस्।

### 2.2 निर्भरता त्रुटिहरूको कारण बिल्ड असफल हुन्छ

**समाधान:** `requirements.txt` को वर्तनी जाँच गर्नुहोस्, पहिलो स्थानीय रूपमा परीक्षण गर्नुहोस्: `pip install -r requirements.txt`।

### 2.3 प्लेटफर्म असङ्गति (एप्पल सिलिकन)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. प्रमाणीकरण त्रुटिहरू

### 3.1 `DefaultAzureCredential` असफल हुन्छ

**समाधान (क्रम अनुसार प्रयास गर्नुहोस्):**
1. `az login` (पुनः प्रमाणीकरण)
2. `az account set --subscription "<id>"` (सही सदस्यता)
3. VS Code → खाताहरू → साइन आउट → फेरि साइन इन गर्नुहोस्
4. जाँच गर्नुहोस्: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 टोकन स्थानीय रूपमा काम गर्छ तर होस्ट गरिएको छैन

**अपेक्षित:** होस्ट गरिएको एजेन्टहरू प्रणाली-प्रबन्धित पहिचान प्रयोग गर्छन्, तपाईंको प्रमाणपत्र होइन। यदि होस्ट गरिएको एजेन्टमा प्रमाणीकरण त्रुटि आउँछ भने:
- `AZURE_AI_MODEL_DEPLOYMENT_NAME` लाई जाँच गर्नुहोस् कि यो `agent.yaml` मा तपाईंको मोडेल परिनियोजन नाममा समाधान हुन्छ (`FOUNDRY_PROJECT_ENDPOINT` Foundry द्वारा रनटाइममा इंजेक्ट गरिन्छ - यसलाई `agent.yaml` मा घोषणा नगर्नुहोस्)
- परियोजनाको प्रबन्धित पहिचानसँग मोडेल पहुँच छ कि छैन जाँच गर्नुहोस्

---

## ४. मोडेल त्रुटिहरू

### 4.1 मोडेल परिनियोजन फेला परेन

**समाधान:** नाम **अपरमाणित संवेदनशील** छ। Foundry साइडबार → मोडेलहरूमा भएको सही नामसँग `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` तुलना गर्नुहोस्।

### 4.2 अप्रत्याशित मोडेल आउटपुट

**समाधान:** `AGENT_INSTRUCTIONS` मा `main.py` समीक्षा गर्नुहोस् (छाँटकाँट गरिएको छैन?). विभिन्न मोडेल प्रयास गर्नुहोस् (`gpt-4.1` बनाम `gpt-4.1-mini`)।

---

## 5. परिनियोजन त्रुटिहरू

### 5.1 ACR पुल अनधिकृत

**समाधान:** Azure पोर्टल → कन्टेनर रजिस्ट्री → एक्सेस कन्ट्रोल (IAM) → Foundry प्रोजेक्टको व्यवस्थापित पहिचानमा **AcrPull** भूमिका थप्नुहोस्।

### 5.2 एजेन्ट सुरु हुन असफल (अवस्थित "पेंडिंग" वा "फेल्ड")

साइडबारमा कन्टेनर लगहरू जाँच गर्नुहोस्। सामान्य कारणहरू:

| लग सन्देश | समाधान |
|-------------|-----|
| `ModuleNotFoundError` | `requirements.txt` मा हराइरहेको प्याकेज थप्नुहोस्, पुनः डिप्लोय गर्नुहोस् |
| `ValueError: Missing required environment variables` | पुष्टि गर्नुहोस् कि `AZURE_AI_MODEL_DEPLOYMENT_NAME` को घोषणा `agent.yaml` भित्र `environment_variables` अन्तर्गत गरिएको छ र मान छ, त्यसपछि पुनः डिप्लोय गर्नुहोस्। `FOUNDRY_PROJECT_ENDPOINT` Foundry द्वारा रनटाइममा इन्जेक्ट गरिएको छ |
| `Address already in use` | सुनिश्चित गर्नुहोस् कि पोर्ट 8088 मा केवल एक प्रक्रिया बाँधिएको छ |

### 5.3 डिप्लोइमेन्ट समय समाप्त हुन्छ

**समाधान:** इन्टरनेट कनेक्सन जाँच गर्नुहोस्। पहिलो डिप्लोयले >100MB पठाउँछ। प्रोक्सी पछाडि छ? Docker डेस्कटप प्रोक्सी सेटिङहरू कन्फिगर गर्नुहोस्।

## 6. पथ B - Foundry लोकल

### 6.1 Foundry लोकल सुरु हुँदैन

| समस्या | समाधान |
|-------|-----|
| `foundry: command not found` | पुन: स्थापना गर्नुहोस्: `winget install Microsoft.FoundryLocal` |
| स्रोतहरू अपर्याप्त | Foundry लोकललाई लगभग 4GB RAM खाली चाहिन्छ। अन्य अनुप्रयोगहरू बन्द गर्नुहोस्। |
| मोडेल डाउनलोड असफल | डिस्क स्पेस जाँच गर्नुहोस् (मोडेलहरू 2–8 GB का हुन्छन्)। पुन: प्रयास गर्नुहोस्: `foundry local models pull <name>` |

### 6.2 Foundry लोकल मोडेल त्रुटिहरू

| समस्या | समाधान |
|-------|-----|
| प्रतिक्रिया ढिलो | अपेक्षित - स्थानीय मोडेलहरू CPU मा चल्छन् जबसम्म तपाईंसँग GPU छैन। धैर्य राख्नुहोस्। |
| कमजोर गुणस्तर आउटपुट | यदि तपाईंसँग हार्डवेयर अनुमति छ भने ठूलो मोडेल प्रयास गर्नुहोस्। `phi-4-mini` राम्रो सन्तुलन हो। |
| कनेक्शन अस्वीकृत | Foundry लोकल चलिरहेको छ भनेर पुष्टि गर्नुहोस्: `foundry local status`। आवश्यक परे पुनः सुरु गर्नुहोस्। |

## 7. छिटो सन्दर्भ: RBAC भूमिका

| भूमिका | दायरा | अनुमति दिन्छ |
|------|-------|--------|
| **Azure AI प्रयोगकर्ता** | प्रोजेक्ट | डेटा कार्यहरू: `agents/write`, `agents/read` |
| **Azure AI विकासकर्ता** | प्रोजेक्ट/खाता | डेटा कार्यहरू + प्रोजेक्ट सिर्जना |
| **Azure AI मालिक** | खाता | पूर्ण पहुँच + भूमिका व्यवस्थापन |
| **योगदानकर्ता** | सदस्यता/आरजी | व्यवस्थापन कार्यहरू मात्र (**डेटा कार्यहरू छैनन्**) |
| **मालिक** | सदस्यता/आरजी | व्यवस्थापन + भूमिका असाइनमेन्ट (**डेटा कार्यहरू छैनन्**) |
