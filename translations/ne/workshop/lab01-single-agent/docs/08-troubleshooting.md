# मोड्युल ८ - समस्या समाधान

यो मोड्युल सामान्य समस्याहरूको लागि सन्दर्भ मार्गदर्शक हो। यसलाई बुकमार्क गर्नुहोस् र केही गलत भएमा फर्कनुहोस्।

---

## १. अनुमति त्रुटिहरू

### १.१ `agents/write` अनुमति अस्वीकृत

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**मूल कारण:** **परियोजना** स्तरमा `Azure AI User` भूमिका बाहेक छ। यो #1 कार्यशाला त्रुटि हो।

**समाधान:**
१. [portal.azure.com](https://portal.azure.com) खोल्नुहोस्।
२. आफ्नो Foundry **परियोजना** नाम खोज्नुहोस् → **"Microsoft Foundry project"** प्रकारको परिणाममा क्लिक गर्नुहोस् (अभिभावक खाता होइन)।
३. **Access control (IAM)** → **+ Add** → **Add role assignment**।
४. भूमिका: **Azure AI User** → अर्को।
५. सदस्यहरू: आफै चयन गर्नुहोस् → समीक्षा + असाइन → समीक्षा + असाइन।
६. **१–२ मिनेट पर्खनुहोस्** → पुनः प्रयास गर्नुहोस्।

> **किन Owner/Contributor पर्याप्त छैन:** यी भूमिकाहरूले केवल *प्रबन्धन* क्रियाहरू दिन्छन्। एजेन्ट अपरेसनहरू `agents/write` *डेटा क्रिया* आवश्यक छ, जुन केवल `Azure AI User`, `Azure AI Developer`, वा `Azure AI Owner` मा मात्र छ। [Foundry RBAC कागजातहरू](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) हेर्नुहोस्।

### १.२ प्रावधानिकरणको समयमा `AuthorizationFailed`

**समाधान:** तपाईंको प्रशासकलाई स्रोत समूहमा **Contributor** असाइन गर्न भन्नुहोस्, वा तिनीहरूलाई तपाईंको लागि परियोजना सिर्जना गरेर त्यसमा तपाईंलाई **Azure AI User** दिन भन्नुहोस्।

### १.३ `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# पर्खनुहोस् जबसम्म: "दर्ता भएको"
```

## २. डकर त्रुटिहरू

> डकर **ऐच्छिक** हो। यी तब मात्र लागु हुन्छन् जब डकर डेस्कटप इन्स्टल गरिएको छ र विस्तारले स्थानीय निर्माण प्रयास गर्छ।

### २.१ डकर डेमन चलिरहेको छैन

**समाधान:** डकर डेस्कटप सुरु गर्नुहोस् → "running" स्थिति पर्खनुहोस् → `docker info` बाट पुष्टि गर्नुहोस् → पुनः प्रयास गर्नुहोस्।

### २.२ निर्भरता त्रुटिहरूका साथ निर्माण असफल

**समाधान:** `requirements.txt` वर्तनी जाँच गर्नुहोस्, पहिले स्थानीय रूपमा परीक्षण गर्नुहोस्: `pip install -r requirements.txt`।

### २.३ प्लेटफर्म असंगति (एप्पल सिलिकन)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## ३. प्रमाणीकरण त्रुटिहरू

### ३.१ `DefaultAzureCredential` असफल

**समाधान (क्रममा प्रयास गर्नुहोस्):**
१. `az login` (पुनः प्रमाणीकरण)
२. `az account set --subscription "<id>"` (सही सदस्यता)
३. VS Code → खाताहरू → साइन आउट → फेरि साइन इन
४. पुष्टि गर्नुहोस्: `az account get-access-token --resource https://cognitiveservices.azure.com`

### ३.२ टोकन स्थानीय रूपमा काम गर्छ तर होस्ट गरिएकोमा हुन्न

**अपेक्षित:** होस्ट एजेन्टहरूले तपाईंको क्रेडेन्शियल होइन, प्रणाली-प्रबन्धित पहिचान प्रयोग गर्छन्। होस्ट एजेन्टलाई प्रमाणीकरण त्रुटिहरू आएमा:
- `agent.yaml` मा `AZURE_AI_PROJECT_ENDPOINT` सही छ कि छैन जाँच गर्नुहोस्
- परियोजनाको प्रबन्धित पहिचानसँग मोडेल पहुँच छ कि छैन जाँच गर्नुहोस्

---

## ४. मोडेल त्रुटिहरू

### ४.१ मोडेल प्रावधान फेला परेन

**समाधान:** नाम **केस-संवेदनशील** छ। `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` सटीक नामलाई Foundry साइडबार → मोडेलहरूमा तुलना गर्नुहोस्।

### ४.२ अनपेक्षित मोडेल आउटपुट

**समाधान:** `main.py` मा `AGENT_INSTRUCTIONS` समीक्षा गर्नुहोस् (ट्रन्केटेड होइन?). फरक मोडेल प्रयास गर्नुहोस् (`gpt-4.1` बनाम `gpt-4.1-mini`)।

---

## ५. प्रावधान त्रुटिहरू

### ५.१ ACR पुल अनधिकृत

**समाधान:** Azure Portal → Container Registry → Access control (IAM) → Foundry परियोजनाको प्रबन्धित पहिचानमा **AcrPull** भूमिका थप्नुहोस्।

### ५.२ एजेन्ट सुरु हुन असफल (स्थिति "Pending" वा "Failed" मा रहन्छ)

साइडबारमा कन्टेनर लग जाँच गर्नुहोस्। सामान्य कारणहरू:

| लग सन्देश | समाधान |
|-------------|-----|
| `ModuleNotFoundError` | `requirements.txt` मा हराइरहेको प्याकेज थप्नुहोस्, पुनः प्रावधान गर्नुहोस् |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | `agent.yaml` मा `environment_variables` अन्तर्गत env var थप्नुहोस् |
| `Address already in use` | सुनिश्चित गर्नुहोस् कि केवल एउटा प्रक्रिया पोर्ट ८०८८ मा बाँधिएको छ |

### ५.३ प्रावधान समयमै समाप्त भयो

**समाधान:** इन्टरनेट जडान जाँच गर्नुहोस्। पहिलो प्रावधानले >१००MB पठाउँछ। प्रोक्सी पछाडि? डकर डेस्कटप प्रोक्सी सेटिङहरू कन्फिगर गर्नुहोस्।

## ६. मार्ग बी - Foundry Local

### ६.१ Foundry Local सुरु हुँदैन

| समस्या | समाधान |
|-------|-----|
| `foundry: command not found` | पुनः स्थापना गर्नुहोस्: `winget install Microsoft.FoundryLocal` |
| पर्याप्त स्रोत छैन | Foundry Local लाई ~४GB RAM खाली आवश्यक छ। अन्य एपहरू बन्द गर्नुहोस्। |
| मोडेल डाउनलोड असफल | डिस्क स्पेस जाँच गर्नुहोस् (मोडेलहरू २–८ GB छन्)। पुनः प्रयास गर्नुहोस्: `foundry local models pull <name>` |

### ६.२ Foundry Local मोडेल त्रुटिहरू

| समस्या | समाधान |
|-------|-----|
| ढिला प्रतिक्रियाहरू | अपेक्षित - स्थानीय मोडेलहरू CPU मा चल्छन् जबसम्म तपाईंसँग GPU छैन। धैर्य गर्नुहोस्। |
| खराब गुणस्तरको आउटपुट | यदि तपाईंको हार्डवेयर अनुमति दिन्छ भने ठूलो मोडेल प्रयास गर्नुहोस्। `phi-4-mini` राम्रो सन्तुलन हो। |
| कनेक्सन अस्वीकृत | Foundry Local चलिरहेको छ कि छैन जाँच गर्नुहोस्: `foundry local status`। आवश्यक परे पुनः सुरु गर्नुहोस्। |

## ७. छिटो सन्दर्भ: RBAC भूमिकाहरू

| भूमिका | सीमा | अनुमति दिन्छ |
|------|-------|--------|
| **Azure AI User** | परियोजना | डेटा क्रियाहरू: `agents/write`, `agents/read` |
| **Azure AI Developer** | परियोजना/खाता | डेटा क्रियाहरू + परियोजना सिर्जना |
| **Azure AI Owner** | खाता | पूर्ण पहुँच + भूमिका व्यवस्थापन |
| **Contributor** | सदस्यता/आरजी | केवल प्रबन्धन क्रियाहरू (**डेटा क्रिया छैन**) |
| **Owner** | सदस्यता/आरजी | प्रबन्धन + भूमिका असाइनमेन्ट (**डेटा क्रिया छैन**) |
