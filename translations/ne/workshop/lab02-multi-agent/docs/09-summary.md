# मोड्युल ९ - सारांश र अर्को चरणहरू

⏱️ ~५ मिनेट

**बधाई छ!** तपाईंले Microsoft Foundry र Foundry Toolkit for VS Code प्रयोग गरेर एक बहु-एजेन्ट वर्कफ्लो निर्माण, परीक्षण, र (यदि Path A मा हुनुहुन्छ भने) तैनाथ गर्नुभएको छ।

---

## तपाईंले के बनाउनु भयो

**Resume → Job Fit Evaluator** - एक बहु-एजेन्ट होस्ट गरिएको वर्कफ्लो जसले:
- HTTP मार्फत रिजुमे + जागिर विवरण प्राप्त गर्छ (`POST /responses`)
- चार विशेष एजेन्टहरूलाई अनुक्रमिक पाइपलाइनमा चलाउँछ - प्रत्येक एजेन्टले यसको उत्तराधिकारीले चाहिने डाटा सञ्‍चार गर्छ
- फिट स्कोर (०–१०० फ्रयाक्सनसहित), सीप र प्रमाणपत्रको अन्तर सूची, र प्रत्येक अन्तरका लागि वास्तविक Microsoft Learn लिङ्कसहित व्यक्तिगत सिकाइ रोडम्याप फर्काउँछ
- Microsoft Learn MCP सर्भर (`https://learn.microsoft.com/api/mcp`) कल गर्छ प्रत्येक पहिचान गरिएको सीप अन्तरका लागि आधिकारिक सिकाइ स्रोतहरू ल्याउन
- Microsoft Foundry Agent Service मा एकल कन्टेनरयुक्त होस्ट गरिएको एजेन्टको रूपमा चल्छ

## मुख्य अवधारणाहरू जुन सिक्नुभयो

| अवधारणा | तपाईंले अभ्यास गर्नुभएको |
|---------|-------------------|
| **बहु-एजेन्ट अरेञ्जमेन्ट** | `WorkflowBuilder` अनुक्रमिक पाइपलाइन `add_edge()` सहित |
| **एजेन्ट विशेषज्ञता** | चार केन्द्रित एजेन्टहरूले एक सामान्य-उद्देश्य एजेन्टभन्दा राम्रो प्रदर्शन गर्छ |
| **सामग्री राउटर प्याटर्न** | ResumeParser ले राउटरको रूपमा पनि काम गर्छ - यसले JD पाठ `[JOB DESCRIPTION PASS-THROUGH]` सेक्सनमा राख्छ ताकि तलका एजेन्टहरूले पहुँच गर्न सकोस् (आवश्यक कारण `context_mode="last_agent"`ले मात्र `start_executor` ले कच्चा प्रयोगकर्ता सन्देश देख्छ) |
| **सामग्री सञ्चार प्याटर्न** | JD Agentले `[PARSED RESUME PASS-THROUGH]` अगाडि पठाउँछ जसले MatchingAgent लाई दुबै प्रोफाइलहरू प्राप्त हुन्छन्; यसले OR-सेमेन्टिक्स डबल-ट्रिगर जुन फ्यान-इन ग्राफहरूले सिर्जना गर्छन्, रोक्छ |
| **MCP उपकरण एकीकरण** | `@tool` + `streamable_http_client` प्रयोग गरेर बाह्य MCP सर्भर कल गर्ने |
| **होस्टेड एजेन्ट जीवनचक्र** | Scaffold → कन्फिगर → स्थानीय रुपमा परीक्षण → तैनाथ → क्लाउडमा प्रमाणित गर्नुहोस् |
| **`context_mode="last_agent"`** | प्रत्येक कार्यकारीले केवल आफ्ना सीधै पूर्ववर्तीको आउटपुट देख्छ |
| **Foundry Toolkit वर्कफ्लो** | Scaffold विजार्ड, एजेन्ट निरीक्षक, वर्कफ्लो भिजुअलाइजर, एक-क्लिक तैनाथ |

## अर्को चरणहरू

### सिकाइ जारी राख्नुहोस्

| स्रोत | विवरण |
|----------|-------------|
| **[Agent Framework SDK सन्दर्भ](https://learn.microsoft.com/agent-framework/)** | `agent-framework-foundry`, `WorkflowBuilder`, `AgentExecutor` का लागि API डकुमेन्टहरू |
| **[MCP उपकरण सूची](https://learn.microsoft.com/azure/foundry/agents/how-to/tools/model-context-protocol)** | एजेन्टहरूलाई अन्य MCP सर्भरहरूसँग जडान गर्ने (Bing, GitHub, कस्टम) |
| **[ज्ञान थप्नुहोस् (RAG)](https://learn.microsoft.com/azure/foundry/agents/concepts/knowledge)** | एजेन्टहरूलाई कागजात, भेक्टर स्टोरहरू, वा Bing खोजबाट आधार दिनुहोस् |
| **[Foundry मूल्यांकनहरू](https://learn.microsoft.com/azure/foundry/evaluations/overview)** | स्वचालित मूल्यांकन गर्नुहोस् एजेन्ट गुणस्तर ठूलो परिमाणमा नाप्न |
| **[Microsoft Foundry डकुमेन्टेसन](https://learn.microsoft.com/azure/foundry/)** | पूर्ण प्लेटफर्म सन्दर्भ |
| **[Foundry Toolkit - नयाँ के छ](https://marketplace.visualstudio.com/items?itemName=ms-windows-ai-studio.windows-ai-studio&ssr=false#version-history)** | विस्तार रिलिज नोटहरू र परिवर्तन विवरण |

### यस वर्कफ्लोलाई विस्तार गर्ने विचारहरू

- **५ औं एजेन्ट थप्नुहोस्** - एक अन्तर्वार्ता प्रशिक्षक जसले अन्तर रिपोर्टको आधारमा सम्भावित अन्तर्वार्ता प्रश्नहरू उत्पादन गर्छ
- **एक Bing आधार उपकरण थप्नुहोस्** - JD Agent लाई समान जागिर पोस्टिङ खोज्न दिनुहोस् आवश्यकताहरूलाई समृद्ध बनाउन
- **रिजुमे डेटाबेससँग जडान गर्नुहोस्** - क्यान्डिडेट प्रोफाइलहरू कस्टम `@tool` मार्फत डेटाबेसबाट तान्नुहोस्
- **विभिन्न मोडेलहरू प्रयास गर्नुहोस्** - `gpt-4.1` र `gpt-4.1-mini` को उत्पादन गुणस्तर र विलम्बता तुलना गर्नुहोस्
- **Foundry सँग मूल्यांकन गर्नुहोस्** - Evaluations फिचर प्रयोग गरेर फिट रिपोर्टहरूलाई सुनौलो डाटासेटसँग स्कोर गर्नुहोस्

### Path B प्रयोगकर्ताहरूका लागि: क्लाउड तैनाथमा उन्नयन गर्नुहोस्

जब तपाईं क्लाउडमा तैनाथ गर्न तयार हुनुहुन्छ:
1. Azure सदस्यता प्राप्त गर्नुहोस् ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. पूरा गर्नुहोस् [Lab 01, Module 01](../../lab01-single-agent/docs/01-setup.md) (प्रोजेक्ट सिर्जना गर्नुहोस्, मोडेल तैनाथ गर्नुहोस्, RBAC असाइन गर्नुहोस्)
3. Foundry प्रोजेक्ट अन्तबिन्दु र मोडेल तैनाथ नाम सहित आफ्नो `.env` अपडेट गर्नुहोस्
4. जारी राख्नुहोस् [Module 06 - Deploy to Foundry](06-deploy-to-foundry.md) बाट

## स्रोतहरू सफा गर्नुहोस् (वैकल्पिक)

यदि तपाईंले यो कार्यशाला दौरान सिर्जना गरिएको Azure स्रोतहरू हटाउन चाहनुहुन्छ भने:

### विकल्प १: स्रोत समूह हटाउनुहोस् (सबै कुरा मेटाउँछ)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### विकल्प २: केवल होस्टेड एजेन्ट मेटाउनुहोस्

१. खोल्नुहोस् [ai.azure.com](https://ai.azure.com) → आफ्नो प्रोजेक्ट → **Build** → **Agents**।
२. **PersonalCareerCopilot** खोज्नुहोस् → **Delete** क्लिक गर्नुहोस्।

### विकल्प ३: मोडेल तैनाथ मेटाउनुहोस्

१. Foundry साइडबारमा, आफ्नो प्रोजेक्ट विस्तार गर्नुहोस् → **Models**।
२. मोडेल तैनाथमा दायाँ-क्लिक गर्नुहोस् → **Delete**।

> **लागत नोट:** होस्टेड एजेन्टहरू केवल चल्दा मात्र लागत लाग्छ। यदि तपाईं एजेन्ट रोक्नुहुन्छ वा मेटाउनुहुन्छ भने, कुनै निरन्तर शुल्क छैन। मोडेल तैनाथले सानो आरक्षित क्षमता शुल्क लगाउन सक्छ - समाप्त भएपछि यसलाई मेटाउनुहोस्।
