# Як провести цю сесію

Дякуємо, що проводить цю сесію!

Перед проведенням майстер-класу, будь ласка:

1. Прочитайте цей документ та всі включені ресурси повністю.
2. Перегляньте запис проведення сесії та повний огляд майстер-класу.
3. Пройдіть обидві практичні лабораторні роботи повністю на власному комп’ютері **принаймні один раз** перед заходом.
4. Перевірте свій проект Microsoft Foundry, розгортання моделей та квоти.
5. Зв’яжіться з відповідальним, якщо щось незрозуміло.

## Початок роботи

Цей майстер-клас навчає розробників, як створювати, тестувати та розгортати AI-агентів до **Microsoft Foundry Agent Service** як **Хостовані агенти** повністю з VS Code, використовуючи розширення **Microsoft Foundry Toolkit**.

Майстер-клас поділений на кілька секцій, включаючи слайди, **2 живі демонстрації** та **2 практичні лабораторні роботи**.

### Вимоги до тренера

Перед проведенням переконайтеся, що у вас є:

- **Підписка Azure** з правами на створення ресурсів (Власник або Співавтор на групі ресурсів).
- Доступ до **проекту Microsoft Foundry** у [регіоні, який підтримує хостованих агентів](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability).
- Квота на **gpt-4.1** (або **gpt-4.1-mini**) у вашому проекті Foundry.
- Встановлені такі інструменти:
  - [Visual Studio Code](https://code.visualstudio.com/)
  - [Розширення Microsoft Foundry Toolkit](https://marketplace.visualstudio.com/items?itemName=ms-windows-ai-studio.windows-ai-studio)
  - [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli)
  - [Azure Developer CLI (`azd`)](https://learn.microsoft.com/azure/developer/azure-developer-cli/install-azd)
  - [Docker Desktop](https://www.docker.com/) (опційно)
  - Python 3.10 або новіше

Перед проведенням виконайте [швидкий старт для хостованих агентів з `azd`](https://learn.microsoft.com/azure/foundry/agents/quickstarts/quickstart-hosted-agent?pivots=azd) принаймні один раз, щоб мати відомий робочий проект Foundry, розгортання моделей та Azure Container Registry для посилання у разі проблем у учнів.

## Демонстрації

У сесії передбачено дві живі демонстрації. Відведіть по 10 хвилин на кожну.

| Демонстрація             | Лабораторна | Файли                                                               | Що показувати                                     |
|-------------------------|-------------|---------------------------------------------------------------------|--------------------------------------------------|
| Executive Agent          | Лаб 01      | [`workshop/lab01-single-agent/agent/`](../../../workshop/lab01-single-agent/agent)                | Один хостований агент; переклад технічного жаргону у виконавчий підсумок |
| Resume to Job Fit Evaluator | Лаб 02      | [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot) | 4-агентна оркестрація; оцінка відповідності резюме до вакансії та генерація рекомендації |

### Демо 1: Executive Agent

Окремий агент у [`workshop/lab01-single-agent/agent/`](../../../workshop/lab01-single-agent/agent). Використовуйте це як 10-хвилинне демо перед Лаб 01.

1. Відкрийте [`workshop/lab01-single-agent/agent/main.py`](../../../workshop/lab01-single-agent/agent/main.py) і розгляньте визначення агента (системний підказ, модель, фреймворк).
2. Натисніть `F5`, щоб запустити **Agent Inspector** локально.
3. Вставте приклад підказу з [README](../README.md#see-it-in-action) і покажіть відповідь у вигляді виконавчого підсумку.
4. Покажіть [`workshop/lab01-single-agent/agent/agent.yaml`](../../../workshop/lab01-single-agent/agent/agent.yaml) та [`workshop/lab01-single-agent/agent/Dockerfile`](../../../workshop/lab01-single-agent/agent/Dockerfile) для пояснення артефактів розгортання.
5. Продемонструйте потік розгортання (створення Docker, деплой у ACR, створення хостованого агента) без очікування завершення.

### Демо 2: Resume to Job Fit Evaluator

4-агентний робочий процес у [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot). Використовуйте це як 10-хвилинне демо перед Лаб 02.

1. Відкрийте [`PersonalCareerCopilot/main.py`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/main.py) і покажіть, як чотири агенти зв’язані послідовною оркестрацією.
2. Натисніть `F5`, щоб запустити **Agent Inspector** для мультиагентного робочого процесу.
3. Вставте короткий опис вакансії та приклад резюме у чат Inspectora.
4. Пройдіться по чотирьох агентам конвеєра: парсер резюме, екстрактор вимог до роботи, оцінювач відповідності, автор рекомендацій.
5. Поясніть, як вихідні дані кожного підагента стають контекстом наступного агента, наголосивши на патерні передачі.
6. Покажіть [`PersonalCareerCopilot/agent.yaml`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/agent.yaml) для порівняння з еквівалентом одиночного агента з Демо 1.

## Поради для проведення

- **Встановіть очікування з самого початку.** Хостовані агенти перебувають у перегляді — заздалегідь повідомте про обмеження регіонів і квоти, щоб учасники не були здивовані під час лабораторії.
- **Спочатку запустіть завдання перевірки передумов.** Обидві лабораторні мають завдання VS Code `Validate prerequisites` — нехай учасники запустять його перед початком роботи з кодом.
- **Тримайте Agent Inspector відкритим.** Більшість моментів "ага" відбувається, коли учні бачать живий цикл локальних `/responses`.
- **Майте запасний проект.** Якщо проект Foundry учня стикнеться з обмеженнями квоти, надайте наперед підготовлений проект для кроку розгортання, щоб уникнути блокування групи.
- **Об’єднуйте учасників парами.** Лаб 02 (мультиагент) значно простіший, коли учні можуть обговорювати оркестрацію з партнером.
- **Використовуйте модулі документації як контрольні точки.** Кожна папка `docs/` лабораторної поділена на 8 нумерованих модулів — використовуйте їх як природні точки зупинки.
- **Заздалегідь завантажте базовий Docker образ** на спільних лабораторних машинах, щоб уникнути обмежень реєстру.

## Вирішення проблем під час проведення

| Симптом                                      | Перше, що варто спробувати                                                                            |
|----------------------------------------------|--------------------------------------------------------------------------------------------------------|
| Agent Inspector не може підключитися        | Переконайтеся, що порт `8088` вільний, і завдання `Run Lab01 HTTP Server` / `Run Lab02 HTTP Server` запущено. |
| Відлагоджувач не підключається               | Перевірте, що порт `5679` вільний; перезапустіть VS Code, якщо `debugpy` вже зв’язаний.               |
| `azd up` не вдається через помилку автентифікації | Виконайте `az login` та `azd auth login`, упевніться, що вибрано правильного орендаря.                |
| Розгортання зависає на пуші в ACR            | Перевірте, що Docker Desktop запущений і користувач має роль `AcrPush` у реєстрі.                     |
| Модель повертає 404 / deployment-not-found   | Ім'я розгортання моделі в `agent.yaml` має відповідати розгортанню у проекті Foundry.                  |

| Закріплений агент застряг у стані `Provisioning` | Перевірте, що регіон проєкту [підтримує закріплених агентів](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability) та що квота доступна.               |
| Playground повертає 401                         | Повторно автентифікуйте розширення Foundry з панелі активності VS Code.                                   |

Для глибшого керівництва кожна лабораторія має власний документ `08-troubleshooting.md` — надішліть учням посилання туди:

- Лабораторія 01: [`workshop/lab01-single-agent/docs/08-troubleshooting.md`](../workshop/lab01-single-agent/docs/08-troubleshooting.md)
- Лабораторія 02: [`workshop/lab02-multi-agent/docs/08-troubleshooting.md`](../workshop/lab02-multi-agent/docs/08-troubleshooting.md)

## Налаштування цієї сесії

Ви можете адаптувати воркшоп під свою аудиторію. Поширені варіанти:

- **Аудиторії бекенду:** більше часу приділяти `agent.yaml`, Docker та ACR; скоротити демонстрацію playground.
- **Аудиторії громадян-розробників:** залишатися в UI розширення Foundry для scaffold-інгу; зменшити кроки CLI.
- **Одиночний 60-хвилинний блок:** провести вступ, демонстрацію і лише Лабораторію 01.
- **Формат лише воркшопу (без слайдів):** відкривати обидва README лабораторій і використовувати їх як основний сценарій.

Якщо ви розширюєте лабораторії, будь ласка, внесіть зміни назад через PR, щоб інші тренери отримали користь.
