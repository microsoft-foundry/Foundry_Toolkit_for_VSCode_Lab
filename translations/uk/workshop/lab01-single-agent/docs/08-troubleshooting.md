# Модуль 8 - Виправлення неполадок

Цей модуль є довідником для розв’язання поширених проблем. Додайте його до закладок і повертайтеся, коли щось піде не так.

---

## 1. Помилки дозволів

### 1.1 Відмовлено у дозволі `agents/write`

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**Корінь проблеми:** Відсутня роль `Azure AI User` на рівні **проєкту**. Це найпоширеніша помилка на майстер-класі.

**Виправлення:**
1. Відкрийте [portal.azure.com](https://portal.azure.com).
2. Знайдіть назву вашого Foundry **проєкту** → натисніть на результат типу **"Microsoft Foundry project"** (НЕ на батьківський акаунт).
3. **Контроль доступу (IAM)** → **+ Додати** → **Додати призначення ролі**.
4. Роль: **Azure AI User** → Далі.
5. Учасники: оберіть себе → Переглянути + призначити → Переглянути + призначити.
6. **Зачекайте 1–2 хвилини** → повторіть спробу.

> **Чому ролі Owner/Contributor недостатньо:** Ці ролі надають лише дії управління. Операції агента вимагають *дії з даними* `agents/write`, яка є лише в ролях `Azure AI User`, `Azure AI Developer` або `Azure AI Owner`. Дивіться [документацію Foundry RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` під час розгортання

**Виправлення:** Попросіть вашого адміністратора призначити роль **Contributor** на групі ресурсів, або нехай вони створять проєкт для вас і нададуть роль **Azure AI User** на ньому.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Очікуйте, доки не буде: "Зареєстровано"
```

## 2. Помилки Docker

> Docker є **необов’язковим**. Ці помилки виникають лише якщо встановлено Docker Desktop і розширення намагається зібрати локально.

### 2.1 Демон Docker не запущений

**Виправлення:** Запустіть Docker Desktop → зачекайте, поки статус стане "запущено" → перевірте командою `docker info` → повторіть спробу.

### 2.2 Збірка не вдається через помилки залежностей

**Виправлення:** Перевірте написання `requirements.txt`, спершу протестуйте локально: `pip install -r requirements.txt`.

### 2.3 Несумісність платформи (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. Помилки автентифікації

### 3.1 Помилка `DefaultAzureCredential`

**Виправлення (спробуйте по черзі):**
1. `az login` (повторна автентифікація)
2. `az account set --subscription "<id>"` (правильна підписка)
3. VS Code → Облікові записи → Вийти → Увійти знову
4. Перевірте: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 Токен працює локально, але не на хості

**Очікувано:** Зазвичай хостовані агенти використовують системно керовану ідентичність, а не ваші облікові дані. Якщо хостований агент має помилки автентифікації:
- Перевірте, що `AZURE_AI_PROJECT_ENDPOINT` у `agent.yaml` правильний
- Переконайтеся, що керована ідентичність проєкту має доступ до моделі

## 4. Помилки моделі

### 4.1 Розгортання моделі не знайдено

**Виправлення:** Ім'я **чутливе до регістру**. Порівняйте `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` з точним ім’ям у бічній панелі Foundry → Моделі.

### 4.2 Несподіваний вивід моделі

**Виправлення:** Перегляньте `AGENT_INSTRUCTIONS` у `main.py` (чи не обрізано?). Спробуйте іншу модель (`gpt-4.1` проти `gpt-4.1-mini`).

## 5. Помилки розгортання

### 5.1 Відмова в доступі при pull ACR

**Виправлення:** Відкрийте Azure Portal → Container Registry → Контроль доступу (IAM) → Додайте роль **AcrPull** керованій ідентичності проєкту Foundry.

### 5.2 Агент не запускається (залишається у стані "Очікування" або "Помилка")

Перегляньте логи контейнера у бічній панелі. Поширені причини:

| Повідомлення в логах | Виправлення |
|-------------|-----|
| `ModuleNotFoundError` | Додайте відсутній пакет у `requirements.txt`, розгорніть повторно |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | Додайте змінну середовища у `agent.yaml` під `environment_variables` |
| `Address already in use` | Переконайтеся, що лише один процес прив’язаний до порту 8088 |

### 5.3 Таймаут розгортання

**Виправлення:** Перевірте інтернет-з’єднання. Перше розгортання передає понад 100 МБ. Якщо ви за проксі? Налаштуйте параметри проксі в Docker Desktop.

## 6. Шлях B - Foundry Local

### 6.1 Foundry Local не запускається

| Проблема | Виправлення |
|-------|-----|
| `foundry: command not found` | Перевстановіть: `winget install Microsoft.FoundryLocal` |
| Недостатньо ресурсів | Foundry Local потребує ~4 ГБ вільної ОЗП. Закрийте інші програми. |
| Завантаження моделі не вдається | Перевірте вільне місце на диску (моделі 2–8 ГБ). Повторіть: `foundry local models pull <name>` |

### 6.2 Помилки моделей Foundry Local

| Проблема | Виправлення |
|-------|-----|
| Повільна відповідь | Очікувано - локальні моделі працюють на CPU, якщо у вас немає GPU. Будьте терплячі. |
| Низька якість результату | Спробуйте більшу модель, якщо ваше обладнання дозволяє. `phi-4-mini` — хороший баланс. |
| Відмова з’єднання | Перевірте, чи працює Foundry Local: `foundry local status`. За потреби перезапустіть. |

## 7. Швидкий довідник: ролі RBAC

| Роль | Область | Надає |
|------|-------|--------|
| **Azure AI User** | Проєкт | Дії з даними: `agents/write`, `agents/read` |
| **Azure AI Developer** | Проєкт/Акаунт | Дії з даними + створення проєкту |
| **Azure AI Owner** | Акаунт | Повний доступ + керування ролями |
| **Contributor** | Підписка/ГР | Лише дії управління (**без** дій з даними) |
| **Owner** | Підписка/ГР | Управління + призначення ролей (**без** дій з даними) |
