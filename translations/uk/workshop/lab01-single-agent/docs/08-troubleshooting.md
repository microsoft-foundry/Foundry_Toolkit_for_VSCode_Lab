# Модуль 8 - Усунення несправностей

Цей модуль є довідником з поширених проблем. Додайте його до закладок і повертайтеся, коли щось піде не так.

---

## 1. Помилки дозволів

### 1.1 `agents/write` доступ заборонено

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**Корінна причина:** Відсутня роль `Azure AI User` на рівні **проєкту**. Це найбільш поширена помилка на воркшопі.

**Виправлення:**
1. Відкрийте [portal.azure.com](https://portal.azure.com).
2. Знайдіть назву вашого **проєкту** Foundry → натисніть на результат типу **"Microsoft Foundry project"** (НЕ батьківський акаунт).
3. **Контроль доступу (IAM)** → **+ Додати** → **Додати призначення ролі**.
4. Роль: **Azure AI User** → Далі.
5. Учасники: Виберіть себе → Перегляд + призначення → Перегляд + призначення.
6. **Зачекайте 1–2 хвилини** → спробуйте ще раз.

> **Чому роль Власника/Співавтора недостатня:** Ці ролі надають лише дії *керування*. Операції агента вимагають `agents/write` *дії з даними*, які доступні лише в `Azure AI User`, `Azure AI Developer` або `Azure AI Owner`. Див. [документацію Foundry RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` під час розгортання

**Виправлення:** Попросіть адміністратора призначити вам роль **Contributor** на групу ресурсів або нехай він створить проект для вас і надасть роль **Azure AI User** у ньому.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Wait until: "Registered"
```

## 2. Помилки Docker

> Docker є **опціональним**. Ці помилки виникають лише, якщо встановлено Docker Desktop і розширення намагається виконати локальну збірку.

### 2.1 Демон Docker не запущений

**Виправлення:** Запустіть Docker Desktop → дочекайтесь статусу «running» → перевірте за допомогою `docker info` → спробуйте знову.

### 2.2 Спроба збірки завершується помилками залежностей

**Виправлення:** Перевірте написання `requirements.txt`, спершу протестуйте локально: `pip install -r requirements.txt`.

### 2.3 Несумісність платформи (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. Помилки автентифікації

### 3.1 `DefaultAzureCredential` не вдається

**Виправлення (спробуйте по черзі):**
1. `az login` (повторна аутентифікація)
2. `az account set --subscription "<id>"` (правильна підписка)
3. VS Code → Облікові записи → Вийти → Увійти знову
4. Перевірте: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 Токен працює локально, але не на хостингу

**Очікувано:** Хостовані агенти використовують ідентичність, керовану системою, а не ваші облікові дані. Якщо хостований агент отримує помилки автентифікації:
- Переконайтесь, що `AZURE_AI_MODEL_DEPLOYMENT_NAME` в `agent.yaml` вказує на ім'я вашого розгортання моделі (`FOUNDRY_PROJECT_ENDPOINT` додається Foundry під час виконання - не вказуйте змінну в `agent.yaml`)
- Перевірте, що керована ідентичність проєкту має доступ до моделі

## 4. Помилки моделі

### 4.1 Розгортання моделі не знайдено

**Виправлення:** Ім'я **чутливе до регістру**. Порівняйте `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` з точним ім’ям у боковій панелі Foundry → Моделі.

### 4.2 Неочікуваний вихід моделі

**Виправлення:** Перегляньте `AGENT_INSTRUCTIONS` у `main.py` (чи не обрізане?). Спробуйте іншу модель (`gpt-4.1` проти `gpt-4.1-mini`).

## 5. Помилки розгортання

### 5.1 Відмова в доступі для ACR pull

**Виправлення:** Увійдіть в Azure Portal → Container Registry → Контроль доступу (IAM) → Додайте роль **AcrPull** для керованої ідентичності проєкту Foundry.

### 5.2 Агент не запускається (залишається "Pending" або "Failed")

Перевірте логи контейнера в боковій панелі. Поширені причини:

| Повідомлення у журналі | Виправлення |
|-------------|-----|
| `ModuleNotFoundError` | Додайте відсутній пакет до `requirements.txt`, розгорніть заново |
| `ValueError: Missing required environment variables` | Переконайтесь, що `AZURE_AI_MODEL_DEPLOYMENT_NAME` оголошено в `agent.yaml` під `environment_variables` і має значення, потім повторно розгорніть. `FOUNDRY_PROJECT_ENDPOINT` додається Foundry під час виконання |
| `Address already in use` | Переконайтесь, що лише один процес прив’язаний до порту 8088 |

### 5.3 Час розгортання вичерпано

**Виправлення:** Перевірте інтернет-з’єднання. Перше розгортання відправляє >100МБ. Працюєте через проксі? Налаштуйте проксі в Docker Desktop.

## 6. Шлях Б - Foundry Local

### 6.1 Foundry Local не запускається

| Проблема | Виправлення |
|-------|-----|
| `foundry: command not found` | Перевстановіть: `winget install Microsoft.FoundryLocal` |
| Недостатньо ресурсів | Foundry Local потребує ~4 ГБ вільної оперативної пам’яті. Закрийте решту застосунків. |
| Помилка завантаження моделі | Перевірте місце на диску (моделі займають 2–8 ГБ). Спробуйте знову: `foundry local models pull <name>` |

### 6.2 Помилки моделей Foundry Local

| Проблема | Виправлення |
|-------|-----|
| Повільні відповіді | Очікувано - локальні моделі працюють на CPU, якщо немає GPU. Будьте терплячі. |
| Погана якість вихідних даних | Спробуйте більшу модель, якщо ваше обладнання дозволяє. `phi-4-mini` — хороший баланс. |
| Відмова з’єднання | Переконайтесь, що Foundry Local запущено: `foundry local status`. За потреби перезапустіть. |

## 7. Швидкий довідник: ролі RBAC

| Роль | Область застосування | Надання прав |
|------|-------|--------|
| **Azure AI User** | Проєкт | Дії з даними: `agents/write`, `agents/read` |
| **Azure AI Developer** | Проєкт/Обліковий запис | Дії з даними + створення проєктів |
| **Azure AI Owner** | Обліковий запис | Повний доступ + керування ролями |
| **Contributor** | Підписка/Група ресурсів | Лише дії керування (**без** дій з даними) |
| **Owner** | Підписка/Група ресурсів | Дії керування + призначення ролей (**без** дій з даними) |
