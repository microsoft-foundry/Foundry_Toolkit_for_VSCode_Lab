# Модуль 9 - Підсумок та наступні кроки

⏱️ ~5 хв

**Вітаємо!** Ви створили, протестували, а (якщо на Шляху A) також розгорнули багатоуагентний робочий процес за допомогою Microsoft Foundry та Foundry Toolkit для VS Code.

---

## Що ви створили

**Оцінювач відповідності резюме до вакансії** - багатоуагентний розміщений робочий процес, який:
- Отримує резюме + опис вакансії через HTTP (`POST /responses`)
- Запускає чотири спеціалізовані агенти у послідовній конвеєрній ланцюжку - кожен агент передає дані наступному
- Повертає оцінку відповідності (0–100 з деталізацією), список розривів у навичках та сертифікаціях, а також персоналізовану дорожню карту навчання з реальними посиланнями Microsoft Learn для кожного розриву
- Викликає Microsoft Learn MCP сервер (`https://learn.microsoft.com/api/mcp`), щоб отримати офіційні навчальні ресурси для кожного виявленого розриву навичок
- Запускається як один контейнеризований розміщений агент у Microsoft Foundry Agent Service

## Основні вивчені концепції

| Концепція | Що ви практикували |
|---------|-------------------|
| **Оркестрація багатоуагентних систем** | `WorkflowBuilder` послідовна конвеєрна ланцюжок із `add_edge()` |
| **Спеціалізація агентів** | Чотири сфокусовані агенти перевершують одного універсального агента |
| **Патерн Content Router** | ResumeParser виконує роль маршрутизатора - зберігає текст вакансії у секції `[JOB DESCRIPTION PASS-THROUGH]`, щоб агенти наступних етапів могли отримати до нього доступ (потрібно, бо `context_mode="last_agent"` означає, що лише `start_executor` бачить сире повідомлення користувача) |
| **Патерн Content Relay** | Агент JD передає `[PARSED RESUME PASS-THROUGH]` далі, щоб MatchingAgent отримував обидва профілі; уникнення двократного спрацьовування семантики OR, що буває у графах конвергенції |
| **Інтеграція з інструментом MCP** | `@tool` + `streamable_http_client`, що викликає зовнішній MCP сервер |
| **Життєвий цикл розміщеного агента** | Scaffold → Конфігурація → Локальне тестування → Розгортання → Перевірка в хмарі |
| **`context_mode="last_agent"`** | Кожен виконавець бачить лише вихід своїх безпосередніх попередників |
| **Foundry Toolkit робочий процес** | Майстер scaffold, Інспектор агента, Візуалізатор робочого процесу, розгортання в один клік |

### Ідеї для розширення цього робочого процесу

- **Додати 5-го агента** - Коуч з інтерв’ю, який створює ймовірні питання на основі звіту про розриви
- **Додати інструмент підстави Bing** - Дозволити агенту JD шукати схожі вакансії для збагачення вимог
- **Підключитись до бази резюме** - Витягувати профілі кандидатів із бази даних через кастомний `@tool`
- **Спробувати різні моделі** - Порівняти якість виходу `gpt-4.1` та `gpt-4.1-mini` і затримку
- **Оцінити за допомогою Foundry** - Використати функцію Evaluations для оцінки звітів відповідності на основі золотого набору даних

## Прибирання ресурсів (за бажанням)

Якщо хочете видалити ресурси Azure, створені під час цього воркшопу:

### Варіант 1: Видалити групу ресурсів (видаляє все)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### Варіант 2: Видалити лише розміщеного агента

1. Відкрийте [ai.azure.com](https://ai.azure.com) → ваш проєкт → **Build** → **Agents**.
2. Знайдіть **PersonalCareerCopilot** → натисніть **Delete**.

### Варіант 3: Видалити розгортання моделі

1. У панелі Foundry розгорніть ваш проєкт → **Models**.
2. Клікніть правою кнопкою по розгортанню моделі → **Delete**.

> **Примітка з витрат:** Розміщені агенти генерують витрати лише під час роботи. Якщо зупинити або видалити агента, подальших оплат немає. Розгортання моделі може спричинити невелику плату за зарезервовану потужність — видаліть його, якщо не потрібне.
