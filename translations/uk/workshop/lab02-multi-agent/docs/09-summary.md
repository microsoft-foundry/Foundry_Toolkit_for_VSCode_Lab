## Що ви побудували

**Оцінювач відповідності резюме вакансії** – мультиагентський розміщений робочий процес, який:
- Отримує резюме + опис вакансії через HTTP (`POST /responses`)
- Запускає чотири спеціалізовані агенти послідовно – кожен агент передає дані наступнику
- Повертає оцінку відповідності (0–100 з деталізацією), список навичок і сертифікаційних прогалин, а також персоналізовану дорожню карту навчання з реальними посиланнями Microsoft Learn для кожної прогалини
- Викликає Microsoft Learn MCP сервер (`https://learn.microsoft.com/api/mcp`) для отримання офіційних навчальних ресурсів для кожної виявленої прогалини в навичках
- Працює як один контейнеризований розміщений агент у Microsoft Foundry Agent Service

## Ключові вивчені концепції

| Концепція | Що ви практикували |
|---------|-------------------|
| **Оркестрація мультиагентів** | `WorkflowBuilder` послідовна конвеєрна схема з `add_edge()` |
| **Спеціалізація агента** | Чотири сфокусовані агенти працюють краще за одного універсального агента |
| **Патерн Content Router** | ResumeParser одночасно є маршрутизатором – він зберігає текст JD у розділі `[JOB DESCRIPTION PASS-THROUGH]` для доступу наступних агентів (потрібно, бо `context_mode="last_agent"` означає, що лише `start_executor` бачить сире повідомлення користувача) |
| **Патерн Content Relay** | JD Agent передає `[PARSED RESUME PASS-THROUGH]` далі, тому MatchingAgent отримує обидва профілі; уникає подвійного спрацьовування за OR-логікою, яке виникає в графах із кількома входами |
| **Інтеграція інструменту MCP** | `@tool` + `streamable_http_client` виклик зовнішнього MCP сервера |
| **Життєвий цикл Hosted Agent** | Scaffold → Налаштування → Локальне тестування → Розгортання → Перевірка в хмарі |
| **`context_mode="last_agent"`** | Кожен виконавець бачить лише вихід безпосереднього попередника |
| **Foundry Toolkit workflow** | Майстер Scaffold, Agent Inspector, Workflow Visualizer, розгортання в один клік |

### Ідеї для розширення цього робочого процесу

- **Додати 5-го агента** – Коуч для інтерв’ю, який генерує ймовірні питання на основі звіту про прогалини
- **Додати інструмент для пошуку Bing** – Дозволити JD Agent шукати схожі вакансії для збагачення вимог
- **Підключитися до бази резюме** – Отримувати профілі кандидатів із бази через кастомний `@tool`
- **Спробувати різні моделі** – Порівняти якість і затримку виводу між `gpt-4.1` і `gpt-4.1-mini`
- **Оцінка через Foundry** – Використовувати функцію Evaluations для оцінювання звітів відповідності за золотою вибіркою

## Очистити ресурси (опціонально)

Якщо хочете видалити Azure ресурси, створені під час цього воркшопу:

### Варіант 1: Видалити групу ресурсів (видаляє все)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### Варіант 2: Видалити лише розміщеного агента

1. Відкрийте [ai.azure.com](https://ai.azure.com) → ваш проект → **Build** → **Agents**.
2. Знайдіть **PersonalCareerCopilot** → натисніть **Delete**.

### Варіант 3: Видалити розгортання моделі

1. У бічному меню Foundry розгорніть ваш проект → **Models**.
2. Клікніть правою кнопкою на розгортанні моделі → **Delete**.

> **Примітка щодо вартості:** Розміщені агенти спричиняють вартість лише під час роботи. Якщо зупинити або видалити агента, подальші витрати відсутні. Розгортання моделі може спричинити невеликий збір за резервовану потужність – видаліть його, якщо воно не потрібне.
