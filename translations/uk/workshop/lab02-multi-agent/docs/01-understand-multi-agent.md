⏱️ ~5 хв

Перед тим, як писати будь-який код, ось короткий огляд того, що ви створюєте і як це працює.

---

## Що ви створюєте

Ви вставляєте **резюме** та **опис вакансії**. Робочий процес повертає:

- Оцінку відповідності (0–100 із деталізацією)
- Список прогалин у навичках і сертифікаціях
- Персоналізовану дорожню карту навчання з посиланнями на Microsoft Learn для кожної прогалини

---

## Чотири агенти

Один агент, який намагається одночасно парсити, оцінювати та планувати, як правило, поспішатиме і вироблятиме поверхневий результат. Розподіл роботи на чотири спеціалізовані агенти дає кращі результати:

| Агент | Що він робить |
|-------|-------------|
| **ResumeParser** | Парсить резюме; копіює опис вакансії дослівно в `[JOB DESCRIPTION PASS-THROUGH]` для подальших агентів |
| **JobDescriptionAgent** | Витягує вимоги з опису вакансії; передає `[PARSED RESUME]` далі як `[PARSED RESUME PASS-THROUGH]` |
| **MatchingAgent** | Порівнює обидві марковані секції; генерує оцінку відповідності 0–100 і список прогалин |
| **GapAnalyzer** | Створює дорожню карту навчання; шукає на Microsoft Learn для кожної прогалини |

---

## Граф оркестрації

Робочий процес — це **послідовний конвеєр** — кожен агент передає свій результат наступному:

```mermaid
flowchart LR
    A["Вхідні дані користувача"] --> B["Парсер резюме"]
    B -- "розпарсене резюме + передача ОР" --> C["Агент опису роботи"]
    C -- "вимоги ОР + передача резюме" --> D["Агент співставлення"]
    D -- "звіт відповідності + прогалини" --> E["Аналізатор прогалин + MCP"]
    E --> F["Фінальний вихід"]

    style A fill:#4A90D9,color:#fff
    style B fill:#7B68EE,color:#fff
    style C fill:#7B68EE,color:#fff
    style D fill:#E67E22,color:#fff
    style E fill:#27AE60,color:#fff
    style F fill:#4A90D9,color:#fff
```

1. **ResumeParser** отримує вхідні дані користувача, парсить резюме та копіює опис вакансії в `[JOB DESCRIPTION PASS-THROUGH]`.
2. **JD Agent** витягує структуровані вимоги і передає `[PARSED RESUME PASS-THROUGH]` далі.
3. **MatchingAgent** порівнює обидві секції і виробляє оцінку відповідності та список прогалин.
4. **GapAnalyzer** створює дорожню карту та викликає інструмент Microsoft Learn MCP для кожної прогалини.

## Як це відображається в коді

У `main.py` ви описуєте цей граф за допомогою `WorkflowBuilder`:

```python
workflow_agent = (
    WorkflowBuilder(
        start_executor=resume_executor,       # перший агент, який отримує вхідні дані користувача
        output_executors=[gap_executor],      # останній агент - його вивід є відповіддю
    )
    .add_edge(resume_executor, jd_executor)       # ResumeParser → агент JD
    .add_edge(jd_executor, matching_executor)     # агент JD → MatchingAgent
    .add_edge(matching_executor, gap_executor)    # MatchingAgent → GapAnalyzer
    .build()
    .as_agent()
)
```

Кожен `Agent` обгорнуто в `AgentExecutor`. Виклики `add_edge()` визначають строго послідовний конвеєр — кожен агент отримує лише результат свого безпосереднього попередника.

> `context_mode="last_agent"` означає, що кожен виконавець бачить лише результат свого безпосереднього попередника. ResumeParser і JD Agent передають дані далі у маркованих секціях, щоб кожен наступний агент мав саме те, що йому потрібно.

## Інструмент MCP

GapAnalyzer має один інструмент: `search_microsoft_learn_for_plan`. Він підключається до `https://learn.microsoft.com/api/mcp` і повертає реальні посилання Microsoft Learn для кожної прогалини у навичках.

Коли інструмент працює, ви побачите ці логи — це все очікувані повідомлення:

```
GET  https://learn.microsoft.com/api/mcp → 405   ← connection probe, normal
POST https://learn.microsoft.com/api/mcp → 200   ← actual tool call
DELETE https://learn.microsoft.com/api/mcp → 405 ← cleanup probe, normal
```

Хвилюватись варто лише, якщо `POST` повертає помилку.
