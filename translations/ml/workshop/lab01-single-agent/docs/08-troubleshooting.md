# മോഡ്യൂൾ 8 - പ്രശ്ന പരിഹാര മാർഗ്ഗദർശിക

സാധാരണ പ്രശ്നങ്ങൾക്ക് ഈ മോഡ്യൂൾ ഒരു റഫറൻസ് ഗൈഡ് ആണ്. ഇത് ബുക്ക്മാർക്ക് ചെയ്ത് എന്തെങ്കിലും തെറ്റായപ്പോൾ തിരിച്ചുകെത്തുക.

---

## 1. അനുവാദ പിശകുകൾ

### 1.1 `agents/write` അനുവാദം നിഷേധിക്കപ്പെട്ടു

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**മൂല കാരണം:** **പProjeto** തലത്തിൽ `Azure AI User` റോൾ ഇല്ല. ഇത് ഏറ്റവും പ്രധാനപ്പെട്ട വർക്ക്ഷോപ്പ് പിശകാണ്.

**പരിഹാരം:**
1. [portal.azure.com](https://portal.azure.com) തുറക്കുക.
2. നിങ്ങളുടെ Foundry **project** നാമം തിരയുക → ടൈപ്പ് **"Microsoft Foundry project"** ഫലമായതിൽ ക്ലിക്ക് ചെയ്യുക (parent account അല്ല).
3. **Access control (IAM)** → **+ Add** → **Add role assignment**.
4. റോൾ: **Azure AI User** → Next.
5. അംഗങ്ങൾ: നിങ്ങളെ തിരഞ്ഞെടുക്കുക → Review + assign → Review + assign.
6. **1–2 മിനിറ്റ് കാത്തിരിക്കുക** → വീണ്ടും ശ്രമിക്കുക.

> **എന്തുകൊണ്ട് Owner/Contributor മതിയല്ല:** ഈ റോളുകൾ *management* നടപടികൾ മാത്രമേ അനുവദിക്കൂ. Agent പ്രവർത്തനങ്ങൾക്ക് ആവശ്യമാണ് `agents/write` *ഡാറ്റാ ആക്ഷൻ*, ഇത് വരെ `Azure AI User`, `Azure AI Developer`, അല്ലെങ്കിൽ `Azure AI Owner` റോളുകളിൽ മാത്രമേ ഉണ്ടാകൂ. കാണുക [Foundry RBAC docs](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 പ്രൊവിഷനിംഗ് സമയത്ത് `AuthorizationFailed`

**പരിഹാരം:** നിങ്ങളുടെ അഡ്മിനോട് റിസോഴ്‌സ് ഗ്രൂപ്പിൽ **Contributor** നിയോഗിക്കാൻ അപേക്ഷിക്കുക, അല്ലെങ്കിൽ അവർ നിങ്ങളുടെ വേണ്ടി പ്രൊജക്ട് സൃഷ്ടിച്ച് നിങ്ങൾക്ക് അതിൽ **Azure AI User** നൽകണം.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# "Registered" എന്ന് വരെ കാത്തിരിക്കുക
```

## 2. Docker പിശകുകൾ

> Docker **ഐച്ഛികമാണ്**. Docker Desktop ഇൻസ്റ്റാൾ ചെയ്തിരിക്കുകയാണെങ്കിൽ മാത്രമേ ഈ പിശകുകൾ ബാധകമായിരിക്കുക, എക്സ്റ്റൻഷൻ ലോക്കൽ ബിൽഡ് ശ്രമിക്കുമ്പോൾ.

### 2.1 Docker ഡൊമൻ പ്രവർത്തിക്കുന്നില്ല

**പരിഹാരം:** Docker Desktop തുടങ്ങുക → "running" നിലയ്ക്ക് കാത്തിരിക്കുക → `docker info` ഉപയോഗിച്ച് പരിശോധിക്കുക → വീണ്ടും ശ്രമിക്കുക.

### 2.2 നിർമാണം ലംഘന പിശകുകൾ കൊണ്ട് പരാജയപ്പെടുന്നു

**പരിഹാരം:** `requirements.txt` വൃതാന്തം പരിശോധിക്കുക, ആദ്യം ലോക്കലായി പരീക്ഷിക്കുക: `pip install -r requirements.txt`.

### 2.3 പ്ലാറ്റ്‌ഫോം പൊരുത്തക്കേട് (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. തിരിച്ചറിയൽ പിശകുകൾ

### 3.1 `DefaultAzureCredential` പരാജയപ്പെടുന്നു

**പരിഹാരം (ക്രമത്തിൽ പരീക്ഷിക്കുക):**
1. `az login` (പുനഃ-പ്രാമാണീകരിക്കുക)
2. `az account set --subscription "<id>"` (കരുത്തിന്റെ സബ്സ്ക്രിപ്ഷൻ)
3. VS Code → അക്കൗണ്ടുകൾ → സൈൻ ഔട്ട് → വീണ്ടും സൈൻ ഇൻ ചെയ്യുക
4. സ്ഥിരീകരിക്കുക: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 ടോക്കൺ ലോക്കലായി പ്രവർത്തിക്കും, എന്നാൽ ഹോസ്റ്റ ചെയ്തു പിടിക്കുമ്പോൾ പ്രവർത്തിക്കില്ല

**പ്രതീക്ഷിക്കുക:** ഹോസ്റ്റുചെയ്ത ഏജന്റുകൾ സിസ്റ്റം-മാനേജ്ഡ് ഐഡന്റിറ്റി ഉപയോഗിക്കുന്നു, നിങ്ങളുടെ ക്രെഡൻഷ്യൽ അല്ല. ഹോസ്റ്റുചെയ്ത ഏജന്റ് ഓത് പിശകുകൾ ഉണ്ടെങ്കിൽ:
- `agent.yaml` ൽ `AZURE_AI_PROJECT_ENDPOINT` ശരിയാണെന്ന് ഉറപ്പുവരുത്തുക
- പ്രൊജക്ടിന്റെ മാനേജ് ചെയ്ത ഐഡന്റിറ്റിക്ക് മോഡൽ ആക്സസ് ഉണ്ടെന്ന് പരിശോധിക്കുക

## 4. മോഡൽ പിശകുകൾ

### 4.1 മോഡൽ ഡിപ്പ്ലോയ്മെന്റ് കണ്ടെത്താനായില്ല

**പരിഹാരം:** പേര് **കേസ്-സെൻസിറ്റീവ്** ആണെന്ന് ശ്രദ്ധിക്കുക. `.env` യിലെ `AZURE_AI_MODEL_DEPLOYMENT_NAME` ഫൗണ്ട്രി സൈഡ്ബാറിലെ → മോഡലുകളിലെ യഥാർത്ഥ പേറിന്റെ കൂടെ താരതമ്യം ചെയ്യുക.

### 4.2 അപ്രതീക്ഷിത മോഡൽ ഔട്ട്പുട്ട്

**പരിഹാരം:** `main.py` യിലെ `AGENT_INSTRUCTIONS` പരിശോധിക്കുക (തെളിച്ചമാക്കാത്തത്?). വ്യത്യസ്ത മോഡൽ ശ്രമിക്കുക (`gpt-4.1` vs `gpt-4.1-mini`).

## 5. ഡിപ്പ്ലോയ്മെന്റ് പിശകുകൾ

### 5.1 ACR പുൾ അനുവാദമില്ല

**പരിഹാരം:** Azure Portal → Container Registry → Access control (IAM) → Foundry പ്രോജക്ടിന്റെ മാനേജ്ഡ് ഐഡന്റിറ്റിക്ക് **AcrPull** റോൾ നൽകുക.

### 5.2 ഏജന്റ് തുടങ്ങാൻ പരാജയപ്പെടുന്നു ("Pending" അല്ലെങ്കിൽ "Failed" ആയി നിലനിർത്തും)

സൈഡ്ബാറിലെ കണ്ടെയ്‌നർ ലോഗുകൾ പരിശോധിക്കുക. സാധാരണ കാരണം:

| ലോഗ് സന്ദേശം | പരിഹാരം |
|-------------|---------|
| `ModuleNotFoundError` | `requirements.txt` ൽ കാണാത്ത പാക്കേജ് ചേർക്കുക, വീണ്ടും ഡിപ്പ്ലോയ് ചെയ്യുക |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | `agent.yaml` ൽ `environment_variables` കീഴിൽ എൻവയറൺമെന്റ് വാരി ചേർക്കുക |
| `Address already in use` | പോർട്ട് 8088 ന് മുപ്പൂർ പ്രോസസ്സ് ബന്ധിപ്പിക്കാത്തത് ഉറപ്പുവരുത്തുക |

### 5.3 ഡിപ്പ്ലോയ്മെന്റ് സമയം കഴിഞ്ഞുപോകുന്നു

**പരിഹാരം:** ഇന്റർനെറ്റ് ബന്ധം പരിശോധിക്കുക. ആദ്യം ഡിപ്പ്ലോയ്മെന്റ് >100MB ആണ്. പ്രോക്സി ശേഷം പ്രവർത്തിക്കുകയാണെങ്കിൽ Docker Desktop പ്രോക്സി സെറ്റിംഗുകൾ കോൺഫിഗർ ചെയ്യുക.

## 6. പാത്ത് ബി - ഫൗണ്ട്രി ലോക്കൽ

### 6.1 ഫൗണ്ട്രി ലോക്കൽ തുടങ്ങുന്നില്ല

| പ്രശ്നം | പരിഹാരം |
|-------|---------|
| `foundry: command not found` | പുനഃസ്ഥാപിക്കുക: `winget install Microsoft.FoundryLocal` |
| പ്രയോജനക്കുറവ് | ഫൗണ്ട്രി ലോക്കലിന് ~4GB RAM ഒഴിവാക്കണം. മറ്റ് ആപ്പുകൾ അടച്ച് ഈ സമയത്ത് പ്രവർത്തിക്കുക. |
| മോഡൽ ഡൗൺലോഡ് പരാജയം | ഡിസ്ക് സ്‌പേസ് പരിശോധിക്കുക (മോഡലുകൾ 2–8 GB വരെയാണ്). വീണ്ടും ശ്രമിക്കുക: `foundry local models pull <name>` |

### 6.2 ഫൗണ്ട്രി ലോക്കൽ മോഡൽ പിശകുകൾ

| പ്രശ്നം | പരിഹാരം |
|-------|---------|
| പ്രതികരണങ്ങൾ മന്ദഗതിയുള്ളവ | പ്രതീക്ഷിക്കുക - ലോക്കൽ മോഡലുകൾ CPU-യിൽ പ്രവർത്തിക്കും GPU ഇല്ലെങ്കിൽ. ക്ഷമിക്കുക. |
| ദുർബലമായ ഔട്ട്പുട്ട് | നിങ്ങളുടെ ഹാർഡ്‌വെയർ അനുവദിക്കുന്നെങ്കിൽ വലിയ മോഡൽ പരീക്ഷിക്കുക. `phi-4-mini` നല്ല സമതുലനം ആണ്. |
| ബന്ധം നിഷേധിച്ചു | ഫൗണ്ട്രി ലോക്കൽ പ്രവർത്തിക്കുന്നുവെന്ന് സ്ഥിരീകരിക്കുക: `foundry local status`. ആവശ്യമെങ്കിൽ പുനരാരംഭിക്കുക. |

## 7. ത്വരിത റഫറൻസ്: RBAC റോളുകൾ

| റോൾ | പരിധി | അനുമതികൾ |
|------|--------|-----------|
| **Azure AI User** | പ്രോജക്ട് | ഡാറ്റ പ്രവർത്തനങ്ങൾ: `agents/write`, `agents/read` |
| **Azure AI Developer** | പ്രോജക്ട്/അക്കൗണ്ട് | ഡാറ്റ പ്രവർത്തനങ്ങൾ + പ്രോജക്ട് സൃഷ്ടി |
| **Azure AI Owner** | അക്കൗണ്ട് | പൂര്‍ണ്ണ ആക്സസ് + റോൾ മാനേജ്മെന്റ് |
| **Contributor** | സബ്സ്ക്രിപ്ഷൻ/ആർജി | മാത്രം മാനേജ്മെന്റ് പ്രവർത്തനങ്ങൾ (ഡാറ്റ പ്രവർത്തനങ്ങൾ **ഇല്ല**) |
| **Owner** | സബ്സ്ക്രിപ്ഷൻ/ആർജി | മാനേജ്മെന്റ് + റോൾ നിയോഗം (ഡാറ്റ പ്രവർത്തനങ്ങൾ **ഇല്ല**) |
