# മൊഡ്യൂൾ 1 - ആർക്കിടെക്ചർ മനസിലാക്കുക

⏱️ ~5 മിനിറ്റ്

ഏത് കോഡും എഴുതുന്നതിനുമുമ്പ്, നിങ്ങൾ നിർമ്മിക്കുന്നതു എന്താണെന്നും അത് എങ്ങനെ പ്രവർത്തിക്കുന്നുവെന്നും ഒരു എളുപ്പത്തിൽ ഉള്ള അവലോകനം.

---

## നിങ്ങൾ നിർമ്മിക്കുന്നതെന്ത്

നിങ്ങൾ ഒരു **റെസ്യൂമെ**യും ഒരു **ജോബ് വിവരണം**യും പകർത്തി വയ്ക്കുന്നു. പ്രവൃത്തി പ്രവാഹം താഴെ നൽകുന്നതാണ്:

- ഒരു ഫിറ്റ് സ്കോർ (0–100 ലും വിരാമ വിവരണവും)
- സ്കിൽയും സർട്ടിഫിക്കേഷനും ഇല്ലാത്ത ഭാഗങ്ങളുടെ പട്ടിക
- ഓരോ ഉള്ളടക്കത്തിനും Microsoft Learn ലിങ്കുകളോടെ വ്യക്തിഗത പഠന റോഡ്‌മാപ്പ്

---

## നാല് ഏജന്റുമാർ

ഒരേ സമയം എല്ലാ പ്രവർത്തനങ്ങളും പരിസമാപ്തിയോടെ നിർവ്വഹിക്കാൻ ശ്രമിക്കുന്ന ഒരു ഏജന്റ് സാധാരണയായി പെട്ടെന്ന് പ്രവർത്തിക്കുകയും ആഴമില്ലാത്ത ഫലം ഉണ്ടാക്കുകയും ചെയ്യും. നാല് പ്രത്യേകതകളുള്ള ഏജന്റുകളായി ജോലി വിഭജിക്കുന്നത് മികച്ച ഫലങ്ങൾ നൽകുന്നു:

| ഏജന്റ് | അതിന്റെ പ്രവർത്തനം |
|-------|-------------|
| **ResumeParser** | റെസ്യൂമെ പാഴ്‌സുചെയ്യുന്നു; ജോബ് വിവരണം പാസ്സും-ത്രൂ ആയി `[JOB DESCRIPTION PASS-THROUGH]` എന്നിടയ്ക്ക് മറ്റു ഏജന്റുകള്ക്ക് ഉള്ളടക്കമായി നൽകുന്നു |
| **JobDescriptionAgent** | പാസ്സും-ത്രൂയിൽ നിന്നുള്ള ജോബ് വേതനങ്ങൾ പാഴ്‌സുചെയ്യുന്നു; `[PARSED RESUME]` അടുത്ത തലത്തിലേക്ക് `[PARSED RESUME PASS-THROUGH]` ആയി ഫോർവേഡ് ചെയ്യുന്നു |
| **MatchingAgent** | രണ്ട് ലേബൽ നൽകിയ സെക്ഷനുകളെയും താരതമ്യപ്പെടുത്തുന്നു; 0–100 ഫിറ്റ് സ്കോർയും ഗോൾ പട്ടികയും സൃഷ്ടിക്കുന്നു |
| **GapAnalyzer** | പഠന റോഡ്‌മാപ്പ് ഒരുക്കുന്നു; ഓരോ ഗോൾക്കും Microsoft Learn തിരയുന്നു |

## ഒർക്കസ്ട്രേഷൻ ഗ്രാഫ്

പ്രവൃത്തി പ്രവാഹം ഒരു **അനുക്ക്രമ പൈപ്പ്ലൈൻ** ആണ് - ഓരോ ഏജന്റുമാരും തന്റെ ഔട്പുട്ട് അടുത്തതിനോട് കൈമാറുന്നു:

```mermaid
flowchart LR
    A["ഉപയോക്തൃ ഇൻപുട്ട്"] --> B["റിസ്യൂം പാർസ്സർ"]
    B -- "പാർსുചെയ്ത റിസ്യൂം + ജെഡി റീലേ" --> C["ജോബ് വിവരണം ഏജന്റ്"]
    C -- "ജെഡി ആവശ്യകതകൾ + റിസ്യൂം റീലേ" --> D["മെച്ചിപ്പെടുത്തൽ ഏജന്റ്"]
    D -- "അനുയോജ്യമായ റിപ്പോർട്ട് + ഗ്യാപ്പുകൾ" --> E["ഗ്യാപ് അനലസർ + MCP"]
    E --> F["അവസാന ഔട്ട്‌പുട്ട്"]

    style A fill:#4A90D9,color:#fff
    style B fill:#7B68EE,color:#fff
    style C fill:#7B68EE,color:#fff
    style D fill:#E67E22,color:#fff
    style E fill:#27AE60,color:#fff
    style F fill:#4A90D9,color:#fff
```

1. **ResumeParser** ഉപയോക്തൃ ഇൻപുട്ട് സ്വീകരിച്ച്, റെസ്യൂമെയ്റ്റ് പാഴ്‌സുചെയ്യുകയും ജോബ് വിവരണം `[JOB DESCRIPTION PASS-THROUGH]` ആയി പാസ്സും-ത്രൂ ചെയ്യുകയും ചെയ്യുന്നു.
2. **JD Agent** ഘടനപ്പെടുത്തിയ ആവശ്യങ്ങൾ പാഴ്‌സുചെയ്യുകയും `[PARSED RESUME PASS-THROUGH]` മുന്നോട്ട് പ്രേഷണം ചെയ്യുകയും ചെയ്യുന്നു.
3. **MatchingAgent** രണ്ടു സെക്ഷനുകളും താരതമ്യപ്പെടുത്തുകയും ഫിറ്റ് സ്കോറും ഗോൾ പട്ടികയും ഉണ്ടാക്കുകയും ചെയ്യുന്നു.
4. **GapAnalyzer** റോഡ്‌മാപ്പ് നിർമ്മിക്കുകയും Microsoft Learn MCP ടൂൾ ഓരോ ഗോൾക്കും വിളിക്കുകയും ചെയ്യുന്നു.

## ഇത് കോഡിൽ എങ്ങനെ മാപ്പ് ചെയ്യുന്നു

`main.py`-യിൽ, നിങ്ങൾ ഈ ഗ്രാഫ് `WorkflowBuilder` ഉപയോഗിച്ച് വിവരിക്കുന്നു:

```python
workflow_agent = (
    WorkflowBuilder(
        start_executor=resume_executor,       # ഉപയോക്തൃ ഇൻപുട്ട് സ്വീകരിക്കുന്ന ആദ്യ ഏജൻറ്
        output_executors=[gap_executor],      # അവസാന ഏജൻറ് - ഇതിന്റെ ഔട്ട്പുട്ട് പ്രതികരണമാണ്
    )
    .add_edge(resume_executor, jd_executor)       # ResumeParser → JD ഏജൻറ്
    .add_edge(jd_executor, matching_executor)     # JD ഏജൻറ് → MatchingAgent
    .add_edge(matching_executor, gap_executor)    # MatchingAgent → GapAnalyzer
    .build()
    .as_agent()
)
```

ഓരോ `Agent` നും `AgentExecutor` ലേക്ക് പൊതിഞ്ഞിരിക്കുന്നു. `add_edge()` കോൾസ് കർശനമായ അനുക്ക്രമ പൈപ്പ്ലൈൻ നിർവ്വചിക്കുന്നു - ഓരോ ഏജന്റും നേരിട്ടുള്ള മുൻപ്‌ പ്രവർത്തകന്റെ ഔട്പുട്ട് മാത്രമേ സ്വീകരിക്കൂ.

> `context_mode="last_agent"` എന്നത്, ഓരോ എക്സിക്യൂട്ടറും തന്റെ നേരിട്ടുള്ള മുൻപ്‌ പ്രവർത്തകന്റെ ഔട്പുട്ട് മാത്രം കാണും. ResumeParser, JD Agent ലേബൽ ചെയ്ത സെക്ഷനുകളിൽ ഡാറ്റ മുൻപോട്ടു പ്രേഷണം ചെയ്യുന്നു അതിനാൽ ഓരോ പിന്നീട് പ്രവർത്തിക്കുന്ന ഏജന്റ് വേണ്ടത് മാത്രമേ ലഭിക്കൂ.

## MCP ടൂൾ

GapAnalyzer ന് ഒരു ടൂൾ മാത്രമേ ഉള്ളൂ: `search_microsoft_learn_for_plan`. ഇത് `https://learn.microsoft.com/api/mcp`-ൻറെ ബന്ധപ്പെട്ടു ഓരോ സ്കിൽ ഗ്യാപിനും യഥാർത്ഥ Microsoft Learn ലിങ്കുകൾ നൽകുന്നു.

ടൂൾ പ്രവർത്തിക്കുമ്പോൾ താഴെയുള്ള ലോഗുകൾ കാണാം - എല്ലാം സാധാരണമാണ്:

```
GET  https://learn.microsoft.com/api/mcp → 405   ← connection probe, normal
POST https://learn.microsoft.com/api/mcp → 200   ← actual tool call
DELETE https://learn.microsoft.com/api/mcp → 405 ← cleanup probe, normal
```

`POST` പിഴവ് നൽകുന്നുവെങ്കിൽ മാത്രമേ ചിന്തിക്കേണ്ടതുള്ളൂ.
