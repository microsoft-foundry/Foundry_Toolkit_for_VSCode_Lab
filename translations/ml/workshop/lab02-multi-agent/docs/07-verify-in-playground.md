# മോഡ്യൂൾ 7 - പ്ലേഗ്രൗണ്ടിൽ പരിശോധന നടത്തുക

⏱️ ~10 മിനിറ്റ്

ഈ മോഡ്യൂളിൽ, നിങ്ങൾ വികസിപ്പിച്ചിട്ടുള്ള മൾട്ടി-ഏജന്റ് വർക്ക്ഫ്‌ളോയെ VS കോഡ്, ഫൗണ്ടറി പോര്‍ട്ടലിൽ പരിശോധിച്ച്, ഏജന്റ് ലോക്കൽ ടെസ്റ്റിംഗിനുപോലെ പ്രവർത്തിക്കുന്നുവെന്ന് സ്ഥിരീകരിക്കുന്നു.

---

## വിന്യാസത്തിന് ശേഷം വീണ്ടും പരീക്ഷിക്കാൻ എന്തുകൊണ്ട്?

ഹോസ്റ്റ് ചെയ്ത പരിസ്ഥിതിയിൽ ലോക്കലിൽ നിന്ന് ചില പ്രധാനം വശങ്ങളിൽ വ്യത്യാസമുണ്ട്:

| | ലോക്കൽ | ഹോസ്റ്റ് ചെയ്തവ |
|--|-------|--------|
| **ഐഡന്റിറ്റി** | നിങ്ങളുടെ വ്യക്തിഗത സൈൻ-ഇൻ (`DefaultAzureCredential`) | ഡെഡിക്കേറ്റഡ് പ്രീ ഏജന്റ് എൻട്ര അശയൻ (ഡിപ്ലോയ്മെന്റ് സമയത്ത് സ്വയം ഒരുക്കും) |
| **എന്റ്പോയിൻറ്** | `http://localhost:8088/responses` | ഫൗണ്ടറി ഏജന്റ് സർവീസ് മാനേജുചെയ്യുന്ന URL |
| **നെറ്റ്‌വർക്കി** | നിങ്ങളുടെ മെഷീൻ → Azure OpenAI + MCP | Azure ബാക്ക്ബോൺ (കുറഞ്ഞ ലേറ്റൻസി) |

ഒരു തെറ്റായ ക്യാവൈറ്റി variable, RBAC പ്രശ്നം, അല്ലെങ്കിൽ MCP ഔട്ട്‌ബൗണ്ട് കോൾ തടയപ്പെട്ടാൽ ഇതുപേരെ ആദ്യമായി പ്രത്യക്ഷപ്പെടും.

---

## ഓപ്ഷൻ A: VS കോഡ് പ്ലേഗ്രൗണ്ടിൽ പരീക്ഷിക്കുക (അടിസ്ഥാനപരമായി പരാമർശിക്കുന്നു)

### പടി 1: നിങ്ങളുടെ ഹോസ്റ്റ് ചെയ്ത ഏജന്റിലേക്ക് നാവിഗേറ്റ് ചെയ്യുക

1. ആക്ടിവിറ്റി ബാറിൽ **Foundry Toolkit** ഐക്കൺ ക്ലിക്ക് ചെയ്യുക.
2. നിങ്ങളുടെ പ്രോജക്ട് വികസിപ്പിച്ച് → **Hosted Agents (Preview)** → നിങ്ങളുടെ ഏജന്റ് കണ്ടെത്തുക.

![Foundry Toolkit sidebar showing Hosted Agents (Preview) with resume-job-fit-evaluator and its deployed versions](../../../../../translated_images/ml/06-foundry-sidebar-agent-status.a45994bfb5c21284.webp)

### പടി 2: ഒരു വേർഷൻ തിരഞ്ഞെടുക്കുക

1. ഏജന്റിനെ ക്ലിക്ക് ചെയ്ത് ആന്റെ വേർഷനുകൾ വ്യാപിപ്പിക്കുക.
2. `v1` ക്ലിക്ക് ചെയ്യുക → സ്റ്റാറ്റസ് **സജീവം** ആണെന്ന് സ്ഥിരീകരിക്കുക (സൈഡ്‌ബാർ "Running" അല്ലെങ്കിൽ "Started" കാണിക്കാം - രണ്ടും ഒരേ റെഡിയായ നില സൂചിപ്പിക്കുന്നു).

### പടി 3: പ്ലേഗ്രൗണ്ട് തുറക്കുക

1. **Playground** ക്ലിക്ക് ചെയ്യുക (അല്ലെങ്കിൽ വേർഷൻ റൈറ്റ്-ക്ലിക്ക് → **Open in Playground**).
2. VS കോഡ് ടാബിൽ ഒരു ചാറ്റ് വിൻഡോ തുറക്കും.

### പടി 4: നിങ്ങളുടെ സ്മോക്ക് ടെസ്റ്റുകൾ നടത്തുക

[മോഡ്യൂൾ 5](05-test-locally.md)ൽ നിന്നുള്ള ഒരുപോലെ 3 ടെസ്റ്റുകളും പ്ലേഗ്രൗണ്ട് ഇൻപുട്ട് ബോക്സിൽ ടൈപ്പ് ചെയ്ത് **Send** (അല്ലെങ്കിൽ **Enter**) അമർത്തുക.

#### ടെസ്റ്റ് 1 - പൂർണ്ണ റിസ്യൂം + JD (സാധാരണ പ്രവാഹം)

മോഡ്യൂൾ 5, ടെസ്റ്റ് 1 ലിലെ പൂർണ്ണ റിസ്യൂം + JD പ്രാമ്പ്റ്റ് പേസ്റ്റ് ചെയ്യുക (ജെയ്ൻ ഡോ + സീനിയർ ക്ലൗഡ് എഞ്ചിനീയർ കോൺടോസോ ലിമിറ്റഡ്).

**പ്രതീക്ഷിക്കുന്നത്:**
- ഫിറ്റ് സ്കോർ തസ്തികഭാഗം ഗണിതവുമായ് (100 പോയിന്റ് സ്കെയിൽ)
- മത്സ്യമാറ്റം ചെയ്യുന്ന സ്കിൽസ് വിഭാഗം
- നഷ്ടപ്പെട്ട സ്കിൽസ് വിഭാഗം
- **ഒരു സ്കിൽ നഷ്ടപ്പെടുന്ന ഓരോ ഗ്യാപ് കാർഡും** Microsoft Learn URLs ഉൾപ്പെടെ
- പഠന റോഡ്‌മാപ്പ് ടൈംലൈൻ ഉപയോഗിച്ച്

#### ടെസ്റ്റ് 2 - ദ്രുതമൊച്ചയായ ചെറിയ ടെസ്റ്റ് (കുറഞ്ഞ ഇൻപുട്ട്)

```
RESUME: 3 years Python developer, knows Django and PostgreSQL, no cloud experience.

JOB: Cloud DevOps Engineer requiring AWS, Kubernetes, Terraform, CI/CD. 5 years needed.
```

**പ്രതീക്ഷിക്കുന്നത്:**
- കിടയെ കുറവുള്ള ഫിറ്റ് സ്കോർ (< 40)
- സത്യസന്ധമായ വിലയിരുത്തൽ സ്റ്റെജ് ചെയ്‍ത പഠന പാതയോടെ
- നിരവധി ഗ്യാപ് കാർഡുകൾ (AWS, കുബർണീറ്റസ്, ടെറഫോം, CI/CD, അനുഭവ കുറവ്)

#### ടെസ്റ്റ് 3 - ഉയർന്ന ഫിറ്റ് പ്രാർത്ഥകന്

```
RESUME:
10 years Azure Cloud Architect. AZ-305 certified. Expert in AKS, Terraform, Azure DevOps, 
Azure Functions, Helm, Prometheus, Grafana, Python, Go. Led platform team of 8.

JOB:
Senior Cloud Engineer. Required: AKS, Terraform, Azure DevOps, Python. Preferred: Helm, Go.
5+ years experience. AZ-305 preferred.
```

**പ്രതീക്ഷിക്കുന്നത്:**
- ഉയർന്ന ഫിറ്റ് സ്കോർ (≥ 80)
- അഭിമുഖ സജ്ജതയിലും തീർക്കലിലും ശ്രദ്ധ കേന്ദ്രീകരിക്കുക
- കുറച്ച് അല്ലെങ്കിൽ ഒന്നും ഇല്ലാത്ത ഗ്യാപ് കാർഡുകൾ
- തയ്യാറെടുപ്പിനുള്ള ചെറിയ ടൈംലൈൻ

### പടി 5: ലോക്കൽ ഫലങ്ങളുമായി താരതമ്യം ചെയ്യുക

നിങ്ങളുടെ നോട്ടുകളും ബ്രൗസർ ടാബും (മോഡ്യൂൾ 5ൽ ലൊക്കൽ പ്രതികരണങ്ങൾ സംരക്ഷിച്ചത്) തുറന്ന് ഓരോ ടെസ്റ്റിനും:

- പ്രതികരണത്തിൽ **അImpro ത.same ഘടന** (ഫിറ്റ് സ്കോർ, ഗ്യാപ് കാർഡുകൾ, റോഡ്‌മാപ്പ്) ഉണ്ടോ?
- **അImpro ത.same സ്കോറിംഗ് റൂബ്രിക്** (100 പോയിന്റ് വിഭജനത്തിന്) അനുസരിക്കുന്നുണ്ടോ?
- **Microsoft Learn URLs** ഗ്യാപ് കാർഡുകളിൽ ഇപ്പോഴും ഉണ്ടോ?
- **ഒരു പോലെ ഓരോ പാർട്ടി സ്കിൽക്ക് ഒരുമാത്രം ഗ്യാപ് കാർഡ്** ഉണ്ടോ (മുട്ടിവെട്ടില്ലാതെ)?

> **ചെറിയ വാക്കുകളിലെ വ്യത്യാസങ്ങൾ സാധാരണമാണ്** - മോഡൽ നിർണായകമല്ല. ഘടന, സ്കോറിംഗ് സ്ഥിരത, MCP ടൂൾ ഉപയോഗം ശ്രദ്ധിക്കുക.

## ഓപ്ഷൻ B: ഫൗണ്ടറി പോര്‍ട്ടലിൽ പരീക്ഷിക്കുക

[ഫൗണ്ടറി പോർട്ടൽ](https://ai.azure.com) വെബ്ബ് അധിഷ്ടിത പ്ലേഗ്രൗണ്ട് നൽകുന്നു, ടീംമേറ്റുകളോ സ്റ്റേക്ക്‌ഹോൾഡർമാരോടോ പങ്കിടാൻ ഉപകരിക്കുന്നു.

### പടി 1: ഫൗണ്ടറി പോര്‍ട്ടൽ തുറക്കുക

1. നിങ്ങളുടെ ബ്രൗസർ തുറന്ന് [https://ai.azure.com](https://ai.azure.com) ലേക്ക് നാവിഗേറ്റ് ചെയ്യുക.
2. നിങ്ങൾ ഇപ്പോൾ വരെ വർക്‌ഷോപ്പിൽ ഉപയോഗിക്കുന്ന Azure അക്കൗണ്ടിൽ സൈൻ ഇൻ ചെയ്യുക.

### പടി 2: നിങ്ങളുടെ പ്രോജക്റ്റിലേക്ക് നാവിഗേറ്റ് ചെയ്യുക

1. ഹോം പേജിൽ, ഇടത് സൈഡ്‌ബാറിൽ **Recent projects** തിരയുക.
2. നിങ്ങളുടെ പ്രോജക്റ്റ് പേര് ക്ലിക്ക് ചെയ്യുക (ഉദാ., `workshop-agents`).
3. കാണാത്ത പക്ഷം **All projects** ക്ലിക്ക് ചെയ്ത് തിരയുക.

### പടി 3: ഡിപ്ലോയ്മെന്റ് ഏജന്റ് കണ്ടെത്തുക

1. പ്രോജക്റ്റ് ഇടത് നാവിഗേഷനിൽ 클릭하여 **Build** → **Agents** (അല്ലെങ്കിൽ **Agents** വിഭാഗം തിരയുക).
2. ഏജന്റുകളുടെ പട്ടിക കാണണം. നിങ്ങളുടെ ഡിപ്ലോയ്മെന്റ് ഏജന്റ് കണ്ടെത്തുക (ഉദാ., `resume-job-fit-evaluator`).
3. ഏജന്റ് പേരിൽ ക്ലിക്ക് ചെയ്ത് വിശദാംശ പേജ് തുറക്കുക.

### പടി 4: പ്ലേഗ്രൗണ്ട് തുറക്കുക

1. ഏജന്റ് വിശദാംശ പേജിൽ, ടോപ്പ് ടൂൾബാറിൽ നോക്കുക.
2. **Open in playground** (അല്ലെങ്കിൽ **Try in playground**) ക്ലിക്ക് ചെയ്യുക.
3. ഒരു ചാറ്റ് ഇന്റർഫേസ് തുറക്കും.

### പടി 5: സമാനമായ സ്മോക്ക് ടെസ്റ്റുകൾ നടത്തുക

VS കോഡ് പ്ലേഗ്രൗണ്ട് വിഭാഗത്തിൽ താഴെപ്പറഞ്ഞ 3 ടെസ്റ്റുകളും ആവർത്തിക്കുക. ഓരോ പ്രതികരണവും തുല്യമായി ലൊക്കൽ ഫലങ്ങളുമായി (മോഡ്യൂൾ 5) VS കോഡ് പ്ലേഗ്രൗണ്ട് ഫലങ്ങളുമായി (ഓപ്ഷൻ A മുകളിൽ) താരതമ്യം ചെയ്യുക.

## മൾട്ടി-ഏജന്റ് مخصوص പരിശോദന

അടിസ്ഥാന ശരിത്വത്തിന് പുറമെ, മൾട്ടി-ഏജന്റ്-പ്രത്യേക പ്രവർത്തനങ്ങൾ പരിശോധിക്കുക:

### MCP ടൂൾ تنفيذ

| പരിശോധിക്കുക | എങ്ങനെ സ്ഥിരീകരിക്കാം | പാസ് ശര്‍ത്ത് |
|-------|---------------|----------------|
| MCP കോൾസ് വിജയിക്കുന്നു | ഗ്യാപ് കാർഡുകളിൽ `learn.microsoft.com` URLs ഉണ്ട് | യഥാർത്ഥ URLs, ബാക്ക്അപ്പ് സന്ദേശങ്ങൾ അല്ല |
| ഒരിലധികം MCP കോൾസ് | ഓരോ ഉയർന്ന/മധ്യ ഗ്യാപിനും ഗുണഭോ​ഗങ്ങൾ ആണെന്ന് | ആദ്യ ഗ്യാപ് കാർഡിൽ മാത്രം അല്ല |
| MCP ഫ്ബാക്ക് പ്രവർത്തിക്കുന്നു | URLs ഇല്ലെങ്കിൽ ബാക്ക്അപ് ടെക്സ്റ്റ് പരിശോധിക്കുക | ഏജന്റ് ഇപ്പോഴും ഗ്യാപ് കാർഡുകൾ ഉൽപ്പാദിപ്പിക്കുന്നു (URLs ഓടെ അല്ലയോ) |

### ഏജന്റ് കോ-ഓർഡിനേഷൻ

| പരിശോധിക്കുക | എങ്ങനെ സ്ഥിരീകരിക്കാം | പാസ് ശര്‍ത്ത് |
|-------|---------------|----------------|
| എല്ലാ 4 ഏജന്റും ഓടി | ഔട്ട്പുട്ട് ഫിറ്റ് സ്കോർ ആൻഡ് ഗ്യാപ് കാർഡുകൾ ഉൾക്കൊള്ളുന്നു | സ്കോർ MatchingAgent യിൽ നിന്നും, കാർഡുകൾ GapAnalyzerൽ നിന്നുമാണ് |
| തുള്ളികളുള്ള നിർവഹണം | പ്രതികരണ സമയമർത്ഥം ഉള്ളത് (< 2 മിനിറ്റ്) | 3 മിനിറ്റേക്കാൾ കൂടുതൽ എങ്കിൽ ടർമിനൽ ലോഗിൽ പിശകുകൾ പരിശോധിക്കുക |
| ഡാറ്റാ ഫ്ലോ ജീർണ്ണത | ഗ്യാപ് കാർഡുകൾ മാച്ചിങ് റിപ്പോർട്ടിലെ സ്കിലുകളിൽ റഫറൻസ് ചെയ്യുന്നു | JDയിൽ ഇല്ലാത്ത ഹലൂസിനേറ്റഡ് സ്കിലുകൾ ഇല്ല |

## സ്ഥിരീകരണ റൂബ്രിക്

നിങ്ങളുടെ മൾട്ടി-ഏജന്റ് വർക്ക്ഫ്‌ളോയുടെ ഹോസ്റ്റഡ് പെരുമാറ്റം വിലയിരുത്താൻ ഈ റൂബ്രിക് ഉപയോഗിക്കുക:

| # | മാനദണ്ഡം | പാസ് ശര്‍ത്ത് | പാസ്? |
|---|----------|---------------|-------|
| 1 | **പ്രവർത്തനപരമായ ശരിത്വം** | ഏജന്റ് റിസ്യൂം + JD ന് ഫിറ്റ് സ്കോർ, ഗ്യാപ് വിശകലനവുമായി പ്രതികരിക്കുന്നു | |
| 2 | **സ്കോറിംഗ് സ്ഥിരത** | ഫിറ്റ് സ്കോർ 100 പോയിന്റ് സ്കെയിൽ ഗണിതവിഭാഗം ഉപയോഗിക്കുന്നു | |
| 3 | **ഗ്യാപ് കാർഡ് പൂർണ്ണത** | ഓരോ നഷ്ടപ്പെട്ട സ്കിൽക്കും ഒരു കാർഡ് (മുട്ടിവെട്ടിയ അല്ല, സംയോജിപ്പിച്ച അല്ല) | |
| 4 | **MCP ടൂൾ ഇന്റഗ്രേഷൻ** | ഗ്യാപ് കാർഡുകളിൽ യഥാർത്ഥ Microsoft Learn URLs ഉണ്ട് | |
| 5 | **ഘടനാത്മക സ്ഥിരത** | ലോക്കൽ, ഹോസ്റ്റഡ് പ്രവർത്തനങ്ങളിലെ ഔട്ട്പുട്ട് ഘടന സാമ്യം | |
| 6 | **പ്രതികരണ സമയം** | പൂർണ്ണ വിലയിരുത്തലിനായി ഹോസ്റ്റ് ചെയ്ത ഏജന്റ് 2 മിനിറ്റിനുള്ളിൽ പ്രതികരിക്കും | |
| 7 | **പിശകുകൾ ഇല്ല** | HTTP 500 പിശകുകൾ, ടൈംഔട്ടുകൾ, ശൂന്യ പ്രതികരണങ്ങൾ ഇല്ല | |

> "പാസ്" അഥവാ 7 മാനദണ്ഡങ്ങളും എല്ലാവിധ 3 സ്മോക്ക് ടെസ്റ്റുകളും കുറഞ്ഞത് ഒരു പ്ലേഗ്രൗണ്ടിൽ (VS കോഡ് അല്ലെങ്കിൽ പോർട്ടൽ) പാലിക്കുന്നതാണ്.

## പ്ലേഗ്രൗണ്ട് പ്രശ്നങ്ങൾ പരിഹരിക്കൽ

| ലക്ഷണം | സാധ്യത പ്രധാന കാരണം | പരിഹാരം |
|---------|-------------|-----|
| പ്ലേഗ്രൗണ്ട് ലോഡ് ആകുന്നില്ല | കൺടെയ്നർ `active` നിലയിലല്ല | [മോഡ്യൂൾ 6](06-deploy-to-foundry.md) തിരികെ പോയി ഡിപ്ലോയ്മെന്റ് സ്ഥിതി പരിശോധിക്കുക. `creating` ആണെങ്കിൽ കാത്തിരിക്കുക |
| ഏജന്റ് ശൂന്യ പ്രതികരണം നൽകുന്നു | മോഡൽ ഡിപ്ലോയ്മെന്റ് പേര് പൊരുത്തക്കേടാണ് | `agent.yaml` → `environment_variables` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` നിങ്ങളുടെ മോഡലിന് പൊരുത്തമുള്ളതാണെന്ന് പരിശോധിക്കുക |
| ഏജന്റ് പിശക് സന്ദേശം നൽകുന്നു | [RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) അനുയോജ്യസാധനം ഇല്ല | പ്രോജക്റ്റ് പരിധിയിൽ **[Foundry User](https://aka.ms/foundry-ext-project-role)** (മുമ്പ് Azure AI User) നിയോഗിക്കുക |
| ഗ്യാപ് കാർഡുകളിൽ Microsoft Learn URLs ഇല്ല | MCP ഔട്ട്‌ബൗണ്ട് തടയപ്പെട്ടത് അല്ലെങ്കിൽ MCP സെർവർ ലഭ്യമല്ല | കൺടെയ്നർ `learn.microsoft.com` എത്തിച്ചേരാൻ കഴിയും എന്ന് പരിശോധിക്കുക. [മോഡ്യൂൾ 8](08-troubleshooting.md) കാണുക |
| ഒരേയൊരു ഗ്യാപ് കാർഡ് മാത്രം (മുട്ടിവെട്ടി) | GapAnalyzer നിർദ്ദേശങ്ങളിൽ "CRITICAL" ബ്ലോക്ക് ഇല്ല | [മോഡ്യൂൾ 3, പടി 2.4](03-configure-agents.md) തുറന്ന് പരിശോധിക്കുക |
| ഫിറ്റ് സ്കോർ ലോക്കലിൽ നിന്നും വളരെ വ്യത്യസ്തം | വ്യത്യസ്ത മോഡൽ അല്ലെങ്കിൽ നിർദ്ദേശങ്ങൾ ഡിപ്ലോയ്ചെയ്തത് | `agent.yaml` envi vars ലൊക്കൽ `.env` നും താരതമ്യം ചെയ്യുക. ആവശ്യമെങ്കിൽ വീണ്ടും ഡിപ്ലോയ്ചെയ്യുക |
| പോർട്ടലിൽ "Agent not found" | ഡിപ്ലോയ്മെന്റ് ഇപ്പോഴും പ്രചരിക്കുന്നതോ പരാജയപ്പെട്ടതോ | 2 മിനിറ്റ് കാത്തുനോക്കുക, പുനഃപ്രാപ്‌തമാക്കുക. ഇല്ലെങ്കിൽ [മോഡ്യൂൾ 6](06-deploy-to-foundry.md) നിന്ന് വീണ്ടും ഡിപ്ലോയ്ചെയ്യുക |
