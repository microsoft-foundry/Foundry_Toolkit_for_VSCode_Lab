# ਮਾਡਿਊਲ 9 - ਸੰਖੇਪ ਅਤੇ ਅਗਲੇ ਕਦਮ

⏱️ ~5 ਮਿੰਟ

**ਵਧਾਈਆਂ!** ਤੁਸੀਂ ਮਾਈਕ੍ਰੋਸਾਫਟ ਫਾਉਂਡਰੀ ਅਤੇ ਫਾਉਂਡਰੀ ਟੂਲਕਿਟ ਫਾਰ VS ਕੋਡ ਦੀ ਵਰਤੋਂ ਕਰਕੇ ਇੱਕ ਮਲਟੀ-ਏਜੰਟ ਵਰਕਫਲੋ ਬਣਾਇਆ, ਟੈਸਟ ਕੀਤਾ ਅਤੇ (ਜੇ ਪਾਥ A 'ਤੇ ਹੋ) ਤੈਨਾਤ ਕੀਤਾ ਹੈ।

---

## ਤੁਸੀਂ ਜੋ ਬਣਾਇਆ

**Resume → Job Fit Evaluator** - ਇੱਕ ਮਲਟੀ-ਏਜੰਟ ਹੋਸਟ ਕੀਤਾ ਗਿਆ ਵਰਕਫਲੋ ਜੋ:
- HTTP ਰਾਹੀਂ ਰਿਜੂਮੇ + ਨੌਕਰੀ ਦੇ ਵੇਰਵੇ ਪ੍ਰਾਪਤ ਕਰਦਾ ਹੈ (`POST /responses`)
- ਲਗਾਤਾਰ ਚਾਰ ਵਿਸ਼ੇਸ਼ ਏਜੰਟ ਚਲਾਉਂਦਾ ਹੈ - ਹਰ ਏਜੰਟ ਆਪਣੇ ਉੱਤਰਾਧਿਕਾਰੀ ਲਈ ਜਰੂਰੀ ਡਾਟਾ ਭੇਜਦਾ ਹੈ
- ਇੱਕ ਫਿੱਟ ਸਕੋਰ ਵਾਪਸ ਕਰਦਾ ਹੈ (0–100 ਨਾਲ ਵਿਗੜਾਵ), ਇੱਕ ਹੁਨਰ ਅਤੇ ਪ੍ਰਮਾਣਕ ਸਰਟੀਫਿਕੇਟ ਦੀ कमी ਦੀ ਸੂਚੀ, ਅਤੇ ਹਰ ਕਮੀ ਲਈ ਵਾਸਤਵਿਕ ਮਾਈਕ੍ਰੋਸਾਫਟ ਲਰਨ ਲਿੰਕਸ ਨਾਲ ਵਿਅਕਤੀਗਤ ਸਿੱਖਣ ਦਾ ਰੋਡਮੇਪ
- ਮਾਈਕ੍ਰੋਸਾਫਟ ਲਰਨ MCP ਸਰਵਰ (`https://learn.microsoft.com/api/mcp`) ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ ਤਾਂ ਜੋ ਹਰ ਪਛਾਣੀ ਗਈ ਹੁਨਰ ਦੀ ਕਮੀ ਲਈ ਅਧਿਕਾਰਿਕ ਸਿੱਖਣ ਵਾਲੇ ਸਰੋਤ ਲੈ ਸਕੇ
- ਮਾਈਕ੍ਰੋਸਾਫਟ ਫਾਉਂਡਰੀ ਏਜੰਟ ਸੇਵਾ ਵਿੱਚ ਇੱਕ ਸਿੰਗਲ ਕੰਟੇਨਰਾਈਜ਼ਡ ਹੋਸਟ ਕੀਤਾ ਗਿਆ ਏਜੰਟ ਵਜੋਂ ਚੱਲਦਾ ਹੈ

## ਮੁੱਖ ਸਿਧਾਂਤ ਸਿੱਖੇ ਗਏ

| ਸਿਧਾਂਤ | ਤੁਸੀਂ ਕੀ ਅਭਿਆਸ ਕੀਤਾ |
|---------|-------------------|
| **ਮਲਟੀ-ਏਜੰਟ ਆਰਕਿਸਟ੍ਰੇਸ਼ਨ** | `WorkflowBuilder` ਲਗਾਤਾਰ ਪਾਈਪਲਾਈਨ ਨਾਲ `add_edge()` |
| **ਏਜੰਟ ਵਿਸ਼ੇਸ਼ਤਾ** | ਚਾਰ ਕੇਂਦਰਿਤ ਏਜੰਟ ਇੱਕ ਸਰਬ-ਉਦੇਸ਼ੀਏ ਏਜੰਟ ਤੋਂ ਬਿਹਤਰ ਹਨ |
| **ਸਮੱਗਰੀ ਰਾਊਟਰ ਪੈਟਰਨ** | ResumeParser ਇੱਕ ਰਾਊਟਰ ਵਾਂਗ ਕੰਮ ਕਰਦਾ ਹੈ - ਇਹ ਜੇਡੀ ਟੈਕਸਟ ਨੂੰ `[JOB DESCRIPTION PASS-THROUGH]` ਸੈਕਸ਼ਨ ਵਿੱਚ ਸੁਰੱਖਿਅਤ ਕਰਦਾ ਹੈ ਤਾਂ ਜੋ ਹੇਠਲੇ ਏਜੰਟ ਇਸ ਤੱਕ ਪਹੁੰਚ ਕਰ ਸਕਣ (ਲੋੜੀਂਦਾ ਹੈ ਕਿਉਂਕਿ `context_mode="last_agent"` ਮਤਲਬ ਹੈ ਕੇਵਲ `start_executor` ਹੀ ਕੱਚਾ ਯੂਜ਼ਰ ਸੁਨੇਹਾ ਵੇਖਦਾ ਹੈ) |
| **ਸਮੱਗਰੀ ਰੀਲੇ ਪੈਟਰਨ** | JD Agent `[PARSED RESUME PASS-THROUGH]` ਅੱਗੇ ਭੇਜਦਾ ਹੈ ਤਾਂ ਜੋ MatchingAgent ਨੂੰ ਦੋਹਾਂ ਪ੍ਰੋਫਾਈਲਾਂ ਮਿਲਣ; OR-ਸਮੀਕਰਨ ਡਬਲ ਟ੍ਰਿਗਰ ਤੋਂ ਬਚਦਾ ਜੋ ਫੈਨ-ਇਨ ਗ੍ਰਾਫਾਂ ਕਰਦੇ ਹਨ |
| **MCP ਟੂਲ ਇੰਟਿਗ੍ਰੇਸ਼ਨ** | `@tool` + `streamable_http_client` ਇੱਕ ਬਾਹਰੀ MCP ਸਰਵਰ ਨੂੰ ਕਾਲ ਕਰਦਾ ਹੈ |
| **ਹੋਸਟ ਕੀਤਾ ਗਿਆ ਏਜੰਟ ਲਾਈਫਸਾਈਕਲ** | Scaffold → Configurate → ਲੋਕਲ ਟੈਸਟ → ਤੈਨਾਤ → ਕਲਾਉਡ ਵਿੱਚ ਵੈਰੀਫਾਈ |
| **`context_mode="last_agent"`** | ਹਰ ਐਕਜ਼ੀਕਿਊਟਰ ਸਿਰਫ ਆਪਣੇ ਸਿੱਧੇ ਪੂਰਵ ਇਨਪੁੱਟ ਨੂੰ ਵੇਖਦਾ ਹੈ |
| **ਫਾਉਂਡਰੀ ਟੂਲਕਿਟ ਵਰਕਫਲੋ** | Scaffold ਵਿਜਾਰਡ, ਏਜੰਟ ਇੰਸਪੈਕਟਰ, ਵਰਕਫਲੋ ਵਿਜੁਆਲਾਈਜ਼ਰ, ਇਕ-ਕਲਿੱਕ ਤੈਨਾਤ |

### ਇਸ ਵਰਕਫਲੋ ਨੂੰ ਵਧਾਉਣ ਦੇ ਵਿਚਾਰ

- **5ਵਾਂ ਏਜੰਟ ਸ਼ਾਮਲ ਕਰੋ** - ਇੱਕ ਇੰਟਰਵਿਊ ਕੋਚ ਜੋ ਖ਼ਾਲੀ ਗੈਪ ਰਿਪੋਰਟ ਦੇ ਆਧਾਰ 'ਤੇ ਸੰਭਾਵਿਤ ਇੰਟਰਵਿਊ ਸਵਾਲ ਬਣਾਉਂਦਾ ਹੈ
- **Bing ਗਰਾਊਂਡਿੰਗ ਟੂਲ ਸ਼ਾਮਲ ਕਰੋ** - JD Agent ਨੂੰ ਸਮਾਨ ਨੌਕਰੀਆਂ ਦੀ ਖੋਜ ਕਰਨ ਦਿਓ ਤਾਂ ਜੋ ਲੋੜਾਂ ਨੂੰ ਸੰਵਧਿਤ ਕੀਤਾ ਜਾ ਸਕੇ
- **ਰਿਜੂਮੇ ਡੇਟਾਬੇਸ ਨਾਲ ਜੋੜੋ** - ਇੱਕ ਕਸਟਮ `@tool` ਰਾਹੀਂ ਡੇਟਾਬੇਸ ਤੋਂ ਉਮੀਦਵਾਰ ਪ੍ਰੋਫਾਈਲ ਖਿੱਚੋ
- **ਵੱਖ-ਵੱਖ ਮਾਡਲ ਟ੍ਰਾਈ ਕਰੋ** - `gpt-4.1` ਅਤੇ `gpt-4.1-mini` ਦੀ ਆਉਟਪੁੱਟ ਗੁਣਵੱਤਾ ਅਤੇ ਲੇਟੈਂਸੀ ਦੀ ਤੁਲਨਾ ਕਰੋ
- **Foundry ਨਾਲ ਮੁਲਾਂਕਣ ਕਰੋ** - ਇੱਕ ਸੋਨੇਰੀ ਡਾਟਾਸੇਟ ਦੇ ਖਿਲਾਫ ਫਿੱਟ ਰਿਪੋਰਟਾਂ ਨੂੰ ਸਕੋਰ ਕਰਨ ਲਈ ਮੁਲਾਂਕਣ ਕਾਰਜ ਵਰਤੋ

### ਪਾਥ B ਉਪਭੋਗਤਾਵਾਂ ਲਈ: ਕਲਾਉਡ ਤੈਨਾਤ ਤੱਕ ਅਪਗਰੇਡ ਕਰੋ

ਜਦੋਂ ਤੁਸੀਂ ਕਲਾਉਡ 'ਤੇ ਤੈਨਾਤ ਕਰਨ ਲਈ ਤਿਆਰ ਹੋ:
1. ਇੱਕ Azure ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਪ੍ਰਾਪਤ ਕਰੋ ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. [Lab 01, Module 01](../../lab01-single-agent/docs/01-setup.md) ਨੂੰ ਪੂਰਾ ਕਰੋ (ਪ੍ਰੋਜੈਕਟ ਬਣਾਓ, ਮਾਡਲ ਤੈਨਾਤ ਕਰੋ, RBAC ਲਗਾਓ)
3. ਆਪਣੀ `.env` ਫਾਈਲ ਵਿੱਚ ਫਾਉਂਡਰੀ ਪ੍ਰੋਜੈਕਟ ਐਂਡਪੌਇੰਟ ਅਤੇ ਮਾਡਲ ਤੈਨਾਤ ਨਾਮ ਅਪਡੇਟ ਕਰੋ
4. [Module 06 - Deploy to Foundry](06-deploy-to-foundry.md) ਤੋਂ ਜਾਰੀ ਰੱਖੋ

## ਸਰੋਤ ਸਾਫ਼ ਕਰੋ (ਚੋਣਵੀਂ)

ਜੇ ਤੁਸੀਂ ਇਸ ਵਰਕਸ਼ਾਪ ਦੌਰਾਨ ਬਣਾਏ ਗਏ Azure ਸਰੋਤਾਂ ਨੂੰ ਹਟਾਉਣਾ ਚਾਹੁੰਦੇ ਹੋ:

### ਵਿਕਲਪ 1: ਰਿਸੋਰਸ ਗਰੁੱਪ ਨੂੰ ਮਿਟਾਓ (ਸਭ ਕੁਝ ਹਟਾ ਦਿੰਦਾ ਹੈ)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### ਵਿਕਲਪ 2: ਸਿਰਫ਼ ਹੋਸਟ ਕੀਤਾ ਗਿਆ ਏਜੰਟ ਹਟਾਓ

1. [ai.azure.com](https://ai.azure.com) ਖੋਲ੍ਹੋ → ਆਪਣਾ ਪ੍ਰੋਜੈਕਟ → **Build** → **Agents**.
2. **PersonalCareerCopilot** ਲੱਭੋ → **Delete** 'ਤੇ ਕਲਿੱਕ ਕਰੋ।

### ਵਿਕਲਪ 3: ਮਾਡਲ ਤੈਨਾਤ ਮਿਟਾਓ

1. ਫਾਉਂਡਰੀ ਸਾਈਡਬਾਰ ਵਿੱਚ ਆਪਣੇ ਪ੍ਰੋਜੈਕਟ ਨੂੰ ਵਧਾਓ → **Models**.
2. ਮਾਡਲ ਤੈਨਾਤ 'ਤੇ ਰਾਈਟ-ਕਲਿੱਕ ਕਰੋ → **Delete**.

> **ਖ਼ਰਚ ਨੋਟ:** ਹੋਸਟ ਕੀਤੇ ਗਏ ਏਜੰਟ ਸਿਰਫ ਦੌੜਦੇ ਸਮੇਂ ਖ਼ਰਚਾ ਕਰਦੇ ਹਨ। ਜੇ ਤੁਸੀਂ ਏਜੰਟ ਨੂੰ ਰੋਕਦੇ ਜਾਂ ਮਿਟਾਉਂਦੇ ਹੋ, ਤਾਂ ਹੋਰ ਚੱਲਦਾ ਖ਼ਰਚਾ ਨਹੀਂ ਹੈ। ਮਾਡਲ ਤੈਨਾਤ ਲਈ ਰਿਜ਼ਰਵਡ ਕੈਪੈਸੀਟੀ ਦਾ ਥੋੜ੍ਹਾ ਖ਼ਰਚਾ ਹੋ ਸਕਦਾ ਹੈ - ਜੇ ਤੁਸੀਂ ਖਤਮ ਕਰ ਚੁੱਕੇ ਹੋ ਤਾਂ ਇਸਨੂੰ ਮਿਟਾ ਦਿਓ।
