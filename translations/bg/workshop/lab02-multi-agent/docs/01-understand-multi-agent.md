# Модул 1 - Разбиране на архитектурата

⏱️ ~5 мин

Преди да напишете код, ето кратък преглед на това, което изграждате и как работи.

---

## Какво изграждате

Вмъквате **резюме** и **описание на работа**. Работният поток връща:

- Оценка за съвпадение (0–100 с разбивка)
- Списък с пропуснати умения и сертификати
- Персонализиран учебен план с линкове към Microsoft Learn за всяка пропуска

---

## Четирите агента

Един агент, който се опитва да анализира, оценява и планира всичко наведнъж, има склонност да бърза и да дава повърхностен резултат. Разделянето на работата на четири специализирани агенти дава по-добри резултати:

| Агент | Какво прави |
|-------|-------------|
| **ResumeParser** | Анализира резюмето; копира описанието на работата дословно в `[JOB DESCRIPTION PASS-THROUGH]` за следващите агенти |
| **JobDescriptionAgent** | Извлича изискванията от описанието; препраща `[PARSED RESUME]` като `[PARSED RESUME PASS-THROUGH]` напред |
| **MatchingAgent** | Сравнява двата етикетирани раздела; изчислява оценка за съвпадение от 0–100 и списък с пропуски |
| **GapAnalyzer** | Създава учебен план; търси Microsoft Learn ресурс за всеки пропуск |

---

## Графикът на оркестрацията

Работният поток е **последователен конвейер** – всеки агент предава своя изход на следващия:

```mermaid
flowchart LR
    A["Вход от потребител"] --> B["Анализатор на автобиографии"]
    B -- "анализирано резюме + препращане на JD" --> C["Агент за описание на работата"]
    C -- "изисквания на JD + препращане на резюме" --> D["Агент за съвпадение"]
    D -- "отчет за съвпадение + пропуски" --> E["Анализатор на пропуски + MCP"]
    E --> F["Краен резултат"]

    style A fill:#4A90D9,color:#fff
    style B fill:#7B68EE,color:#fff
    style C fill:#7B68EE,color:#fff
    style D fill:#E67E22,color:#fff
    style E fill:#27AE60,color:#fff
    style F fill:#4A90D9,color:#fff
```

1. **ResumeParser** получава входа от потребителя, анализира резюмето и копира описанието на работата в `[JOB DESCRIPTION PASS-THROUGH]`.
2. **JD Agent** извлича структурирани изисквания и препраща `[PARSED RESUME PASS-THROUGH]` напред.
3. **MatchingAgent** сравнява двата раздела и изчислява оценка за съвпадение и списък с пропуски.
4. **GapAnalyzer** изготвя учебния план и извиква инструмента Microsoft Learn MCP за всеки пропуск.

## Как това се отразява в кода

В `main.py` описвате този граф с `WorkflowBuilder`:

```python
workflow_agent = (
    WorkflowBuilder(
        start_executor=resume_executor,       # първият агент, който получава потребителски вход
        output_executors=[gap_executor],      # последен агент - неговият изход е отговорът
    )
    .add_edge(resume_executor, jd_executor)       # ResumeParser → JD агент
    .add_edge(jd_executor, matching_executor)     # JD агент → MatchingAgent
    .add_edge(matching_executor, gap_executor)    # MatchingAgent → GapAnalyzer
    .build()
    .as_agent()
)
```

Всеки `Agent` е обвит в `AgentExecutor`. Повикванията `add_edge()` дефинират строго последователен конвейер – всеки агент получава само изхода на своя непосредствен предшественик.

> `context_mode="last_agent"` означава, че всеки изпълнител вижда само изхода на своя непосредствен предшественик. ResumeParser и JD Agent препращат данни напред в етикетирани секции, така че всеки агент надолу по веригата има точно това, от което се нуждае.

## Инструментът MCP

GapAnalyzer има един инструмент: `search_microsoft_learn_for_plan`. Той се свързва с `https://learn.microsoft.com/api/mcp` и връща реални линкове от Microsoft Learn за всяка пропусната умение.

Когато инструментът работи, ще видите тези логове – всички очаквани:

```
GET  https://learn.microsoft.com/api/mcp → 405   ← connection probe, normal
POST https://learn.microsoft.com/api/mcp → 200   ← actual tool call
DELETE https://learn.microsoft.com/api/mcp → 405 ← cleanup probe, normal
```

Трябва да се притеснявате само, ако `POST` връща грешка.
