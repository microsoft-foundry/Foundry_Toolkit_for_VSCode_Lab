# Модул 9 - Обобщение и следващи стъпки

⏱️ ~5 мин

**Поздравления!** Създадохте, тествахте и (ако сте по Път А) внедрихте многоагентен работен процес, използвайки Microsoft Foundry и Foundry Toolkit за VS Code.

---

## Какво създадохте

**Оценител на съвместимост резюме → работа** - многоагентен хостван работен процес, който:
- Получава резюме + описание на работата чрез HTTP (`POST /responses`)
- Изпълнява четири специализирани агента в последователен конвейер - всеки агент предава необходимите на следващия данни
- Връща оценка за съвместимост (0–100 със разбивка), списък с липсващи умения и сертификати и персонализиран учебен път с реални линкове към Microsoft Learn за всяка пропуск
- Извиква MCP сървър на Microsoft Learn (`https://learn.microsoft.com/api/mcp`) за извличане на официални учебни ресурси за всеки установен пропуск
- Работи като един контейнеризиран хостван агент в Microsoft Foundry Agent Service

## Основни научени концепции

| Концепция | Какво упражнявахте |
|---------|-------------------|
| **Многоагентна оркестрация** | `WorkflowBuilder` последователен конвейер с `add_edge()` |
| **Специализация на агент** | Четири фокусирани агента превъзхождат един универсален агент |
| **Шаблон Content Router** | ResumeParser служи и като маршрутизатор - запазва текста на JD в секция `[JOB DESCRIPTION PASS-THROUGH]`, за да могат агенти надолу по веригата да го достъпват (нужно, защото `context_mode="last_agent"` означава, че само `start_executor` вижда първичното съобщение на потребителя) |
| **Шаблон Content Relay** | JD Agent предава напред `[PARSED RESUME PASS-THROUGH]`, за да получи MatchingAgent и двата профила; избягва двукратното задействане с OR-семантика, което причиняват fan-in графите |
| **Интеграция с MCP инструмент** | `@tool` + `streamable_http_client`, използващ външен MCP сървър |
| **Жизнен цикъл на хостван агент** | Създаване на основа → Конфигуриране → Локално тестване → Внедряване → Проверка в облака |
| **`context_mode="last_agent"`** | Всеки изпълнител вижда само изхода на директния си предшественик |
| **Foundry Toolkit работен процес** | Магьосник за създаване, Agent Inspector, Workflow Visualizer, внедряване с един клик |

### Идеи за разширяване на този работен процес

- **Добавяне на 5-и агент** - Треньор за интервюта, който създава вероятни въпроси на база отчет за пропуски
- **Добавяне на Bing търсещ инструмент** - Да се позволи на JD Agent да търси подобни обяви за работа за обогатяване на изискванията
- **Свързване с база данни с резюмета** - Извличане на кандидатски профили от база данни чрез персонализиран `@tool`
- **Пробване на различни модели** - Сравнение на качество и латентност между `gpt-4.1` и `gpt-4.1-mini`
- **Оценяване с Foundry** - Използване на функцията Evaluations за оценка на отчетите спрямо златен набор от данни

## Изтриване на ресурси (по желание)

Ако искате да премахнете Azure ресурсите, създадени по време на този семинар:

### Вариант 1: Изтрийте групата с ресурси (премахва всичко)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### Вариант 2: Изтрийте само хоствания агент

1. Отворете [ai.azure.com](https://ai.azure.com) → вашият проект → **Build** → **Agents**.
2. Намерете **PersonalCareerCopilot** → кликнете **Delete**.

### Вариант 3: Изтрийте внедряването на модел

1. В Foundry страничната лента, разширете вашия проект → **Models**.
2. Кликнете с десен бутон върху внедряването на модел → **Delete**.

> **Забележка за разходите:** Хостваните агенти начисляват разходи само при работа. Ако спрете или изтриете агента, няма текущи разходи. Внедряването на модел може да има малка такса за резервиран капацитет - изтрийте го, ако сте приключили.
