# Модул 8 - Отстраняване на проблеми

Този модул е справочно ръководство за често срещани проблеми. Запазете го и се върнете, когато нещо се обърка.

---

## 1. Грешки с разрешенията

### 1.1 Отказан достъп до `agents/write`

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**Основна причина:** Липсва ролята `Azure AI User` на ниво **проект**. Това е най-честата грешка в работилницата.

**Поправка:**
1. Отворете [portal.azure.com](https://portal.azure.com).
2. Потърсете името на вашия Foundry **проект** → кликнете резултата от тип **"Microsoft Foundry project"** (НЕ родителски акаунт).
3. **Access control (IAM)** → **+ Add** → **Add role assignment**.
4. Роля: **Azure AI User** → Next.
5. Членове: Изберете себе си → Review + assign → Review + assign.
6. **Изчакайте 1–2 минути** → опитайте отново.

> **Защо Owner/Contributor не е достатъчно:** Тези роли предоставят само *действия за управление*. Операциите на агента изискват `agents/write` *действие с данни*, което има само `Azure AI User`, `Azure AI Developer` или `Azure AI Owner`. Вижте [Foundry RBAC docs](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` по време на подготовка

**Поправка:** Помолете администратора ви да ви зададе **Contributor** в групата ресурси, или той да създаде проекта и да ви даде **Azure AI User** на него.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Изчакайте до: "Регистриран"
```

## 2. Грешки с Docker

> Docker е **по избор**. Тези грешки важат само ако Docker Desktop е инсталиран и разширението се опитва да сглоби локално.

### 2.1 Docker демонът не работи

**Поправка:** Стартирайте Docker Desktop → изчакайте "running" статус → проверете с `docker info` → опитайте отново.

### 2.2 Грешка при зависимостите по време на изграждане

**Поправка:** Проверете правописа в `requirements.txt`, тествайте локално първо: `pip install -r requirements.txt`.

### 2.3 Несъответствие на платформата (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. Грешки при удостоверяване

### 3.1 `DefaultAzureCredential` не успява

**Поправка (пробвайте по ред):**
1. `az login` (преудостоверете се)
2. `az account set --subscription "<id>"` (правилно абонамент)
3. VS Code → Accounts → Изход → Вход отново
4. Проверете: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 Токенът работи локално, но не и хостван

**Очаквано:** Хостваните агенти използват управлявана от системата идентичност, а не вашия сертификат. Ако хостван агент има грешки при удостоверяване:
- Проверете дали `AZURE_AI_PROJECT_ENDPOINT` в `agent.yaml` е правилен
- Уверете се, че управляваната идентичност на проекта има достъп до модела

---

## 4. Грешки при моделите

### 4.1 Не е намерено разгръщане на модел

**Поправка:** Името е **чувствително към главни и малки букви**. Сравнете `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` с точното име в страничната лента на Foundry → Models.

### 4.2 Неочакван изход от модела

**Поправка:** Прегледайте `AGENT_INSTRUCTIONS` в `main.py` (не е съкратен?). Опитайте друг модел (`gpt-4.1` срещу `gpt-4.1-mini`).

---

## 5. Грешки при разгръщането

### 5.1 ACR pull не е упълномощен

**Поправка:** Azure Portal → Container Registry → Access control (IAM) → Добавете ролята **AcrPull** на управляваната идентичност на Foundry проекта.

### 5.2 Агентът не може да стартира (остава "Pending" или "Failed")

Проверете логовете на контейнера в страничната лента. Чести причини:

| Съобщение в лог | Поправка |
|-----------------|---------|
| `ModuleNotFoundError` | Добавете липсващия пакет в `requirements.txt`, разгръщане отново |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | Добавете променлива на средата в `agent.yaml` под `environment_variables` |
| `Address already in use` | Уверете се, че само един процес ползва порт 8088 |

### 5.3 Разгръщането изтича във времето

**Поправка:** Проверете интернет връзката. Първото разгръщане качва >100MB. Зад прокси ли сте? Конфигурирайте прокси настройките на Docker Desktop.

## 6. Път Б - Foundry Local

### 6.1 Foundry Local не стартира

| Проблем | Поправка |
|--------|---------|
| `foundry: command not found` | Преинсталирайте: `winget install Microsoft.FoundryLocal` |
| Липса на ресурси | Foundry Local се нуждае от ~4GB свободна RAM. Затворете други приложения. |
| Неуспешно сваляне на модел | Проверете дисковото пространство (моделите са 2–8 GB). Опитайте отново: `foundry local models pull <name>` |

### 6.2 Грешки при моделите в Foundry Local

| Проблем | Поправка |
|--------|---------|
| Бавни отговори | Очаквано - локалните модели работят на CPU, освен ако нямате GPU. Бъдете търпеливи. |
| Лошо качество на изхода | Опитайте по-голям модел, ако хардуерът ви позволява. `phi-4-mini` е добър баланс. |
| Връзката е отказана | Проверете дали Foundry Local работи: `foundry local status`. Рестартирайте, ако е необходимо. |

## 7. Бърза справка: RBAC роли

| Роля | Обхват | Дава права |
|------|---------|-----------|
| **Azure AI User** | Проект | Действия с данни: `agents/write`, `agents/read` |
| **Azure AI Developer** | Проект/Акаунт | Действия с данни + създаване на проект |
| **Azure AI Owner** | Акаунт | Пълен достъп + управление на роли |
| **Contributor** | Абонамент/Група ресурси | Само действия за управление (**без** действия с данни) |
| **Owner** | Абонамент/Група ресурси | Управление + възлагане на роли (**без** действия с данни) |
