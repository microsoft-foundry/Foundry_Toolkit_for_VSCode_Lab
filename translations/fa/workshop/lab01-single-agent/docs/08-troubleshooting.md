# ماژول ۸ - عیب‌یابی

این ماژول، راهنمای مرجعی برای مسائل رایج است. آن را نشانه‌گذاری کنید و هنگام بروز مشکل بازگردید.

---

## ۱. خطاهای دسترسی

### ۱.۱ `agents/write` اجازه دسترسی رد شد

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**علت اصلی:** نقش `Azure AI User` در سطح **پروژه** موجود نیست. این شایع‌ترین خطا در کارگاه است.

**رفع مشکل:**
۱. به [portal.azure.com](https://portal.azure.com) بروید.
۲. نام **پروژه** Foundry خود را جستجو کنید → نتیجه‌ای با نوع **"Microsoft Foundry project"** (نه حساب اصلی) را کلیک کنید.
۳. **کنترل دسترسی (IAM)** → **+ افزودن** → **افزودن انتساب نقش**.
۴. نقش: **کاربر Azure AI** → بعدی.
۵. اعضا: خودتان را انتخاب کنید → بازبینی + اختصاص → بازبینی + اختصاص.
۶. **۱ تا ۲ دقیقه صبر کنید** → دوباره تلاش کنید.

> **چرا نقش Owner/Contributor کافی نیست:** این نقش‌ها فقط اقدام‌های *مدیریتی* را مجاز می‌کنند. عملیات‌های عامل به اقدام `agents/write` *داده‌ای* نیاز دارند که فقط در `Azure AI User`، `Azure AI Developer` یا `Azure AI Owner` وجود دارد. به [مستندات RBAC Foundry](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) مراجعه کنید.

### ۱.۲ خطا در هنگام ارائه `AuthorizationFailed`

**رفع مشکل:** از مدیر خود بخواهید نقش **مشارکت‌کننده** روی گروه منابع اختصاص دهد، یا پروژه را برای شما بسازد و نقش **کاربر Azure AI** روی آن بدهد.

### ۱.۳ `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Wait until: "Registered"
```

## ۲. خطاهای داکر

> داکر **اختیاری** است. این مسائل فقط زمانی اعمال می‌شود که Docker Desktop نصب شده باشد و افزونه تلاش کند ساخت محلی انجام دهد.

### ۲.۱ فعال نبودن دیمون داکر

**رفع مشکل:** Docker Desktop را اجرا کنید → منتظر وضعیت "در حال اجرا" بمانید → با `docker info` بررسی کنید → دوباره تلاش کنید.

### ۲.۲ خطا در ساخت با وابستگی‌ها

**رفع مشکل:** املای `requirements.txt` را بررسی کنید، ابتدا محلی تست کنید: `pip install -r requirements.txt`.

### ۲.۳ ناسازگاری پلتفرم (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## ۳. خطاهای احراز هویت

### ۳.۱ `DefaultAzureCredential` شکست خورد

**رفع مشکل (به ترتیب امتحان کنید):**
۱. `az login` (دوباره احراز هویت)
۲. `az account set --subscription "<id>"` (اشتراک صحیح)
۳. VS Code → حساب‌ها → خروج → ورود مجدد
۴. تأیید کنید: `az account get-access-token --resource https://cognitiveservices.azure.com`

### ۳.۲ توکن در لوکال کار می‌کند ولی در میزبان نه

**انتظار می‌رود:** عوامل میزبان از هویت مدیریت‌شده سیستم استفاده می‌کنند، نه اعتبار شما. اگر عامل میزبانی خطای احراز داشت:
- بررسی کنید `AZURE_AI_MODEL_DEPLOYMENT_NAME` در `agent.yaml` به نام ارائه مدل شما اشاره دارد (`FOUNDRY_PROJECT_ENDPOINT` توسط Foundry در زمان اجرا تزریق می‌شود - آن را در `agent.yaml` اعلام نکنید)
- اطمینان حاصل کنید هویت مدیریت‌شده پروژه به مدل دسترسی دارد

---

## ۴. خطاهای مدل

### ۴.۱ ارائه مدل یافت نشد

**اصلاح:** نام به **حساس به حروف بزرگ و کوچک** است. `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` را با نام دقیق در نوار کناری Foundry → Models مقایسه کنید.

### ۴.۲ خروجی غیرمنتظره مدل

**اصلاح:** `AGENT_INSTRUCTIONS` را در `main.py` بررسی کنید (آیا کوتاه نشده است؟). یک مدل دیگر را امتحان کنید (`gpt-4.1` در مقابل `gpt-4.1-mini`).

---

## ۵. خطاهای استقرار

### ۵.۱ مجوز کشیدن از ACR ندارد

**اصلاح:** در Azure Portal → Container Registry → کنترل دسترسی (IAM) → نقش **AcrPull** را به هویت مدیریت شده پروژه Foundry اضافه کنید.

### ۵.۲ عامل شروع نمی‌شود (در وضعیت «در انتظار» یا «ناموفق» می‌ماند)

لاگ‌های کانتینر را در نوار کناری بررسی کنید. علل رایج:

| پیام لاگ | اصلاح |
|-------------|-----|
| `ModuleNotFoundError` | بسته‌ی گم‌شده را به `requirements.txt` اضافه کنید، مجدداً استقرار دهید |
| `ValueError: Missing required environment variables` | تأیید کنید که `AZURE_AI_MODEL_DEPLOYMENT_NAME` در `agent.yaml` زیر `environment_variables` اعلام شده و دارای مقدار است، سپس مجدداً استقرار دهید. `FOUNDRY_PROJECT_ENDPOINT` توسط Foundry در زمان اجرا تزریق می‌شود |
| `Address already in use` | اطمینان حاصل کنید که فقط یک فرایند به پورت ۸۰۸۸ متصل شده است |

### ۵.۳ استقرار زمان‌بر است

**اصلاح:** اتصال اینترنت را بررسی کنید. اولین استقرار بیشتر از ۱۰۰ مگابایت است. پشت یک پراکسی هستید؟ تنظیمات پراکسی Docker Desktop را پیکربندی کنید.

## ۶. مسیر ب – Foundry Local

### ۶.۱ Foundry Local شروع نمی‌شود

| مشکل | اصلاح |
|-------|-----|
| `foundry: command not found` | دوباره نصب کنید: `winget install Microsoft.FoundryLocal` |
| منابع ناکافی | Foundry Local به حدود ۴ گیگابایت رم آزاد نیاز دارد. برنامه‌های دیگر را ببندید. |
| دانلود مدل ناموفق است | فضای دیسک را بررسی کنید (مدل‌ها ۲–۸ گیگابایت هستند). دوباره امتحان کنید: `foundry local models pull <name>` |

### ۶.۲ خطاهای مدل Foundry Local

| مشکل | اصلاح |
|-------|-----|
| پاسخ‌های کند | طبیعی است — مدل‌های محلی روی CPU اجرا می‌شوند مگر اینکه GPU داشته باشید. صبور باشید. |
| خروجی با کیفیت پایین | اگر سخت‌افزار اجازه می‌دهد، مدل بزرگ‌تری را امتحان کنید. `phi-4-mini` تعادل خوبی است. |
| اتصال رد شد | تأیید کنید که Foundry Local در حال اجرا است: `foundry local status`. در صورت نیاز ریستارت کنید. |

## ۷. مرجع سریع: نقش‌های RBAC

| نقش | دامنه | مجوزها |
|------|-------|--------|
| **Azure AI User** | پروژه | عملیات داده: `agents/write`، `agents/read` |
| **Azure AI Developer** | پروژه/اکانت | عملیات داده + ایجاد پروژه |
| **Azure AI Owner** | اکانت | دسترسی کامل + مدیریت نقش‌ها |
| **Contributor** | اشتراک/گروه منبع | فقط عملیات مدیریتی (**بدون** عملیات داده) |
| **Owner** | اشتراک/گروه منبع | مدیریت + تخصیص نقش (**بدون** عملیات داده) |
