# ماژول ۸ - عیب‌یابی

این ماژول راهنمای مرجع برای مشکلات رایج است. آن را نشانه‌گذاری کنید و هرگاه مشکلی پیش آمد بازگردید.

---

## ۱. خطاهای دسترسی

### ۱.۱ مجوز `agents/write` رد شده

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**علت اصلی:** نقش `Azure AI User` در سطح **پروژه** وجود ندارد. این شایع‌ترین خطای کارگاه است.

**رفع مشکل:**
۱. به [portal.azure.com](https://portal.azure.com) وارد شوید.
۲. نام **پروژه** Foundry خود را جستجو کنید → روی نتیجه با نوع **"Microsoft Foundry project"** کلیک کنید (حساب والد نباشد).
۳. **دسترسی کنترل (IAM)** → **+ افزودن** → **افزودن تخصیص نقش**.
۴. نقش: **Azure AI User** → بعدی.
۵. اعضا: خودتان را انتخاب کنید → مرور + انتساب → مرور + انتساب.
۶. **۱–۲ دقیقه صبر کنید** → دوباره تلاش کنید.

> **چرا مالک/مشارکت‌کننده کافی نیست:** این نقش‌ها فقط عملیات *مدیریتی* را می‌دهند. عملیات عامل نیاز به `agents/write` به عنوان *عملیات داده* دارد که فقط در `Azure AI User`، `Azure AI Developer` یا `Azure AI Owner` موجود است. به [مستندات RBAC Foundry](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) مراجعه کنید.

### ۱.۲ خطای `AuthorizationFailed` هنگام تخصیص

**رفع مشکل:** از مدیر خود بخواهید نقش **Contributor** را روی گروه منابع اختصاص دهد، یا پروژه را برای شما بسازد و نقش **Azure AI User** را به شما بدهد.

### ۱.۳ خطای `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# صبر کنید تا: "ثبت شد"
```

## ۲. خطاهای Docker

> Docker **اختیاری** است. اینها فقط وقتی صدق می‌کند که Docker Desktop نصب باشد و افزونه اقدام به ساخت محلی کند.

### ۲.۱ Docker daemon اجرا نمی‌شود

**رفع مشکل:** Docker Desktop را اجرا کنید → منتظر وضعیت "running" باشید → با `docker info` تأیید کنید → دوباره تلاش کنید.

### ۲.۲ ساخت با خطای وابستگی‌ها شکست می‌خورد

**رفع مشکل:** املای `requirements.txt` را بررسی کنید، ابتدا محلی تست کنید: `pip install -r requirements.txt`.

### ۲.۳ ناسازگاری پلتفرم (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## ۳. خطاهای احراز هویت

### ۳.۱ خطای `DefaultAzureCredential`

**رفع مشکل (ترتیب را رعایت کنید):**
۱. `az login` (دوباره وارد شوید)
۲. `az account set --subscription "<id>"` (مشترک درست)
۳. VS Code → حساب‌ها → خروج → دوباره ورود
۴. بررسی: `az account get-access-token --resource https://cognitiveservices.azure.com`

### ۳.۲ توکن محلی کار می‌کند اما در هاست شده نه

**انتظار می‌رود:** عوامل هاست شده از شناسه مدیریت‌شده سیستم استفاده می‌کنند، نه از اعتبارنامه شما. اگر عامل هاست شده خطای احراز هویت دارد:
- بررسی کنید `AZURE_AI_PROJECT_ENDPOINT` در `agent.yaml` درست باشد
- مطمئن شوید شناسه مدیریت‌شده پروژه به مدل دسترسی دارد

## ۴. خطاهای مدل

### ۴.۱ استقرار مدل پیدا نشد

**رفع مشکل:** نام حساس به حروف است. مقدار `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` را با نام دقیق در نوار کناری Foundry → مدل‌ها مقایسه کنید.

### ۴.۲ خروجی غیرمنتظره مدل

**رفع مشکل:** `AGENT_INSTRUCTIONS` در `main.py` را بررسی کنید (آیا کوتاه نشده؟). مدل دیگری را امتحان کنید (`gpt-4.1` در مقابل `gpt-4.1-mini`).

---

## ۵. خطاهای استقرار

### ۵.۱ دسترسی به کشیدن ACR غیرمجاز است

**رفع مشکل:** Azure Portal → Container Registry → کنترل دسترسی (IAM) → نقش **AcrPull** را به شناسه مدیریت‌شده پروژه Foundry اضافه کنید.

### ۵.۲ عامل شروع نمی‌شود (وضعیت «در انتظار» یا «ناموفق»)

لاگ‌های کانتینر در نوار کناری را بررسی کنید. علل رایج:

| پیام لاگ | رفع مشکل |
|-------------|-----|
| `ModuleNotFoundError` | بسته مفقود شده را به `requirements.txt` اضافه کنید، دوباره استقرار دهید |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | متغیر محیطی را در `agent.yaml` زیر `environment_variables` اضافه کنید |
| `Address already in use` | مطمئن شوید فقط یک فرایند به پورت ۸۰۸۸ متصل است |

### ۵.۳ استقرار زمان‌ بندی شده

**رفع مشکل:** اتصال اینترنت را بررسی کنید. اولین استقرار بیش از ۱۰۰ مگابایت داده ارسال می‌کند. پشت پراکسی هستید؟ تنظیمات پراکسی Docker Desktop را پیکربندی کنید.

## ۶. مسیر ب - Foundry Local

### ۶.۱ Foundry Local اجرا نمی‌شود

| مشکل | رفع مشکل |
|-------|-----|
| `foundry: command not found` | دوباره نصب کنید: `winget install Microsoft.FoundryLocal` |
| منابع ناکافی | Foundry Local نیاز به حدود ۴ گیگابایت رم آزاد دارد. برنامه‌های دیگر را ببندید. |
| دانلود مدل شکست می‌خورد | فضای دیسک را بررسی کنید (مدل‌ها ۲–۸ گیگابایت هستند). دوباره تلاش: `foundry local models pull <name>` |

### ۶.۲ خطاهای مدل Foundry Local

| مشکل | رفع مشکل |
|-------|-----|
| پاسخ‌های کند | انتظار می‌رود - مدل‌های محلی روی CPU اجرا می‌شوند مگر اینکه GPU داشته باشید. صبور باشید. |
| خروجی کیفیت پایین | اگر سخت‌افزار اجازه می‌دهد مدل بزرگتری امتحان کنید. `phi-4-mini` تعادل خوبی است. |
| اتصال رد شد | مطمئن شوید Foundry Local در حال اجراست: `foundry local status`. در صورت نیاز راه‌اندازی مجدد کنید. |

## ۷. مرجع سریع: نقش‌های RBAC

| نقش | حوزه | مجوزها |
|------|-------|--------|
| **Azure AI User** | پروژه | عملیات داده: `agents/write`، `agents/read` |
| **Azure AI Developer** | پروژه/اکانت | عملیات داده + ایجاد پروژه |
| **Azure AI Owner** | اکانت | دسترسی کامل + مدیریت نقش |
| **Contributor** | اشتراک/گروه منابع | فقط عملیات مدیریت (**هیچ** عملیات داده) |
| **Owner** | اشتراک/گروه منابع | مدیریت + تخصیص نقش (**هیچ** عملیات داده) |
