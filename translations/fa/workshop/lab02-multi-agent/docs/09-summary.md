# ماژول ۹ - خلاصه و مراحل بعدی

⏱️ ~۵ دقیقه

**تبریک!** شما یک جریان کاری چندعاملۀ میزبانی شده با استفاده از Microsoft Foundry و Foundry Toolkit برای VS Code ساخته، تست و (اگر در مسیر A بودید) مستقر کردید.

---

## آنچه ساخته‌اید

**ارزیاب تناسب رزومه به شغل** - یک جریان کاری چندعامله میزبانی شده که:
- رزومه + شرح شغل را از طریق HTTP دریافت می‌کند (`POST /responses`)
- چهار عامل تخصصی را به صورت خطی اجرا می‌کند - هر عامل داده‌هایی که عامل بعدی نیاز دارد را منتقل می‌کند
- امتیاز تناسب (۰–۱۰۰ همراه با تجزیه و تحلیل)، لیست کاستی مهارت‌ها و گواهینامه‌ها، و نقشه راه یادگیری شخصی‌شده با لینک‌های واقعی Microsoft Learn برای هر کاستی را بازمی‌گرداند
- از سرور Microsoft Learn MCP (`https://learn.microsoft.com/api/mcp`) برای دریافت منابع رسمی آموزش هر مهارت شناسایی‌شده استفاده می‌کند
- به‌عنوان یک عامل میزبانی شده تک‌کانتینر در سرویس Foundry Agent اجرا می‌شود

---

## مفاهیم کلیدی یادگرفته شده

| مفهوم | آنچه تمرین کردید |
|---------|-------------------|
| **هماهنگی چندعامله** | خط لوله متوالی `WorkflowBuilder` با `add_edge()` |
| **تخصص عامل** | چهار عامل متمرکز عملکرد بهتری نسبت به یک عامل عمومی دارند |
| **الگوی مسیریاب محتوا** | ResumeParser به‌عنوان مسیریاب نیز عمل می‌کند - متن JD را در بخشی به نام `[JOB DESCRIPTION PASS-THROUGH]` نگه می‌دارد تا عوامل پایین‌دستی بتوانند به آن دسترسی یابند (این لازم است چون `context_mode="last_agent"` یعنی فقط `start_executor` پیام خام کاربر را می‌بیند) |
| **الگوی انتقال محتوا** | JD Agent بخش `[PARSED RESUME PASS-THROUGH]` را به جلو منتقل می‌کند تا MatchingAgent هر دو پروفایل را دریافت کند؛ از ایجاد دو بار تریگر با معنای OR که در گراف‌های fan-in رخ می‌دهد، جلوگیری می‌کند |
| **یکپارچه‌سازی ابزار MCP** | `@tool` همراه با `streamable_http_client` که به سرور MCP خارجی وصل می‌شود |
| **چرخه زندگی عامل میزبانی شده** | Scaffold → تنظیم پیکربندی → تست محلی → استقرار → تأیید در فضای ابری |
| **`context_mode="last_agent"`** | هر اجرا کننده فقط خروجی مستقیم پیشین خود را می‌بیند |
| **جریان کاری Foundry Toolkit** | جادوگر scaffold، بازرس عامل، نمایشگر جریان کاری، استقرار با یک کلیک |

### ایده‌هایی برای توسعه این جریان کاری

- **اضافه کردن عامل پنجم** - مربی مصاحبه که بر اساس گزارش کاستی سوالات محتمل مصاحبه را تولید می‌کند
- **اضافه کردن ابزار Bing Grounding** - اجازه به JD Agent برای جستجوی آگهی‌های مشابه برای غنی‌سازی نیازمندی‌ها
- **اتصال به پایگاه داده رزومه** - کشیدن پروفایل‌های کاندید از بانک اطلاعاتی از طریق `@tool` سفارشی
- **آزمایش مدل‌های متفاوت** - مقایسه کیفیت و تأخیر خروجی `gpt-4.1` در مقابل `gpt-4.1-mini`
- **ارزیابی با Foundry** - استفاده از قابلیت ارزیابی برای نمره‌دهی گزارش‌های تناسب علیه مجموعه داده طلایی

### برای کاربران مسیر B: ارتقا به استقرار ابری

وقتی آماده استقرار در ابر هستید:
1. یک اشتراک Azure تهیه کنید ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. آزمایشگاه ۰۱، ماژول ۰۱ را کامل کنید (ایجاد پروژه، استقرار مدل، تعیین RBAC)
3. فایل `.env` خود را با نقطه انتهایی پروژه Foundry و نام استقرار مدل به‌روز کنید
4. ادامه از [ماژول ۰۶ - استقرار به Foundry](06-deploy-to-foundry.md)

## پاک‌سازی منابع (اختیاری)

اگر می‌خواهید منابع Azure ایجاد شده در طول این کارگاه را حذف کنید:

### گزینه ۱: حذف گروه منابع (حذف همه چیز)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### گزینه ۲: فقط حذف عامل میزبانی شده

1. به [ai.azure.com](https://ai.azure.com) → پروژه خود → **Build** → **Agents** بروید.
2. عامل **PersonalCareerCopilot** را پیدا کنید → روی **Delete** کلیک کنید.

### گزینه ۳: حذف استقرار مدل

1. در نوار کناری Foundry، پروژه خود را باز کنید → **Models**.
2. بر روی استقرار مدل کلیک راست کنید → **Delete**.

> **توجه هزینه:** عوامل میزبانی شده فقط هنگام اجرا هزینه دارند. اگر عامل را توقف دهید یا حذف کنید، هزینه جاری نخواهد داشت. استقرار مدل ممکن است برای ظرفیت رزرو شده هزینه کمی داشته باشد - اگر کارتان تمام شده حذفش کنید.
