# ماژول ۹ - خلاصه و گام‌های بعدی

⏱️ ~۵ دقیقه

**تبریک می‌گوییم!** شما یک جریان کاری چندعاملی را با استفاده از Microsoft Foundry و Foundry Toolkit برای VS Code ساخته، آزمایش کرده‌اید و (اگر در مسیر A هستید) مستقر کرده‌اید.

---

## آنچه ساختید

**ارزیاب تناسب رزومه به شغل** - یک جریان کاری چندعاملی میزبان که:
- رزومه و شرح شغل را از طریق HTTP دریافت می‌کند (`POST /responses`)
- چهار عامل تخصصی را به ترتیب اجرا می‌کند - هر عامل داده‌ای را که عامل بعدی لازم دارد منتقل می‌کند
- نمره تناسب (۰–۱۰۰ با تجزیه و تحلیل)، فهرست شکاف مهارت‌ها و گواهی‌نامه‌ها، و نقشه راه شخصی‌سازی شده یادگیری با لینک‌های واقعی Microsoft Learn برای هر شکاف را بازمی‌گرداند
- سرور MCP مایکروسافت لرن را صدا می‌زند (`https://learn.microsoft.com/api/mcp`) تا منابع یادگیری رسمی برای هر شکاف مهارتی شناسایی شده را بیابد
- به عنوان یک عامل میزبانی شده کانتینری منفرد در Microsoft Foundry Agent Service اجرا می‌شود

## مفاهیم کلیدی آموخته شده

| مفهوم | آنچه تمرین کردید |
|---------|-------------------|
| **ارکستراسیون چندعامل‌­ای** | خط لوله متوالی `WorkflowBuilder` با `add_edge()` |
| **تخصصی سازی عامل** | چهار عامل متمرکز عملکرد بهتری نسبت به یک عامل چندمنظوره دارند |
| **الگوی مسیریاب محتوا** | ResumeParser دو نقش دارد؛ هم مسیریاب است و هم متن JD را در بخشی از نوع `[JOB DESCRIPTION PASS-THROUGH]` نگه می‌دارد تا عوامل پایین‌دست به آن دسترسی داشته باشند (لازم است چون `context_mode="last_agent"` به این معناست که فقط `start_executor` پیام خام کاربر را می‌بیند) |
| **الگوی انتقال محتوا** | JD Agent داده‌های `[PARSED RESUME PASS-THROUGH]` را به جلو ارسال می‌کند تا MatchingAgent به هر دو پروفایل دسترسی داشته باشد؛ از ایجاد محرک دوتایی ناشی از منطق OR در نمودارهای fan-in جلوگیری می‌کند |
| **ادغام ابزار MCP** | تماس همزمان `@tool` + `streamable_http_client` با یک سرور خارجی MCP |
| **چرخه عمر عامل میزبانی‌شده** | ایجاد پروژه → پیکربندی → تست محلی → استقرار → تأیید در فضای ابری |
| **`context_mode="last_agent"`** | هر مجری فقط خروجی مستقیم قبلی خود را می‌بیند |
| **گردش کاری Foundry Toolkit** | راهنمای ایجاد پروژه، بازرس عامل، نمایشگر گردش کار، استقرار با یک کلیک |

### ایده‌­هایی برای گسترش این گردش کار

- **اضافه کردن پنجمین عامل** - مربی مصاحبه که سوالات محتمل مصاحبه را بر اساس گزارش شکاف تولید می‌کند
- **اضافه کردن ابزار جستجوی بینگ** - اجازه دهید JD Agent به دنبال آگهی‌های شغلی مشابه بگردد تا نیازمندی‌ها را غنی‌سازی کند
- **اتصال به پایگاه داده رزومه** - گرفتن پروفایل‌های کاندیداها از پایگاه داده از طریق یک `@tool` سفارشی
- **آزمایش مدل‌های مختلف** - مقایسه خروجی و تأخیر `gpt-4.1` در مقابل `gpt-4.1-mini`
- **ارزیابی با Foundry** - استفاده از قابلیت ارزیابی‌ها برای امتیازدهی به گزارش‌های تناسب نسبت به یک مجموعه داده طلایی

### برای کاربران مسیر B: ارتقا به استقرار ابری

وقتی آماده‌اید برای استقرار در فضای ابری:
1. یک اشتراک Azure بگیرید ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. تکمیل [آزمایشگاه ۰۱، ماژول ۰۱](../../lab01-single-agent/docs/01-setup.md) (ایجاد پروژه، استقرار مدل، اختصاص RBAC)
3. به‌روزرسانی `.env` خود با نقطه انتهایی پروژه Foundry و نام استقرار مدل
4. ادامه از [ماژول ۰۶ - استقرار در Foundry](06-deploy-to-foundry.md)

## پاک‌سازی منابع (اختیاری)

اگر می‌خواهید منابع Azure ایجادشده در طول این کارگاه را حذف کنید:

### گزینه ۱: حذف گروه منابع (حذف همه موارد)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### گزینه ۲: حذف فقط عامل میزبان

۱. باز کردن [ai.azure.com](https://ai.azure.com) → پروژه شما → **Build** → **Agents**.
۲. پیدا کردن **PersonalCareerCopilot** → کلیک روی **Delete**.

### گزینه ۳: حذف استقرار مدل

۱. در نوار کناری Foundry، پروژه خود را گسترش دهید → **Models**.
۲. کلیک راست روی استقرار مدل → **Delete**.

> **نکته هزینه:** عوامل میزبان فقط زمانی هزینه دارند که در حال اجرا باشند. اگر عامل را متوقف یا حذف کنید، هیچ هزینه جاری وجود ندارد. استقرار مدل ممکن است هزینه کوچکی برای ظرفیت رزرو شده داشته باشد — اگر کارتان با آن تمام شده است، حذفش کنید.
