# ماژول ۱ - درک معماری

⏱️ ~۵ دقیقه

قبل از نوشتن هر کدی، در اینجا یک مرور سریع از آنچه می‌سازید و نحوه کارکرد آن وجود دارد.

---

## آنچه می‌سازید

شما یک **رزومه** و یک **شرح شغل** وارد می‌کنید. گردش کار موارد زیر را بازمی‌گرداند:

- یک امتیاز مطابقت (۰–۱۰۰ با تجزیه و تحلیل)
- فهرستی از شکاف‌های مهارتی و گواهینامه‌ای
- یک نقشه راه یادگیری شخصی‌سازی شده با لینک‌های Microsoft Learn برای هر شکاف

---

## چهار عامل

یک عامل واحد که سعی می‌کند همه را به‌طور همزمان تجزیه کند، امتیاز دهد و برنامه‌ریزی کند، معمولاً شتابزده عمل کرده و خروجی سطحی تولید می‌کند. تقسیم کار به چهار عامل تخصصی نتیجه بهتری می‌دهد:

| عامل | کاری که انجام می‌دهد |
|-------|-------------|
| **ResumeParser** | رزومه را تجزیه می‌کند؛ شرح شغل را دقیقاً به `[JOB DESCRIPTION PASS-THROUGH]` کپی می‌کند برای عوامل بعدی |
| **JobDescriptionAgent** | الزامات شرح شغل را از گذرگاه استخراج می‌کند؛ `[PARSED RESUME]` را به جلو به عنوان `[PARSED RESUME PASS-THROUGH]` انتقال می‌دهد |
| **MatchingAgent** | هر دو بخش برچسب‌خورده را مقایسه می‌کند؛ امتیاز مطابقت ۰–۱۰۰ و فهرست شکاف تولید می‌کند |
| **GapAnalyzer** | نقشه راه یادگیری را می‌سازد؛ برای هر شکاف در Microsoft Learn جستجو می‌کند |

---

## نمودار هماهنگی

گردش کار یک **خط لوله ترتیبی** است - هر عامل خروجی خود را به عامل بعدی می‌فرستد:

```mermaid
flowchart LR
    A["ورودی کاربر"] --> B["تجزیه‌کننده رزومه"]
    B -- "رزومه تجزیه‌شده + انتقال شرح شغل" --> C["عامل شرح شغل"]
    C -- "نیازهای شرح شغل + انتقال رزومه" --> D["عامل تطبیق"]
    D -- "گزارش تطابق + شکاف‌ها" --> E["تحلیلگر شکاف + MCP"]
    E --> F["خروجی نهایی"]

    style A fill:#4A90D9,color:#fff
    style B fill:#7B68EE,color:#fff
    style C fill:#7B68EE,color:#fff
    style D fill:#E67E22,color:#fff
    style E fill:#27AE60,color:#fff
    style F fill:#4A90D9,color:#fff
```

1. **ResumeParser** ورودی کاربر را دریافت می‌کند، رزومه را تجزیه می‌کند و شرح شغل را در `[JOB DESCRIPTION PASS-THROUGH]` کپی می‌کند.
2. **عامل شرح شغل** الزامات ساختاری را استخراج کرده و `[PARSED RESUME PASS-THROUGH]` را به جلو ارسال می‌کند.
3. **MatchingAgent** هر دو بخش را مقایسه کرده و امتیاز مطابقت و فهرست شکاف تولید می‌کند.
4. **GapAnalyzer** نقشه راه را می‌سازد و برای هر شکاف ابزار MCP مایکروسافت لرن را فراخوانی می‌کند.

## چگونه این به کد مربوط می‌شود

در `main.py`، این نمودار را با `WorkflowBuilder` توصیف می‌کنید:

```python
workflow_agent = (
    WorkflowBuilder(
        start_executor=resume_executor,       # اولین عامل برای دریافت ورودی کاربر
        output_executors=[gap_executor],      # عامل آخر - خروجی آن پاسخ است
    )
    .add_edge(resume_executor, jd_executor)       # ResumeParser → عامل JD
    .add_edge(jd_executor, matching_executor)     # عامل JD → عامل Matching
    .add_edge(matching_executor, gap_executor)    # عامل Matching → GapAnalyzer
    .build()
    .as_agent()
)
```

هر `Agent` در یک `AgentExecutor` بسته‌بندی شده است. فراخوانی‌های `add_edge()` یک خط لوله کاملاً ترتیبی تعریف می‌کنند - هر عامل فقط خروجی عامل مستقیم قبلی خود را دریافت می‌کند.

> `context_mode="last_agent"` به این معنی است که هر اجراکننده فقط خروجی عامل مستقیم قبلی خود را می‌بیند. ResumeParser و JD Agent داده‌ها را در بخش‌های برچسب‌خورده به جلو انتقال می‌دهند تا هر عامل پایین‌دستی دقیقاً آنچه نیاز دارد را داشته باشد.

## ابزار MCP

GapAnalyzer یک ابزار دارد: `search_microsoft_learn_for_plan`. این ابزار به `https://learn.microsoft.com/api/mcp` متصل می‌شود و لینک‌های واقعی Microsoft Learn را برای هر شکاف مهارتی بازمی‌گرداند.

وقتی ابزار اجرا شود، این گزارش‌ها را خواهید دید - همه مورد انتظار هستند:

```
GET  https://learn.microsoft.com/api/mcp → 405   ← connection probe, normal
POST https://learn.microsoft.com/api/mcp → 200   ← actual tool call
DELETE https://learn.microsoft.com/api/mcp → 405 ← cleanup probe, normal
```

فقط اگر `POST` خطا برگرداند نگران باشید.
