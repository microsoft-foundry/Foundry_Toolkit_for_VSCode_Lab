# چگونه این جلسه را ارائه دهیم

از اینکه این جلسه را ارائه می‌دهید، سپاسگزاریم!

پیش از ارائه کارگاه، لطفاً:

1. این سند و تمام منابع ضمیمه شده را به طور کامل بخوانید.
2. ضبط ارائه جلسه و مرور کامل کارگاه را تماشا کنید.
3. هر دو آزمایشگاه عملی را حداقل یک‌بار به‌طور کامل روی دستگاه خود انجام دهید.
4. پروژه Microsoft Foundry خود، استقرار مدل‌ها و سهمیه‌های خود را اعتبارسنجی کنید.
5. در صورت ابهام با شخص مسئول تماس بگیرید.

### پیش‌نیازهای مربی

قبل از ارائه، مطمئن شوید که دارید:

- یک **اشتراک Azure** با مجوز ایجاد منابع (مالک یا همکار در یک گروه منابع).
- دسترسی به **پروژه Microsoft Foundry** در [منطقه‌ای که از عوامل میزبان پشتیبانی می‌کند](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability).
- سهمیه برای **gpt-4.1** (یا **gpt-4.1-mini**) در پروژه Foundry خود.
- ابزارهای زیر نصب شده باشند:
  - [Visual Studio Code](https://code.visualstudio.com/)
  - [افزونه Microsoft Foundry Toolkit](https://marketplace.visualstudio.com/items?itemName=ms-windows-ai-studio.windows-ai-studio)
  - [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli)
  - [Azure Developer CLI (`azd`)](https://learn.microsoft.com/azure/developer/azure-developer-cli/install-azd)
  - [Docker Desktop](https://www.docker.com/) (اختیاری)
  - پایتون نسخه ۳.۱۰ یا بالاتر

قبل از ارائه حداقل یک‌بار [شروع سریع عوامل میزبانی شده با `azd`](https://learn.microsoft.com/azure/foundry/agents/quickstarts/quickstart-hosted-agent?pivots=azd) را اجرا کنید تا پروژه Foundry، استقرار مدل و Azure Container Registry شناخته‌شده و معتبر داشته باشید تا اگر فراگیری دچار مشکل شد بتوانید به آن رجوع کنید.

| ارزیاب تطابق رزومه و شغل | آزمایشگاه ۰۲ | [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot) | هماهنگی ۴عاملی؛ امتیازدهی تطابق رزومه با شغل و تولید توصیه  |

### دمو ۱: عامل اجرایی

یک عامل مستقل در [`workshop/lab01-single-agent/agent/`](../../../workshop/lab01-single-agent/agent). این را به عنوان دمو ۱۰ دقیقه‌ای قبل از آزمایشگاه ۰۱ استفاده کنید.

1. فایل [`workshop/lab01-single-agent/agent/main.py`](../../../workshop/lab01-single-agent/agent/main.py) را باز کرده و تعریف عامل (سیستم پرامپت، مدل، چارچوب) را مرور کنید.
2. کلید `F5` را فشار دهید تا **Agent Inspector** به صورت محلی اجرا شود.
3. پرامپت نمونه را از [README](../README.md#see-it-in-action) بچسبانید و پاسخ خلاصه اجرایی را نشان دهید.
4. فایل‌های [`workshop/lab01-single-agent/agent/agent.yaml`](../../../workshop/lab01-single-agent/agent/agent.yaml) و [`workshop/lab01-single-agent/agent/Dockerfile`](../../../workshop/lab01-single-agent/agent/Dockerfile) را نشان دهید تا اجزای استقرار را توضیح دهید.
5. فرآیند استقرار (ساخت Docker، فشار به ACR، ایجاد عامل میزبان) را بدون انتظار برای اتمام نشان دهید.

### دمو ۲: ارزیاب تطابق رزومه و شغل

یک جریان کاری ۴عاملی در [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot). این را به عنوان دمو ۱۰ دقیقه‌ای قبل از آزمایشگاه ۰۲ استفاده کنید.

1. فایل [`PersonalCareerCopilot/main.py`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/main.py) را باز کرده و نحوه اتصال چهار عامل در هماهنگی ترتیبی را نشان دهید.
2. کلید `F5` را فشار دهید تا **Agent Inspector** برای جریان کاری چندعاملی اجرا شود.
3. یک شرح شغل کوتاه و یک نمونه رزومه را در چت Inspector پیست کنید.
4. خط لوله چهارعاملی را مرور کنید: تجزیه‌کننده رزومه، استخراج‌کننده نیازمندی شغل، امتیازدهنده تطابق و نویسنده توصیه.
5. توضیح دهید چگونه خروجی هر زیرعامل زمینه عامل بعدی می‌شود و الگوی تحویل دست را برجسته کنید.
6. فایل [`PersonalCareerCopilot/agent.yaml`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/agent.yaml) را نشان دهید تا با معادل تک‌عاملی دمو ۱ مقایسه شود.

## نکات ارائه

- **انتظارات را زود مشخص کنید.** عوامل میزبان در حالت پیش‌نمایش هستند - محدودیت مناطق و سهمیه را از ابتدا اعلام کنید تا شرکت‌کنندگان وسط آزمایشگاه غافلگیر نشوند.
- **اول وظیفه پیش‌نیازها را اجرا کنید.** هر دو آزمایشگاه یک تسک VS Code به نام `Validate prerequisites` دارند - از شرکت‌کنندگان بخواهید قبل از نوشتن کد آن را اجرا کنند.
- **Agent Inspector را همیشه نمایان نگه دارید.** اکثر لحظات «آهان» زمانی اتفاق می‌افتد که فراگیران ببینند چرخه رفت و برگشت `/responses` محلی روشن می‌شود.
- **پروژه جایگزین داشته باشید.** اگر پروژه Foundry یکی از فراگیران به محدودیت سهمیه خورد، پروژه پیش‌تامین‌شده برای مرحله استقرار را به اشتراک بگذارید تا کلاس قفل نشود.
- **شرکت‌کنندگان را جفتی کنید.** آزمایشگاه ۰۲ (چندعاملی) وقتی فراگیران می‌توانند جریان هماهنگی را با یک هم‌گروه بررسی کنند آسان‌تر به‌نظر می‌رسد.
- **از ماژول‌های مستندات به عنوان نقاط توقف استفاده کنید.** پوشه `docs/` هر آزمایشگاه به ۸ ماژول شماره‌دار تقسیم شده است - از آنها به عنوان نقاط توقف طبیعی بهره ببرید.
- **تصویر پایه Docker را از قبل روی ماشین‌های اشتراکی آزمایشگاه بکشید** تا از محدودیت نرخ رجیستری جلوگیری شود.
