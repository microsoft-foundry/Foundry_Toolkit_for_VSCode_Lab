# چگونه این جلسه را ارائه دهیم

از اینکه این جلسه را ارائه می‌دهید سپاسگزاریم!

قبل از ارائه کارگاه، لطفاً:

1. این سند و تمامی منابع درج‌شده را به طور کامل مطالعه کنید.
2. ضبط ارائه جلسه و آموزش گام‌به‌گام کارگاه را تماشا کنید.
3. هر دو آزمایشگاه عملی را **حداقل یک بار** به صورت کامل روی ماشین خود انجام دهید.
4. پروژه Microsoft Foundry خود، استقرار مدل‌ها و سهمیه‌ها را اعتبارسنجی کنید.
5. در صورت وجود هر گونه ابهام، با نگهدارنده پروژه تماس بگیرید.

### پیش‌نیازهای مربی

قبل از تحویل، مطمئن شوید که دارید:

- یک **اشتراک Azure** با اجازه ایجاد منابع (مالک یا مشارکت‌کننده روی یک گروه منابع).
- دسترسی به یک **پروژه Microsoft Foundry** در [منطقه‌ای که از عامل‌های میزبانی شده پشتیبانی می‌کند](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability).
- سهمیه برای **gpt-4.1** (یا **gpt-4.1-mini**) در پروژه Foundry شما.
- ابزارهای زیر نصب شده باشد:
  - [Visual Studio Code](https://code.visualstudio.com/)
  - [افزونه Microsoft Foundry Toolkit](https://marketplace.visualstudio.com/items?itemName=ms-windows-ai-studio.windows-ai-studio)
  - [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli)
  - [Azure Developer CLI (`azd`)](https://learn.microsoft.com/azure/developer/azure-developer-cli/install-azd)
  - [Docker Desktop](https://www.docker.com/) (اختیاری)
  - Python نسخه 3.12 به بعد

اجرای [شروع سریع عامل‌های میزبانی شده با `azd`](https://learn.microsoft.com/azure/foundry/agents/quickstarts/quickstart-hosted-agent?pivots=azd) حداقل یک بار قبل از تحویل برای داشتن یک پروژه Foundry، استقرار مدل و Azure Container Registry شناخته شده و کارآمد به مرجع در صورتی‌که یادگیرنده دچار مشکل شود.

### دموی ۱: نماینده اجرایی

یک نماینده مستقل در [`workshop/lab01-single-agent/agent/`](../../../workshop/lab01-single-agent/agent). از این به عنوان دموی ۱۰ دقیقه‌ای پیش از آزمایشگاه ۰۱ استفاده کنید.

۱. [`workshop/lab01-single-agent/agent/main.py`](../../../workshop/lab01-single-agent/agent/main.py) را باز کرده و تعریف نماینده را مرور کنید (دستور سیستم، مدل، چارچوب).
۲. دکمه `F5` را فشار دهید تا **بازرس نماینده** به صورت محلی اجرا شود.
۳. نمونه فرمان را از [README](../README.md#see-it-in-action) کپی کرده و پاسخ خلاصه اجرایی را نمایش دهید.
۴. [`workshop/lab01-single-agent/agent/agent.yaml`](../../../workshop/lab01-single-agent/agent/agent.yaml) و [`workshop/lab01-single-agent/agent/Dockerfile`](../../../workshop/lab01-single-agent/agent/Dockerfile) را نشان دهید تا آثار استقرار توضیح داده شود.
۵. جریان استقرار (ساخت Docker، ارسال به ACR، ایجاد نماینده میزبانی شده) را بدون انتظار برای اتمام نشان دهید.

### دموی ۲: ارزیاب تناسب رزومه با شغل

یک جریان کاری با ۴ نماینده در [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot). از این به عنوان دموی ۱۰ دقیقه‌ای پیش از آزمایشگاه ۰۲ استفاده کنید.

۱. [`PersonalCareerCopilot/main.py`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/main.py) را باز کرده و نحوه اتصال چهار نماینده در ارکستراسیون ترتیبی را نشان دهید.
۲. دکمه `F5` را فشار دهید تا **بازرس نماینده** برای جریان کاری چند نماینده‌ای اجرا شود.
۳. یک توضیح کوتاه شغل و نمونه رزومه را در چت بازرس قرار دهید.
۴. جریان کاری چهار نماینده را مرور کنید: تجزیه‌کننده رزومه، استخراج‌کننده نیازهای شغلی، امتیازدهنده تناسب، و نویسنده توصیه‌نامه.
۵. نشان دهید که خروجی هر زیرنماینده چگونه به متن نماینده بعدی تبدیل می‌شود و الگوی انتقال را برجسته کنید.
۶. [`PersonalCareerCopilot/agent.yaml`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/agent.yaml) را برای مقایسه با معادل نماینده منفرد دموی ۱ نشان دهید.

## نکات اجرای ارائه

- **انتظارات را زود مشخص کنید.** نمایندگان میزبانی شده در پیش‌نمایش هستند - محدودیت‌های منطقه و سهمیه‌ها را از ابتدا بیان کنید تا شرکت‌کنندگان وسط آزمایشگاه غافلگیر نشوند.
- **اول کار پیش‌نیازها را اجرا کنید.** هر دو آزمایشگاه دارای یک تسک `Validate prerequisites` در VS Code هستند - از شرکت‌کنندگان بخواهید پیش از نوشتن هر کدی آن را اجرا کنند.
- **بازرس نماینده را قابل دید نگه دارید.** بیشتر لحظات «آها» وقتی رخ می‌دهد که فراگیران تنظیم چرخه تکراری محلی `/responses` را ببینند که فعال می‌شود.
- **یک پروژه پشتیبان داشته باشید.** اگر پروژه Foundry فراگیر به دیوار سهمیه برخورد کرد، یک پروژه از پیش تأمین‌شده برای مرحله استقرار به جای مسدود کردن کلاس به اشتراک بگذارید.
- **شرکت‌کنندگان را جفت کنید.** آزمایشگاه ۰۲ (چند نماینده) زمانی که فراگیران بتوانند در مورد ارکستراسیون با یک شریک صحبت کنند، بسیار آسان‌تر است.
- **از ماژول‌های مستندات به عنوان نقاط توقف استفاده کنید.** پوشه `docs/` هر آزمایشگاه به ماژول‌های شماره‌دار تقسیم شده است - از آنها به عنوان نقاط توقف طبیعی استفاده کنید.
- **پیش‌کشیدن تصویر پایه Docker** روی ماشین‌های آزمایشگاه مشترک برای جلوگیری از محدودیت‌های نرخ ثبت.

## شخصی‌سازی این جلسه

شما می‌توانید کارگاه را برای مخاطبان خود تطبیق دهید. تغییرات رایج:
