# ម៉ូឌុល 7 - ផ្ទៀងផ្ទាត់នៅក្នុងកន្លែងលេង

⏱️ ~10 នាទី

នៅក្នុងម៉ូឌុលនេះ អ្នកនឹងសាកល្បងចរន្តការងារពហុភ្នាក់ងារដែលបានផ្សាយចេញរបស់អ្នកនៅក្នុង VS Code និង Foundry Portal ដើម្បីបញ្ជាក់ថាភ្នាក់ងារប្រព្រឹត្តទៅដូចនឹងការសាកល្បងក្នុងផ្លូវមូលដ្ឋាន។

---

## ហេតុផលក្នុងការសាកល្បងម្ដងទៀតបន្ទាប់ពីបានផ្សាយចេញ?

បរិយាកាសដែលបម្រើផ្តល់សេវាកម្មមានភាពខុសគ្នាពីក្នុងផ្លូវមូលដ្ឋាននៅក្នុងបញ្ជាក់ចំនួនប៉ុន្មានៈ

| | ផ្លូវមូលដ្ឋាន | បម្រើផ្តល់សេវាកម្ម |
|--|---------------|-----------------|
| **អត្តសញ្ញាណ** | ការចូលប្រើផ្ទាល់ខ្លួនរបស់អ្នក (`DefaultAzureCredential`) | អត្តសញ្ញាណ Entra ច្បាប់សម្រាប់ភ្នាក់ងារតែម្នាក់ (បានផ្តល់ដោយស្វ័យប្រវត្តិពេលផ្សាយចេញ) |
| **ចំណុចផតថល** | `http://localhost:8088/responses` | URL ដែលគ្រប់គ្រងដោយសេវាកម្ម Foundry Agent |
| **បណ្តាញ** | ម៉ាស៊ីនរបស់អ្នក → Azure OpenAI + MCP | ខ្សែបណ្ដាញ Azure (Latency ទាបជាង) |

ការកំណត់បរិយាកាសខុសឆ្គង ការអនុវត្ត RBAC បញ្ហា ឬការហាមឃាត់ការហៅចេញ MCP នឹងត្រូវបង្ហាញនៅទីនេះជាមុន។

## ជម្រើស A: សាកល្បងនៅក្នុង VS Code Playground (ផ្ដល់អនុសាសន៍ជាលើកដំបូង)

### ជំហាន 1: ទៅកាន់ភ្នាក់ងារដែលបានបម្រើប្រាស់របស់អ្នក

1. ចុចរូបតំណាង **Foundry Toolkit** នៅក្នុងរបារសកម្មភាព។
2. ពង្រីកគម្រោងរបស់អ្នក → **Hosted Agents (Preview)** → រកភ្នាក់ងាររបស់អ្នក។

![Foundry Toolkit sidebar showing Hosted Agents (Preview) with resume-job-fit-evaluator and its deployed versions](../../../../../translated_images/km/06-foundry-sidebar-agent-status.a45994bfb5c21284.webp)

### ជំហាន 2: ជ្រើសរើសកំណែ

1. ចុចលើភ្នាក់ងារដើម្បីពង្រីកកំណែនៃវា។
2. ចុច `v1` → ផ្ទៀងផ្ទាត់ស្ថានភាពថា **សកម្ម** (sidebar អាចបង្ហាញ "Running" ឬ "Started" - ទាំងពីរនេះបង្ហាញដំណើរការត្រៀមរួច)។

### ជំហាន 3: បើកកន្លែងលេង (Playground)

1. ចុច **Playground** (ឬចុចរូបសញ្ញាគ្រាប់ម៉ៅស្ដាំលើកំណែ → **Open in Playground**)។
2. បង្អួចការជជែកបើកនៅក្នុងផ្ទាំង VS Code។

### ជំហាន 4: រៀបចំការសាកល្បង smoke test

ប្រើសាកល្បងដដែល 3 ករណីពី [ម៉ូឌុល 5](05-test-locally.md)។ វាយសារទាំងអស់នៅក្នុងប្រអប់បញ្ចូលក្នុង Playground ហើយចុច **Send** (ឬ **Enter**)។

#### សាកល្បង 1 - ប្រវត្តិរូបពេញ + JD (ចរន្តធម្មតា)

បិទសារប្រវត្តិរូបពេញ + លំនាំ JD ពីម៉ូឌុល 5, សាកល្បង 1 (Jane Doe + Senior Cloud Engineer នៅ Contoso Ltd)។

**ដែលគេរំពឹងថា:**
- ពិន្ទុ fit score ជាមួយគណិតវិទ្យាពិស្តារ (តាមស្កែល 100 ពិន្ទុ)
- ផ្នែកជំនាញដែលត្រូវបានតំរូវ
- ផ្នែកជំនាញខ្វះ
- **កាតមួយសម្រាប់ជំនាញខ្វះមួយៗ** ជាមួយ URL Microsoft Learn
- ផែនទីរៀនជាមួយពេលវេលា

#### សាកល្បង 2 - សាកល្បងខ្លីលឿន (បញ្ចូលតិច)

```
RESUME: 3 years Python developer, knows Django and PostgreSQL, no cloud experience.

JOB: Cloud DevOps Engineer requiring AWS, Kubernetes, Terraform, CI/CD. 5 years needed.
```

**ដែលគេរំពឹងថា:**
- ពិន្ទុ fit score ទាបជាង (< 40)
- ការវាយតម្លៃពិតប្រាកដជាមួយផ្លូវរៀនតាមដំណាក់កាល
- កាតខ្វះច្រើន (AWS, Kubernetes, Terraform, CI/CD, បទពិសោធន៍ខ្វះ)

#### សាកល្បង 3 -បេក្ខជនភាពល្អខ្ពស់

```
RESUME:
10 years Azure Cloud Architect. AZ-305 certified. Expert in AKS, Terraform, Azure DevOps, 
Azure Functions, Helm, Prometheus, Grafana, Python, Go. Led platform team of 8.

JOB:
Senior Cloud Engineer. Required: AKS, Terraform, Azure DevOps, Python. Preferred: Helm, Go.
5+ years experience. AZ-305 preferred.
```

**ដែលគេរំពឹងថា:**
- ពិន្ទុ fit score ខ្ពស់ (≥ 80)
- ផ្ដោតលើការត្រៀមសំរាប់ការសម្ភាសន៍ និងការពន្លឺ
- អតិបរមា ឬគ្មានកាតខ្វះជាច្រើន
- ពេលវេលាសង្ខេបផ្ដោតលើការត្រៀម

### ជំហាន 5: ប្រៀបធៀបជាមួយលទ្ធផលក្នុងផ្លូវមូលដ្ឋាន

បើកកំណត់ត្រា ឬផ្ទាំងរុករកពីម៉ូឌុល 5 ដែលអ្នកបានរក្សាទុកបទបញ្ចូលក្នុងផ្លូវមូលដ្ឋាន។ សម្រាប់ការសាកល្បងនីមួយៗ:

- តើចម្លើយមាន **រចនាសម្ព័ន្ធដូចគ្នា** (pint score, gap cards, roadmap)?
- តើវាធ្វើតាម **សន្ទស្សន៍ពិន្ទុដូចគ្នា** (ការបំបែកតាមស្កែល 100 ពិន្ទុ)?
- តើមាន URL **Microsoft Learn** នៅក្នុងកាតខ្វះទេ?
- តើមាន **កាតខ្វះមួយសម្រាប់ជំនាញខ្វះមួយ** (មិនបានកាត់បន្ថយ)?

> **ភាពខុសគ្នាខ្នាតតូចនៃពាក្យគឺធម្មតា** - ម៉ូដែលនេះមិនមានភាពកំណត់ធ្វើម្ដងទេ។ ផ្ដោតលើរចនាសម្ព័ន្ធ ការដំណើរការពិន្ទុត្រឹមត្រូវ និងការប្រើប្រាស់ឧបករណ៍ MCP។

## ជម្រើស B: សាកល្បងនៅក្នុង Foundry Portal

[Foundry Portal](https://ai.azure.com) ផ្ដល់ជាកន្លែងលេងតាមបណ្ដាញ ដែលមានប្រយោជន៍សម្រាប់ចែករំលែកជាមួយសមាជិកក្រុម ឬភ្នាក់ងារចូលរួមផ្សេងទៀត។

### ជំហាន 1: បើក Foundry Portal

1. បើកកម្មវិធីរុករករបស់អ្នក ហើយចូលទៅកាន់ [https://ai.azure.com](https://ai.azure.com)។
2. ចូលប្រើជាមួយគណនី Azure ដដែលដែលអ្នកប្រើនៅក្នុងវគ្គហ្វឹកហាត់នេះ។

### ជំហាន 2: ទៅកាន់គម្រោងរបស់អ្នក

1. នៅទំព័រដើម ស្វែងរក **Recent projects** នៅក្នុងរបារឆ្វេង។
2. ចុចលើឈ្មោះគម្រោងរបស់អ្នក (ឧ. `workshop-agents`)។
3. បើមិនឃើញ ចុច **All projects** ហើយស្វែងរកវា។

### ជំហាន 3: រកភ្នាក់ងារដែលបានផ្សាយចេញរបស់អ្នក

1. នៅរបារចរាចរខាងឆ្វេងនៃគម្រោង ចុច **Build** → **Agents** (ឬស្វែងរកផ្នែក **Agents**)។
2. អ្នកគួរមើលឃើញបញ្ជីភ្នាក់ងារ។ រកភ្នាក់ងារដែលបានផ្សាយ (ឧ. `resume-job-fit-evaluator`)។
3. ចុចលើឈ្មោះភ្នាក់ងារដើម្បីបើកទំព័រព័ត៌មានរបស់វា។

### ជំហាន 4: បើកកន្លែងលេង

1. នៅទំព័រព័ត៌មានភ្នាក់ងារ សូមមើលរបារឧបករណ៍ខាងលើ។
2. ចុច **Open in playground** (ឬ **Try in playground**)។
3. វាត្រូវបើកម៉ាស៊ីនចរចារថ្មី។

### ជំហាន 5: រត់ការសាកល្បង smoke ដដែលៗ

ធ្វើការសាកល្បងទាំង 3 ពីផ្នែក VS Code Playground ខាងលើម្តងទៀត។ ប្រៀបធៀបចម្លើយនីមួយៗជាមួយលទ្ធផលក្នុងផ្លូវមូលដ្ឋាន (ម៉ូឌុល 5) និងលទ្ធផលពី VS Code Playground (ជម្រើស A ខាងលើ)។

## ការផ្ទៀងផ្ទាត់ពិសេសសម្រាប់ភ្នាក់ងារពហុភ្នាក់ងារ

លើសពីភាពត្រឹមត្រូវមូលដ្ឋាន សូមផ្ទៀងផ្ទាត់អាកប្បកិរិយាពិសេសទាំងនេះសម្រាប់ភ្នាក់ងារពហុភ្នាក់ងារ:

### ការប្រតិបត្ដិ MCP tool

| ពិនិត្យ | របៀបផ្ទៀងផ្ទាត់ | លក្ខខណ្ឌជាប់ |
|-------|----------------|------------|
| ការហៅ MCP ជោគជ័យ | កាតខ្វះមាន URL `learn.microsoft.com` | URL ពិត មិនមែនសារ fallback ទេ |
| មានការហៅ MCP ច្រើន | រាល់ gap ដែលមានអាទិភាពខ្ពស់/មធ្យមមានធនធាន | មិនត្រឹមតែ gap အបូបទេ |
| MCP fallback ធ្វើការ | ប្រសិនបើអត់មាន URL សូមពិនិត្យសម្រាប់សារ fallback | ភ្នាក់ងារមានបន្តបង្កើត gap cards (មានឬគ្មាន URLs) |

### សមិទ្ធភាពភ្នាក់ងារជាក្រុម

| ពិនិត្យ | របៀបផ្ទៀងផ្ទាត់ | លក្ខខណ្ឌជាប់ |
|-------|----------------|------------|
| ភ្នាក់ងារទាំង 4 បានរត់ | បញ្ចេញបាន fit score និង gap cards | ពិន្ទុមកពី MatchingAgent, កាតពី GapAnalyzer |
| ការកាត់បន្ថយជាបន្តបន្ទាប់ | ពេលវេលាចម្លើយត្រឹមត្រូវ (< 2 នាទី) | ប្រសិនបើ > 3 នាទី សូមពិនិត្យកំហុសក្នុងបន្ទាត់តភ្ជាប់ |

## សេចក្ដីផ្នែកវាយតម្លៃ

ប្រើសេចក្ដីផ្នែកនេះដើម្បីវាយតម្លៃអាកប្បកិរិយាបម្រើផ្តល់សេវាកម្មពហុភ្នាក់ងាររបស់អ្នក៖

| # | គោលលក្ខណៈ | លក្ខខណ្ឌជាប់ | ជាប់ទេ? |
|---|----------|----------------|---------|
| 1 | **ភាពត្រឹមត្រូវមុខងារ** | ភ្នាក់ងារឆ្លើយតបទៅប្រវត្តិរូប+JD ជាមួយ fit score និងវិភាគ gap | |
| 2 | **ភាពសរុបពិន្ទុដូចគ្នា** | fit score ប្រើស្កែល 100 ពិន្ទុដែលមានគណិតវិទ្យាផ្ដល់ដាច់ខាត | |
| 3 | **ភាពពេញលេញនៃ gap card** | កាតមួយសម្រាប់ជំនាញខ្វះមួយ (មិនបានកាត់បន្ថយឬរួមបញ្ចូល) | |
| 4 | **ការបញ្ចូលឧបករណ៍ MCP** | កាតខ្វះមាន URL Microsoft Learn ពិត | |
| 5 | **ភាពស្របគ្នារចនាសម្ព័ន្ធ** | រចនាសម្ព័ន្ធបញ្ចេញស្របគ្នារវាងកំណែផ្លូវមូលដ្ឋាន និងកំណែបម្រើ | |
| 6 | **ពេលវេលាចម្លើយ** | ភ្នាក់ងារបម្រើឆ្លើយក្នុងរយៈពេល 2 នាទីសម្រាប់ការវាយតម្លៃពេញលេញ | |
| 7 | **គ្មានកំហុស** | គ្មានកំហុស HTTP 500, ការតម្លើងពេលវេលា ឬចម្លើយទទេ | |

> អត្ថន័យ "ជាប់" គឺគោលលក្ខណៈទាំង 7 ត្រូវបានបំពេញសម្រាប់សាកល្បង smoke 3 ករណីទាំងអស់ក្នុងយ៉ាងហោចណាស់កន្លែងលេង១ (VS Code ឬ Portal)។

## ដោះស្រាយបញ្ហាក្នុងកន្លែងលេង

| រោគសញ្ញា | ការបំពានលើនៅកន្លែងណា | ដោះស្រាយ |
|---------|--------------------|---------|
| កន្លែងលេងមិនផ្ទុកឡើង | បែបផែនមិនស្ថិតក្នុងស្ថានភាព `active` | ចូលទៅវិញ [ម៉ូឌុល 6](06-deploy-to-foundry.md) ដើម្បីផ្ទៀងផ្ទាត់ស្ថានភាពផ្សាយចេញ។ សូមរង់ចាំបើជា `creating` |
| ភ្នាក់ងារបញ្ជូនចម្លើយទទេ | ឈ្មោះផ្សាយម៉ូដែលមិនផ្គូផ្គង | ពិនិត្យ `agent.yaml` → `environment_variables` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` ត្រូវគ្នានឹងម៉ូដែលដែលបានផ្សាយ |
| ភ្នាក់ងារបញ្ជូនសារកំហុស | [RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) គ្មានសិទ្ធិ | មើល **[Foundry User](https://aka.ms/foundry-ext-project-role)** (មុនគឺជា Azure AI User) ជាបន្ទប់គម្រោង |
| គ្មាន URL Microsoft Learn នៅក្នុងកាតខ្វះ | MCP បានហាមឃាត់ចេញ ឬម៉ាស៊ីនបម្រើ MCP មិនមាន | ពិនិត្យមើលថាតើ container អាចចូលដល់ `learn.microsoft.com` បានទេ។ មើល [ម៉ូឌុល 8](08-troubleshooting.md) |
| មានតែ 1 កាតខ្វះ (កាត់បន្ថយ) | សេចក្តីណែនាំ GapAnalyzer មាន欠ភាព "CRITICAL" | សូមពិនិត្យ [ម៉ូឌុល 3, ជំហាន 2.4](03-configure-agents.md) |
| ពិន្ទុ fit score ខុសគ្នាខ្លាំងពីនៅក្នុងផ្លូវមូលដ្ឋាន | ប្រើម៉ូដែល ថ្នាក់ ឬសេចក្តីណែនាំខុសគ្នា | ប្រៀបធៀប `agent.yaml` env vars ជាមួយ `.env` ក្នុងផ្លូវមូលដ្ឋាន។ ផ្សាយឡើងវិញ ប្រសិនបើចាំបាច់ |
| "Agent not found" នៅក្នុង Portal | ការផ្សាយនៅកំពុងបណ្តាល ឬបរាជ័យ | រង់ចាំ 2 នាទី ហើយបញ្ចេញថ្មី។ ប្រសិនបើនៅតែមិនមាន សូមផ្សាយឡើងវិញពី [ម៉ូឌុល 6](06-deploy-to-foundry.md) |
