# មូឌុល 9 - សង្ខេប និងជំហានបន្ទាប់

⏱️ ~5 នាទី

**អបអរសាទរ!** អ្នកបានបង្កើត សាកល្បង និង (បើនៅលើផ្លូវ A) បញ្ចូនកម្មវិធីច្រើនភ្នាក់ងារមួយដោយប្រើ Microsoft Foundry និង Foundry Toolkit សម្រាប់ VS Code។

## អ្វីដែលអ្នកបានបង្កើត

**Resume → Job Fit Evaluator** - ជាកម្មវិធីច្រើនភ្នាក់ងារ ដែលបង្ហោះ ដែល:
- ទទួលបានប្រវត្តិរូប និងការពិពណ៌នាការងារតាមរយៈ HTTP (`POST /responses`)
- ប្រតិបត្តិការភ្នាក់ងារពិសេសប្រាំបួនក្នុងស៊េរី - ភ្នាក់ងារមួយៗបញ្ជូនទិន្នន័យដែលភ្នាក់ងារបន្ទាប់ត្រូវការ
- ត្រឡប់មកវិញនូវពិន្ទុសម្រប (0–100 ជាមួយការបំបែក), បញ្ជីខ្វះជំនាញ និងវិញ្ញាបនបត្រ, និងផែនទីការសិក្សាបុគ្គលិកជាមួយតំណ Microsoft Learn ផ្លូវការ សម្រាប់គ្រប់ចំណុចខ្វះ
- ហៅម៉ាស៊ីនមេ Microsoft Learn MCP (`https://learn.microsoft.com/api/mcp`) ដើម្បីទាញយកធនធានសិក្សាផ្លូវការសម្រាប់ចំណុចខ្វះនីមួយៗ
- ប្រតិបត្តិការជាភ្នាក់ងារបង្ហោះតែមួយក្នុងកុងតឺន័រ នៅក្នុងសេវាកម្មភ្នាក់ងារ Microsoft Foundry

## គំនិតសំខាន់ៗដែលបានរៀន

| គំនិត | អ្វីដែលអ្នកបានហាត់ប្រាណ |
|---------|-------------------|
| **ការគ្រប់គ្រងភ្នាក់ងារច្រើន** | ស៊េរី `WorkflowBuilder` ជាមួយ `add_edge()` |
| **ការបំបែកភ្នាក់ងារជាពិសេស** | ភ្នាក់ងារប្រាំបួនដែលមានការផ្ដោតលើមុខរបរ លើសពីភ្នាក់ងារធម្មតាមួយ |
| **គំរូ Content Router** | ResumeParser ជាថ្នាក់រុញផ្លូវតែមួយ - វាអាចរក្សាទុកអត្ថបទ JD នៅក្នុងផ្នែក `[JOB DESCRIPTION PASS-THROUGH]` ដើម្បីឱ្យភ្នាក់ងារខាងក្រោមអាចចូលដំណើរការ (ចាំបាច់ព្រោះ `context_mode="last_agent"` មានន័យថា តែ `start_executor` ពិសេសគឺឃើញសារប្រើប្រាស់ដើម) |
| **គំរូ Content Relay** | ភ្នាក់ងារ JD ផ្ញើបញ្ជូន `[PARSED RESUME PASS-THROUGH]` ទៅមុខ ដូច្នេះ MatchingAgent ទទួលបានប្រវត្តិរូបទាំងពីរ; ជៀសវាង OR-semantics បង្កើតការរំខានពីក្រាហ្វផ្លូវចូលជាច្រើន |
| **ការរួមបញ្ចូលឧបករណ៍ MCP** | `@tool` + `streamable_http_client` ហៅម៉ាស៊ីនមេ MCP ក្រៅ |
| **ជីវវិទ្យាភ្នាក់ងារបង្ហោះ** | Scaffold → កំណត់រចនា → សាកល្បងក្នុងតំបន់ → បញ្ចូន → ផ្ទៀងផ្ទាត់នៅមេឈើ |
| **`context_mode="last_agent"`** | ឯកសារនីមួយៗបានឃើញប៉ុណ្ណោះលទ្ធផលពីភ្នាក់ងារមុន |
| **រកស៊ី Foundry Toolkit** | វិសារជំនួយបង្កើត, Agent Inspector, Workflow Visualizer, បញ្ចូនដោយចុចមួយលើ |

### គំនិតដើម្បីពង្រីកកម្មវិធីនេះ

- **បន្ថែមភ្នាក់ងារទី ៥** - មនុស្សបង្វឹកការសម្ភាសន៍ ដែលបង្កើតសំណួរសម្ភាសន៍ទន់តាមរបាយការណ៍ខ្វះ
- **បន្ថែមឧបករណ៍ Bing Grounding** - អោយភ្នាក់ងារ JD រកស្វែងរកការងារដូចគ្នា ដើម្បីបន្ថែមការទាមទារ
- **ភ្ជាប់ទៅមូលដ្ឋានទិន្នន័យប្រវត្តិរូប** - ទាញយកប្រវត្តិរូបពីមូលដ្ឋានទិន្នន័យតាមរយៈ `@tool` ផ្ទាល់ខ្លួន
- **សាកល្បងម៉ូឌែលផ្សេងៗ** - ប្រៀបធៀបគុណភាពនិងកម្រិតពេលវេលាចេញផលិតផលរបស់ `gpt-4.1` និង `gpt-4.1-mini`
- **វាយតម្លៃជាមួយ Foundry** - ប្រើមុខងារ Evaluations ដើម្បីវាយតម្លៃរបាយការណ៍សម្របសម្រូលជាមួយសំណុំទិន្នន័យមាស

### សម្រាប់អ្នកប្រើផ្លូវ B៖ ធ្វើឱ្យប្រសើរឡើងទៅការបញ្ចូនក្នុងពពក

ពេលអ្នករៀបចំសម្រាប់បញ្ចូនទៅពពក:
1. ទទួលបានការជាវ Azure ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. បញ្ចប់ [Lab 01, Module 01](../../lab01-single-agent/docs/01-setup.md) (បង្កើតគម្រោង, បញ្ចូនម៉ូឌែល, ផ្ដល់ RBAC)
3. បន្ទាន់សម័យ `.env` របស់អ្នកជាមួយចំណុចចាប់ផ្តើមគម្រោង Foundry និងឈ្មោះបញ្ចូនម៉ូឌែល
4. បន្តពី [Module 06 - Deploy to Foundry](06-deploy-to-foundry.md)

## សម្អាតធនធាន (ជាជម្រើស)

ប្រសិនបើអ្នកចង់បញ្ឈប់ប្រើធនធាន Azure ដែលបានបង្កើតក្នុងវគ្គនេះ:

### ជម្រើស ១៖ លុបក្រុមធនធាន (លុបគ្រប់យ៉ាង)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### ជម្រើស ២៖ លុបទាំងភ្នាក់ងារបង្ហោះទេ

1. បើក [ai.azure.com](https://ai.azure.com) → គម្រោងរបស់អ្នក → **Build** → **Agents**។
2. ស្វែងរក **PersonalCareerCopilot** → ចុច **Delete**។

### ជម្រើស ៣៖ លុបការបញ្ចូនម៉ូឌែល

1. នៅក្នុងផ្ទាំង Foundry, ពង្រីកគម្រោងរបស់អ្នក → **Models**។
2. ចុចស្ដាំលើការបញ្ចូនម៉ូឌែល → **Delete**។

> **កំណត់ចំណាំថ្លៃ៖** ភ្នាក់ងារបង្ហោះគ្រាន់តែកើតមានថ្លៃពេលដំណើរការ បើអ្នកទប់ស្កាត់ ឬលុបភ្នាក់ងារ នោះមិនមានការបង់ថ្លៃបន្តទៀត។ ការបញ្ចូនម៉ូឌែលអាចមានថ្លៃតិចតួចសម្រាប់សមត្ថភាពរក្សាទុក - សូមលុបវាបើអ្នកបានបញ្ចប់។
