# ម៉ូឌុល 1 - យល់ដឹងអំពីស្ថាបត្យកម្ម

⏱️ ~5 នាទី

មុននឹងសរសេរកូដណាមួយនេះគឺជាពិចារណាយ៉ាងឆាប់រហ័សអំពីអ្វីដែលអ្នកកំពុងបង្កើត និងវិធីដែលវាដំណើរការ។

---

## អ្វីដែលអ្នកកំពុងបង្កើត

អ្នកបិទចម្លង **របាយការណ៍ជីវប្រវត្តិ** និង **ការពិពណ៌នាការងារ** ។ វិធីសាស្រ្តការងារប្រឞ័ន្ធនឹងត្រឡប់មក៖

- ពិន្ទុល្អគ្រប់គ្រាន់ (0–100 ជាមួយនឹងការបំបែក)
- បញ្ជីកម្រិតជំនាញ និងវិញ្ញាបនបត្រដែលខ្វះ
- ផែនទីការសិក្សាផ្ទាល់ខ្លួនជាមួយតំណ Microsoft Learn សម្រាប់គ្រប់កម្រិតខ្វះ

---

## អ្នកប្រតិបត្តិការចំនួនបួន

អ្នកប្រតិបត្តិការតែម្នាក់ដែលព្យាយាមបកស្រាយ បូកពិន្ទុ និងរៀបចំផែនការពេញលេញភ្លាមភ្លៅនឹងរត់វ៉ៃរហ័ស និងបង្កើតចំនុចបញ្ចេញខ្សោយ។ ការបំបែកការងារជាអ្នកប្រតិបត្តិការរួមបួនជំនាញឲ្យលទ្ធផលល្អជាង៖

| អ្នកប្រតិបត្តិការ | អ្វីដែលវាធ្វើ |
|-------|-------------|
| **ResumeParser** | បកស្រាយរបាយការណ៍ជីវប្រវត្តិ; ចម្លងការពិពណ៌នាការងារទៅក្នុង `[JOB DESCRIPTION PASS-THROUGH]` សម្រាប់អ្នកប្រតិបត្តិការនៅខាងក្រោម |
| **JobDescriptionAgent** | ដកយកតម្រូវការការងារពីការចម្លង; បញ្ជូនបន្ត `[PARSED RESUME]` ជា `[PARSED RESUME PASS-THROUGH]` |
| **MatchingAgent** | ប្រៀបធៀបទាំងពីរផ្នែកដែលបានសរសេរ; បង្កើតពិន្ទុល្អគ្រប់គ្រាន់ 0–100 និងបញ្ជីកម្រិតខ្វះ |
| **GapAnalyzer** | បង្កើតផែនទីសិក្សា; ស្វែងរក Microsoft Learn សម្រាប់គ្រប់កម្រិតខ្វះ |

## ក្រាហ្វិកនៃការគ្រប់គ្រងដំណើរការ

វិធីសាស្រ្តការងារនេះគឺជាភ្លឺប៉ាញលលំដាប់ - អ្នកប្រតិបត្តិការនិទ្ទេសក៏បញ្ចូនចេញមកអ្នកអន្ទង់បន្ទាប់៖

1. **ResumeParser** ទទួលបានបញ្ចូលពីអ្នកប្រើ បកស្រាយរបាយការណ៍ជីវប្រវត្តិ និងចម្លងការពិពណ៌នាការងារទៅក្នុង `[JOB DESCRIPTION PASS-THROUGH]`។
2. **JD Agent** ដកយកតម្រូវការដែលមានរចនាសម្ព័ន្ធនិងបញ្ជូន `[PARSED RESUME PASS-THROUGH]` បន្ត។
3. **MatchingAgent** ប្រៀបធៀបពីរ​ផ្នែកហើយបង្កើតពិន្ទុល្អគ្រប់គ្រាន់ និងបញ្ជីកម្រិតខ្វះ។
4. **GapAnalyzer** បង្កើតផែនទី និងហៅឧបករណ៍ Microsoft Learn MCP សម្រាប់គ្រប់កម្រិតខ្វះ។

## របៀបដែលវាផ្គូផ្គងទៅកូដ

នៅក្នុង `main.py` អ្នកពិពណ៌នាក្រាហ្វិកនេះជាមួយ `WorkflowBuilder`:

```python
workflow_agent = (
    WorkflowBuilder(
        start_executor=resume_executor,       # បេក្ខជនទីមួយទទួលការបញ្ចូលពីអ្នកប្រើ
        output_executors=[gap_executor],      # បេក្ខជនចុងក្រោយ - លទ្ធផលរបស់វាគឺជាចម្លើយ
    )
    .add_edge(resume_executor, jd_executor)       # ResumeParser → អាជ្ញាធរប័ណ្ណជីវប្រវត្តិ
    .add_edge(jd_executor, matching_executor)     # អាជ្ញាធរប័ណ្ណជីវប្រវត្តិ → អ្នកផ្គូផ្គង
    .add_edge(matching_executor, gap_executor)    # អ្នកផ្គូផ្គង → អ្នកវិភាគចន្លោះ
    .build()
    .as_agent()
)
```

អ្នកប្រតិបត្តិការត្រូវបានដាក់រួមក្នុង `AgentExecutor` ម្នាក់មួយ។ ការហៅ `add_edge()` កំណត់ភ្លឺប៉ាញលតែមួយជាលំដាប់ - អ្នកប្រតិបត្តិការម្នាក់ទទួលការចេញផ្ទាល់ពីអ្នកប្រតិបត្តិការកម្សត់មុខគត់ប៉ុណ្ណោះ។

> `context_mode="last_agent"` មានន័យថា អ្នកអនុវត្តម្នាក់ម្នាក់មើលឃើញតែចេញផ្ទាល់ពីអ្នកប្រតិបត្តិការកម្សត់មុខគត់របស់វា។ ResumeParser និង JD Agent បញ្ជូនទិន្នន័យបន្តក្នុងផ្នែកដែលបានស្លាក ដូច្នេះអ្នកប្រតិបត្តិការនៅក្រោមទទួលបានអ្វីដែលវាត្រូវការ។

## ឧបករណ៍ MCP

GapAnalyzer មានឧបករណ៍មួយគត់ៈ `search_microsoft_learn_for_plan`។ វាភ្ជាប់ទៅតទៅតំណ `https://learn.microsoft.com/api/mcp` និងត្រឡប់តំណ Microsoft Learn ជាការពិតសម្រាប់គ្រប់កម្រិតជំនាញខ្វះ។

ពេលឧបករណ៍ដំណើរការ អ្នកនឹងឃើញកំណត់ហេតុទាំងនេះ - ទាំងអស់គឺមានការរំពឹងទុក៖

```
GET  https://learn.microsoft.com/api/mcp → 405   ← connection probe, normal
POST https://learn.microsoft.com/api/mcp → 200   ← actual tool call
DELETE https://learn.microsoft.com/api/mcp → 405 ← cleanup probe, normal
```

គ្រាន់តែលំបាកយ៉ាងតិចបំផុតប្រសិនបើ `POST` ត្រឡប់កំហុសមក។
