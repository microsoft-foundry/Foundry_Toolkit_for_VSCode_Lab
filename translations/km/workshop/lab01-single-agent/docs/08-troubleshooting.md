# មូឌុល 8 - ការដោះស្រាយបញ្ហា

មូឌុលនេះគឺជាអ្នកយោងសម្រាប់បញ្ហា​ដែលគេជួបប្រទៈ​ជាញឹកញាប់។ ចំណាំវា ហើយត្រឡប់មកវិញពេលមានអ្វីមួយមិនប្រក្រតី។

## 1. កំហុសសិទ្ធិ

### 1.1 កំហុសសិទ្ធិ `agents/write` permission denied

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**មូលហេតុដើម៖** ខ្វះតួនាទី `Azure AI User` នៅកម្រិត **គម្រោង**។ នេះគឺជាកំហុសលេខ ១ ក្នុងមហោស្រព។

**ដោះស្រាយ៖**
1. បើក [portal.azure.com](https://portal.azure.com)។
2. ស្វែងរកឈ្មោះគម្រោង Foundry របស់អ្នក → ចុចលើលទ្ធផលប្រភេទ **"Microsoft Foundry project"** (មិនមែនគណនីមេ)។
3. **Access control (IAM)** → **+ Add** → **Add role assignment**។
4. តួនាទីៈ **Azure AI User** → បន្ទាប់។
5. សមាជិកៈ ជ្រើសយកខ្លួនអ្នក → ពិនិត្យឡើងវិញ + កំណត់ → ពិនិត្យឡើងវិញ + កំណត់។
6. **រង់ចាំ 1–2 នាទី** → សូមព្យាយាមម្ដងទៀត។

> **ហេតុអ្វីដែលម្ចាស់/អ្នករួមចំណែកមិនគាប់គ្រប់គ្រាន់៖** តួនាទីទាំងនេះផ្ដល់នូវសកម្មភាព *គ្រប់គ្រង* តែប៉ុណ្ណោះ។ ប្រតិបត្តិការប្រតិបត្តិករ ត្រូវការសកម្មភាព `agents/write` *ទិន្នន័យ* ដែលមានតែ​នៅ​ក្នុង `Azure AI User`, `Azure AI Developer`, ឬ `Azure AI Owner` ប៉ុណ្ណោះ។ មើល [ឯកសារ RBAC របស់ Foundry](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry)។

### 1.2 `AuthorizationFailed` នៅពេលផ្គត់ផ្គង

**ដំណោះស្រាយ៖** សូមស្នើអ្ន់ដំណើរការរបស់អ្នកដើម្បីផ្ដល់ **Contributor** លើក្រុមធនធាន ឬឲ្យពួកគេបង្កើតគម្រោងឲ្យអ្នកហើយផ្ដល់សិទ្ធិ **Azure AI User** លើវា។

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Wait until: "Registered"
```

## 2. កំហុស Docker

> Docker គឺជាជម្រើស **បូករួម** មានតែនៅពេលដែលបានដំឡើង Docker Desktop ហើយការពន្យល់ពេញពាក្យពិនិត្យភារកិច្ចស្ថានការណ៍ក្នុងកន្លែង។

### 2.1 Docker daemon មិនដំណើរការ

**ដំណោះស្រាយ៖** ចាប់ផ្ដើម Docker Desktop → រងចាំស្ថានភាព "កំពុងដំណើរការ" → ផ្ទៀងផ្ទាត់ជាមួយ `docker info` → ព្យាយាមម្ដងទៀត។

### 2.2 ការសាងសង់បរាជ័យដោយមានកំហុសអាស្រ័យភាព

**ដំណោះស្រាយ៖** ផ្ទៀងផ្ទាត់ការចុះអក្សរ `requirements.txt`, សាកល្បងក្នុងកន្លែងជាចម្បងជាមុន៖ `pip install -r requirements.txt`។

### 2.3 មិនសមរម្យវេទិកា (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. កំហុសសម្បទា

### 3.1 `DefaultAzureCredential` បរាជ័យ

**ដំណោះស្រាយ (សាកល្បងតាមលំដាប់):**
1. `az login` (បញ្ចូលសម្គាល់ឡើងវិញ)
2. `az account set --subscription "<id>"` (ជ្រើសរើសអត្ថប្រយោជន៍ត្រឹមត្រូវ)
3. VS Code → គណនី → ចេញពី시ស → ចូលវិញ
4. ផ្ទៀងផ្ទាត់៖ `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 អត្តសញ្ញាណប័ណ្ណធ្វើការនៅក្នុងកន្លែងតែពីរប្រព័ន្ធភ្ជាប់មិនធ្វើការ

**រំពឹងទុក៖** ប្រតិបត្តិករ​បានផ្ដល់សំណុំសម្គាល់បានគ្រប់គ្រងដោយប្រព័ន្ធ មិនមែនប័ណ្ណរាជសិទិ្ធរបស់អ្នក។ ប្រសិនបើប្រតិបត្តិករត្រូវបានផ្ទុកមានកំហុសសម្បទា៖
- ផ្ទៀងផ្ទាត់ `AZURE_AI_MODEL_DEPLOYMENT_NAME` ក្នុង `agent.yaml` សម្របសម្រួលទៅនាមការតំឡើងម៉ូឌែលរបស់អ្នក (`FOUNDRY_PROJECT_ENDPOINT` ត្រូវបាន Foundry ចាក់បញ្ចូលនៅពេលដំណើរការ - មិនត្រូវប្រកាសវា ក្នុង `agent.yaml`)
- ពិនិត្យមើលថា អត្តសញ្ញាណគ្រប់គ្រងគម្រោងមានការចូលដំណើរការម៉ូឌែល

## 4. កំហុសម៉ូឌែល

### 4.1 មិនរកឃើញការតំឡើងម៉ូឌែល

**ដំណោះស្រាយ៖** ឈ្មោះមានភាព **សូមប្រុងប្រយ័ត្នចំពោះអក្សរធំ-តូច**។ ប្រៀបធៀប `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` ជាមួយឈ្មោះច្បាស់លាស់នៅក្នុងជួរប្រាប់ Foundry → ម៉ូឌែល។

### 4.2 លទ្ធផលម៉ូឌែលមិនរំពឹងទុក

**ដំណោះស្រាយ៖** ពិនិត្យឡើងវិញ `AGENT_INSTRUCTIONS` នៅក្នុង `main.py` (មិនចកចេញទេឬ?)។ សាកល្បងម៉ូឌែលផ្សេងទៀត (`gpt-4.1` ប្រៀបធៀប `gpt-4.1-mini`)។

## 5. កំហុសការតំឡើង

### 5.1 មិនមានការចូលដំណើរការ ACR pull

**ដំណោះស្រាយ៖** ចូលទៅកាន់ Azure Portal → Container Registry → ការត្រួតពិនិត្យចូល (IAM) → បន្ថែមតួនាទី **AcrPull** ទៅអត្តសញ្ញាណគ្រប់គ្រងគម្រោង Foundry។

### 5.2 ប្រតិបត្តិករបរាជ័យក្នុងការចាប់ផ្ដើម (នៅស្ថានភាព "Pending" ឬ "Failed")

ពិនិត្យកំណត់ហេតុរបស់ container នៅក្នុងជួរប្រាប់។ មូលហេតុខ្លះ៖

| សារ​កំណត់ហេតុ | ដំណោះស្រាយ |
|-------------|-----|
| `ModuleNotFoundError` | បន្ថែមកញ្ចប់ដែលខ្វះទៅ `requirements.txt`, បញ្ចូល​ឡើងវិញ |
| `ValueError: Missing required environment variables` | ផ្ទៀងផ្ទាត់ថា `AZURE_AI_MODEL_DEPLOYMENT_NAME` ត្រូវបានប្រកាសនៅក្នុង `agent.yaml` ប្រកបដោយ `environment_variables` ហើយមានតម្លៃ បន្ទាប់មក​ធ្វើការចាក់ដោតឡើងវិញ។ `FOUNDRY_PROJECT_ENDPOINT` ត្រូវបានបញ្ចូលដោយ Foundry នៅពេលរត់កម្មវិធី |
| `Address already in use` | ធានាថា​មានតែ​មួយ​ដំណើរការ​តែប៉ុណ្ណោះ​ដែល​ត្រូវបានភ្ជាប់ទៅកាន់ទីតាំង ៨០៨៨ |

### 5.3 ពេលវេលាចាក់ដោតបានផុតកំណត់

**ជួសជុល៖** ពិនិត្យការតភ្ជាប់អ៊ីនធឺណិត។ ការចាក់ដោតដំបូងផ្ញើរ>100MB។ នៅពីក្រោយប្រ៉ុកស៊ី? រៀបចំការកំណត់ប្រ៉ុកស៊ី Docker Desktop។

## 7. ជំនួយរហ័ស៖ តួនាទី RBAC

| តួនាទី | វិសាលភាព | អនុញ្ញាត |
|------|-------|--------|
| **Azure AI User** | គម្រោង | សកម្មភាពទិន្នន័យ៖ `agents/write`, `agents/read` |
| **Azure AI Developer** | គម្រោង/គណនី | សកម្មភាពទិន្នន័យ + ការបង្កើតគម្រោង |
| **Azure AI Owner** | គណនី | ប្រើប្រាស់ពេញលេញ + គ្រប់គ្រងតួនាទី |
| **Contributor** | សំបុត្រជាវ/RG | សកម្មភាពគ្រប់គ្រងតែប៉ុណ្ណោះ (**មិនមាន** សកម្មភាពទិន្នន័យ) |
| **Owner** | សំបុត្រជាវ/RG | សកម្មភាពគ្រប់គ្រង + ការចាត់តួនាទី (**មិនមាន** សកម្មភាពទិន្នន័យ) |
