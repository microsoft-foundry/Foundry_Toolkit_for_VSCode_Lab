## Что вы создадите

В этом мастер-классе вы создадите агента **"Объясни, как директору"** - хостингового ИИ-агента, который берет сложные технические обновления и переписывает их в понятные исполнительные резюме на простом английском языке.

```mermaid
flowchart LR
    A["🧑‍💻 You send a\ntechnical update"] --> B["🤖 Executive Summary\nAgent"]
    B --> C["📝 Plain-English\nexecutive summary"]
```

**Агент использует:**
- **Microsoft Agent Framework** - для логики и структуры агента
- **Foundry Toolkit для VS Code** - для создания каркаса, локального тестирования и развертывания
- **ИИ-модель** (например, `gpt-4.1-mini/gpt-5-mini`) - для создания резюме

К концу этой лабораторной работы у вас будет работающий агент, которого вы сможете тестировать локально через Agent Inspector, а опционально развернуть в облаке.

## Что такое хостинговые агенты?

**Хостинговый агент** — это ИИ-агент, который работает как управляемый сервис в Microsoft Foundry. Вместо того чтобы управлять собственной инфраструктурой, вы помещаете код агента в контейнер, и Foundry занимается масштабированием, хостингом и предоставлением доступа к нему через стандартную HTTP-точку входа.

| Понятие | Значение |
|---------|--------------|
| **Агент** | Ваш код на Python, который принимает сообщение пользователя, вызывает ИИ-модель и возвращает структурированный ответ |
| **Хостинг** | Foundry запускает ваш контейнер за вас - без ВМ, без Kubernetes, без управления инфраструктурой |
| **Протокол ответов** | Стандартный HTTP API (`POST /responses`), к которому может обращаться любой клиент для взаимодействия с вашим агентом |
| **Agent Inspector** | Локальный пользовательский интерфейс для тестирования (встроен в Foundry Toolkit), позволяющий общаться с вашим агентом перед развертыванием |

В этом мастер-классе вы пройдете путь от нуля до полностью хостингового агента — или остановитесь на локальном тестировании, если предпочитаете.

## Все пути: необходимые инструменты

Установите каждый из инструментов ниже. После установки проверьте их работу командой проверки.

| # | Инструмент | Версия | Установка | Проверка (ожидаемый результат) |
|---|------------|---------|------------|-------------------------------|
| 1 | **Visual Studio Code** | Последняя | [code.visualstudio.com](https://code.visualstudio.com/) | Открывается без ошибок |
| 2 | **Python** | 3.12 или выше | [python.org/downloads](https://www.python.org/downloads/) | `python --version` $\rightarrow$ `Python 3.12.x` |
| 3 | **Foundry Toolkit для VS Code** | Последняя | Идентификатор расширения: `ms-windows-ai-studio.windows-ai-studio` | Иконка Foundry в панели активности |
| 4 | **Расширение Python для VS Code** | Последняя | Идентификатор расширения: `ms-python.python` | Установлено в панели расширений |

> [!TIP]
> **Советы по установке:**
> - **Python PATH (Windows):** Всегда отмечайте **«Add Python to PATH»** на первом экране установщика Python. Без этого `python` не будет распознаваться в терминале.
> - **Несколько версий Python:** Если у вас установлены Python 3.10 и 3.12, используйте `python3.12 -m venv .venv`, чтобы убедиться, что для виртуального окружения используется правильная версия.
> - **Docker WSL 2 (Windows):** При установке Docker Desktop убедитесь, что выбран **бэкенд WSL 2**. Docker с Hyper-V работает медленнее и может вызвать проблемы с построением контейнеров Foundry.
> - **Docker не запускается?** Подождите 30–60 секунд после запуска Docker Desktop. Запустите `docker info` - если появится сообщение «Cannot connect to the Docker daemon», Docker все еще инициализируется.
> - **Расширения VS Code не загружаются?** После установки расширений перезагрузите окно: `Ctrl+Shift+P` → `Developer: Reload Window`.

> **Пользователи Windows:** Отметьте **«Add Python to PATH»** при установке Python.
