# Модуль 8 – Устранение неполадок

Этот модуль является справочником по распространённым проблемам. Добавьте его в закладки и возвращайтесь, если что-то пойдёт не так.

---

## 1. Ошибки разрешений

### 1.1 `agents/write` отказано в доступе

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**Корень проблемы:** Отсутствует роль `Azure AI User` на уровне **проекта**. Это ошибка №1 на воркшопе.

**Решение:**
1. Откройте [portal.azure.com](https://portal.azure.com).
2. Найдите имя вашего Foundry **проекта** → нажмите на результат типа **"Microsoft Foundry project"** (НЕ родительский аккаунт).
3. **Управление доступом (IAM)** → **+ Добавить** → **Добавить назначение роли**.
4. Роль: **Azure AI User** → Далее.
5. Участники: выберите себя → Проверить + назначить → Проверить + назначить.
6. **Подождите 1–2 минуты** → повторите попытку.

> **Почему Owner/Contributor недостаточно:** Эти роли дают только *управленческие* действия. Операции агента требуют `agents/write` *действия с данными*, которые есть только в `Azure AI User`, `Azure AI Developer` или `Azure AI Owner`. Смотрите [документацию Foundry RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` во время развертывания

**Решение:** Попросите администратора назначить **Contributor** на группу ресурсов либо создать проект за вас и выдать вам роль **Azure AI User**.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Wait until: "Registered"
```

## 2. Ошибки Docker

> Docker является **необязательным**. Эти ошибки возникают только если установлен Docker Desktop и расширение пытается локально собрать образ.

### 2.1 Демон Docker не запущен

**Решение:** Запустите Docker Desktop → дождитесь статуса «запущен» → проверьте с помощью `docker info` → повторите попытку.

### 2.2 Сборка завершается ошибками зависимостей

**Решение:** Проверьте правильность написания `requirements.txt`, сначала протестируйте локально: `pip install -r requirements.txt`.

### 2.3 Несовпадение платформы (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. Ошибки аутентификации

### 3.1 `DefaultAzureCredential` не работает

**Решение (пробуйте по порядку):**
1. `az login` (повторная аутентификация)
2. `az account set --subscription "<id>"` (правильная подписка)
3. VS Code → Аккаунты → Выйти → Войти снова
4. Проверьте: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 Токен работает локально, но не на хосте

**Ожидаемо:** Хостированные агенты используют системно управляемую идентичность, а не ваши учетные данные. Если у хостированного агента возникают ошибки аутентификации:
- Убедитесь, что `AZURE_AI_MODEL_DEPLOYMENT_NAME` в `agent.yaml` разрешается в имя вашего развертывания модели (`FOUNDRY_PROJECT_ENDPOINT` подставляется Foundry во время выполнения – не объявляйте в `agent.yaml`)
- Проверьте, что управляемая идентичность проекта имеет доступ к модели

## 4. Ошибки моделей

### 4.1 Развертывание модели не найдено

**Решение:** Имя **чувствительно к регистру**. Сравните `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` с точным именем в боковой панели Foundry → Модели.

### 4.2 Неожиданный вывод модели

**Решение:** Проверьте `AGENT_INSTRUCTIONS` в `main.py` (не усечён?). Попробуйте другую модель (`gpt-4.1` против `gpt-4.1-mini`).

## 5. Ошибки развертывания

### 5.1 Запрос ACR неавторизован

**Решение:** Портал Azure → Реестр контейнеров → Управление доступом (IAM) → Добавить роль **AcrPull** управляемой идентичности проекта Foundry.

### 5.2 Агент не запускается (остаётся в состоянии «В ожидании» или «Ошибка»)

Проверьте логи контейнера в боковой панели. Распространённые причины:

| Сообщение лога | Решение |
|-------------|-----|
| `ModuleNotFoundError` | Добавьте недостающий пакет в `requirements.txt`, разверните заново |
| `ValueError: Missing required environment variables` | Убедитесь, что `AZURE_AI_MODEL_DEPLOYMENT_NAME` объявлена в `agent.yaml` под `environment_variables` и имеет значение, затем разверните заново. `FOUNDRY_PROJECT_ENDPOINT` подставляется Foundry во время выполнения |
| `Address already in use` | Убедитесь, что только один процесс слушает порт 8088 |

### 5.3 Превышено время развертывания

**Решение:** Проверьте интернет-соединение. Первое развертывание переносит >100MB. Вы за прокси? Настройте прокси в Docker Desktop.

## 6. Путь B – Foundry Local

### 6.1 Foundry Local не запускается

| Проблема | Решение |
|-------|-----|
| `foundry: command not found` | Переустановите: `winget install Microsoft.FoundryLocal` |
| Недостаточно ресурсов | Foundry Local требует около 4 ГБ свободной ОЗУ. Закройте другие приложения. |
| Ошибка скачивания модели | Проверьте место на диске (модели 2–8 ГБ). Повторите попытку: `foundry local models pull <name>` |

### 6.2 Ошибки модели Foundry Local

| Проблема | Решение |
|-------|-----|
| Медленные ответы | Ожидаемо — локальные модели работают на CPU, если у вас нет GPU. Терпение. |
| Плохое качество вывода | Попробуйте модель больше, если позволяет железо. `phi-4-mini` — хороший баланс. |
| Отказ соединения | Убедитесь, что Foundry Local запущен: `foundry local status`. Перезапустите при необходимости. |

## 7. Быстрая справка: роли RBAC

| Роль | Область | Предоставляет |
|------|-------|--------|
| **Azure AI User** | Проект | Действия с данными: `agents/write`, `agents/read` |
| **Azure AI Developer** | Проект/Аккаунт | Действия с данными + создание проекта |
| **Azure AI Owner** | Аккаунт | Полный доступ + управление ролями |
| **Contributor** | Подписка/ГР | Только управленческие действия (**без** действий с данными) |
| **Owner** | Подписка/ГР | Управленческие + назначение ролей (**без** действий с данными) |
