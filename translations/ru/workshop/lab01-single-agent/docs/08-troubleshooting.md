# Модуль 8 - Поиск и устранение неисправностей

Этот модуль служит справочником по распространённым проблемам. Добавьте его в закладки и возвращайтесь сюда, если что-то пойдёт не так.

---

## 1. Ошибки разрешений

### 1.1 Отказано в разрешении `agents/write`

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**Корень проблемы:** Отсутствует роль `Azure AI User` на уровне **проекта**. Это самая частая ошибка на практических занятиях.

**Исправление:**
1. Откройте [portal.azure.com](https://portal.azure.com).
2. Найдите ваш Foundry **проект** по имени → нажмите на результат с типом **"Microsoft Foundry project"** (НЕ родительский аккаунт).
3. **Контроль доступа (IAM)** → **+ Добавить** → **Добавить назначение роли**.
4. Роль: **Azure AI User** → Далее.
5. Участники: Выберите себя → Проверить + назначить → Проверить + назначить.
6. **Подождите 1–2 минуты** → повторите попытку.

> **Почему роль Владелец/Участник недостаточна:** Эти роли предоставляют только права *управления*. Операции агента требуют *действия с данными* `agents/write`, которые есть только у ролей `Azure AI User`, `Azure AI Developer` или `Azure AI Owner`. Подробнее в [Foundry RBAC документации](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` при развертывании

**Исправление:** Попросите администратора назначить роль **Contributor** на группу ресурсов или чтобы он создал проект для вас и выдал вам роль **Azure AI User** на проект.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Подождите до: "Зарегистрировано"
```

## 2. Ошибки Docker

> Docker **не обязателен**. Эти ошибки возможны, если установлен Docker Desktop и расширение пытается выполнить локальную сборку.

### 2.1 Демон Docker не запущен

**Исправление:** Запустите Docker Desktop → дождитесь статуса "запущен" → проверьте командой `docker info` → повторите попытку.

### 2.2 Сборка завершается ошибками зависимостей

**Исправление:** Проверьте правильность написания `requirements.txt`, предварительно протестируйте локально: `pip install -r requirements.txt`.

### 2.3 Несоответствие платформы (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. Ошибки аутентификации

### 3.1 Неудача `DefaultAzureCredential`

**Исправление (пробуйте по порядку):**
1. `az login` (повторная аутентификация)
2. `az account set --subscription "<id>"` (установите правильную подписку)
3. VS Code → Accounts → Выйти → Войти снова
4. Проверка: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 Токен работает локально, но не на хостинге

**Ожидаемое:** Хостинговые агенты используют системно управляемую идентичность, а не ваши учётные данные. Если у хостингового агента возникают ошибки аутентификации:
- Проверьте правильность `AZURE_AI_PROJECT_ENDPOINT` в `agent.yaml`
- Убедитесь, что управляемая идентичность проекта имеет доступ к модели

## 4. Ошибки модели

### 4.1 Развертывание модели не найдено

**Исправление:** Имя чувствительно к регистру. Сравните `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` с точным именем в боковой панели Foundry → Модели.

### 4.2 Неожиданный вывод модели

**Исправление:** Проверьте `AGENT_INSTRUCTIONS` в `main.py` (не усечены ли они?). Попробуйте другую модель (`gpt-4.1` против `gpt-4.1-mini`).

## 5. Ошибки развертывания

### 5.1 Ошибка авторизации при вытягивании из ACR

**Исправление:** В Azure Portal → Реестр контейнеров → Контроль доступа (IAM) → Добавьте роль **AcrPull** для управляемой идентичности проекта Foundry.

### 5.2 Агент не запускается (статус "Ожидание" или "Ошибка")

Проверьте журналы контейнера в боковой панели. Частые причины:

| Сообщение в логе | Исправление |
|-----------------|------------|
| `ModuleNotFoundError` | Добавьте отсутствующий пакет в `requirements.txt`, разверните заново |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | Добавьте переменную окружения в `agent.yaml` в разделе `environment_variables` |
| `Address already in use` | Убедитесь, что только один процесс использует порт 8088 |

### 5.3 Время развертывания истекло

**Исправление:** Проверьте интернет-соединение. Первое развертывание отправляет >100 МБ. Находитесь за прокси? Настройте прокси в Docker Desktop.

## 6. Путь В - Foundry Local

### 6.1 Foundry Local не запускается

| Проблема | Исправление |
|---------|------------|
| `foundry: command not found` | Переустановите: `winget install Microsoft.FoundryLocal` |
| Недостаточно ресурсов | Foundry Local требует ~4 ГБ свободной RAM. Закройте другие приложения. |
| Сбой скачивания модели | Проверьте место на диске (модели занимают 2–8 ГБ). Повторите: `foundry local models pull <name>` |

### 6.2 Ошибки модели Foundry Local

| Проблема | Исправление |
|---------|------------|
| Медленные ответы | Нормально — локальные модели работают на CPU, если у вас нет GPU. Наберитесь терпения. |
| Плохое качество вывода | Попробуйте более крупную модель, если позволяет оборудование. `phi-4-mini` — хороший компромисс. |
| Отказ подключения | Убедитесь, что Foundry Local работает: `foundry local status`. При необходимости перезапустите. |

## 7. Быстрая справка: роли RBAC

| Роль | Область действия | Предоставляет |
|------|----------------|------------|
| **Azure AI User** | Проект | Действия с данными: `agents/write`, `agents/read` |
| **Azure AI Developer** | Проект/Аккаунт | Действия с данными + создание проекта |
| **Azure AI Owner** | Аккаунт | Полный доступ + управление ролями |
| **Contributor** | Подписка/Группа ресурсов | Только действия управления (**без** действий с данными) |
| **Owner** | Подписка/Группа ресурсов | Управление + назначение ролей (**без** действий с данными) |
