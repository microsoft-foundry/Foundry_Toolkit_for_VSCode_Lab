# Лабораторная работа 02 - Многоагентный рабочий процесс: Оценка соответствия резюме вакансии

## Обзор

В этой практической лабораторной работе вы создадите **многоагентное приложение, ориентированное на рабочий процесс**, используя Foundry Toolkit в VS Code и развернете его в Microsoft Foundry Agent Service.

**Что вы создадите:** Оценщик соответствия резюме и вакансии, который анализирует резюме и описание вакансий, оценивает совпадение и создает персональную дорожную карту обучения с использованием ресурсов Microsoft Learn.

---

## Архитектура

```mermaid
flowchart TD
    A["User Input"] --> B["Resume Parser"]
    B -->|"[PARSED RESUME] + [JOB DESCRIPTION PASS-THROUGH]"| C["Job Description Agent"]
    C -->|"[JD REQUIREMENTS] + [PARSED RESUME PASS-THROUGH]"| D["Matching Agent"]
    D -->|fit report + gaps| E["Gap Analyzer + Microsoft Learn MCP"]
    E -->|fit score + roadmap| F["Output"]

    style A fill:#4A90D9,color:#fff
    style B fill:#7B68EE,color:#fff
    style C fill:#7B68EE,color:#fff
    style D fill:#E67E22,color:#fff
    style E fill:#27AE60,color:#fff
    style F fill:#4A90D9,color:#fff
```

**Как это работает:**
1. Пользователь вставляет резюме и описание вакансии.
2. **ResumeParser** парсит резюме и копирует описание вакансии дословно в `[JOB DESCRIPTION PASS-THROUGH]` раздел.
3. **JD Agent** извлекает структурированные требования из переданного текста, затем передает `[PARSED RESUME]` дальше как `[PARSED RESUME PASS-THROUGH]`.
4. **MatchingAgent** сравнивает `[PARSED RESUME PASS-THROUGH]` и `[JD REQUIREMENTS]` и выдает оценку соответствия.
5. **GapAnalyzer** преобразует пробелы в практическую дорожную карту и получает реальные ссылки Microsoft Learn через MCP.

## Паттерны оркестровки

В лабораторной работе 02 используется **последовательная цепочка**: вывод каждого агента передается следующему, а рабочий процесс возвращает ответ последнего агента. Для этого работают два паттерна:

- **Последовательная цепочка** - `WorkflowBuilder` соединяет ResumeParser → JD Agent → MatchingAgent → GapAnalyzer с одним вызовом `add_edge()` на каждом шаге
- **Передача содержимого** - так как каждый агент видит только вывод своего непосредственного предшественника, ResumeParser и JD Agent копируют данные, необходимые нижестоящим агентам, в помеченные проходные разделы

В документации также объясняется, почему лабораторная работа не использует распараллеливание (fan-out/fan-in), и как расширить граф еще одним агентом.

Смотрите [docs/04-orchestration-patterns.md](docs/04-orchestration-patterns.md).
