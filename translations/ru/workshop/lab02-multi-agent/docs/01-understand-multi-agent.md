# Модуль 1 - Понимание архитектуры

⏱️ ~5 мин

Прежде чем писать код, вот краткий обзор того, что вы создаёте и как это работает.

---

## Что вы создаёте

Вы вставляете **резюме** и **описание вакансии**. Рабочий процесс возвращает:

- Балл соответствия (0–100 с разбивкой)
- Список пробелов в навыках и сертификатах
- Персонализированную дорожную карту обучения с ссылками Microsoft Learn для каждого пробела

---

## Четыре агента

Один агент, пытающийся анализировать, оценивать и планировать одновременно, склонен спешить и выдавать поверхностный результат. Разделение работы на четыре специализированных агента даёт лучшие результаты:

| Агент | Что он делает |
|-------|--------------|
| **ResumeParser** | Анализирует резюме; копирует JD дословно в `[JOB DESCRIPTION PASS-THROUGH]` для последующих агентов |
| **JobDescriptionAgent** | Извлекает требования JD из пропуска; передаёт `[PARSED RESUME]` дальше как `[PARSED RESUME PASS-THROUGH]` |
| **MatchingAgent** | Сравнивает обе размеченные секции; выдаёт балл соответствия от 0 до 100 и список пробелов |
| **GapAnalyzer** | Создаёт дорожную карту обучения; ищет Microsoft Learn по каждому пробелу |

---

## Граф оркестровки

Рабочий процесс — это **последовательный конвейер** — каждый агент передаёт результат следующему:

```mermaid
flowchart LR
    A["Ввод пользователя"] --> B["Парсер резюме"]
    B -- "пересланное резюме + описание вакансии" --> C["Агент описания вакансии"]
    C -- "требования из описания вакансии + пересланное резюме" --> D["Агент поиска совпадений"]
    D -- "отчет о соответствии + пробелы" --> E["Анализатор пробелов + MCP"]
    E --> F["Итоговый результат"]

    style A fill:#4A90D9,color:#fff
    style B fill:#7B68EE,color:#fff
    style C fill:#7B68EE,color:#fff
    style D fill:#E67E22,color:#fff
    style E fill:#27AE60,color:#fff
    style F fill:#4A90D9,color:#fff
```

1. **ResumeParser** получает ввод пользователя, анализирует резюме и копирует JD в `[JOB DESCRIPTION PASS-THROUGH]`.
2. **JD Agent** извлекает структурированные требования и передаёт `[PARSED RESUME PASS-THROUGH]` дальше.
3. **MatchingAgent** сравнивает обе секции и выдаёт балл соответствия и список пробелов.
4. **GapAnalyzer** создаёт дорожную карту и вызывает инструмент Microsoft Learn MCP для каждого пробела.

---

## Как это отображается в коде

В `main.py` вы описываете этот граф с помощью `WorkflowBuilder`:

```python
workflow_agent = (
    WorkflowBuilder(
        start_executor=resume_executor,       # первый агент, который получает ввод пользователя
        output_executors=[gap_executor],      # последний агент - его вывод является ответом
    )
    .add_edge(resume_executor, jd_executor)       # ResumeParser → агент по описанию вакансии
    .add_edge(jd_executor, matching_executor)     # агент по описанию вакансии → MatchingAgent
    .add_edge(matching_executor, gap_executor)    # MatchingAgent → GapAnalyzer
    .build()
    .as_agent()
)
```

Каждый `Agent` обёрнут в `AgentExecutor`. Вызовы `add_edge()` определяют строго последовательный конвейер — каждый агент получает только вывод своего непосредственного предшественника.

> `context_mode="last_agent"` означает, что каждый исполнитель видит только вывод своего непосредственного предшественника. ResumeParser и JD Agent передают данные дальше в размеченных секциях, чтобы каждый последующий агент имел именно то, что ему нужно.

---

## Инструмент MCP

GapAnalyzer использует один инструмент: `search_microsoft_learn_for_plan`. Он подключается к `https://learn.microsoft.com/api/mcp` и возвращает реальные ссылки Microsoft Learn для каждого пробела навыков.

При запуске инструмента вы увидите эти логи — всё ожидаемо:

```
GET  https://learn.microsoft.com/api/mcp → 405   ← connection probe, normal
POST https://learn.microsoft.com/api/mcp → 200   ← actual tool call
DELETE https://learn.microsoft.com/api/mcp → 405 ← cleanup probe, normal
```

Волноваться стоит, только если `POST` вернёт ошибку.
