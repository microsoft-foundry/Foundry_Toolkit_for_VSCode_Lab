# Модуль 7 - Проверка в Playground

⏱️ ~10 мин

В этом модуле вы тестируете развернутый многопользовательский рабочий процесс в VS Code и портале Foundry, подтверждая, что агент ведет себя так же, как при локальном тестировании.

---

## Почему нужно тестировать снова после развертывания?

Хостинговая среда отличается от локальной по нескольким важным параметрам:

| | Локально | На хостинге |
|--|-------|--------|
| **Идентификация** | Ваша личная учетная запись (`DefaultAzureCredential`) | Выделенная учетная запись Entra на каждого агента (автоматически создается при развертывании) |
| **Конечная точка** | `http://localhost:8088/responses` | Управляемый URL Foundry Agent Service |
| **Сеть** | Ваш компьютер → Azure OpenAI + MCP | Ядро Azure (меньшая задержка) |

Ошибка в настройках переменных среды, проблема с RBAC или блокировка исходящих вызовов MCP проявятся именно здесь.

---

## Вариант A: Тестирование в VS Code Playground (рекомендуется сначала)

### Шаг 1: Перейдите к вашему хостинговому агенту

1. Нажмите на иконку **Foundry Toolkit** на панели активности.
2. Разверните ваш проект → **Hosted Agents (Preview)** → найдите вашего агента.

![Foundry Toolkit sidebar showing Hosted Agents (Preview) with resume-job-fit-evaluator and its deployed versions](../../../../../translated_images/ru/06-foundry-sidebar-agent-status.a45994bfb5c21284.webp)

### Шаг 2: Выберите версию

1. Нажмите на агента, чтобы развернуть его версии.
2. Нажмите `v1` → убедитесь, что статус **активен** (на боковой панели может отображаться "Running" или "Started" - оба означают, что агент готов).

### Шаг 3: Откройте Playground

1. Нажмите **Playground** (или кликните правой кнопкой на версии → **Open in Playground**).
2. Вкладка с чатом откроется в VS Code.

### Шаг 4: Запустите ваши базовые тесты

Используйте те же 3 теста из [Модуля 5](05-test-locally.md). Введите каждое сообщение в поле ввода Playground и нажмите **Send** (или **Enter**).

#### Тест 1 - Полное резюме + JD (стандартный сценарий)

Вставьте полный запрос с резюме + JD из Модуля 5, Тест 1 (Jane Doe + Senior Cloud Engineer в Contoso Ltd).

**Ожидается:**
- Оценка соответствия с подробным расчетом (шкала из 100 баллов)
- Раздел "Сопоставленные навыки"
- Раздел "Отсутствующие навыки"
- **Одна карточка недостатка на каждый отсутствующий навык** c URL Microsoft Learn
- План обучения с временной шкалой

#### Тест 2 - Быстрый краткий тест (минимальный ввод)

```
RESUME: 3 years Python developer, knows Django and PostgreSQL, no cloud experience.

JOB: Cloud DevOps Engineer requiring AWS, Kubernetes, Terraform, CI/CD. 5 years needed.
```

**Ожидается:**
- Низкая оценка соответствия (< 40)
- Честная оценка с поэтапным планом обучения
- Несколько карточек недостатков (AWS, Kubernetes, Terraform, CI/CD, пробелы в опыте)

#### Тест 3 - Кандидат с высоким уровнем соответствия

```
RESUME:
10 years Azure Cloud Architect. AZ-305 certified. Expert in AKS, Terraform, Azure DevOps, 
Azure Functions, Helm, Prometheus, Grafana, Python, Go. Led platform team of 8.

JOB:
Senior Cloud Engineer. Required: AKS, Terraform, Azure DevOps, Python. Preferred: Helm, Go.
5+ years experience. AZ-305 preferred.
```

**Ожидается:**
- Высокая оценка соответствия (≥ 80)
- Акцент на готовности к интервью и доработке
- Мало или нет карточек недостатков
- Краткий временной план с фокусом на подготовку

### Шаг 5: Сравните с локальными результатами

Откройте ваши заметки или вкладку браузера из Модуля 5, где сохранены локальные ответы. Для каждого теста:

- Совпадает ли в ответе **структура** (оценка соответствия, карточки недостатков, план обучения)?
- Используется ли **одинаковая система оценивания** (разбивка на 100 баллов)?
- Присутствуют ли **URL Microsoft Learn** в карточках недостатков?
- Есть ли **одна карточка на каждый отсутствующий навык** (не усечена)?

> **Незначительные различия в формулировках нормальны** - модель не является детерминированной. Сосредоточьтесь на структуре, согласованности оценивания и использовании MCP инструментов.

## Вариант B: Тестирование в портале Foundry

Портал [Foundry Portal](https://ai.azure.com) предоставляет веб-базированную площадку для тестирования, удобную для совместного использования с командой и заинтересованными лицами.

### Шаг 1: Откройте портал Foundry

1. Откройте браузер и перейдите по адресу [https://ai.azure.com](https://ai.azure.com).
2. Войдите, используя ту же учетную запись Azure, что и в ходе всего воркшопа.

### Шаг 2: Перейдите к вашему проекту

1. На главной странице найдите **Recent projects** в левой боковой панели.
2. Нажмите на название проекта (например, `workshop-agents`).
3. Если не находите, нажмите **All projects** и выполните поиск.

### Шаг 3: Найдите вашего развернутого агента

1. В навигации проекта слева нажмите **Build** → **Agents** (или найдите секцию **Agents**).
2. Вы увидите список агентов. Найдите вашего развернутого агента (например, `resume-job-fit-evaluator`).
3. Нажмите на имя агента, чтобы открыть страницу деталей.

### Шаг 4: Откройте Playground

1. На странице деталей агента посмотрите на верхнюю панель инструментов.
2. Нажмите **Open in playground** (или **Try in playground**).
3. Откроется чат-интерфейс.

### Шаг 5: Запустите те же базовые тесты

Повторите все 3 теста из раздела VS Code Playground выше. Сравните каждый ответ с локальными результатами (Модуль 5) и с результатами в VS Code Playground (Вариант A).

## Специфическая проверка для многопользовательской среды

Кроме базовой корректности, проверьте следующие особенности поведения в многопользовательской среде:

### Выполнение инструментов MCP

| Проверка | Как проверить | Условие прохождения |
|-------|---------------|----------------|
| Вызовы MCP успешны | Карточки недостатков содержат URL `learn.microsoft.com` | Реальные URL, не сообщения-заглушки |
| Множественные вызовы MCP | Каждая карточка недостатка с высоким/средним приоритетом имеет ресурсы | Не только первая карточка |
| Запасной механизм MCP работает | При отсутствии URL проверьте наличие текста-запаски | Агент все равно генерирует карточки (с URL или без) |

### Координация агентов

| Проверка | Как проверить | Условие прохождения |
|-------|---------------|----------------|
| Все 4 агента запущены | Вывод содержит оценку соответствия И карточки недостатков | Оценка от MatchingAgent, карточки от GapAnalyzer |
| Последовательное выполнение | Время отклика разумное (< 2 мин) | Если > 3 мин, проверьте ошибки в терминальном логе |
| Целостность потока данных | Карточки недостатков ссылаются на навыки из отчета сопоставления | Нет вымышленных навыков, отсутствующих в JD |

## Критерии проверки

Используйте эту матрицу для оценки поведения вашего многопользовательского рабочего процесса на хостинге:

| # | Критерий | Условие прохождения | Пройдено? |
|---|----------|---------------|-------|
| 1 | **Функциональная корректность** | Агент отвечает на резюме + JD с оценкой соответствия и анализом недостатков | |
| 2 | **Согласованность оценивания** | Оценка соответствия использует 100-балльную шкалу с детальной разбивкой | |
| 3 | **Полнота карточек недостатков** | Одна карточка на каждый отсутствующий навык (не усечена и не объединена) | |
| 4 | **Интеграция MCP инструментов** | Карточки содержат реальные URL Microsoft Learn | |
| 5 | **Структурная согласованность** | Структура вывода совпадает при локальном и хостинговом запуске | |
| 6 | **Время отклика** | Агент на хостинге отвечает в течение 2 минут для полной оценки | |
| 7 | **Отсутствие ошибок** | Нет ошибок HTTP 500, таймаутов или пустых ответов | |

> "Пройдено" означает, что все 7 критериев выполнены для всех 3 базовых тестов хотя бы в одном из playground (VS Code или портал).

## Устранение неполадок в playground

| Симптом | Возможная причина | Решение |
|---------|-------------|-----|
| Playground не загружается | Контейнер не в состоянии `active` | Вернитесь к [Модулю 6](06-deploy-to-foundry.md), проверьте статус развертывания. Подождите, если статус `creating` |
| Агент возвращает пустой ответ | Несовпадение названия развертывания модели | Проверьте `agent.yaml` → `environment_variables` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` соответствует вашей развернутой модели |
| Агент возвращает сообщение об ошибке | Отсутствует разрешение [RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) | Назначьте **[Foundry User](https://aka.ms/foundry-ext-project-role)** (ранее Azure AI User) на уровне проекта |
| Нет URL Microsoft Learn в карточках | Исходящие вызовы MCP заблокированы или MCP сервер недоступен | Проверьте, может ли контейнер обращаться к `learn.microsoft.com`. Смотрите [Модуль 8](08-troubleshooting.md) |
| Только 1 карточка недостатка (усечена) | В инструкциях GapAnalyzer отсутствует блок "CRITICAL" | Ознакомьтесь с [Модулем 3, Шаг 2.4](03-configure-agents.md) |
| Оценка соответствия сильно отличается от локальной | Развернута другая модель или другие инструкции | Сравните переменные среды в `agent.yaml` с локальным `.env`. При необходимости переразверните |
| В портале сообщение "Агент не найден" | Развертывание все еще в процессе или завершилось с ошибкой | Подождите 2 минуты, обновите страницу. Если агент не появился, повторите развертывание из [Модуля 6](06-deploy-to-foundry.md) |

- [ ] Нет ошибок или таймаутов в процессе тестирования
