## Что вы создали

**Оценщик соответствия резюме и вакансии** — многозадачный хостинг-воркфлоу, который:
- Получает резюме + описание вакансии через HTTP (`POST /responses`)
- Запускает четыре специализированных агента последовательно — каждый агент передает данные следующему
- Возвращает оценку соответствия (0–100 с подробным разбором), список недостающих навыков и сертификатов, а также персональную обучающую дорожную карту с реальными ссылками Microsoft Learn на каждый пробел
- Обращается к серверу Microsoft Learn MCP (`https://learn.microsoft.com/api/mcp`), чтобы получить официальные обучающие ресурсы для каждого выявленного пробела в навыках
- Работает как единый контейнеризированный хостинг-агент в Microsoft Foundry Agent Service

## Ключевые изученные концепции

| Концепция | Что вы практиковали |
|---------|-------------------|
| **Оркестрация многозадачных агентов** | Последовательная конвейерная `WorkflowBuilder` с `add_edge()` |
| **Специализация агентов** | Четыре специализированных агента лучше одного универсального |
| **Паттерн Content Router** | ResumeParser выступает также как маршрутизатор — сохраняет текст вакансии в секции `[JOB DESCRIPTION PASS-THROUGH]`, чтобы нижестоящие агенты имели к ней доступ (необходимо, так как `context_mode="last_agent"` означает, что только `start_executor` видит исходное сообщение пользователя) |
| **Паттерн Content Relay** | JD Agent пересылает `[PARSED RESUME PASS-THROUGH]` дальше, чтобы MatchingAgent получил оба профиля; избегает двойной активации OR-семантикой графов слиянья |
| **Интеграция с инструментом MCP** | `@tool` + `streamable_http_client` для вызовов внешнего MCP сервера |
| **Жизненный цикл хостинг-агента** | Создание → Настройка → Локальное тестирование → Развертывание → Проверка в облаке |
| **`context_mode="last_agent"`** | Каждый исполнитель видит только вывод своего непосредственного предшественника |
| **Foundry Toolkit workflow** | Мастер создания проекта, Инспектор агента, Визуализатор рабочего процесса, деплой в один клик |

### Идеи для расширения рабочего процесса

- **Добавить пятого агента** — Коуч по собеседованиям, который генерирует вероятные вопросы на основе отчёта о пробелах
- **Добавить инструмент Bing grounding** — Позволить JD Agent искать похожие вакансии для обогащения требований
- **Подключить базу резюме** — Получать профили кандидатов из базы через кастомный `@tool`
- **Попробовать разные модели** — Сравнить качество и задержку вывода `gpt-4.1` и `gpt-4.1-mini`
- **Оценивать с помощью Foundry** — Используйте функцию Evaluations для оценки отчетов соответствия на эталонном наборе данных

## Очистка ресурсов (по желанию)

Если хотите удалить Azure-ресурсы, созданные в ходе этой мастерской:

### Вариант 1: Удалить группу ресурсов (удалит всё)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### Вариант 2: Удалить только хостинг-агента

1. Откройте [ai.azure.com](https://ai.azure.com) → ваш проект → **Build** → **Agents**.
2. Найдите **PersonalCareerCopilot** → нажмите **Delete**.

### Вариант 3: Удалить развертывание модели

1. В боковой панели Foundry откройте ваш проект → **Models**.
2. Кликните правой кнопкой по развертыванию модели → **Delete**.

> **Примечание о стоимости:** Хостинг-агенты тарифицируются только во время работы. При остановке или удалении агента плата не взимается. Развертывание модели может незначительно стоить за резервирование ресурсов — удалите его, если оно больше не нужно.
