# كيفية تقديم هذه الجلسة

شكرًا لتقديمك هذه الجلسة!

قبل تقديم الورشة، يرجى:

1. قراءة هذا المستند وجميع الموارد المدرجة بالكامل.
2. مشاهدة تسجيل تقديم الجلسة واستعراض الورشة من البداية للنهاية.
3. تنفيذ كلا المختبرين العمليين من البداية للنهاية على جهازك الخاص **مرة واحدة على الأقل** قبل الحدث.
4. التحقق من مشروع Microsoft Foundry الخاص بك، ونشر النماذج، والحصص.
5. التواصل مع المسؤول في حال وجود أي استفسار.

### متطلبات المدرب

قبل التسليم، تأكد من توفر:

- **اشتراك Azure** مع صلاحيات إنشاء الموارد (مالك أو مساهم في مجموعة موارد).
- الوصول إلى **مشروع Microsoft Foundry** في [منطقة تدعم الوكلاء المستضافين](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability).
- حصة لـ **gpt-4.1** (أو **gpt-4.1-mini**) في مشروع Foundry الخاص بك.
- تثبيت الأدوات التالية:
  - [Visual Studio Code](https://code.visualstudio.com/)
  - [امتداد Microsoft Foundry Toolkit](https://marketplace.visualstudio.com/items?itemName=ms-windows-ai-studio.windows-ai-studio)
  - [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli)
  - [Azure Developer CLI (`azd`)](https://learn.microsoft.com/azure/developer/azure-developer-cli/install-azd)
  - [Docker Desktop](https://www.docker.com/) (اختياري)
  - Python 3.12 أو أحدث

شغّل [بدء سريع للوكلاء المستضافين باستخدام `azd`](https://learn.microsoft.com/azure/foundry/agents/quickstarts/quickstart-hosted-agent?pivots=azd) مرة واحدة على الأقل قبل التسليم لتملك مشروع Foundry صالح، ونشر نموذج، وسجل حاويات Azure مرجعي إذا واجه متعلم صعوبة.

## العروض التوضيحية

يشمل التسليم عرضين توضيحيين مباشرين. خصص 10 دقائق لكل منهما.

| العرض التوضيحي | المختبر | الملفات | ماذا تعرض |
|------|-----|-------|--------------|
| الوكيل التنفيذي | المختبر 01 | [`workshop/lab01-single-agent/agent/`](../../../workshop/lab01-single-agent/agent) | وكيل مستضاف واحد؛ تحويل المصطلحات التقنية إلى ملخص تنفيذي |
| تقييم ملاءمة السيرة الذاتية للوظيفة | المختبر 02 | [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot) | تنسيق أربعة وكلاء؛ تقييم ملاءمة السيرة الذاتية للوظيفة وتوليد توصية |

### العرض التوضيحي 1: الوكيل التنفيذي

وكيل مستقل في [`workshop/lab01-single-agent/agent/`](../../../workshop/lab01-single-agent/agent). استخدم هذا كعرض توضيحي لمدة 10 دقائق قبل المختبر 01.

1. افتح [`workshop/lab01-single-agent/agent/main.py`](../../../workshop/lab01-single-agent/agent/main.py) واستعرض تعريف الوكيل (موجه النظام، النموذج، الإطار).
2. اضغط `F5` لتشغيل **مفتش الوكيل** محليًا.
3. الصق الموجه النموذجي من [README](../README.md#see-it-in-action) وعرض استجابة الملخص التنفيذي.
4. عرض [`workshop/lab01-single-agent/agent/agent.yaml`](../../../workshop/lab01-single-agent/agent/agent.yaml) و [`workshop/lab01-single-agent/agent/Dockerfile`](../../../workshop/lab01-single-agent/agent/Dockerfile) لشرح قطع النشر.
5. عرض تدفق النشر (بناء Docker، دفع ACR، إنشاء الوكيل المستضاف) بدون انتظار الاكتمال.

### العرض التوضيحي 2: تقييم ملاءمة السيرة الذاتية للوظيفة

سير عمل بأربعة وكلاء في [`workshop/lab02-multi-agent/PersonalCareerCopilot/`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot). استخدم هذا كعرض توضيحي لمدة 10 دقائق قبل المختبر 02.

1. افتح [`PersonalCareerCopilot/main.py`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/main.py) وأعرض كيفية ربط الوكلاء الأربعة معًا في تنسيق متسلسل.
2. اضغط `F5` لتشغيل **مفتش الوكيل** لسير العمل متعدد الوكلاء.
3. الصق وصفًا مختصرًا للوظيفة وسيرة ذاتية نموذجية في دردشة المفتش.
4. استعرض خط أنابيب الوكلاء الأربعة: محلل السيرة الذاتية، مستخرج متطلبات الوظيفة، مقيم الملاءمة، وكاتب التوصية.
5. أشر إلى كيف يصبح إخراج كل وكيل فرعي هو سياق الوكيل التالي، مبرزًا نمط التسليم.
6. عرض [`PersonalCareerCopilot/agent.yaml`](../../../workshop/lab02-multi-agent/PersonalCareerCopilot/agent.yaml) للمقارنة مع ما يعادله من وكيل واحد في العرض 1.

## نصائح التسليم

- **حدد التوقعات مبكرًا.** الوكلاء المستضافون في مرحلة المعاينة - بيّن حدود المناطق والحصص مقدمًا حتى لا يفاجأ الحضور أثناء المختبر.
- **شغل مهمة المتطلبات الأولى.** كل المختبرين يشملان مهمة `Validate prerequisites` في VS Code - اجعل الحضور يشغلوها قبل كتابة أي كود.
- **احتفظ بمفتش الوكيل مرئيًا.** تحدث معظم لحظات "آها" عندما يرى المتعلمون تفاعل `/responses` المحلي.
- **احتفظ بمشروع بديل.** إذا وصل مشروع Foundry لمتعلم إلى حد الحصة، شارك مشروعًا مهيأ مسبقًا لخطوة النشر بدلاً من حجب الصف.
- **وزع الحضور على أزواج.** المختبر 02 (متعدد الوكلاء) أسهل بكثير عندما يستطيع المتعلمون مناقشة التنسيق مع شريك.
- **استخدم وحدات الوثائق كنقاط توقف.** مجلد `docs/` في كل مختبر مقسم إلى وحدات مرقمة - استخدمها كنقاط توقف طبيعية.
- **اسحب صورة Docker الأساسية مسبقًا** على أجهزة المختبر المشتركة لتجنب حدود معدل السجل.

## استكشاف الأخطاء أثناء التسليم

| العرض                                      | أول ما يجب تجربته                                                                                       |
|----------------------------------------------|----------------------------------------------------------------------------------------------------------|
| لا يمكن لمفتش الوكيل الاتصال               | تحقق أن المنفذ `8088` متاح وأن مهمة `Run Agent HTTP Server` تعمل.               |
| فشل المُصحح في الالتحاق                     | تحقق من أن المنفذ `5679` متاح؛ أعد تشغيل VS Code إذا كان `debugpy` مربوطًا.                           |
| `azd up` يفشل بخطأ مصادقة               | شغل `az login` و `azd auth login`، وتأكد من اختيار المستأجر الصحيح.                              |
| التوقف عند دفع ACR                 | تحقق من تشغيل Docker Desktop وأن المستخدم لديه `AcrPush` على السجل.                              |
| النموذج يرجع 404 / لم يتم العثور على النشر     | اسم نشر النموذج في `agent.yaml` يجب أن يتطابق مع النشر في مشروع Foundry.              |
| الوكيل المستضاف عالق في `Provisioning`         | تحقق من أن منطقة المشروع [تدعم الوكلاء المستضافين](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents#region-availability) وأن الحصة متوفرة. |
| الملعب يرجع 401                       | أعد تسجيل الدخول إلى امتداد Foundry من شريط نشاط VS Code.                                     |

## تخصيص هذه الجلسة

يمكنك تعديل الورشة لجمهورك. التنويعات الشائعة:

- **الجمهور التقني الخلفي:** قضاء وقت أطول على `agent.yaml`, Docker, و ACR؛ تقليل العرض التوضيحي للملعب.
- **الجمهور من مطوري المواطنين:** البقاء في واجهة امتداد Foundry للهيكلة؛ تقليل خطوات CLI.
- **جلسة بمسار واحد لمدة 60 دقيقة:** تقديم المقدمة، العرض التوضيحي، والمختبر 01 فقط.
- **صيغة ورشة العمل فقط (بدون شرائح):** افتح كلا ملفي README للمختبر واستخدمهما كنص أساسي.

إذا قمت بتوسيع المختبرات، يرجى المساهمة بالتغييرات عبر طلب سحب ليستفيد المدربون الآخرون.
