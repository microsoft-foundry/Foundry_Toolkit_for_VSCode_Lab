# الوحدة 7 - التحقق في الملعب

⏱️ ~10 دقائق

في هذه الوحدة، تختبر سير العمل متعدد الوكلاء الذي نشرته في VS Code وبوابة Foundry، مؤكداً أن الوكيل يتصرف بنفس طريقة الاختبار المحلي.

---

## لماذا نختبر مرة أخرى بعد النشر؟

يختلف البيئة المستضافة عن البيئة المحلية في بعض الطرق المهمة:

| | محلي | مستضاف |
|--|-------|--------|
| **الهوية** | تسجيل الدخول الشخصي الخاص بك (`DefaultAzureCredential`) | هوية Entra مخصصة لكل وكيل (يتم توفيرها تلقائياً عند وقت النشر) |
| **النقطة النهائية** | `http://localhost:8088/responses` | URL تديره خدمة Foundry Agent |
| **الشبكة** | جهازك → Azure OpenAI + MCP | العمود الفقري لـ Azure (زمن استجابة أقل) |

قد يظهر هنا أولاً متغير بيئة خاطئ التكوين، مشكلة في RBAC، أو مكالمة MCP الصادرة المحجوبة.

---

## الخيار أ: الاختبار في ملعب VS Code (موصى به أولاً)

### الخطوة 1: انتقل إلى وكيلك المستضاف

1. انقر على أيقونة **Foundry Toolkit** في شريط النشاط.
2. وسّع مشروعك → ** Hosted Agents (Preview)** → وابحث عن وكيلك.

![شريط Foundry Toolkit الجانبي يظهر Hosted Agents (Preview) مع resume-job-fit-evaluator وإصداراته المنشورة](../../../../../translated_images/ar/06-foundry-sidebar-agent-status.a45994bfb5c21284.webp)

### الخطوة 2: اختر إصدارًا

1. انقر على الوكيل لتوسيع إصداراته.
2. انقر على `v1` → تحقق من أن الحالة **نشطة** (قد يعرض الشريط الجانبي "تشغيل" أو "بدأ" - كلاهما يشير إلى حالة استعداد مماثلة).

### الخطوة 3: افتح الملعب

1. انقر على **Playground** (أو انقر بزر الماوس الأيمن على الإصدار → **فتح في الملعب**).
2. تفتح نافذة دردشة في تبويب VS Code.

### الخطوة 4: شغل اختبارات التدخين الخاصة بك

استخدم نفس الاختبارات الثلاثة من [الوحدة 5](05-test-locally.md). اكتب كل رسالة في مربع الإدخال الخاص بالملعب واضغط **إرسال** (أو **إدخال**).

#### الاختبار 1 - السيرة الذاتية الكاملة + وصف الوظيفة (التدفق القياسي)

الصق موجه السيرة الذاتية الكاملة + وصف الوظيفة من الوحدة 5، الاختبار 1 (Jane Doe + مهندس سحابي أول في Contoso Ltd).

**المتوقع:**
- درجة توافق مع حساب التحليل (مقياس من 100 نقطة)
- قسم المهارات المتطابقة
- قسم المهارات المفقودة
- **بطاقة فجوة واحدة لكل مهارة مفقودة** مع روابط Microsoft Learn
- خارطة تعلم مع جدول زمني

#### الاختبار 2 - اختبار قصير سريع (حد أدنى من الإدخال)

```
RESUME: 3 years Python developer, knows Django and PostgreSQL, no cloud experience.

JOB: Cloud DevOps Engineer requiring AWS, Kubernetes, Terraform, CI/CD. 5 years needed.
```

**المتوقع:**
- درجة توافق منخفضة (< 40)
- تقييم صادق مع مسار تعلم مرحلي
- بطاقات فجوة متعددة (AWS، Kubernetes، Terraform، CI/CD، فجوة في الخبرة)

#### الاختبار 3 - مرشح عالي التوافق

```
RESUME:
10 years Azure Cloud Architect. AZ-305 certified. Expert in AKS, Terraform, Azure DevOps, 
Azure Functions, Helm, Prometheus, Grafana, Python, Go. Led platform team of 8.

JOB:
Senior Cloud Engineer. Required: AKS, Terraform, Azure DevOps, Python. Preferred: Helm, Go.
5+ years experience. AZ-305 preferred.
```

**المتوقع:**
- درجة توافق عالية (≥ 80)
- تركيز على جاهزية المقابلة والتلميع
- عدد قليل أو لا توجد بطاقات فجوة
- جدول زمني قصير يركز على التحضير

### الخطوة 5: قارن مع النتائج المحلية

افتح ملاحظاتك أو تبويب المتصفح من الوحدة 5 حيث حفظت الردود المحلية. لكل اختبار:

- هل الرد يحتوي على **الهيكل نفسه** (درجة التوافق، بطاقات الفجوة، خارطة الطريق)؟
- هل يتبع **نفس مقياس الدرجات** (تحليل 100 نقطة)؟
- هل لا تزال **روابط Microsoft Learn** موجودة في بطاقات الفجوة؟
- هل هناك **بطاقة فجوة واحدة لكل مهارة مفقودة** (غير مقطعة)؟

> **الاختلافات الطفيفة في الصياغة طبيعية** - النموذج غير حتمي. ركز على الهيكل، اتساق الدرجات، واستخدام أداة MCP.

## الخيار ب: الاختبار في بوابة Foundry

توفر [بوابة Foundry](https://ai.azure.com) ملعبًا يعتمد على الويب مفيدًا للمشاركة مع زملاء العمل أو أصحاب المصلحة.

### الخطوة 1: افتح بوابة Foundry

1. افتح متصفحك وانتقل إلى [https://ai.azure.com](https://ai.azure.com).
2. سجل الدخول بنفس حساب Azure الذي كنت تستخدمه طوال الورشة.

### الخطوة 2: انتقل إلى مشروعك

1. على الصفحة الرئيسية، ابحث عن **المشاريع الأخيرة** في الشريط الجانبي الأيسر.
2. انقر على اسم مشروعك (مثل `workshop-agents`).
3. إذا لم تجده، انقر على **كل المشاريع** وابحث عنه.

### الخطوة 3: ابحث عن وكيلك المنشور

1. في التنقل الأيسر للمشروع، انقر على **بناء** → **وكلاء** (أو ابحث عن قسم **وكلاء**).
2. يجب أن ترى قائمة الوكلاء. ابحث عن وكيلك المنشور (مثل `resume-job-fit-evaluator`).
3. انقر على اسم الوكيل لفتح صفحة التفاصيل الخاصة به.

### الخطوة 4: افتح الملعب

1. في صفحة تفاصيل الوكيل، انظر إلى شريط الأدوات العلوي.
2. انقر على **فتح في الملعب** (أو **التجربة في الملعب**).
3. تفتح واجهة الدردشة.

### الخطوة 5: شغل نفس اختبارات التدخين

كرر جميع الاختبارات الثلاثة من قسم ملعب VS Code أعلاه. قارن كل رد مع النتائج المحلية (الوحدة 5) ونتائج ملعب VS Code (الخيار أ أعلاه).

## التحقق الخاص متعدد الوكلاء

بالإضافة إلى الصحة الأساسية، تحقق من هذه السلوكيات الخاصة بعدد الوكلاء:

### تنفيذ أداة MCP

| التحقق | كيفية التحقق | شرط النجاح |
|-------|---------------|----------------|
| نجاح مكالمات MCP | بطاقات الفجوة تحتوي على روابط `learn.microsoft.com` | روابط حقيقية، وليست رسائل بديلة |
| مكالمات MCP متعددة | لكل فجوة ذات أولوية عالية/متوسطة هناك موارد | ليس فقط بطاقة الفجوة الأولى |
| آلية تراجع MCP تعمل | إذا كانت الروابط مفقودة، تحقق من نص التراجع | الوكيل لا يزال ينتج بطاقات الفجوة (مع أو بدون روابط) |

### تنسيق الوكلاء

| التحقق | كيفية التحقق | شرط النجاح |
|-------|---------------|----------------|
| جميع الوكلاء الأربعة نفذوا | الإخراج يحتوي على درجة التوافق و بطاقات الفجوة | الدرجة من MatchingAgent، البطاقات من GapAnalyzer |
| التنفيذ المتسلسل | وقت الاستجابة معقول (< 2 دقيقة) | إذا تجاوز 3 دقائق، تحقق من الأخطاء في سجل الطرفية |
| سلامة تدفق البيانات | بطاقات الفجوة تشير إلى المهارات من تقرير المطابقة | لا مهارات مخترعة غير موجودة في وصف الوظيفة |

## مقياس التحقق

استخدم هذا المقياس لتقييم سلوك سير العمل متعدد الوكلاء المستضاف:

| # | المعايير | شرط النجاح | نجاح؟ |
|---|----------|---------------|-------|
| 1 | **الصحة الوظيفية** | يستجيب الوكيل للسيرة الذاتية ووصف الوظيفة مع درجة التوافق وتحليل الفجوة | |
| 2 | **اتساق الدرجات** | تستخدم درجة التوافق مقياس 100 نقطة مع حساب التحليل | |
| 3 | **اكتمال بطاقة الفجوة** | بطاقة واحدة لكل مهارة مفقودة (غير مقطوعة أو مدمجة) | |
| 4 | **تكامل أداة MCP** | بطاقات الفجوة تشمل روابط حقيقية من Microsoft Learn | |
| 5 | **اتساق الهيكل** | هيكل الإخراج متطابق بين التشغيل المحلي والمستضاف | |
| 6 | **زمن الاستجابة** | يستجيب الوكيل المستضاف خلال دقيقتين للتقييم الكامل | |
| 7 | **لا أخطاء** | لا أخطاء HTTP 500، لا تجاوزات زمنية، ولا ردود فارغة | |

> يعني "نجاح" استيفاء جميع المعايير السبع لجميع اختبارات التدخين الثلاثة في ملعب واحد على الأقل (VS Code أو البوابة).

## استكشاف مشاكل الملعب وإصلاحها

| العرض | السبب المحتمل | الحل |
|---------|-------------|-----|
| لا يتم تحميل الملعب | الحاوية ليست في حالة `نشطة` | عد إلى [الوحدة 6](06-deploy-to-foundry.md)، تحقق من حالة النشر. انتظر إذا كانت `جارٍ الإنشاء` |
| يعيد الوكيل ردًا فارغًا | اسم نشر النموذج غير مطابق | تحقق من `agent.yaml` → `environment_variables` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` يطابق النموذج المنشور |
| يعيد الوكيل رسالة خطأ | مفقود إذن [RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) | عيّن **[مستخدم Foundry](https://aka.ms/foundry-ext-project-role)** (المستخدم Azure AI سابقًا) على نطاق المشروع |
| لا توجد روابط Microsoft Learn في بطاقات الفجوة | تم حظر MCP الصادر أو خادم MCP غير متوفر | تحقق مما إذا كانت الحاوية يمكنها الوصول إلى `learn.microsoft.com`. انظر [الوحدة 8](08-troubleshooting.md) |
| بطاقة فجوة واحدة فقط (مقطوعة) | تعليمات GapAnalyzer تفتقد "المقطع الحرج" | راجع [الوحدة 3، الخطوة 2.4](03-configure-agents.md) |
| درجة التوافق مختلفة جدًا عن المحلية | تم نشر نموذج أو تعليمات مختلفة | قارن متغيرات البيئة في `agent.yaml` مع `.env` المحلية. أعد النشر إذا لزم الأمر |
| "الوكيل غير موجود" في البوابة | لا يزال النشر قيد الانتشار أو فشل | انتظر دقيقتين، حدث الصفحة. إذا ظل مفقودًا، أعد النشر من [الوحدة 6](06-deploy-to-foundry.md) |

---

### نقطة تحقق

- [ ] تم اختبار الوكيل في ملعب VS Code - اجتياز جميع اختبارات التدخين الثلاثة
- [ ] تم اختبار الوكيل في ملعب [Foundry Portal](https://ai.azure.com) - اجتياز جميع اختبارات التدخين الثلاثة
- [ ] الردود متسقة هيكلياً مع الاختبار المحلي (درجة التوافق، بطاقات الفجوة، خارطة الطريق)
- [ ] روابط Microsoft Learn موجودة في بطاقات الفجوة (أداة MCP تعمل في البيئة المستضافة)
- [ ] بطاقة فجوة واحدة لكل مهارة مفقودة (بدون تقطيع)
- [ ] لا توجد أخطاء أو تجاوزات زمنية أثناء الاختبار
- [ ] أكمل مقياس التحقق (تم اجتياز جميع المعايير السبعة)
