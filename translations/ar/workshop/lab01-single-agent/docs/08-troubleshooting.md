# الوحدة 8 - استكشاف الأخطاء وإصلاحها

هذه الوحدة هي دليل مرجعي للمشكلات الشائعة. قم بإضافتها إلى المفضلة وعد عندما يحدث خطأ ما.

---

## 1. أخطاء الأذونات

### 1.1 `agents/write` رفض الإذن

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**السبب الجذري:** نقص `Azure AI User` الدور على مستوى **المشروع**. هذا هو الخطأ رقم 1 في الورشة.

**الإصلاح:**
1. افتح [portal.azure.com](https://portal.azure.com).
2. ابحث عن اسم **مشروع** Foundry الخاص بك → انقر على النتيجة من النوع **"مشروع Microsoft Foundry"** (ليس حساب الوالد).
3. **التحكم في الوصول (IAM)** → **+ إضافة** → **إضافة تعيين دور**.
4. الدور: **مستخدم Azure AI** → التالي.
5. الأعضاء: اختر نفسك → مراجعة + تعيين → مراجعة + تعيين.
6. **انتظر 1-2 دقيقة** → أعد المحاولة.

> **لماذا لا يكفي مالك/مساهم:** هذه الأدوار تمنح فقط إجراءات *الإدارة*. عمليات الوكيل تتطلب `agents/write` *إجراء البيانات*، وهو متوفر فقط في `Azure AI User`، `Azure AI Developer`، أو `Azure AI Owner`. انظر [وثائق Foundry RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` أثناء التوفير

**الإصلاح:** اطلب من المسؤول تعيين **مساهم** على مجموعة الموارد، أو دعهم ينشئون المشروع لك ويمنحوك **مستخدم Azure AI** عليه.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Wait until: "Registered"
```

## 2. أخطاء Docker

> Docker هو **اختياري**. تنطبق هذه فقط إذا تم تثبيت Docker Desktop وحاولت الإضافة بناء محلي.

### 2.1 خدمة Docker لا تعمل

**الإصلاح:** ابدأ Docker Desktop → انتظر حتى تعلن حالة "تشغيل" → تحقق بواسطة `docker info` → أعد المحاولة.

### 2.2 يفشل البناء مع أخطاء التبعيات

**الإصلاح:** تحقق من تهجئة `requirements.txt`، جرب أولاً محليًا: `pip install -r requirements.txt`.

### 2.3 عدم تطابق المنصة (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. أخطاء المصادقة

### 3.1 فشل `DefaultAzureCredential`

**الإصلاح (جرب بالترتيب):**
1. `az login` (إعادة المصادقة)
2. `az account set --subscription "<id>"` (الاشتراك الصحيح)
3. VS Code → الحسابات → تسجيل الخروج → تسجيل الدخول مجددًا
4. تحقق: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 الرمز يعمل محليًا ولكن ليس على المضيف

**المتوقع:** الوكلاء المضيفون يستخدمون الهوية المدارة من النظام، وليس بيانات اعتمادك. إذا تلقى الوكيل المضيف أخطاء مصادقة:
- تحقق من أن `AZURE_AI_MODEL_DEPLOYMENT_NAME` في `agent.yaml` تشير إلى اسم نشر النموذج الخاص بك (`FOUNDRY_PROJECT_ENDPOINT` يحقنه Foundry وقت التشغيل - لا تعلن عنه في `agent.yaml`)
- تحقق من أن هوية المشروع المدارة لديها وصول للنموذج

## 4. أخطاء النموذج

### 4.1 لم يتم العثور على نشر النموذج

**الإصلاح:** الاسم **حساس لحالة الحروف**. قارن `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` مع الاسم الدقيق في شريط Foundry الجانبي → النماذج.

### 4.2 إخراج نموذج غير متوقع

**الإصلاح:** راجع `AGENT_INSTRUCTIONS` في `main.py` (هل هو غير مقصوص؟). جرب نموذج مختلف (`gpt-4.1` مقابل `gpt-4.1-mini`).

## 5. أخطاء النشر

### 5.1 غير مصرح بالسحب من ACR

**الإصلاح:** بوابة Azure → سجل الحاويات → التحكم في الوصول (IAM) → إضافة دور **AcrPull** لهوية مشروع Foundry المدارة.

### 5.2 فشل بدء الوكيل (يبقى "قيد الانتظار" أو "فشل")

تحقق من سجلات الحاوية في الشريط الجانبي. الأسباب الشائعة:

| رسالة السجل | الإصلاح |
|-------------|-----|
| `ModuleNotFoundError` | أضف الحزمة المفقودة إلى `requirements.txt`، أعد النشر |
| `ValueError: Missing required environment variables` | تأكد من أن `AZURE_AI_MODEL_DEPLOYMENT_NAME` معلن في `agent.yaml` تحت `environment_variables` وله قيمة، ثم أعد النشر. `FOUNDRY_PROJECT_ENDPOINT` يحقنه Foundry وقت التشغيل |
| `Address already in use` | تأكد من أن عملية واحدة فقط تربط المنفذ 8088 |

### 5.3 انتهاء مهلة النشر

**الإصلاح:** تحقق من الاتصال بالإنترنت. أول نشر يدفع >100MB. هل خلف وكيل؟ قم بتكوين إعدادات وكيل Docker Desktop.

## 6. المسار ب - Foundry Local

### 6.1 لا يبدأ Foundry Local

| المشكلة | الإصلاح |
|-------|-----|
| `foundry: command not found` | أعد التثبيت: `winget install Microsoft.FoundryLocal` |
| موارد غير كافية | يحتاج Foundry Local إلى ~4GB رام متاحة. أغلق التطبيقات الأخرى. |
| يفشل تنزيل النموذج | تحقق من مساحة القرص (النماذج بحجم 2-8 جيجابايت). أعد المحاولة: `foundry local models pull <name>` |

### 6.2 أخطاء نموذج Foundry Local

| المشكلة | الإصلاح |
|-------|-----|
| استجابات بطيئة | متوقع - النماذج المحلية تعمل على وحدة المعالجة المركزية إلا إذا كان لديك وحدة معالجة رسومات. كن صبورًا. |
| إخراج بجودة ضعيفة | جرب نموذجًا أكبر إذا سمحت أجهزتك. `phi-4-mini` توازن جيد. |
| تم رفض الاتصال | تحقق من أن Foundry Local يعمل: `foundry local status`. أعد التشغيل إذا لزم الأمر. |

## 7. مرجع سريع: أدوار RBAC

| الدور | النطاق | يمنح |
|------|-------|--------|
| **مستخدم Azure AI** | المشروع | إجراءات البيانات: `agents/write`، `agents/read` |
| **مطور Azure AI** | المشروع/الحساب | إجراءات البيانات + إنشاء المشروع |
| **مالك Azure AI** | الحساب | وصول كامل + إدارة الأدوار |
| **مساهم** | الاشتراك/مجموعة الموارد | إجراءات الإدارة فقط (**لا** إجراءات البيانات) |
| **مالك** | الاشتراك/مجموعة الموارد | الإدارة + تعيين الأدوار (**لا** إجراءات البيانات) |
