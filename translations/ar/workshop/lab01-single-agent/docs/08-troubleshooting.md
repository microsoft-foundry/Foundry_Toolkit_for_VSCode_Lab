# الوحدة 8 - استكشاف الأخطاء وإصلاحها

هذه الوحدة هي دليل مرجعي للمشاكل الشائعة. قم بإضافتها إلى المفضلة وعد إليها عندما يحدث خطأ ما.

---

## 1. أخطاء الأذونات

### 1.1 تم رفض إذن `agents/write`

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**السبب الجذري:** نقص دور `Azure AI User` على مستوى **المشروع**. هذا هو الخطأ رقم 1 في ورشة العمل.

**الإصلاح:**
1. افتح [portal.azure.com](https://portal.azure.com).
2. ابحث عن اسم **المشروع** الخاص بك في Foundry → انقر على النتيجة من نوع **"مشروع Microsoft Foundry"** (ليس حساب الأب).
3. **التحكم في الوصول (IAM)** → **+ إضافة** → **إضافة تعيين دور**.
4. الدور: **Azure AI User** → التالي.
5. الأعضاء: اختر نفسك → مراجعة + تعيين → مراجعة + تعيين.
6. **انتظر 1–2 دقيقة** → أعد المحاولة.

> **لماذا الدوران مالك/مساهم غير كافيين:** تمنح هذه الأدوار *إجراءات الإدارة* فقط. تتطلب عمليات الوكيل `agents/write` *إجراء بيانات*، وهو موجود فقط في `Azure AI User` أو `Azure AI Developer` أو `Azure AI Owner`. انظر [وثائق Foundry RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` أثناء التجهيز

**الإصلاح:** اطلب من مسؤولك تعيين دور **مساهم** على مجموعة الموارد، أو ليُنشئ المشروع لك ويمنحك دور **Azure AI User** عليه.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# انتظر حتى: "مسجل"
```

## 2. أخطاء Docker

> Docker اختياري. تنطبق هذه فقط إذا كان Docker Desktop مثبتًا وحاول الامتداد بناء محلي.

### 2.1 خدمة Docker daemon غير تعمل

**الإصلاح:** ابدأ Docker Desktop → انتظر حالة "تشغيل" → تحقق باستخدام `docker info` → أعد المحاولة.

### 2.2 فشل البناء بأخطاء تبعية

**الإصلاح:** تحقق من تهجئة `requirements.txt`، جرب محليًا أولاً: `pip install -r requirements.txt`.

### 2.3 عدم تطابق المنصة (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. أخطاء المصادقة

### 3.1 فشل `DefaultAzureCredential`

**الإصلاح (جرّب بالترتيب):**
1. `az login` (إعادة المصادقة)
2. `az account set --subscription "<id>"` (اشتراك صحيح)
3. VS Code → الحسابات → تسجيل الخروج → تسجيل الدخول مجددًا
4. تحقق: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 التوكن يعمل محليًا ولا يعمل على الاستضافة

**المتوقع:** الوكلاء المستضافون يستخدمون هوية مُدارة من النظام، وليس بيانات اعتمادك. إذا تلقى الوكيل المستضاف أخطاء مصادقة:
- تحقق من صحة `AZURE_AI_PROJECT_ENDPOINT` في `agent.yaml`
- تحقق من أن هوية المشروع المُدارة لديها وصول إلى النموذج

---

## 4. أخطاء النموذج

### 4.1 لم يتم العثور على نشر النموذج

**الإصلاح:** الاسم حساس لحالة الأحرف. قارن `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` مع الاسم الدقيق في الشريط الجانبي لـ Foundry → النماذج.

### 4.2 مخرج النموذج غير متوقع

**الإصلاح:** راجع `AGENT_INSTRUCTIONS` في `main.py` (هل لم تُقطع؟). جرّب نموذج مختلف (`gpt-4.1` مقابل `gpt-4.1-mini`).

---

## 5. أخطاء النشر

### 5.1 رفض سحب ACR

**الإصلاح:** بوابة Azure → سجل الحاويات → التحكم في الوصول (IAM) → أضف دور **AcrPull** إلى الهوية المُدارة لمشروع Foundry.

### 5.2 فشل الوكيل في البدء (يبقى في "قيد الانتظار" أو "فشل")

تحقق من سجلات الحاوية في الشريط الجانبي. الأسباب الشائعة:

| رسالة السجل | الإصلاح |
|-------------|-----|
| `ModuleNotFoundError` | أضف الحزمة المفقودة إلى `requirements.txt`، وأعد النشر |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | أضف متغير البيئة إلى `agent.yaml` تحت `environment_variables` |
| `Address already in use` | تأكد من أن عملية واحدة فقط تستخدم المنفذ 8088 |

### 5.3 نفاد وقت النشر

**الإصلاح:** تحقق من اتصال الإنترنت. النشر الأول يدفع >100 ميجابايت. هل وراء وكيل؟ اضبط إعدادات الوكيل في Docker Desktop.

## 6. المسار ب - Foundry Local

### 6.1 لا يبدأ Foundry Local

| المشكلة | الإصلاح |
|-------|-----|
| `foundry: command not found` | أعد التثبيت: `winget install Microsoft.FoundryLocal` |
| موارد غير كافية | يحتاج Foundry Local إلى حوالي 4 جيجابايت ذاكرة RAM متاحة. أغلق التطبيقات الأخرى. |
| فشل تنزيل النموذج | تحقق من مساحة القرص (النماذج حجمها 2–8 جيجابايت). أعد المحاولة: `foundry local models pull <name>` |

### 6.2 أخطاء نموذج Foundry Local

| المشكلة | الإصلاح |
|-------|-----|
| استجابات بطيئة | متوقعة - النماذج المحلية تعمل على CPU إلا إذا كان لديك GPU. تحل بالصبر. |
| جودة إخراج ضعيفة | جرّب نموذجًا أكبر إذا سمحت أجهزتك. `phi-4-mini` توازن جيد. |
| تم رفض الاتصال | تأكد من تشغيل Foundry Local: `foundry local status`. أعد التشغيل إذا لزم الأمر. |

## 7. مرجع سريع: أدوار RBAC

| الدور | النطاق | يمنح |
|------|-------|--------|
| **Azure AI User** | المشروع | إجراءات البيانات: `agents/write`، `agents/read` |
| **Azure AI Developer** | المشروع/الحساب | إجراءات البيانات + إنشاء المشاريع |
| **Azure AI Owner** | الحساب | وصول كامل + إدارة الأدوار |
| **مساهم** | الاشتراك/مجموعة الموارد | إجراءات الإدارة فقط (**لا** إجراءات بيانات) |
| **مالك** | الاشتراك/مجموعة الموارد | الإدارة + تعيين الأدوار (**لا** إجراءات بيانات) |
