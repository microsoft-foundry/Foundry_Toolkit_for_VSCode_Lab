# ಅಧ್ಯಾಯ 8 - ಸಮಸ್ಯೆ ನಿವಾರಣೆ

ಈ ಅಧ್ಯಾಯ ಸಾಮಾನ್ಯ ಸಮಸ್ಯೆಗಳಿಗೆ ಪರಿಹಾರಗಳಲ್ಲಿನ ಸೂಚನಾ ಕೈಪಿಡಿ. ಇದನ್ನು ಬುಕ್‌ಮಾರ್ಕ್ ಮಾಡಿ ಮತ್ತು ಏನಾದರು ತಪ್ಪಾದಾಗ ಮರಳಿ ಬನ್ನಿ.

---

## 1. ಅನುಮತಿ ದೋಷಗಳು

### 1.1 `agents/write` ಅನುಮತಿ ನಿರಾಕರಿಸಲಾಗಿದೆ

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**ಮೂಲ ಕಾರಣ:** **ಪ್ರಾಜೆಕ್ಟ್** ಮಟ್ಟದಲ್ಲಿ `Azure AI User` ಪಾತ್ರ ಪಾವತಿಯಾಗಿಲ್ಲ. ಇದು #1 ಕಾರ್ಯಾಗಾರದ ದೋಷ.

**ಮರುಹೊಂದಿಕೆ:**
1. [portal.azure.com](https://portal.azure.com) ತೆರೆಯಿರಿ.
2. ನಿಮ್ಮ Foundry **ಪ್ರಾಜೆಕ್ಟ್** ಹೆಸರನ್ನು ಹುಡುಕಿ → ಫಲಿತಾಂಶದಲ್ಲಿ **"Microsoft Foundry project"** ಪ್ರಕಾರವನ್ನು ಕ್ಲಿಕ್ ಮಾಡಿ (ಮಾತ್ರವಾಗಿ ಪೋಷಕ ಖಾತೆ ಅಲ್ಲ).
3. **Access control (IAM)** → **+ Add** → **Add role assignment**.
4. ಪಾತ್ರ: **Azure AI User** → ಮುಂದುವರೆಯಿರಿ.
5. ಸದಸ್ಯರು: ನಿಮ್ಮನ್ನು ಆಯ್ಕೆಮಾಡಿ → ಪರಿಶೀಲಿಸಿ + ನಿಯೋಜಿಸಿ → ಪರಿಶೀಲಿಸಿ + ನಿಯೋಜಿಸಿ.
6. **1–2 ನಿಮಿಷ ಕಾಯಿರಿ** → ಪುನಃ ಪ್ರಯತ್ನಿಸಿ.

> **ಯಾಕೆ Owner/Contributor ಸಾಕಾಗುವುದಿಲ್ಲ:** ಈ ಪಾತ್ರಗಳು *ನಿರ್ವಹಣಾ* ಕ್ರಿಯೆಗಳನ್ನು ಮಾತ್ರ ನೀಡುತ್ತವೆ. ಏಜೆಂಟ್ ಕಾರ್ಯಗಳಿಗೆ `agents/write` *ಡೇಟಾ ಕ್ರಿಯೆ* ಬೇಕು, ಅದು ಕೇವಲ `Azure AI User`, `Azure AI Developer`, ಅಥವಾ `Azure AI Owner` ನಲ್ಲಿ ಇರುತ್ತದೆ. [Foundry RBAC docs](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) ಅನ್ನು ನೋಡಿ.

### 1.2 ಪ್ರಾವಧಾನದ ವೇಳೆ `AuthorizationFailed`

**ಮರುಹೊಂದಿಕೆ:** ನಿಮ್ಮ ನಿರ್ವಾಹಕನಿಗೆ ಸಂಪನ್ಮೂಲ ಗುಂಪಿನಲ್ಲಿ **Contributor** ನಿಯೋಜಿಸಲು ಹೇಳಿ, ಅಥವಾ ಅವರು ನಿಮಗಾಗಿ ಪ್ರಾಜೆಕ್ಟ್ ಸೃಷ್ಟಿಸಿ ಅದರಲ್ಲಿ ನಿಮಗೆ **Azure AI User** ನೀಡಬೇಕು.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# ಕಾಯಿರಿ: " ನೋಂದಾಯಿತ"
```

## 2. ಡಾಕರ್ ದೋಷಗಳು

> ಡಾಕರ್ **ಐಚ್ಛಿಕ**. ಡಾಕರ್ ಡೆಸ್ಕ್‌ಟಾಪ್ ಸ್ಥಾಪಿಸಲಾಗಿದ್ದರೆ ಮತ್ತು ವಿಸ್ತರಣೆ ಸ್ಥಳೀಯ ನಿರ್ಮಾಣ ಪ್ರಯತ್ನಿಸಿದಾಗ ಮಾತ್ರ ಈ ದೋಷಗಳು ಅನ್ವಯಿಸುತ್ತವೆ.

### 2.1 ಡಾಕರ್ ಡೇಮನ್ ಚಾಲನೆಯಲ್ಲಿಲ್ಲ

**ಮರುಹೊಂದಿಕೆ:** ಡಾಕರ್ ಡೆಸ್ಕ್‌ಟಾಪ್ ಪ್ರಾರಂಭಿಸಿ → "ಚಾಲನೆಯಲ್ಲಿದೆ" ಸ್ಥಿತಿಗೆ ಕಾಯಿರಿ → `docker info` ಜೊತೆ ಪರಿಶೀಲನೆ ಮಾಡಿ → ಪುನಃ ಪ್ರಯತ್ನಿಸಿ.

### 2.2 ಅವಲಂಬನೆ ದೋಷಗಳಿಂದ ನಿರ್ಮಾಣ ವಿಫಲ

**ಮರುಹೊಂದಿಕೆ:** `requirements.txt` ವ್ಯಾಕರಣ ಪರಿಶೀಲಿಸಿ, ಮೊದಲು ಸ್ಥಳೀಯವಾಗಿ ಪರೀಕ್ಷಿಸಿ: `pip install -r requirements.txt`.

### 2.3 ವೇದಿಕೆ ವ್ಯತ್ಯಾಸ (ಆಪಲ್ ಸಿಲಿಕಾನ್)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. ಪ್ರಮಾಣೀಕರಣ ದೋಷಗಳು

### 3.1 `DefaultAzureCredential` ವಿಫಲವಾಗಿದೆ

**ಮರುಹೊಂದಿಕೆ (ಕ್ರಮದಲ್ಲಿ ಪ್ರಯತ್ನಿಸಿ):**
1. `az login` (ಮತ್ತೆ-ಪ್ರಮಾಣೀಕರಿಸಿ)
2. `az account set --subscription "<id>"` (ಸರಿಯಾದ ಚಂದಾದಾರಿಕೆ)
3. VS ಕೋಡ್ → ಖಾತೆಗಳು → ಹೊರಹೋಗಿ → ಮತ್ತೆ ಲಾಗಿನ್ ಮಾಡಿ
4. ಪರಿಶೀಲಿಸಿ: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 ಟೋಕನ್ ಸ್ಥಳೀಯವಾಗಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ ಆದರೆ ಹೋಸ್ಟ್ ಮಾಡಲಾದಲ್ಲಿ ಅಲ್ಲ

**ನಿರೀಕ್ಷಿತ:** ಹೋಸ್ಟ್ ಮಾಡಲಾದ ಏಜೆಂಟುಗಳು ನಿಮ್ಮ ಪ್ರಮಾಣಪತ್ರ ಅಲ್ಲದೆ ವ್ಯವಸ್ಥೆ-ನಿರ್ವಹಿಸಲಾದ ಅಡಿಗೈಕೆಯನ್ನು ಬಳಸುತ್ತವೆ. ಹೋಸ್ಟ್ ಮಾಡಲಾದ ಏಜೆಂಟುಗೆ ಪ್ರಮಾಣೀಕರಣ ದೋಷಗಳು ಬಂದರೆ:
- `agent.yaml` ನಲ್ಲಿ `AZURE_AI_PROJECT_ENDPOINT` ಸರಿಯಾಗಿದೆ ಎಂದು ಪರಿಶೀಲಿಸಿ
- ಪ್ರಾಜೆಕ್ಟಿನ ನಿರ್ವಹಿಸಲಾದ ಅಡಿಗೈಕೆಗೆ ಮಾದರಿ ಪ್ರವೇಶವಿದೆ ಎಂದು ಪರಿಶೀಲಿಸಿ

## 4. ಮಾದರಿ ದೋಷಗಳು

### 4.1 ಮಾದರಿ ನಿಯೋಜನೆ ಸಿಗಲಿಲ್ಲ

**ಮರುಹೊಂದಿಕೆ:** ಹೆಸರು **ಕೆಸ್ಗಳಿಗೆ ಸಂವೇದಿ**. `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` ಅನ್ನು Foundry ಬಾರ್ನಲ್ಲಿ → ಮಾದರಿಗಳಲ್ಲಿ ಇರುವ ನಿಖರ ಹೆಸರಿನೊಂದಿಗೆ ಹೋಲಿಸಿ.

### 4.2 ಅಪ್ರತ್ಯಾಶಿತ ಮಾದರಿ ಫಲಿತಾಂಶ

**ಮರುಹೊಂದಿಕೆ:** `main.py` ರಲ್ಲಿ `AGENT_INSTRUCTIONS` ಪರಿಶೀಲಿಸಿ (ಕಡಿತವಾಗಿಲ್ಲವೇ ಎಂದು?). ಬೇರೆ ಮಾದರಿಯನ್ನು ಪ್ರಯತ್ನಿಸಿ (`gpt-4.1` ವಿರುದ್ಧ `gpt-4.1-mini`).

---

## 5. ನಿಯೋಜನೆ ದೋಷಗಳು

### 5.1 ACR ಡ್ರೋಪ್ಕೆ ಅನುಮತಿ ಇಲ್ಲ

**ಮರುಹೊಂದಿಕೆ:** ಔಜಾರ್ ಪೋರ್ಟಲ್ → ಕಂಟೈನರ್ ರಿಜಿಸ್ಟ್ರಿ → Access control (IAM) → Foundry ಪ್ರಾಜೆಕ್ಟಿನ ನಿರ್ವಹಿಸಲಾದ ಅಡಿಗೈಕೆಗೆ **AcrPull** ಪಾತ್ರವನ್ನು ಸೇರಿಸಿ.

### 5.2 ಏಜೆಂಟ್ ಪ್ರಾರಂಭವಾಗುತ್ತಿಲ್ಲ ("Pending" ಅಥವಾ "Failed" ಸ್ಥಿತಿಯಲ್ಲಿ ಉಳಿಯುತ್ತದೆ)

ಬಾರ್ನಲ್ಲಿ ಕಂಟೈನರ್ ಲಾಗ್‌ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ. ಸಾಮಾನ್ಯ ಕಾರಣಗಳು:

| ಲಾಗ್ ಸಂದೇಶ | ಪರಿಹಾರ |
|-------------|-----|
| `ModuleNotFoundError` | `requirements.txt` ಗೆ ಕಮ್ಮಿ ಪ್ಯಾಕೇಜ್ ಸೇರಿಸಿ, ಪುನಃ ನಿಯೋಜಿಸಿ |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | `agent.yaml` ನಲ್ಲಿ `environment_variables` ಅಡಿ env ವೇರಿಯಬಲ್ ಸೇರಿಸಿ |
| `Address already in use` |ೋರ್ಟು 8088 ಗೆ ಕೇವಲ ಒಬ್ಬ ಪ್ರಕ್ರಿಯೆಯೇ ಸಂಯೋಜಿತವಾಗಿರುವುದನ್ನು ಖಚಿತಪಡಿಸಿ |

### 5.3 ನಿಯೋಜನೆ ಸಮಯ ಮೀರಿದಾಯ್ತು

**ಮರುಹೊಂದಿಕೆ:** ಇಂಟರ್ನೆಟ್ ಸಂಪರ್ಕ ತಪಾಸಿಸಿ. ಮೊದಲ ನಿಯೋಜನೆ >100MB ತಳ್ಳುತ್ತದೆ. ಪ್ರಾಕ್ಸಿ ಹಿಂದೆ ಇದ್ದೀರಾ? ಡಾಕರ್ ಡೆಸ್ಕ್‌ಟಾಪ್ ಪ್ರಾಕ್ಸಿ ಸೆಟ್ಟಿಂಗ್ಸ್ ಕಾನ್ಫಿಗರ್ ಮಾಡಿ.

## 6. ಮಾರ್ಗ B - Foundry ಸ್ಥಳೀಯ

### 6.1 Foundry ಸ್ಥಳೀಯ ಪ್ರಾರಂಭವಾಗುವುದಿಲ್ಲ

| ಸಮಸ್ಯೆ | ಪರಿಹಾರ |
|-------|-----|
| `foundry: command not found` | ಮರುಸ್ಥಾಪಿಸಿ: `winget install Microsoft.FoundryLocal` |
| ಅಪರ್ಯಾಪ್ತ ಸಂಪನ್ಮೂಲಗಳು | Foundry ಸ್ಥಳೀಯಕ್ಕೆ ~4GB RAM ಮುಕ್ತ ಬೇಕು. ಇತರೆ ಅಪ್ಲಿಕೇಶನ್ ಗಳನ್ನು ಮುಚ್ಚಿ. |
| ಮಾದರಿ ಡೌನ್‌ಲೋಡ್ ವಿಫಲ | ಡಿಸ್ಕ್ ಜಾಗ ಪರಿಶೀಲಿಸಿ (ಮಾದರಿಗಳು 2–8 GB). ಮರುಪ್ರಯತ್ನಿಸಿ: `foundry local models pull <name>` |

### 6.2 Foundry ಸ್ಥಳೀಯ ಮಾದರಿ ದೋಷಗಳು

| ಸಮಸ್ಯೆ | ಪರಿಹಾರ |
|-------|-----|
| ನಿಧಾನ ಪ್ರತ್ಯುತ್ತರಗಳು | ನಿರೀಕ್ಷಿತ - ಸ್ಥಳೀಯ ಮಾದರಿಗಳು CPU ನಲ್ಲಿ ಚಲಿಸುತ್ತವೆ, ನೀವು GPU ಹೊಂದಿಲ್ಲದಿದ್ದರೆ. ಧೈರ್ಯ ಧರಿಸಿ. |
| ದುರ್ಬಲ ಗುಣಮಟ್ಟದ ಔಟ್‌ಪುಟ್ | ನಿಮ್ಮ ಹಾರ್ಡ್‌ವೇರ್ ಅನುಮತಿಸುವಿದ್ದರೆ ದೊಡ್ಡ ಮಾದರಿಯನ್ನು ಪ್ರಯತ್ನಿಸಿ. `phi-4-mini` ಉತ್ತಮ ಸಮತೋಲನ. |
| ಸಂಪರ್ಕ ನಿರಾಕರಿಸಲಾಗಿದೆ | Foundry ಸ್ಥಳೀಯ ಚಾಲನೆಯಲ್ಲಿದೆ ಎಂದು ಪರಿಶೀಲಿಸಿ: `foundry local status`. ಅಗತ್ಯವಿದ್ದರೆ ಮರುಪ್ರಾರಂಭಿಸಿ. |

## 7. ಬೇಗಾರಿ ಸೂಚಕ: RBAC ಪಾತ್ರಗಳು

| ಪಾತ್ರ | ವ್ಯಾಪ್ತಿ | ನೀಡುವವುಗಳು |
|------|-------|--------------|
| **Azure AI User** | ಪ್ರಾಜೆಕ್ಟ್ | ಡೇಟಾ ಕ್ರಿಯೆಗಳು: `agents/write`, `agents/read` |
| **Azure AI Developer** | ಪ್ರಾಜೆಕ್ಟ್/ಖಾತೆ | ಡೇಟಾ ಕ್ರಿಯೆಗಳು + ಪ್ರಾಜೆಕ್ಟ್ ಸೃಷ್ಟಿ |
| **Azure AI Owner** | ಖಾತೆ | ಪೂರ್ಣ ಪ್ರವೇಶ + ಪಾತ್ರ ನಿರ್ವಹಣೆ |
| **Contributor** | ಚಂದಾದಾರಿಕೆ/ಆರ್‌ಜಿ | ನಿರ್ವಹಣಾ ಕ್ರಿಯೆಗಳು ಮಾತ್ರ (**ಡೇಟಾ ಕ್ರಿಯೆಗಳು ಇಲ್ಲ**) |
| **Owner** | ಚಂದಾದಾರಿಕೆ/ಆರ್‌ಜಿ | ನಿರ್ವಹಣೆ + ಪಾತ್ರ ನಿಯೋಜನೆ (**ಡೇಟಾ ಕ್ರಿಯೆಗಳು ಇಲ್ಲ**) |
