# ماڈیول 9 - خلاصہ اور اگلے اقدامات

⏱️ ~۵ منٹ

**مبارک ہو!** آپ نے مائیکروسافٹ فاؤنڈری اور VS کوڈ کے لئے فاؤنڈری ٹول کٹ کا استعمال کرتے ہوئے ایک کثیر ایجنٹ ورک فلو بنایا، ٹیسٹ کیا، اور (اگر راستہ A پر ہیں) تعینات کیا ہے۔

---

## آپ نے کیا بنایا

**ریزیومے → جاب فٹ ایویلیویٹر** - ایک کثیر ایجنٹ ہوسٹڈ ورک فلو جو:
- HTTP کے ذریعے ریزیومے + جاب تفصیل وصول کرتا ہے (`POST /responses`)
- چار ماہر ایجنٹس کو ایک تسلسلی پائپ لائن میں چلتا ہے - ہر ایجنٹ اپنے جانشین کو ضروری ڈیٹا پہنچاتا ہے
- ایک فٹ اسکور واپس کرتا ہے (۰-۱۰۰ بریک ڈاؤن کے ساتھ)، مہارت اور سرٹیفیکیشن کی کمی کی فہرست، اور ہر خلاء کے لئے مائیکروسافٹ لرن کے حتمی روابط کے ساتھ ذاتی سیکھنے کا روڈ میپ
- ہر شناخت شدہ مہارت کے خلاء کے لئے سرکاری تعلیمی وسائل لانے کے لئے مائیکروسافٹ لرن MCP سرور (`https://learn.microsoft.com/api/mcp`) کو کال کرتا ہے
- مائیکروسافٹ فاؤنڈری ایجنٹ سروس میں بطور ایک واحد کنٹینرائزڈ ہوسٹڈ ایجنٹ چلتا ہے

---

## کلیدی تصورات جو سیکھے گئے

| تصور | آپ نے کیا مشق کی |
|---------|-------------------|
| **کثیر ایجنٹ آرکسٹرویشن** | `WorkflowBuilder` کے تسلسلی پائپ لائن کے ساتھ `add_edge()` |
| **ایجنٹ تخصص** | چار مخصوص ایجنٹس ایک عمومی مقصد والے ایجنٹ سے بہتر کارکردگی دکھاتے ہیں |
| **کنٹینٹ روٹر پیٹرن** | ResumeParser بطور روٹر کام کرتا ہے - یہ JD متن کو `[JOB DESCRIPTION PASS-THROUGH]` سیکشن میں محفوظ کرتا ہے تاکہ نیچے والے ایجنٹس اسے حاصل کر سکیں (ضروری کیونکہ `context_mode="last_agent"` کا مطلب ہے کہ صرف `start_executor` خام صارف پیغام دیکھتا ہے) |
| **کنٹینٹ ریلی پیٹرن** | JD Agent `[PARSED RESUME PASS-THROUGH]` کو آگے بھیجتا ہے تاکہ MatchingAgent دونوں پروفائلز حاصل کرے؛ OR-semantics ڈبل-ٹرگر سے بچاؤ جو fan-in گرافز پیدا کرتے ہیں |
| **MCP ٹول انٹیگریشن** | `@tool` + `streamable_http_client` استعمال کرتے ہوئے خارجی MCP سرور کو کال کرنا |
| **ہوسٹڈ ایجنٹ لائف سائیکل** | اسکافولڈ → ترتیب دیں → مقامی ٹیسٹ کریں → تعینات کریں → کلاؤڈ میں تصدیق کریں |
| **`context_mode="last_agent"`** | ہر ایکزیکیوٹر صرف اپنے براہ راست پیشرو کی آؤٹ پٹ دیکھتا ہے |
| **فاؤنڈری ٹول کٹ ورک فلو** | اسکافولڈ وزرڈ، ایجنٹ انسپیکٹر، ورک فلو ویزولائزر، ایک کلک تعیناتی |

### اس ورک فلو کو بڑھانے کے خیالات

- **پنچواں ایجنٹ شامل کریں** - ایک انٹرویو کوچ جو گپ رپورٹ کی بنیاد پر ممکنہ انٹرویو سوالات تیار کرے
- **بنگ گراؤنڈنگ ٹول شامل کریں** - JD ایجنٹ کو ملتی جلتی نوکریوں کی تلاش کرنے دیں تاکہ تقاضے کو بڑھایا جا سکے
- **ریزیومے ڈیٹا بیس سے منسلک کریں** - ایک کسٹم `@tool` کے ذریعے امیدوار پروفائلز کو ڈیٹا بیس سے نکالیں
- **مختلف ماڈلز آزمائیں** - `gpt-4.1` بمقابلہ `gpt-4.1-mini` کی آؤٹ پٹ کوالٹی اور تاخیر کا موازنہ کریں
- **فاؤنڈری کے ساتھ جائزہ لیں** - ایویلیویشنز فیچر کا استعمال کرتے ہوئے فٹ رپورٹس کو ایک سنہری ڈیٹاسیٹ کے خلاف اسکور کریں

### راستہ B کے صارفین کے لئے: کلاؤڈ تعیناتی کی طرف اپگریڈ کریں

جب آپ کلاؤڈ پر تعینات کرنے کے لئے تیار ہوں:
1. ایک Azure سبسکرپشن حاصل کریں ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. [Lab 01, Module 01](../../lab01-single-agent/docs/01-setup.md) مکمل کریں (پراجیکٹ بنائیں، ماڈل تعینات کریں، RBAC تفویض کریں)
3. اپنی `.env` فائل کو فاؤنڈری پراجیکٹ اینڈ پوائنٹ اور ماڈل تعیناتی کے نام کے ساتھ اپڈیٹ کریں
4. [Module 06 - Deploy to Foundry](06-deploy-to-foundry.md) سے جاری رکھیں

## وسائل صاف کریں (اختیاری)

اگر آپ اس ورکشاپ کے دوران بنائے گئے Azure وسائل کو ہٹانا چاہتے ہیں:

### آپشن 1: resource group کو حذف کریں (سب کچھ ہٹا دے گا)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### آپشن 2: صرف ہوسٹڈ ایجنٹ کو حذف کریں

1. [ai.azure.com](https://ai.azure.com) کھولیں → اپنا پراجیکٹ → **Build** → **Agents**۔
2. **PersonalCareerCopilot** تلاش کریں → **حذف کریں** پر کلک کریں۔

### آپشن 3: ماڈل تعیناتی کو حذف کریں

1. فاؤنڈری سائیڈ بار میں اپنے پراجیکٹ کو بڑھائیں → **Models**۔
2. ماڈل تعیناتی پر رائٹ کلک کریں → **حذف کریں**۔

> **لاگت کی نوٹ:** ہوسٹڈ ایجنٹس صرف چلنے کے دوران لاگت آتے ہیں۔ اگر آپ ایجنٹ کو روک دیتے ہیں یا حذف کر دیتے ہیں تو کوئی جاری چارج نہیں ہوگا۔ ماڈل تعیناتی ریزروڈ کیپسیٹی کے لئے چھوٹی لاگت لا سکتی ہے - اگر آپ ختم کر چکے ہیں تو اسے حذف کر دیں۔
