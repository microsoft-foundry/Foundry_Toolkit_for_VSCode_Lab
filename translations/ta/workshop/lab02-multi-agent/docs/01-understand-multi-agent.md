# தொகுதி 1 - கட்டமைப்பை புரிந்து கொள்ளுதல்

⏱️ ~5 நிமிடங்கள்

எந்தக் குறியீட்டையும் எழுதுவதற்கு முன், நீங்கள் உருவாக்கும் விஷயமும் அது எப்படி செயல்படுகிறது என்பதன் ஒரு விரைவு பார்வை இதோ.

---

## நீங்கள் உருவாக்கும் ஒன்று

நீங்கள் ஒரு **சுயவிவரம்** மற்றும் ஒரு **வேலை விளக்கம்** ஒட்டு விடுகிறீர்கள். வேலைப்பழக்கம் இதை திரும்ப அளிக்கிறது:

- ஒரு பொருத்த மதிப்பெண் (0–100 உடன் ஒரு விரிவுரை)
- திறன் மற்றும் சான்றிதழ் குறைபாடுகளின் பட்டியல்
- ஒவ்வொரு குறைபாடுக்கும் Microsoft Learn இணைப்புகளுடன் தனிப்பட்ட கற்றல் பாதை வரைபடம்

---

## நான்கு முகவரிகள்

ஒரே முகவர் அனைத்தையும் ஒரே நேரத்தில் பகுப்பாய்வு செய்து, மதிப்பிடும் மற்றும் திட்டமிடும் முயற்சி செய்யும் போது, அது விரைந்து அடிப்படையான முடிவுகளை தரும் போ tendency உள்ளது. வேலை நான்கு சிறப்பு முகவரிகளாக பிரிக்கப்பட்டால் சிறந்த முடிவுகள் கிடைக்கின்றன:

| முகவர் | அது என்ன செய்கிறது |
|-------|-------------|
| **ResumeParser** | சுயவிவரத்தை பகுப்பாய்வு செய்கிறது; JD-வை மாற்றமின்றி `[JOB DESCRIPTION PASS-THROUGH]`-ல் நகலெடுக்கிறது பிற முகவரிகளுக்காக |
| **JobDescriptionAgent** | பாஸ்-துருவிலிருந்து JD தேவைகளை எடுப்பது; `[PARSED RESUME]`-ஐ `[PARSED RESUME PASS-THROUGH]` ஆக போற்றுகிறது |
| **MatchingAgent** | இரு பகுதியையும் ஒப்பிடுகிறது; 0–100 மதிப்பெண் மற்றும் குறைபாட்டு பட்டியலை உருவாக்குகிறது |
| **GapAnalyzer** | கற்றல் பாதை வரைபடத்தை அமைக்கிறது; ஒவ்வொரு குறைபாடுக்கும் Microsoft Learn ஐ தேடுகிறது |

## ஒருங்கிணைப்பு வரைபடம்

வேலைப்பழக்கம் ஒரு **தொடர்புடைய குழாய்** - ஒவ்வொரு முகவரும் தனது வெளியீட்டை அடுத்தவருக்கு கொண்டு செல்கிறது:

```mermaid

    D -- "பொருத்து அறிக்கை + கிடைகள்" --> E["கடவை பகுப்பாய்வாளர் + MCP"]
```

1. **ResumeParser** பயனர் உள்ளீட்டை பெறுகிறது, சுயவிவரத்தை பகுப்பாய்வு செய்கிறது, JD-வை `[JOB DESCRIPTION PASS-THROUGH]`-க்கு நகலெடுக்கிறது.
2. **JD முகவர்** கட்டமைக்கப்பட்ட தேவைகளை எடுப்பது மற்றும் `[PARSED RESUME PASS-THROUGH]`-ஐ முன் கூட்டுகிறது.
3. **MatchingAgent** இரு பகுதிகளையும் ஒப்பிட்டு பொருத்த மதிப்பெண் மற்றும் குறைபாட்டு பட்டியலை உருவாக்குகிறது.
4. **GapAnalyzer** பாதை வரைபடத்தை அமைக்கிறது மற்றும் ஒவ்வொரு குறைபாட்டுக்கும் Microsoft Learn MCP கருவியை அழைக்கிறது.

## இதை குறியீட்டுடன் எப்படி பொருந்துவது

`main.py`-இல் நீங்கள் இந்த வரைபடத்தை `WorkflowBuilder` உடன் விவரிக்கிறீர்கள்:

```python
workflow_agent = (
    WorkflowBuilder(
        start_executor=resume_executor,       # பயனர் உள்ளீட்டை பெற முதல் முகவர்
        output_executors=[gap_executor],      # கடைசி முகவர் - அதன் வெளியீடு பதிலாகும்
    )
    .add_edge(resume_executor, jd_executor)       # ResumeParser → வேலை விளக்கம் முகவர்
    .add_edge(jd_executor, matching_executor)     # வேலை விளக்கம் முகவர் → பொருத்தும் முகவர்
    .add_edge(matching_executor, gap_executor)    # பொருத்தும் முகவர் → இடைவெளி பகுப்பாய்வாளர்
    .build()
    .as_agent()
)
```

ஒவ்வொரு `Agent`-உம் ஒரு `AgentExecutor`-ல் சுற்றப்பட்டிருக்கிறது. `add_edge()` அழைப்புகள் கடுமையான தொடர்ச்சியான குழாயை வரையறுக்கின்றன - ஒவ்வொரு முகவரும் தனது நேரடி முன் முகவரின் வெளியீட்டையே பெறுகிறது.

> `context_mode="last_agent"` என்றால் ஒவ்வொரு செயல்படுத்தும் முகவரும் தனது நேரடி முன் முகவரின் வெளியீட்டை மட்டுமே பார்க்கிறது. ResumeParser மற்றும் JD முகவர் தரவை லேபிள் செய்யப்பட்ட பகுதிகளில் முன்னோக்கி அனுப்புகின்றன, அதனால் ஒவ்வொரு பின்னணி முகவருக்கும் அவர்களுக்கு தேவையானதை துல்லியமாக கிடைக்கும்.

## MCP கருவி

GapAnalyzer உடைய ஒரு கருவி உள்ளது: `search_microsoft_learn_for_plan`. இது `https://learn.microsoft.com/api/mcp` உடன் இணைந்திருக்கும் மற்றும் ஒவ்வொரு திறன் குறைபாட்டிற்கும் உண்மையான Microsoft Learn இணைப்புகளை தருகிறது.

கருவி ஓடும் போது நீங்கள் இதுபோன்ற பதிவுகளை காண்பீர்கள் - அனைத்தும் எதிர்பார்த்தபடி:

```
GET  https://learn.microsoft.com/api/mcp → 405   ← connection probe, normal
POST https://learn.microsoft.com/api/mcp → 200   ← actual tool call
DELETE https://learn.microsoft.com/api/mcp → 405 ← cleanup probe, normal
```

`POST` ஒரு பிழையை திருப்பினால் மட்டும் கவலைப்பட வேண்டும்.
