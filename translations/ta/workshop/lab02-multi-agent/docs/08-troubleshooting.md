# Module 8 - பிழைதிருத்தம்

இந்த பாடம் பல-நேசகர் வேலைநடவடிக்கைக்கு சம்பந்தப்பட்ட பொதுவான பிழைகள், திருத்தங்கள் மற்றும் பிழைத்திருத்தக் கோர்வைகள் பற்றியது.

## வேட்பாளரின் வெளியீட்டு சிக்கல்கள்

### GapAnalyzer “ எனக்கு இன்னும் பொருத்தமான அறிக்கை கிடையாது” என்று சொல்கிறார்

**அறிகுறி:** GapAnalyzer பதில் உங்களிடம் “குறைந்த திறன்கள்” மற்றும் “சான்றிதழ் குறைகளும்” கொண்ட பொருத்த அறிக்கையை ஒட்டுமாறு கேட்கிறார். இது நீங்கள் இரண்டையும் - வாழ்க்கை வரலாறு மற்றும் வேலை விளக்கத்தையும் அனுப்பியபோதும் நிகழ்கிறது.

**காரணம்:** வேலை விளக்கம் (JD) உரை JD வேட்பாளருக்கு கீழதூர அறிவுறுத்தப்படவில்லை. `context_mode="last_agent"` என்றால், `resume_executor` மட்டுமே பயனாளியின் முதன்மை செய்தியை காணும் வெளிப்படுத்துப் படை. `RESUME_PARSER_INSTRUCTIONS` அதின் வெளியீட்டில் JD உரையை உள்ளடக்காவிடின், JD வேட்பாளர் JD-யை பகுப்பாய்வு செய்ய முடியாது, MatchingAgent பொருத்த மதிப்பெண் கணக்கிட முடியாது, மற்றும் GapAnalyzer அர்த்தமற்ற உள்ளீட்டை பெறுகிறது.

**ஆய்வு:**

சேவையகம் பதிவு கோப்புகளில் MatchingAgent பகுதியை பாருங்கள். இதில்:
```
Cannot compute a numeric fit score because no job description (JD) was provided
```
கடத்தல் மறைவு அல்லது உடைந்திருப்பது காணப்படுகிறது.

**திருத்தம்:** `main.py` இல் உள்ள `RESUME_PARSER_INSTRUCTIONS` `[JOB DESCRIPTION PASS-THROUGH]` பிரிவையும் கீழ்கண்ட விதியையும் கொண்டிருப்பதை உறுதிசெய்யவும்:
```
The [JOB DESCRIPTION PASS-THROUGH] section MUST contain the FULL, UNMODIFIED JD text.
```
மேலும் `JOB_DESCRIPTION_INSTRUCTIONS` `[PARSED RESUME PASS-THROUGH]` கடத்தல் விதியையும் கொண்டிருப்பதை உறுதிசெய்யவும்:
```
Copy [PARSED RESUME] verbatim - the Matching Agent depends on it downstream.
```
இரு அறிவுறுத்தல் தொகுதிகள் எந்தவொன்றும் நிராகரிக்கப்படும்படி இருந்தால், அவற்றை [`PersonalCareerCopilot/main.py`](../../../../../workshop/lab02-multi-agent/PersonalCareerCopilot/main.py) உள்ள முழு பதிப்புடன் மாற்றவும்.

### MatchingAgent “பொருத்த மதிப்பெண் கணக்கிட முடியவில்லை - JD வழங்கவில்லை” என்று வெளியீடு செய்கிறது

இதற்கு மேலே கூறிய அதே மூலக் காரணமே உள்ளது. MatchingAgent JD Agent வெளியீட்டை பெற்றார் ஆனால் `[PARSED RESUME PASS-THROUGH]` பகுதி இல்லை அல்லது காலியானதால் இரு பெயர் பட்டியல்களை ஒப்பிட முடியவில்லை. உறுதிசெய்யவும்:
1. `JOB_DESCRIPTION_INSTRUCTIONS` relay விதி: `Copy [PARSED RESUME] verbatim - the Matching Agent depends on it downstream.` உடன் உள்ளது.
2. `MATCHING_AGENT_INSTRUCTIONS` `[JD REQUIREMENTS]` மற்றும் `[PARSED RESUME PASS-THROUGH]` பகுதிகள் உள்ளதா என்பதை முகவர் பார்த்து செயல்படுகிறது.

இரு அறிவுறுத்தல் தொகுதிகளை [`PersonalCareerCopilot/main.py`](../../../../../workshop/lab02-multi-agent/PersonalCareerCopilot/main.py) முழுமையான பதிப்புடன் மாற்றவும்.

### பதில் இருமுறை தோன்றுகிறது

**அறிகுறி:** GapAnalyzer (அல்லது முழு குழாயறுக்கப்பட்ட) வெளியீடு Agent Inspector பதிலில் இருமுறை காணப்படுகிறது.

**காரணம்:** `WorkflowBuilder` உள்ளீடும் வெளியீடும் OR-அர்த்தவியல் மூலம் நிரல்படுத்தப்படுவது - பின்னணியில் ஒரே முன்னோடியின் செயல்பாடு முடிந்தவுடன் கீழ்க் கையாடிகள் செயல்படுவதைத் தொடங்கும். `matching_executor` க்கு இரண்டு உள்ளீடு வழிகள் இருந்தால் (resume_executor மற்றும் jd_executor வழியாக), அது இருமுறை செயற்படும்: ஒருமுறை ResumeParser முடிந்ததும் மற்றொன்று JD Agent முடிந்ததும். இதனால் GapAnalyzer இருமுறை இயங்கும்.

**திருத்தம்:** `WorkflowBuilder` வரைபடம் கடினமான முறையில் மறுகட்டமைப்பு இல்லாத தொடர் குழாய் வடிவில் இருக்க வேண்டும்:

```python
workflow_agent = (
    WorkflowBuilder(start_executor=resume_executor, output_executors=[gap_executor])
    .add_edge(resume_executor, jd_executor)
    .add_edge(jd_executor, matching_executor)    # ரெசுமே_எக்சிகியூட்டரிலிருந்து இல்லை
    .add_edge(matching_executor, gap_executor)
    .build().as_agent()
)
```

தவறுதலாக உள்ள `.add_edge(resume_executor, matching_executor)` வரி இருந்தால் அதை அகற்றி விடவும். JD Agent வெளியீட்டில் உள்ள `[PARSED RESUME PASS-THROUGH]` relay ஏற்கனவே MatchingAgent க்கு வாழ்க்கை வரலாறு கிடைக்கச் செய்கிறது.

## சுற்றுச்சூழல் மற்றும் கட்டமைப்பு சிக்கல்கள்

### மறைந்த அல்லது தவறான `.env` மதிப்புகள்

`.env` கோப்பு `PersonalCareerCopilot/` கோப்பகத்தில் ( `main.py` உடன் ஒரே அடுக்கு) இருக்க வேண்டும்:

```
PersonalCareerCopilot/
├── .env                  ← Must be here
├── main.py
├── agent.yaml
├── Dockerfile
└── requirements.txt
```

எதிர்பார்க்கப்பட்ட `.env` உள்ளடக்கம்:

**பாதை A - Foundry மேகம்:**

```env
FOUNDRY_PROJECT_ENDPOINT=https://<your-project-name>.services.ai.azure.com/api/projects/<your-project-id>
AZURE_AI_MODEL_DEPLOYMENT_NAME=gpt-4.1-mini
```

**பாதை B - Foundry உள்ளூரி:**

```env
FOUNDRY_PROJECT_ENDPOINT=http://localhost:5273/v1
AZURE_AI_MODEL_DEPLOYMENT_NAME=phi-4-mini
```

> இரு பாதைகளிலும் `FOUNDRY_PROJECT_ENDPOINT` பயன்படுத்தப்படுகிறது. மதிப்பு வேறுபடுகிறது: மேகம் ஒரு `https://` Foundry முடிவில்லையைப் பயன்படுத்துகிறது; உள்ளூரி `http://localhost:5273/v1`-ஐப் பயன்படுத்துகிறது. பாதை B-க்கான சரியான மாதிரிக் குறிச்சொல்லை உறுதிப்படுத்த `foundry model list` இயக்கவும்.

> **உங்கள் `FOUNDRY_PROJECT_ENDPOINT` கண்டறிதல்:** 
- VS Code இல் **Foundry Toolkit** பக்கம் திறந்து → உங்கள் திட்டத்தில் வலது கிளிக் → **Copy Project Endpoint** தேர்ந்தெடுக்கவும். 
- அல்லது [Azure Portal](https://portal.azure.com) → உங்கள் Foundry திட்டம் → **கண்ணோட்டம்** → **Project endpoint** செல்லவும்.

> **உங்கள் `AZURE_AI_MODEL_DEPLOYMENT_NAME` கண்டறிதல்:** Foundry Toolkit பக்கம் உங்கள் திட்டத்தை விரிவாக்கு → **Models** → உங்கள் நிறுவப்பட்ட மாதிரி பெயரை (உதா: `gpt-4.1-mini`) கண்டுபிடி.

### சூழல் மாறி முன்னுரிமை

`main.py` இல் `load_dotenv(override=True)` இல் பயன்படுத்தப்பட்டுள்ளது, அதாவது:

| முன்னுரிமை | மூலாதாரம் | இரண்டும் அமைந்தால் வெற்றி பெறும்? |
|----------|--------|------------------------|
| 1 (அதிகம்) | `.env` கோப்பு | ஆம் |
| 2 | ஷெல் / கொண்டெய்னர் சூழல் மாறி | `.env`யில் அதே விசை இல்லாத போது பயன்படுத்தப்படும் |

உள்ளூர் மேம்பாட்டில், இது `.env` உண்மை மூலமாக இருக்கச் செய்கிறது ( `.env` திருத்தம் உடனடியாக இயக்கங்களை பாதிக்கிறது). ஹோஸ்ட் செய்யப்பட்ட விநியோகத்தில், Foundry சூழல் மாற்றிகளை கொண்டெய்னர் நிலைமையில் ஊட்டுகிறது; இந்த தொழில்திட்ட அமைப்பில் `.env` பகுதி நிறுவப்பட்ட படத்திற்குள் இருப்பதால், ஊட்டப்பட்ட கொண்டெய்னர் மதிப்புகள் பயன்படுத்தப்படும்.


## விநியோக சிக்கல்கள்

### கட்டமைப்பு இடைமுகம் செயல்படவில்லை

1. **கொண்டெய்னர் பதிவுகளை சரிபார்க்கவும்:**
   - **Foundry Toolkit** பக்கத்தை திறந்து → **Hosted Agents (Preview)** விரிவாக்கு → உங்கள் முகவரை கிளிக் செய் → பதிப்பை விரிவாக்கு → **Container Details** → **Logs**.
   - பைத்தான் ஸ்டாக் தடைகள் அல்லது மறைந்த தொகுப்பு பிழைகளை கவனியுங்கள்.

2. **சாதாரண கொண்டெய்னர் தொடக்க தோல்விகள்:**

   | பதிவுகளில் பிழை | காரணம் | திருத்தம் |
   |--------------|-------|-----|
   | `ModuleNotFoundError` | `requirements.txt` ல் தொகுப்பு காணவில்லை | தொகுப்பை சேர்த்து, மீள் விநியோகிக்கவும் |
   | `KeyError: 'FOUNDRY_PROJECT_ENDPOINT'` | `agent.yaml` அல்லது `.env` சூழல் மாறிகள் அமைக்கப்படவில்லை | `agent.yaml` → `environment_variables` பகுதி (ஹோஸ்ட்) அல்லது `.env` (உள்ளூர்) புதுப்பிக்கவும் |
   | `azure.identity.CredentialUnavailableError` | மேலாண்மை அடையாளம் கட்டமைக்கப்படவில்லை | Foundry தானாகவே அமைக்கிறது - நீங்கள்தான் நீட்சியறின் மூலம் விநியோகிக்கிறீர்கள் என்பதை உறுதிசெய்க |
   | `OSError: port 8088 already in use` | Dockerfile தவறான போர்ட் வெளிப்படுத்துகிறது அல்லது போர்ட் மோதல் | Dockerfile இல் `EXPOSE 8088` மற்றும் `CMD ["python", "main.py"]` சரிபார்க்கவும் |
   | கெொண்டெய்னர் exit குறியீடு 1 உடன் நிறுத்தம் | `main()`ல் கையாளப்படாத விதிவிலக்கு | உள்ளூரில் முதலில் சோதிக்கவும் ([Module 5](05-test-locally.md)) பிழைகளைப் பிடிக்கவும் |

3. **திருத்தம் செய்த பிறகு மீண்டும் விநியோகிக்கவும்:**
   - `Ctrl+Shift+P` → **Foundry Toolkit: Deploy Hosted Agent** → அதே முகவரை தேர்வு செய்து புதிய பதிப்பை அனுப்பவும்.

### விநியோகம் நீளமாகிறது

பல-நேசகர் கொண்டெய்னர்கள் தொடக்கத்தில் 4 முகவர் அலகுகளை உருவாக்குகின்றன. வழக்கமான தொடக்க நேரம்:

| கட்டம் | எதிர்பார்க்கப்படும் நீளம் |
|-------|------------------|
| கொண்டெய்னர் படம் உருவாக்கம் | 1-3 நிமிடங்கள் |
| படம் ACRக்கு கொடுக்கல் | 30-60 விநாடிகள் |
| கொண்டெய்னர் தொடக்கம் (ஒற்றை முகவர்) | 15-30 விநாடிகள் |
| கொண்டெய்னர் தொடக்கம் (பல-நேசகர்) | 30-120 விநாடிகள் |
| Playground இல் முகவர் கிடைக்கும் | "தொடக்கம்" பின்னர் 1-2 நிமிடங்கள் |

> "நிலைத்திருக்கும்" நிலை 5 நிமிடங்களை விட அதிகமாக நீடித்தால், கொண்டெய்னர் பதிவுகளை பிழைகள் ந்காக உணர்தல் செய்யவும்.

## RBAC மற்றும் அனுமதி சிக்கல்கள்

### `403 Forbidden` அல்லது `AuthorizationFailed`

உங்கள் Foundry திட்டத்தில் **[Foundry User](https://aka.ms/foundry-ext-project-role)** பங்கு (முன்பு **Azure AI User** என்று அறிந்து இருந்தது - பங்கு ஐடி மாறவில்லை) தேவை:

1. [Azure Portal](https://portal.azure.com) → உங்கள் Foundry **திட்ட** வளத்திற்கு செல்லவும்.
2. **அணுகல் கட்டுப்பாடு (IAM)** → **பங்கு ஒதுக்கீடுகள்** கிளிக் செய்யவும்.
3. உங்கள் பெயர் தேடவும் → **Foundry User** (அல்லது பழைய பெயர் **Azure AI User**) பட்டியலில் உள்ளதா பார்க்கவும்.
4. இல்லை என்றால்: **சேர்** → **பங்கு ஒதுக்கீடு சேர்க்கவும்** → **Foundry User** தேடவும் → உங்கள் கணக்குக்கு ஒதுக்கவும்.

விவரங்களுக்கு [RBAC for Microsoft Foundry](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) ஆவணத்தைப் பார்க்கவும்.

### மாதிரி விநியோகம் அணுக முடியவில்லை

முகவர் மாதிரி சம்பந்தப்பட்ட பிழைகளைத் திருப்பினால்:

1. மாதிரி நிறுவப்பட்டது என உறுதிசெய்யவும்: Foundry பக்கம் → திட்டம் விரிவாக்கவும் → **Models** → `gpt-4.1-mini` (அல்லது உங்கள் மாதிரி) நிலை **Succeeded** என்பதைக் காணவும்.
2. நிறுவல் பெயர் பொருந்துகிறதா என உறுதிசெய்யவும்: `.env` (அல்லது `agent.yaml`) இல் உள்ள `AZURE_AI_MODEL_DEPLOYMENT_NAME` மற்றும் பக்கத்தில் உள்ள நிறுவல் பெயரை ஒப்பிடவும்.
3. நிறுவல் காலாவதி ஆனால் (இலவசத் துண்டு): [Model Catalog](https://learn.microsoft.com/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure) இல் இருந்து மீண்டும் நிறுவவும் (`Ctrl+Shift+P` → **Foundry Toolkit: Open Model Catalog**).

## Foundry உள்ளூர் சிக்கல்கள் (பாதை B)

### Foundry உள்ளூர் சேவை இயங்கவில்லை

```powershell
# நிலையை சரிபார்க்கவும்
foundry local status

# சேவை நிறுத்தப்பட்டிருந்தால் அதை துவங்கவும்
foundry local start
```

| அறிகுறி | காரணம் | திருத்தம் |
|---------|-------|-----|
| சுகாதார சரிபார்ப்பு `503` திருப்புகிறது | சேவை ஆரம்பிக்கப்படவில்லை | `foundry local start` அல்லது Foundry Toolkit பக்கத்தில் **Start** கிளிக் செய்யவும் |
| சுகாதார சரிபார்ப்பு நேராவதி | மாதிரி இன்னும் ஏற்றப்படுகிறது | தொடக்கம் பின்னர் 30–60 விநாடிகள் காத்திருக்கவும்; பெரிய மாதிரிகள் கூடுதலாக நேரம் எடுக்கலாம் |
| `/v1/health` இலுள்ள `StatusCode: 404` | தவறான போர்ட் | இயல்பாக `5273`. உண்மையான போர்ட்டிற்கு `foundry local status` பரிசீலனை செய்யவும் |
| சமர்ப்பிக்க நடந்தது | Foundry Localக்கு ~4 GB RAM இலவசம் தேவை | பிற பயன்பாடுகளை மூடு |
| மாதிரி பதிவிறக்கம் தோல்வி | குறைந்த டிஸ்க் இடம் | மாதிரிகள் 2–8 GB. இடம் விடுதி செய்து பின்னர் `foundry model pull <name>` இயக்கவும் |

### மாதிரி பெயர் பொருத்தாது

```powershell
# பதிவிறக்கப்பட்ட மாடல்களையும் அவற்றின் சரியான மாற்றுப்பெயர்களையும் பட்டியலிடவும்
foundry model list
```

`.env` இதழில் `AZURE_AI_MODEL_DEPLOYMENT_NAME` சரியான குறிச்சொல்லாக (உதா: `phi-4-mini`, `Phi-4-mini` அல்ல) அமைக்கவும்.

### உள்ளூர் இயக்கத்தில் `KeyError: 'FOUNDRY_PROJECT_ENDPOINT'` (பாதை B)

இந்த பணிக்கூட `main.py` `os.environ["FOUNDRY_PROJECT_ENDPOINT"]` பயன்படுத்துகிறது. Foundry உள்ளூர் சேவை இன்னும் பாவனைக்கு `AZURE_AI_PROJECT_ENDPOINT` அல்லாமல் இந்த மாறி உள்ளூர்சேவைக்கு காட்டு வேண்டும். உங்கள் `.env` இல்:

```env
FOUNDRY_PROJECT_ENDPOINT=http://localhost:5273/v1
AZURE_AI_MODEL_DEPLOYMENT_NAME=phi-4-mini
```

### MCP கருவி இன்னும் வெளியே அழைக்கிறது (பாதை B)

இது எதிர்பார்க்கப்படும் ஒன்று. `search_microsoft_learn_for_plan` கருவி `https://learn.microsoft.com/api/mcp`-இல் இருந்து கல்வி வளங்களை பெறுகிறது. **திறன் பெயர் கூற்று மட்டுமே** நெட்வொர்க்கில் பயணம் செய்கிறது - வாழ்க்கை வரலாறு மற்றும் JD உரை உங்கள் சாதனத்தில் முழுமையாக செயலாக்கப்படுகிறது என்றும் ஒருபோதும் பரிமாறப்படவில்லை என்றும். முழுமையாக ஆஃப்லைனில் இயங்க வேண்டுமெனில் கருவியில் ஒரு `try/except` காப்பகத்தைச் சேர்த்து அந்த முனையம் இல்லை என்றால் நிலையான `learn.microsoft.com` URLஐ திருப்பவேண்டும்.
