# ஆய்வகம் 02 - பன்முகப்பட்ட செயல்: சுயவிவரம் → வேலை பொருந்தும் மதிப்பீடு

## பார்வை

இந்த செய்முறை ஆய்வகத்தில், நீங்கள் VS கோடில் Foundry கருவித்தொகுப்பை பயன்படுத்தி **செயற்பாடு-முதன்மை பன்முகப்பட்ட செயலி** உருவாக்கி அதை Microsoft Foundry Agent சேவைக்கு அனுப்புவீர்கள்.

**நீங்கள் உருவாக்கப்போகும்து:** ஒரு சுயவிவரம் → வேலை பொருந்தும் மதிப்பீடு செயலி, இது ஒரு சுயவிவரத்தையும் வேலை விளக்கத்தையும் பகுப்பாய்வு செய்து, பொருந்துதலை மதிப்பிட்டு, Microsoft Learn வளங்களைப் பயன்படுத்தி தனிப்பயன் கற்றல் திட்டத்தைக் கொடுக்கிறது.

---

## கட்டமைப்பு

```mermaid
flowchart TD
    A["User Input"] --> B["Resume Parser"]
    B -->|"[PARSED RESUME] + [JOB DESCRIPTION PASS-THROUGH]"| C["Job Description Agent"]
    C -->|"[JD REQUIREMENTS] + [PARSED RESUME PASS-THROUGH]"| D["Matching Agent"]
    D -->|fit report + gaps| E["Gap Analyzer + Microsoft Learn MCP"]
    E -->|fit score + roadmap| F["Output"]

    style A fill:#4A90D9,color:#fff

    style C fill:#7B68EE,color:#fff
    style D fill:#E67E22,color:#fff
    style E fill:#27AE60,color:#fff
    style F fill:#4A90D9,color:#fff
```

**எப்படி வேலை செய்கிறது:**
1. பயனர் ஒரு சுயவிவரத்தையும் வேலை விளக்கத்தையும் ஒட்டுகிறார்.
2. **ResumeParser** சுயவிவரத்தைப் பகுப்பாய்வு செய்து, வேலை விளக்கத்தை `[JOB DESCRIPTION PASS-THROUGH]` பகுதியில் நகலெடுக்கிறது.
3. **JD Agent** பாத்திரத்திலிருந்து கட்டமைக்கப்பட்ட தேவைகளை எடுக்கிறது, பின்னர் `[PARSED RESUME]` ஐ `[PARSED RESUME PASS-THROUGH]` ஆக முன்னெடுக்கும்.
4. **MatchingAgent** `[PARSED RESUME PASS-THROUGH]` மற்றும் `[JD REQUIREMENTS]` ஐ ஒப்பிட்டு பொருந்துதலைக் கணக்கிடுகிறது.
5. **GapAnalyzer** இடைவெளிகளை நடைமுறைப்பட்ட திட்டமாக மாற்றி, MCP மூலம் உண்மையான Microsoft Learn இணைப்புகளை எடுக்கும்.

## பகுதி 2: செயல்முறை கட்டமைத்து சோதனைசெய்யவும்

1. Foundry கருவித்தொகுப்பின் வழிகாட்டியுடன் செயல்முறை அடிப்படையிலான திட்டத்தை உருவாக்கவும்.
2. `PersonalCareerCopilot/main.py` இலிருந்து உரையாடல் தகடுகள் மற்றும் செயல்முறை படத்தை உங்கள் பணியிடத்துக்கு நகலெடுக்கவும்.
3. முகவர் பார்வையாளர் மூலம் உள்ளகமாக இயக்கி நான்கு முகவர்களுக்கும் MCP கருவியும் சரியாக உள்ளதா என்பதை உறுதிப்படுத்தவும்.
4. உள்ளக சோதனை வெற்றியடைந்த பின் Foundry ஆக ஓர்முகவரை வெளியிடவும்.

## ஒருங்கிணைப்பு மாதிரிகள்

ஆய்வகம் 02 **வரிசைப்படுத்தப்பட்ட குழாய்** முறையை பின்பற்றுகிறது: ஒவ்வொரு முகவரின் வெளியீடு அடுத்ததற்க்கு இன்குட்டாகும், மற்றும் செயல்முறை இறுதியான முகவரின் பதிலைத் திரும்ப வழங்கும். இரண்டு மாதிரிகள் இதை செயல்படுத்துகின்றன:

- **வரிசை சங்கிலி** - `WorkflowBuilder` ResumeParser → JD Agent → MatchingAgent → GapAnalyzer ஐ ஒவ்வொரு படியிலும் ஒரு `add_edge()` அழைப்புடன் இணைக்கிறது
- **உள்ளடக்க பரிமாற்றம்** - ஒவ்வொரு முகவரும் தன் நேரடியான முன் முகவரின் வெளியீட்டை மட்டுமே காணும் காரணத்தால், ResumeParser மற்றும் JD Agent தேவையான தரவை குறிச்சொற்கள் கொண்ட பகுப் பகுதியை உருவாக்கி கீழேயுள்ள முகவர்களுக்கு அனுப்புகின்றன

ஆவணங்கள் ஏன் fan-out/fan-in பயன்படுத்தப்படவில்லை என்பதை விளக்குகின்றன மற்றும் மேலும் ஒரு முகவருடன் செயல்முறை வரைபடத்தை எவ்வாறு விரிவாக்குவது என்பதையும் விளக்குகின்றன.
