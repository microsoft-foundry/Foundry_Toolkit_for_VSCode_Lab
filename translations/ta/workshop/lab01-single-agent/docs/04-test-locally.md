# தொகுதி 4 - உள்ளுரையில் சோதனை செய்க

⏱️ ~10 நிமிடம்

இந்த தொகுதியில், நீங்கள் உங்கள் முகவரியை உள்ளுரையில் இயக்கி **மகிழ்ச்சி பாதை செயல்பாட்டு சோதனைகள்** மூலம் அது சரியாக செயல்படுகிறதா என்பதை உறுதிப்படுத்துவீர்கள். முகவரியInspector (காட்சி UI) அல்லது நேரடி HTTP அழைப்புகளைப் பயன்படுத்தி முகவர் கட்டமைக்கப்பட்ட, துல்லியமான பதில்களை உற்பத்தி செய்கிறது என்பதை உறுதி செய்வீர்கள்.

## விருப்பம்செயல் 1: F5 ஐ நுனுக்கவும் - முகவரியInspector உடன் பிழைத்திருத்தம் (சிபாரசு செய்யப்படுகிறது)

### பிழைத்திருத்தியை துவக்குங்கள்

1. **executive-summary-agent/** கோப்புறையை நேரடி முறையில் VS Code (`File → Open Folder`) இல் திறக்கவும்.
2. **Run and Debug** குழுவை திறக்கவும் (`Ctrl+Shift+D`).
3. பட்டியில் இருந்து **Debug Local Agent HTTP Server** ஐ தேர்ந்தெடுக்கவும்.
4. **F5** ஐ நுனுக்கவும் (அல்லது ▶ பிழைத்திருத்தத்தை துவக்கவும் கிளிக் செய்யவும்).

> ⚠️ **முக்கியம்: உங்கள் Python Interpreter ஐ தேர்ந்தெடுக்கவும்**
> நீங்கள் "ModuleNotFoundError" ஐப் பெறினால் அல்லது பிழைத்திருத்தி துவங்காமல் இருந்தால், உங்கள் கட்டமைப்புப் பயன்பாட்டை பயன்படுத்த VS Code ஐ அறிவிக்க வேண்டும்:
  > 1. அழுத்தவும் `Ctrl+Shift+P` $\rightarrow$ தட்டச்சு செய்யவும் **Python: Select Interpreter**.
  > 2. உங்கள் திட்டத்தின் `.venv` அடைவை உள்ளாகி இருக்கும் interpreter-ஐ தேர்ந்தெடுக்கவும் (எடுத்துக்காட்டு, வின்டோஸில் `.\.venv\Scripts\python.exe`).
  > 3. டிபக் அமர்வை மீண்டும் துவக்கவும்.
> நீங்கள் இன்னும் பிழைகள் பெறுகிறீர்களானால், உங்கள் கோப்பு `tasks.json`-ஐ கீழ்காணும் விதமாக கைமுறையாக புதுப்பிக்கவும்:
  > 1. `.vscode/tasks.json` கோப்பிற்குச் செல்லவும்
  > 2. `Run Agent HTTP Server` எனும் குறிச்சொல்லுடன் உள்ள பணிக்கு செல்லவும்
  > 3. கட்டளை மதிப்பை கீழ்காணும் விதமாக புதுப்பிக்கவும்:
  >    - **Windows:** `"value": "${workspaceFolder}/.venv/Scripts/python.exe",`
  >    - **macOS/Linux:** `"value": "${workspaceFolder}/.venv/bin/python",`

### என்ன நடக்கிறது

1. HTTP சேவையகம் `http://localhost:8088/responses`ல் துவங்கும்.
2. **Agent Inspector** பலகை தானாக திறக்கப்படும் - சோதனைக்கான காட்சிப் பேசுதல் இடைமுகம்.
3. `main.py`ல் இடையீட்டு புள்ளிகள் செயல்படுத்தப்படுகின்றன.

டெர்மினல்-ஐ கவனியுங்கள்:
```
Starting executive summary hosted agent
Executive agent server running on http://localhost:8088
```

> **Agent Inspector திறக்கப்படவில்லையெனில்:** அழுத்தவும் `Ctrl+Shift+P` → **Foundry Toolkit: Open Agent Inspector**.

![Agent Inspector connected to localhost:8088 showing an Executive Summary response](../../../../../translated_images/ta/05-agent-inspector-response.9d761cc9bd77818b.webp)

> *திரைபடம் இருக்கலாம் பழைய 'AI TOOLKIT' வரையறுப்பை காட்டும், முன்னாள் இதயவியல் பதிப்பிலிருந்து.*

## விருப்பம் 2: டெர்மினல் வழியாக சோதனை (மாற்று வழி)

ஒரே டெர்மினலில் முகவரியைக் துவக்கவும், மற்றொன்றில் கோரிக்கைகள் அனுப்பவும்:

```bash
# Terminal 1: Start agent
cd executive-summary-agent/
source .venv/bin/activate
python main.py
```

```bash
# Terminal 2: Send test (curl)
curl -sS -X POST http://localhost:8088/responses \
  -H "Content-Type: application/json" \
  -d '{"input": "The API latency increased due to thread pool exhaustion caused by sync calls in v3.2.", "stream": false}'
```

## தருண சோதனைகள்: சந்தோஷமான பாதை செயல்பாட்டு சரிபார்ப்பு

கீழ்காணும் **மூன்று** தருணங்களையும் இயக்கவும். இவை உங்கள் முகவர் சரியான, கட்டமைக்கப்பட்ட வெளியீடு வழங்குகின்றதா என்பதை உண்மையான உள்ளீடுகளுக்கு சரிபார்க்கின்றன.

![VS Code Run and Debug panel showing Agent Inspector running with executive summary response](../../../../../translated_images/ta/04-local-testing.0c9b1b37b14b0b25.webp)

### தருணம் 1: ஐடி சம்பவம் - API தாமத உயர்வு

**உள்ளீடு:**
```
The API latency increased from 200ms to 2s after deploying v3.2.
Root cause: thread pool starvation from synchronous calls in /orders.
Rolled back at 10:14.
```

**எதிர்பார்க்கப்படும் நடத்தை:**
- ✅ "Executive Summary" அமைப்பை பின்பற்றுகிறது (என்ன நடந்தது / வணிக பாதிப்பு / அடுத்த படி)
- ✅ தொழில்நுட்ப சொற்கள் இல்லை ("thread pool" இல்லை, "/orders" இல்லை, "v3.2" இல்லை)
- ✅ தெளிவாக வணிக பாதிப்பை கூறுகிறது (எ.கா., பயனர்கள் தாமதங்களை சந்தித்தனர்)
- ✅ அடுத்த படி உள்ளடக்குகிறது (எ.கா., சரி செய்தல், கண்காணிப்பு நடவடிக்கை)

---

### தருணம் 2: தரவுத் தொற்று - ETL தோல்வி

**உள்ளீடு:**
```
The nightly ETL job failed because the upstream schema changed. APAC dashboards show missing data.
```

**எதிர்பார்க்கப்படும் நடத்தை:**
- ✅ தரவு புதுப்பிப்பு தோல்வியை எளிய மொழியில் சுருக்குகிறது
- ✅ APAC டாஷ்போர்டின் பாதிப்பை குறிப்பிடுகிறது
- ✅ முறையீடு அடுத்த படியை உள்ளடக்கியது
- ✅ "ETL", "schema", அல்லது பிற தொழில்நுட்ப சொற்களை குறிப்பிடவில்லை

---

### தருணம் 3: பாதுகாப்பு - வெளிப்படையான அங்கீகாரம்

**உள்ளீடு:**
```
Static analysis flagged a hardcoded secret in the repository.
The secret may have been exposed in commit history.
```

**எதிர்பார்க்கப்படும் நடத்தை:**
- ✅ அங்கீகாரம்/பாதுகாப்பு பிரச்சனையை நிர்வாகி புரிந்துகொள்ளக்கூடிய மொழியில் விவரிக்கிறது
- ✅ சாத்தியமான ஆபத்தை குறிப்பிடுகிறது (அனுமதியின்றி அணுகல்)
- ✅ முறையீட்டு நடவடிக்கையை தெரிவிக்கிறது (அங்கீகாரம் மறு சுழற்சி, ஆகியவை)
- ✅ "static analysis", "commit history", அல்லது "hardcoded" போன்ற சொற்களை சேர்க்கவில்லை
