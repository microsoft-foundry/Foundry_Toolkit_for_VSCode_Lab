# מודול 7 - אימות ב-Playground

⏱️ ~10 דקות

במודול זה, תבדקו את זרימת העבודה בריבוי סוכנים שהפרסתם ב-VS Code ובפורטל Foundry, ואישרתם שהסוכן מתנהג באותו האופן כמו בבדיקות מקומיות.

---

## מדוע לבדוק שוב לאחר הפריסה?

הסביבה המאוחסנת שונה מהמקומית בכמה דרכים חשובות:

| | מקומי | מאוחסן |
|--|-------|--------|
| **זהות** | הכניסה האישית שלך (`DefaultAzureCredential`) | זהות Entra ייעודית לכל סוכן (מונגשת אוטומטית בזמן הפריסה) |
| **נקודת קצה** | `http://localhost:8088/responses` | URL מנוהל על ידי שירות Foundry Agent |
| **רשת** | המחשב שלך → Azure OpenAI + MCP | שלד Azure (השיהוי נמוך יותר) |

משתנה סביבה שהוגדר לא נכון, בעיית RBAC, או קריאת MCP החוצה שנחסמה יופיעו כאן ראשונים.

---

## אפשרות א: בדיקה ב-VS Code Playground (מומלץ ראשון)

### שלב 1: נווט לסוכן המאוחסן שלך

1. לחץ על סמל **Foundry Toolkit** בסרגל הפעילות.
2. פתח את הפרויקט שלך → **Hosted Agents (Preview)** → מצא את הסוכן שלך.

![Foundry Toolkit sidebar showing Hosted Agents (Preview) with resume-job-fit-evaluator and its deployed versions](../../../../../translated_images/he/06-foundry-sidebar-agent-status.a45994bfb5c21284.webp)

### שלב 2: בחר גרסה

1. לחץ על הסוכן כדי להרחיב את הגרסאות שלו.
2. לחץ על `v1` → אמת שהסטטוס **פעיל** (הסרגל הצדדי עשוי להציג "Running" או "Started" - שניהם מציינים את אותו מצב מוכן).

### שלב 3: פתח את ה-Playground

1. לחץ על **Playground** (או לחיצה ימנית על הגרסה → **Open in Playground**).
2. נפתח חלון שיחה בטאב של VS Code.

### שלב 4: הרץ את בדיקות העשן שלך

השתמש באותן 3 בדיקות מ-[מודול 5](05-test-locally.md). הקלד כל הודעה בתיבת הקלט ב-Playground ולחץ על **Send** (או **Enter**).

#### בדיקה 1 - קורות חיים מלאים + תיאור תפקיד (זרם סטנדרטי)

הדבק את הפקודה של קורות החיים המלאים + תיאור תפקיד ממודול 5, בדיקה 1 (Jane Doe + מהנדס ענן בכיר ב-Contoso Ltd).

**צפוי:**
- ניקוד התאמה עם פירוט מתמטי (בסולם של 100 נקודות)
- סעיף כישורים מתאימים
- סעיף כישורים חסרים
- **כרטיס פער אחד לכל מיומנות חסרה** עם URLs של Microsoft Learn
- מפת למידה עם ציר זמן

#### בדיקה 2 - בדיקה קצרה מהירה (קלט מינימלי)

```
RESUME: 3 years Python developer, knows Django and PostgreSQL, no cloud experience.

JOB: Cloud DevOps Engineer requiring AWS, Kubernetes, Terraform, CI/CD. 5 years needed.
```

**צפוי:**
- ניקוד התאמה נמוך יותר (< 40)
- הערכה כנה עם מסלול למידה בשלבים
- מספר כרטיסי פער (AWS, Kubernetes, Terraform, CI/CD, חסר ניסיון)

#### בדיקה 3 - מועמד עם התאמה גבוהה

```
RESUME:
10 years Azure Cloud Architect. AZ-305 certified. Expert in AKS, Terraform, Azure DevOps, 
Azure Functions, Helm, Prometheus, Grafana, Python, Go. Led platform team of 8.

JOB:
Senior Cloud Engineer. Required: AKS, Terraform, Azure DevOps, Python. Preferred: Helm, Go.
5+ years experience. AZ-305 preferred.
```

**צפוי:**
- ניקוד התאמה גבוה (≥ 80)
- התמקדות במוכנות לראיון וברקוד
- מעט או ללא כרטיסי פער
- ציר זמן קצר המתמקד בהכנה

### שלב 5: השווה לתוצאות המקומיות

פתח את ההערות או טאב הדפדפן ממודול 5 בו שמרת את התגובות המקומיות. עבור כל בדיקה:

- האם לתגובה אותה **מבנה** (ניקוד התאמה, כרטיסי פער, מפת דרכים)?
- האם היא עוקבת אחר **אותו קריטריון ניקוד** (פירוט בסולם של 100 נקודות)?
- האם קיימים עדיין **קישורי Microsoft Learn** בכרטיסי הפער?
- האם יש **כרטיס פער אחד לכל מיומנות חסרה** (לא מקוצר)?

> **הבדלים קלים בניסוח הם נורמליים** - המודל אינו דטרמיניסטי. התרכז במבנה, עקביות ניקוד, ושימוש בכלי MCP.

## אפשרות ב: בדיקה בפורטל Foundry

ה-[Foundry Portal](https://ai.azure.com) מספק סביבה מבוססת רשת שנוחה לשיתוף עם חברי צוות או בעלי עניין.

### שלב 1: פתח את פורטל Foundry

1. פתח את הדפדפן ונווט ל-[https://ai.azure.com](https://ai.azure.com).
2. התחבר עם אותו חשבון Azure שבו השתמשת במהלך הסדנה.

### שלב 2: נווט לפרויקט שלך

1. בדף הבית, חפש **פרויקטים אחרונים** בסרגל הצד השמאלי.
2. לחץ על שם הפרויקט שלך (למשל, `workshop-agents`).
3. אם אינך רואה אותו, לחץ על **כל הפרויקטים** וחפש אותו.

### שלב 3: מצא את הסוכן שהפרסת

1. בניווט השמאלי של הפרויקט, לחץ על **Build** → **Agents** (או חפש את הסעיף **Agents**).
2. אמור להופיע רשימת סוכנים. מצא את הסוכן שהפרסת (למשל, `resume-job-fit-evaluator`).
3. לחץ על שם הסוכן כדי לפתוח את דף הפרטים שלו.

### שלב 4: פתח את ה-Playground

1. בדף פרטי הסוכן, הסתכל על סרגל הכלים העליון.
2. לחץ על **Open in playground** (או **Try in playground**).
3. ממשק שיחה נפתח.

### שלב 5: הרץ את אותן בדיקות עשן

חזור על כל 3 הבדיקות מהסעיף VS Code Playground למעלה. השווה כל תגובה עם התוצאות המקומיות (מודול 5) ועם תוצאות ה-Playground ב-VS Code (אפשרות א לעיל).

## אימות ספציפי לריבוי סוכנים

מעבר לנכונות בסיסית, אמת את ההתנהגויות הספציפיות לריבוי סוכנים הבאים:

### ביצוע כלים של MCP

| בדיקה | איך לאמת | תנאי מעבר |
|-------|---------------|----------------|
| קריאות MCP מצליחות | כרטיסי הפער מכילים URLs של `learn.microsoft.com` | URLs אמיתיים, לא הודעות גיבוי |
| קריאות MCP מרובות | כל פער בעדיפות גבוהה/בינונית מכיל משאבים | לא רק כרטיס הפער הראשון |
| הפעלת גיבוי MCP | אם חסרים URLs, בדוק טקסט גיבוי | הסוכן עדיין מייצר כרטיסי פער (עם או בלי URLs) |

### תיאום הסוכנים

| בדיקה | איך לאמת | תנאי מעבר |
|-------|---------------|----------------|
| כל 4 הסוכנים רצו | הפלט מכיל ניקוד התאמה וגם כרטיסי פער | הניקוד מגיע מ-MatchingAgent, הכרטיסים מ-GapAnalyzer |
| ביצוע סדרתי | זמן תגובה סביר (< 2 דקות) | אם יותר מ-3 דקות, בדוק שגיאות בלוג המסוף |
| שלמות זרימת הנתונים | כרטיסי הפער מתייחסים לכישורים מהדוח</br>התאמה | אין כישורים מדומיינים שאינם מוצגים בתיאור תפקיד |

## קריטריון אימות

השתמש בקריטריון זה להערכת התנהגות זרימת העבודה בריבוי סוכנים באירוח:

| # | קריטריון | תנאי מעבר | עבר? |
|---|----------|---------------|-------|
| 1 | **נכונות פונקציונלית** | הסוכן מגיב לקורות חיים + JD עם ניקוד התאמה וניתוח פער | |
| 2 | **עקביות ניקוד** | ניקוד התאמה משתמש בסולם 100 נקודות עם פירוט מתמטי | |
| 3 | **שלמות כרטיסי פער** | כרטיס אחד לכל מיומנות חסרה (לא מקוצר או משולב) | |
| 4 | **אינטגרציה עם כלי MCP** | כרטיסי הפער כוללים URLs אמיתיים של Microsoft Learn | |
| 5 | **עקביות מבנית** | מבנה הפלט זהה בין ריצות מקומיות למאוחסנות | |
| 6 | **זמן תגובה** | הסוכן המאוחסן מגיב בתוך 2 דקות להערכה מלאה | |
| 7 | **ללא שגיאות** | אין שגיאות HTTP 500, תזמון יתר או תגובות ריקות | |

> "מעבר" משמעותו שכל 7 הקריטריונים מתקיימים בכל 3 בדיקות העשן לפחות באחד מ-Playground (VS Code או פורטל).

## פתרון בעיות ב-Playground

| תסמין | סיבה סבירה | תיקון |
|---------|-------------|-----|
| ה-Playground לא נטען | מכולה לא במצב `active` | חזור ל-[מודול 6](06-deploy-to-foundry.md), אמת את מצב הפריסה. המתן אם ב`creating` |
| הסוכן מחזיר תגובה ריקה | שם פריסת המודל שגוי | בדוק ב-`agent.yaml` → `environment_variables` → שהערך של `AZURE_AI_MODEL_DEPLOYMENT_NAME` מתאים למודל שהפרסת |
| הסוכן מחזיר הודעת שגיאה | חסר הרשאת [RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) | הקצה **[Foundry User](https://aka.ms/foundry-ext-project-role)** (קודם Azure AI User) בהיקף הפרויקט |
| אין URLs של Microsoft Learn בכרטיסי הפער | קריאות MCP החוצה נחסמו או שרת MCP לא זמין | בדוק אם המכולה יכולה להגיע לכתובת `learn.microsoft.com`. ראה [מודול 8](08-troubleshooting.md) |
| רק כרטיס פער אחד (מקוצר) | חסר סעיף "CRITICAL" בהוראות GapAnalyzer | סקור את [מודול 3, שלב 2.4](03-configure-agents.md) |
| ניקוד התאמה שונה באופן קיצוני מהמקומי | פריסת מודל או הוראות שונות | השווה משתני סביבה ב-`agent.yaml` עם `.env` מקומי. פרוס מחדש במידת הצורך |
| "סוכן לא נמצא" בפורטל | הפריסה עדיין מתפשטת או נכשלה | המתן 2 דקות, רענן. אם עדיין חסר, פרוס מחדש מ-[מודול 6](06-deploy-to-foundry.md) |
