# โมดูล 8 - การแก้ไขปัญหา

โมดูลนี้เป็นคู่มืออ้างอิงสำหรับปัญหาทั่วไป ควรบุ๊กมาร์กไว้และกลับมาเมื่อเกิดข้อผิดพลาด

---

## 1. ข้อผิดพลาดเกี่ยวกับสิทธิ์

### 1.1 `agents/write` ปฏิเสธสิทธิ์

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**สาเหตุหลัก:** ขาดบทบาท `Azure AI User` ในระดับ **โปรเจกต์** นี่คือข้อผิดพลาดอันดับ 1 ของเวิร์กช็อป

**การแก้ไข:**
1. เปิด [portal.azure.com](https://portal.azure.com).
2. ค้นหาชื่อ **โปรเจกต์** Foundry ของคุณ → คลิกผลลัพธ์ประเภท **"Microsoft Foundry project"** (ไม่ใช่บัญชีหลัก).
3. **การควบคุมการเข้าถึง (IAM)** → **+ เพิ่ม** → **เพิ่มการกำหนดบทบาท**.
4. บทบาท: **Azure AI User** → ต่อไป.
5. สมาชิก: เลือกตัวคุณเอง → ทบทวน + กำหนด → ทบทวน + กำหนด.
6. **รอ 1–2 นาที** → ลองอีกครั้ง.

> **ทำไม Owner/Contributor ถึงไม่เพียงพอ:** บทบาทเหล่านี้ให้สิทธิ์ *การจัดการ* เท่านั้น การดำเนินงานของเอเย่นต์ต้องใช้ `agents/write` *การดำเนินการกับข้อมูล* ซึ่งมีเฉพาะใน `Azure AI User`, `Azure AI Developer` หรือ `Azure AI Owner` ดู [เอกสาร RBAC ของ Foundry](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` ระหว่างการจัดเตรียม

**แก้ไข:** ขอให้ผู้ดูแลของคุณกำหนด **Contributor** บนกลุ่มทรัพยากร หรือให้พวกเขาสร้างโปรเจกต์ให้คุณและมอบสิทธิ์ **Azure AI User** ให้คุณบนโปรเจกต์นั้น.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Wait until: "Registered"
```

## 2. ข้อผิดพลาด Docker

> Docker เป็น **ตัวเลือก** ข้อผิดพลาดเหล่านี้ใช้ก็ต่อเมื่อมีการติดตั้ง Docker Desktop และส่วนขยายพยายามสร้างแบบท้องถิ่น.

### 2.1 Docker daemon ไม่ทำงาน

**แก้ไข:** เริ่ม Docker Desktop → รอสถานะ "กำลังทำงาน" → ตรวจสอบด้วย `docker info` → ลองใหม่อีกครั้ง.

### 2.2 การสร้างล้มเหลวเนื่องจากข้อผิดพลาดของการพึ่งพิง

**แก้ไข:** ตรวจสอบการสะกด `requirements.txt` ทดสอบในเครื่องก่อน: `pip install -r requirements.txt`.

### 2.3 แพลตฟอร์มไม่ตรงกัน (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. ข้อผิดพลาดการตรวจสอบสิทธิ์

### 3.1 `DefaultAzureCredential` ล้มเหลว

**แก้ไข (ลองตามลำดับ):**
1. `az login` (ยืนยันตัวตนใหม่)
2. `az account set --subscription "<id>"` (สมัครสมาชิกถูกต้อง)
3. VS Code → บัญชี → ออกจากระบบ → เข้าสู่ระบบอีกครั้ง
4. ตรวจสอบ: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 โทเคนใช้งานได้ในเครื่องแต่ไม่ใช่ในโฮสต์

**คาดหวัง:** เอเย่นต์โฮสต์ใช้ระบบจัดการตัวตน ไม่ใช่ข้อมูลรับรองของคุณ หากเอเย่นต์โฮสต์มีข้อผิดพลาดการตรวจสอบสิทธิ์:
- ตรวจสอบว่า `AZURE_AI_MODEL_DEPLOYMENT_NAME` ใน `agent.yaml` ชี้ไปยังชื่อการปรับใช้โมเดลของคุณ (`FOUNDRY_PROJECT_ENDPOINT` ถูกเพิ่มโดย Foundry ในเวลารัน - อย่าประกาศใน `agent.yaml`)
- ตรวจสอบว่าตัวตนที่จัดการของโปรเจกต์มีสิทธิ์เข้าถึงโมเดล

---

## 4. ข้อผิดพลาดโมเดล

### 4.1 ไม่พบการปรับใช้โมเดล

**แก้ไข:** ชื่อ **ต้องตรงตัวพิมพ์ใหญ่/เล็ก** เปรียบเทียบ `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` กับชื่อที่แน่นอนในแถบด้านข้างของ Foundry → โมเดล.

### 4.2 ผลลัพธ์โมเดลไม่คาดคิด

**แก้ไข:** ตรวจสอบ `AGENT_INSTRUCTIONS` ใน `main.py` (ไม่ได้ถูกตัดทอนไม่ใช่?). ลองใช้โมเดลอื่น (`gpt-4.1` เทียบกับ `gpt-4.1-mini`).

## 5. ข้อผิดพลาดการปรับใช้

### 5.1 การดึง ACR ไม่มีสิทธิ์

**แก้ไข:** ไปที่ Azure Portal → Container Registry → การควบคุมการเข้าถึง (IAM) → เพิ่มบทบาท **AcrPull** ให้ตัวตนที่จัดการของโปรเจกต์ Foundry.

### 5.2 Agent ล้มเหลวในการเริ่มต้น (ค้างที่ "Pending" หรือ "Failed")

ตรวจสอบบันทึกคอนเทนเนอร์ในแถบด้านข้าง สาเหตุทั่วไป:

| ข้อความบันทึก | แก้ไข |
|-------------|-----|
| `ModuleNotFoundError` | เพิ่มแพ็กเกจที่ขาดใน `requirements.txt`, ปรับใช้ใหม่ |
| `ValueError: Missing required environment variables` | ยืนยันว่า `AZURE_AI_MODEL_DEPLOYMENT_NAME` ถูกประกาศใน `agent.yaml` ภายใต้ `environment_variables` และมีค่า แล้วปรับใช้ใหม่. `FOUNDRY_PROJECT_ENDPOINT` ถูกเพิ่มโดย Foundry ในเวลารัน |
| `Address already in use` | ตรวจสอบให้มั่นใจว่า มีเพียงหนึ่งกระบวนการที่ผูกพอร์ต 8088 |

### 5.3 การปรับใช้หมดเวลา

**แก้ไข:** ตรวจสอบการเชื่อมต่ออินเทอร์เน็ต การปรับใช้ครั้งแรกจะส่งข้อมูล >100MB อยู่หลังพร็อกซีไหม? กำหนดค่าการตั้งค่าพร็อกซีของ Docker Desktop.

## 6. เส้นทาง B - Foundry Local

### 6.1 Foundry Local เริ่มทำงานไม่ได้

| ปัญหา | แก้ไข |
|-------|-----|
| `foundry: command not found` | ติดตั้งใหม่: `winget install Microsoft.FoundryLocal` |
| ทรัพยากรไม่เพียงพอ | Foundry Local ต้องการ RAM ว่างประมาณ 4GB ปิดแอปอื่น ๆ |
| ดาวน์โหลดโมเดลล้มเหลว | ตรวจสอบพื้นที่ดิสก์ (โมเดลมีขนาด 2–8 GB) ลองใหม่: `foundry local models pull <name>` |

### 6.2 ข้อผิดพลาดโมเดล Foundry Local

| ปัญหา | แก้ไข |
|-------|-----|
| การตอบสนองช้า | คาดไว้ - โมเดลท้องถิ่นทำงานบน CPU เว้นแต่จะมี GPU กรุณารอ |
| ผลลัพธ์คุณภาพต่ำ | ลองโมเดลที่ใหญ่ขึ้นถ้าอุปกรณ์ของคุณรองรับ `phi-4-mini` เป็นสมดุลที่ดี |
| การเชื่อมต่อถูกปฏิเสธ | ตรวจสอบว่า Foundry Local กำลังทำงาน: `foundry local status`. รีสตาร์ทถ้าจำเป็น |

## 7. อ้างอิงด่วน: บทบาท RBAC

| บทบาท | ขอบเขต | สิทธิ์ที่ให้ |
|------|-------|--------|
| **Azure AI User** | โปรเจกต์ | การดำเนินการกับข้อมูล: `agents/write`, `agents/read` |
| **Azure AI Developer** | โปรเจกต์/บัญชี | การดำเนินการกับข้อมูล + การสร้างโปรเจกต์ |
| **Azure AI Owner** | บัญชี | เข้าถึงเต็มที่ + การจัดการบทบาท |
| **Contributor** | การสมัครสมาชิก/กลุ่มทรัพยากร | การดำเนินการจัดการเท่านั้น (**ไม่มี** การดำเนินการกับข้อมูล) |
| **Owner** | การสมัครสมาชิก/กลุ่มทรัพยากร | การจัดการ + การกำหนดบทบาท (**ไม่มี** การดำเนินการกับข้อมูล) |
