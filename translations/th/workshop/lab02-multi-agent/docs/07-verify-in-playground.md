# Module 7 - ตรวจสอบใน Playground

⏱️ ~10 นาที

ในโมดูลนี้ คุณจะทดสอบเวิร์กโฟลว์หลายเอเจนต์ที่คุณปรับใช้ใน VS Code และ Foundry Portal โดยยืนยันว่าเอเจนต์ทำงานเหมือนกับการทดสอบในเครื่อง

---

## ทำไมต้องทดสอบอีกครั้งหลังการปรับใช้?

สภาพแวดล้อมที่โฮสต์แตกต่างจากในเครื่องในบางประการสำคัญ:

| | ในเครื่อง | โฮสต์ |
|--|-------|--------|
| **ตัวตน** | การเข้าสู่ระบบส่วนตัวของคุณ (`DefaultAzureCredential`) | ตัวตน Entra เฉพาะต่อเอเจนต์ (จัดเตรียมโดยอัตโนมัติเมื่อปรับใช้) |
| **Endpoint** | `http://localhost:8088/responses` | URL บริการ Foundry Agent ที่จัดการโดย Foundry |
| **เครือข่าย** | เครื่องของคุณ → Azure OpenAI + MCP | โครงข่ายหลักของ Azure (ความหน่วงต่ำกว่า) |

ตัวแปรสภาพแวดล้อมที่ตั้งค่าไม่ถูกต้อง, ปัญหา RBAC หรือการบล็อกการเรียก MCP ขาออกจะปรากฏที่นี่ก่อนเป็นอันดับแรก

---

## ตัวเลือก A: ทดสอบใน VS Code Playground (แนะนำให้ทำก่อน)

### ขั้นตอนที่ 1: ไปยังเอเจนต์ที่โฮสต์ของคุณ

1. คลิกที่ไอคอน **Foundry Toolkit** ใน Activity Bar
2. ขยายโปรเจกต์ของคุณ → **Hosted Agents (Preview)** → ค้นหาเอเจนต์ของคุณ

![Foundry Toolkit sidebar showing Hosted Agents (Preview) with resume-job-fit-evaluator and its deployed versions](../../../../../translated_images/th/06-foundry-sidebar-agent-status.a45994bfb5c21284.webp)

### ขั้นตอนที่ 2: เลือกเวอร์ชัน

1. คลิกที่เอเจนต์เพื่อขยายเวอร์ชันของมัน
2. คลิกที่ `v1` → ตรวจสอบสถานะให้เป็น **active** (แถบด้านข้างอาจแสดง "Running" หรือ "Started" - ทั้งสองแสดงสถานะพร้อมใช้งานเดียวกัน)

### ขั้นตอนที่ 3: เปิด Playground

1. คลิก **Playground** (หรือคลิกขวาที่เวอร์ชัน → **Open in Playground**)
2. หน้าต่างแชทจะเปิดในแท็บ VS Code

### ขั้นตอนที่ 4: รันการทดสอบแบบ smoke test ของคุณ

ใช้การทดสอบ 3 รายการเดียวกันจาก [Module 5](05-test-locally.md) พิมพ์ข้อความแต่ละข้อความในกล่องป้อนข้อมูลใน Playground แล้วกด **Send** (หรือ **Enter**)

#### การทดสอบ 1 - เรซูเม่เต็มรูปแบบ + JD (โฟลว์มาตรฐาน)

วางข้อมูลเรซูเม่เต็มรูปแบบ + JD จาก Module 5, การทดสอบ 1 (Jane Doe + Senior Cloud Engineer ที่ Contoso Ltd)

**สิ่งที่คาดหวัง:**
- คะแนนความเหมาะสมพร้อมการคำนวณแตกแบออก (มาตราส่วน 100 คะแนน)
- ส่วนทักษะที่ตรงกัน
- ส่วนทักษะที่ขาดหายไป
- **การ์ดเว้นว่างหนึ่งใบต่อทักษะที่ขาดหายไปแต่ละรายการ** พร้อม URL Microsoft Learn
- แผนการเรียนรู้พร้อมไทม์ไลน์

#### การทดสอบ 2 - การทดสอบสั้นอย่างรวดเร็ว (อินพุตน้อยที่สุด)

```
RESUME: 3 years Python developer, knows Django and PostgreSQL, no cloud experience.

JOB: Cloud DevOps Engineer requiring AWS, Kubernetes, Terraform, CI/CD. 5 years needed.
```

**สิ่งที่คาดหวัง:**
- คะแนนความเหมาะสมน้อยกว่า (< 40)
- การประเมินอย่างตรงไปตรงมาพร้อมเส้นทางการเรียนรู้เป็นลำดับขั้น
- การ์ดช่องว่างหลายใบ (AWS, Kubernetes, Terraform, CI/CD, ช่องว่างในประสบการณ์)

#### การทดสอบ 3 - ผู้สมัครที่เหมาะสมสูง

```
RESUME:
10 years Azure Cloud Architect. AZ-305 certified. Expert in AKS, Terraform, Azure DevOps, 
Azure Functions, Helm, Prometheus, Grafana, Python, Go. Led platform team of 8.

JOB:
Senior Cloud Engineer. Required: AKS, Terraform, Azure DevOps, Python. Preferred: Helm, Go.
5+ years experience. AZ-305 preferred.
```

**สิ่งที่คาดหวัง:**
- คะแนนความเหมาะสูง (≥ 80)
- เน้นการเตรียมตัวสัมภาษณ์และการขัดเกลา
- การ์ดช่องว่างน้อยหรือไม่มีเลย
- ไทม์ไลน์สั้นมุ่งเน้นการเตรียมตัว

### ขั้นตอนที่ 5: เปรียบเทียบกับผลลัพธ์ภายในเครื่อง

เปิดโน้ตหรือแท็บเบราว์เซอร์ของคุณจาก Module 5 ที่คุณบันทึกการตอบกลับในเครื่องไว้ สำหรับแต่ละการทดสอบ:

- การตอบสนองมี **โครงสร้างเดียวกัน** หรือไม่ (คะแนนความเหมาะสม, การ์ดช่องว่าง, แผนที่)
- ใช้ **การให้คะแนนแบบเดียวกัน** หรือไม่ (การแยกวิเคราะห์ 100 คะแนน)
- มี **URL Microsoft Learn** อยู่ในการ์ดช่องว่างหรือไม่?
- มี **การ์ดช่องว่างหนึ่งใบต่อทักษะที่ขาดหายไป** หรือไม่ (ไม่ตัดตอน)

> **ความแตกต่างเล็กน้อยของคำเป็นเรื่องปกติ** - โมเดลไม่ใช่แบบกำหนดผลลัพธ์แน่นอน ให้โฟกัสที่โครงสร้าง ความสม่ำเสมอของการให้คะแนน และการใช้งานเครื่องมือ MCP

## ตัวเลือก B: ทดสอบใน Foundry Portal

[Foundry Portal](https://ai.azure.com) มี Playground แบบเว็บที่เหมาะสำหรับการแชร์กับเพื่อนร่วมทีมหรือผู้มีส่วนได้ส่วนเสีย

### ขั้นตอนที่ 1: เปิด Foundry Portal

1. เปิดเบราว์เซอร์ของคุณและไปที่ [https://ai.azure.com](https://ai.azure.com)
2. ลงชื่อเข้าใช้ด้วยบัญชี Azure เดียวกันที่คุณใช้ตลอดการเวิร์กช็อป

### ขั้นตอนที่ 2: ไปยังโปรเจกต์ของคุณ

1. ที่หน้าแรก มองหา **Recent projects** ที่แถบด้านข้างซ้าย
2. คลิกชื่อโปรเจกต์ของคุณ (เช่น `workshop-agents`)
3. ถ้าไม่เห็น ให้คลิก **All projects** แล้วค้นหา

### ขั้นตอนที่ 3: ค้นหาเอเจนต์ที่ถูกปรับใช้ของคุณ

1. ในเมนูทางซ้ายของโปรเจกต์ คลิก **Build** → **Agents** (หรือมองหาส่วน **Agents**)
2. คุณจะเห็นรายชื่อเอเจนต์ ค้นหาเอเจนต์ที่ปรับใช้ของคุณ (เช่น `resume-job-fit-evaluator`)
3. คลิกชื่อเอเจนต์เพื่อเปิดหน้ารายละเอียด

### ขั้นตอนที่ 4: เปิด Playground

1. ในหน้ารายละเอียดเอเจนต์ ดูที่แถบเครื่องมือด้านบน
2. คลิก **Open in playground** (หรือ **Try in playground**)
3. อินเทอร์เฟซแชทจะเปิดขึ้น

### ขั้นตอนที่ 5: รันการทดสอบแบบ smoke test เดียวกัน

ทำซ้ำทั้ง 3 การทดสอบจากส่วน VS Code Playground ข้างต้น เปรียบเทียบแต่ละคำตอบกับผลลัพธ์ภายในเครื่อง (Module 5) และผลลัพธ์ใน VS Code Playground (ตัวเลือก A ข้างต้น)

## การตรวจสอบเฉพาะสำหรับหลายเอเจนต์

นอกเหนือจากความถูกต้องพื้นฐาน ให้ตรวจสอบพฤติกรรมเฉพาะหลายเอเจนต์ดังนี้:

### การทำงานของเครื่องมือ MCP

| ตรวจสอบ | วิธีตรวจสอบ | เงื่อนไขผ่าน |
|-------|---------------|----------------|
| การเรียก MCP สำเร็จ | การ์ดช่องว่างมี URL `learn.microsoft.com` | URL จริง ไม่ใช่ข้อความสำรอง |
| เรียก MCP หลายครั้ง | แต่ละช่องว่างสำคัญ/ปานกลางมีทรัพยากร | ไม่ใช่แค่การ์ดช่องว่างใบแรก |
| การสำรองของ MCP ทำงาน | หากขาด URL ให้ตรวจสอบข้อความสำรอง | เอเจนต์ยังสร้างการ์ดช่องว่างได้ (มีหรือไม่มี URL) |

### การประสานงานเอเจนต์

| ตรวจสอบ | วิธีตรวจสอบ | เงื่อนไขผ่าน |
|-------|---------------|----------------|
| ทั้ง 4 เอเจนต์ทำงาน | ผลลัพธ์มีคะแนนความเหมาะ AND การ์ดช่องว่าง | คะแนนมาจาก MatchingAgent การ์ดมาจาก GapAnalyzer |
| การทำงานแบบเรียงลำดับ | เวลาตอบสนองเหมาะสม (< 2 นาที) | ถ้า > 3 นาที ตรวจสอบข้อผิดพลาดในบันทึกเทอร์มินัล |
| ความสมบูรณ์ของข้อมูล | การ์ดช่องว่างอ้างอิงทักษะจากรายงาน Matching | ไม่มีทักษะคิดขึ้นเองที่ไม่อยู่ใน JD |

## รูบริกการตรวจสอบ

ใช้รูบริกนี้ประเมินพฤติกรรมที่โฮสต์ของเวิร์กโฟลว์หลายเอเจนต์ของคุณ:

| # | เกณฑ์ | เงื่อนไขผ่าน | ผ่าน? |
|---|----------|---------------|-------|
| 1 | **ความถูกต้องในการทำงาน** | เอเจนต์ตอบสนองต่อเรซูเม่ + JD ด้วยคะแนนความเหมาะและการวิเคราะห์ช่องว่าง | |
| 2 | **ความสม่ำเสมอของการให้คะแนน** | คะแนนความเหมาะใช้มาตราส่วน 100 คะแนนพร้อมคำนวณแตกแบ | |
| 3 | **ความสมบูรณ์ของการ์ดช่องว่าง** | การ์ดหนึ่งใบต่อทักษะที่ขาด (ไม่ตัดหรือรวมกัน) | |
| 4 | **การรวมเครื่องมือ MCP** | การ์ดช่องว่างรวม URL Microsoft Learn ที่แท้จริง | |
| 5 | **ความสม่ำเสมอของโครงสร้าง** | โครงสร้างผลลัพธ์เหมือนกันระหว่างรันในเครื่องกับรันโฮสต์ | |
| 6 | **เวลาตอบสนอง** | เอเจนต์โฮสต์ตอบใน 2 นาทีสำหรับการประเมินเต็มรูปแบบ | |
| 7 | **ไม่มีข้อผิดพลาด** | ไม่มีข้อผิดพลาด HTTP 500, หมดเวลา, หรือผลลัพธ์ว่าง | |

> "ผ่าน" หมายความว่าเกณฑ์ทั้ง 7 ถูกต้องครบถ้วนสำหรับทุก 3 การทดสอบ smoke test ใน playground อย่างน้อยหนึ่งแห่ง (VS Code หรือ Portal)

## การแก้ไขปัญหา playground

| อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้ไข |
|---------|-------------|-----|
| โหลด Playground ไม่ได้ | คอนเทนเนอร์ไม่อยู่ในสถานะ `active` | กลับไปที่ [Module 6](06-deploy-to-foundry.md), ตรวจสอบสถานะการปรับใช้ รอถ้าเป็น `creating` |
| เอเจนต์ส่งคืนคำตอบว่าง | ชื่อการปรับใช้โมเดลไม่ตรงกัน | ตรวจสอบ `agent.yaml` → `environment_variables` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` ให้ตรงกับโมเดลที่ปรับใช้ |
| เอเจนต์ส่งข้อความข้อผิดพลาด | ขาดสิทธิ์ [RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) | กำหนดสิทธิ์ **[Foundry User](https://aka.ms/foundry-ext-project-role)** (เดิมคือ Azure AI User) ในระดับโปรเจกต์ |
| ไม่มี URL Microsoft Learn ในการ์ดช่องว่าง | การเรียก MCP ขาออกถูกบล็อก หรือเซิร์ฟเวอร์ MCP ไม่พร้อมใช้งาน | ตรวจสอบว่าคอนเทนเนอร์เข้าถึง `learn.microsoft.com` ได้หรือไม่ ดู [Module 8](08-troubleshooting.md) |
| มีการ์ดช่องว่างเพียงใบเดียว (ถูกตัด) | คำสั่ง GapAnalyzer ขาดบล็อก "CRITICAL" | ทบทวน [Module 3, Step 2.4](03-configure-agents.md) |
| คะแนนความเหมาะแตกต่างอย่างมากจากในเครื่อง | โมเดลหรือคำสั่งต่างกันที่ปรับใช้ | เปรียบเทียบตัวแปร env ใน `agent.yaml` กับ `.env` ในเครื่อง ปรับใช้ใหม่ถ้าจำเป็น |
| "Agent not found" ใน Portal | การปรับใช้อยู่นานหรือไม่สำเร็จ | รอ 2 นาที รีเฟรช หากยังไม่เจอให้ปรับใช้ใหม่จาก [Module 6](06-deploy-to-foundry.md) |

### จุดตรวจสอบ

- [ ] ทดสอบเอเจนต์ใน VS Code Playground - ผ่านทุก 3 การทดสอบ smoke test
- [ ] ทดสอบเอเจนต์ใน [Foundry Portal](https://ai.azure.com) Playground - ผ่านทุก 3 การทดสอบ smoke test
- [ ] การตอบสนองมีโครงสร้างสอดคล้องกับการทดสอบในเครื่อง (คะแนนความเหมาะ, การ์ดช่องว่าง, แผนที่)
- [ ] URL Microsoft Learn ปรากฏในการ์ดช่องว่าง (เครื่องมือ MCP ทำงานในสภาพแวดล้อมโฮสต์)
- [ ] มีการ์ดช่องว่างหนึ่งใบต่อทักษะที่ขาด (ไม่ถูกตัด)
- [ ] ไม่มีข้อผิดพลาดหรือหมดเวลาในระหว่างการทดสอบ
- [ ] ทำแบบประเมินรูบริกเสร็จสมบูรณ์ (เกณฑ์ครบทั้ง 7 ผ่าน)
