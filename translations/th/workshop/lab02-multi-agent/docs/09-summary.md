# โมดูล 9 - สรุป & ขั้นตอนถัดไป

⏱️ ~5 นาที

**ยินดีด้วย!** คุณได้สร้าง ทดสอบ และ (ถ้าอยู่ในเส้นทาง A) ปล่อยใช้งานเวิร์กโฟลว์หลายตัวแทนโดยใช้ Microsoft Foundry และ Foundry Toolkit สำหรับ VS Code

---

## สิ่งที่คุณสร้างขึ้น

**Resume → Job Fit Evaluator** - เวิร์กโฟลว์หลายตัวแทนที่โฮสต์ซึ่ง:
- รับเรซูเม่ + คำอธิบายงานผ่าน HTTP (`POST /responses`)
- รันตัวแทนเฉพาะทางสี่ตัวในสายงานตามลำดับ - แต่ละตัวแทนจะส่งต่อข้อมูลที่ผู้สืบทอดต้องการ
- ส่งคืนคะแนนความเหมาะสม (0–100 พร้อมรายละเอียด), รายการช่องว่างทักษะและใบรับรอง, และแผนการเรียนรู้ส่วนตัวพร้อมลิงก์ Microsoft Learn จริงสำหรับแต่ละช่องว่าง
- เรียกใช้ Microsoft Learn MCP server (`https://learn.microsoft.com/api/mcp`) เพื่อดึงทรัพยากรการเรียนรู้ทางการสำหรับแต่ละช่องว่างทักษะที่ระบุ
- รันในฐานะตัวแทนโฮสต์คอนเทนเนอร์เดียวใน Microsoft Foundry Agent Service

## แนวคิดสำคัญที่ได้เรียนรู้

| แนวคิด | สิ่งที่คุณฝึกฝน |
|---------|-------------------|
| **การประสานงานหลายตัวแทน** | `WorkflowBuilder` สายงานตามลำดับพร้อม `add_edge()` |
| **ความเชี่ยวชาญของตัวแทน** | ตัวแทนที่มุ่งเน้นสี่ตัวทำงานได้ดีกว่าตัวแทนทั่วไปหนึ่งตัว |
| **รูปแบบ Content Router** | ResumeParser ทำงานเป็นเราเตอร์ - มันเก็บข้อความ JD ไว้ในส่วน `[JOB DESCRIPTION PASS-THROUGH]` เพื่อให้ตัวแทนที่อยู่ข้างล่างสามารถเข้าถึงได้ (จำเป็นเพราะ `context_mode="last_agent"` หมายความว่าเฉพาะ `start_executor` เท่านั้นที่เห็นข้อความผู้ใช้ดิบ) |
| **รูปแบบ Content Relay** | JD Agent ส่งต่อ `[PARSED RESUME PASS-THROUGH]` ไปข้างหน้าเพื่อให้ MatchingAgent ได้รับโปรไฟล์ทั้งสอง; หลีกเลี่ยงการทริกเกอร์ซ้ำแบบ OR ที่เกิดจากกราฟ fan-in |
| **การผสมผสานเครื่องมือ MCP** | `@tool` + `streamable_http_client` เรียกใช้ MCP server ภายนอก |
| **วงจรชีวิต Hosted Agent** | Scaffold → กำหนดค่า → ทดสอบในเครื่อง → ปล่อยใช้งาน → ยืนยันในคลาวด์ |
| **`context_mode="last_agent"`** | ผู้ดำเนินการแต่ละคนเห็นเฉพาะผลลัพธ์ของผู้ดำเนินการก่อนหน้าที่ติดต่อโดยตรง |
| **เวิร์กโฟลว์ Foundry Toolkit** | ตัวช่วย Scaffold, ตัวตรวจสอบ Agent, ตัวแสดงเวิร์กโฟลว์, ปล่อยใช้งานด้วยคลิกเดียว |

### ไอเดียสำหรับขยายเวิร์กโฟลว์นี้

- **เพิ่มตัวแทนที่ 5** - โค้ชสัมภาษณ์ที่สร้างคำถามสัมภาษณ์ที่น่าจะเป็นไปได้ตามรายงานช่องว่าง
- **เพิ่มเครื่องมือค้นหาด้วย Bing** - ให้ JD Agent ค้นหาประกาศงานที่คล้ายกันเพื่อลดช่องว่างความต้องการ
- **เชื่อมต่อกับฐานข้อมูลเรซูเม่** - ดึงโปรไฟล์ผู้สมัครจากฐานข้อมูลผ่าน `@tool` กำหนดเอง
- **ลองโมเดลต่าง ๆ** - เปรียบเทียบคุณภาพและความหน่วงของผลลัพธ์ระหว่าง `gpt-4.1` กับ `gpt-4.1-mini`
- **ประเมินด้วย Foundry** - ใช้ฟีเจอร์ Evaluations เพื่อให้คะแนนรายงานความเหมาะสมกับชุดข้อมูลมาตรฐาน

### สำหรับผู้ใช้เส้นทาง B: อัพเกรดเป็นการปล่อยใช้งานบนคลาวด์

เมื่อคุณพร้อมที่จะปล่อยใช้งานบนคลาวด์:
1. รับสมัครสมาชิก Azure ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. ทำให้เสร็จ [Lab 01, Module 01](../../lab01-single-agent/docs/01-setup.md) (สร้างโปรเจกต์, นำแบบจำลองใช้งาน, กำหนด RBAC)
3. อัปเดต `.env` ของคุณด้วยปลายทางโปรเจกต์ Foundry และชื่อการนำแบบจำลองไปใช้งาน
4. ดำเนินการต่อจาก [Module 06 - Deploy to Foundry](06-deploy-to-foundry.md)

## ลบทรัพยากร (ทางเลือก)

หากคุณต้องการลบทรัพยากร Azure ที่สร้างขึ้นในเวิร์กช็อปนี้:

### ตัวเลือกที่ 1: ลบกลุ่มทรัพยากร (ลบทุกอย่าง)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### ตัวเลือกที่ 2: ลบเฉพาะโฮสต์เอเจนต์

1. เปิด [ai.azure.com](https://ai.azure.com) → โปรเจกต์ของคุณ → **Build** → **Agents**.
2. ค้นหา **PersonalCareerCopilot** → คลิก **Delete**.

### ตัวเลือกที่ 3: ลบการนำแบบจำลองไปใช้งาน

1. ใน Foundry sidebar ขยายโปรเจกต์ของคุณ → **Models**.
2. คลิกขวาที่การนำแบบจำลองไปใช้งาน → **Delete**.

> **หมายเหตุค่าใช้จ่าย:** โฮสต์เอเจนต์จะมีค่าใช้จ่ายเฉพาะตอนที่กำลังทำงานเท่านั้น หากคุณหยุดหรือ ลบเอเจนต์ จะไม่มีค่าใช้จ่ายต่อเนื่อง ส่วนการนำแบบจำลองไปใช้งานอาจมีค่าใช้จ่ายเล็กน้อยสำหรับความจุที่จองไว้ — ลบหากคุณใช้งานเสร็จแล้ว
