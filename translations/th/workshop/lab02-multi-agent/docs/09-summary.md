# โมดูล 9 - สรุป & ขั้นตอนถัดไป

⏱️ ~5 นาที

**ขอแสดงความยินดี!** คุณได้สร้าง ทดสอบ และ (ถ้าเลือกเส้นทาง A) นำไปใช้เวิร์กโฟลว์หลายเอเย่นต์โดยใช้ Microsoft Foundry และ Foundry Toolkit สำหรับ VS Code แล้ว

---

## สิ่งที่คุณสร้าง

**Resume → Job Fit Evaluator** - เวิร์กโฟลว์หลายเอเย่นต์ที่โฮสต์ซึ่ง:
- รับประวัติย่อ + คำอธิบายงานผ่าน HTTP (`POST /responses`)
- รันเอเย่นต์เฉพาะทางสี่ตัวตามลำดับ - แต่ละเอเย่นต์ส่งต่อข้อมูลที่ตัวถัดไปต้องการ
- ส่งคืนคะแนนเหมาะสม (0–100 พร้อมรายละเอียด), รายการช่องว่างทักษะและใบรับรอง, และแผนการเรียนรู้ออนไลน์ส่วนบุคคลที่มีลิงก์ Microsoft Learn ที่แท้จริงสำหรับแต่ละช่องว่าง
- เรียกใช้เซิร์ฟเวอร์ Microsoft Learn MCP (`https://learn.microsoft.com/api/mcp`) เพื่อดึงแหล่งเรียนรู้อย่างเป็นทางการสำหรับแต่ละช่องว่างทักษะที่ระบุ
- ทำงานเป็นเอเย่นต์โฮสต์เดียวบรรจุในคอนเทนเนอร์ใน Microsoft Foundry Agent Service

## แนวคิดสำคัญที่เรียนรู้

| แนวคิด | สิ่งที่คุณฝึกฝน |
|---------|-------------------|
| **การประสานงานหลายเอเย่นต์** | ท่อแบบลำดับใน `WorkflowBuilder` ด้วย `add_edge()` |
| **ความเชี่ยวชาญของเอเย่นต์** | เอเย่นต์เฉพาะทางสี่ตัวทำงานได้ดีกว่าเอเย่นต์ทั่วไปตัวเดียว |
| **ลักษณะการทำงาน Content Router** | ResumeParser ทำหน้าที่เป็นเราท์เตอร์ - มันเก็บข้อความ JD ในส่วน `[JOB DESCRIPTION PASS-THROUGH]` เพื่อให้เอเย่นต์ถัดไปสามารถเข้าถึงได้ (จำเป็นเพราะ `context_mode="last_agent"` หมายความว่าเฉพาะ `start_executor` เท่านั้นที่เห็นข้อความผู้ใช้ดิบ) |
| **ลักษณะการทำงาน Content Relay** | JD Agent ส่งต่อ `[PARSED RESUME PASS-THROUGH]` ไปข้างหน้า เพื่อให้ MatchingAgent ได้รับโปรไฟล์ทั้งสอง พร้อมหลีกเลี่ยงการทริกเกอร์ซ้ำแบบ OR ที่เกิดจากกราฟแฟนอิน |
| **การบูรณาการเครื่องมือ MCP** | `@tool` + `streamable_http_client` เรียกใช้เซิร์ฟเวอร์ MCP ภายนอก |
| **วงจรชีวิต Hosted Agent** | เริ่มต้นด้วย Scaffold → กำหนดค่า → ทดสอบในเครื่อง → นำไปใช้ → ยืนยันในคลาวด์ |
| **`context_mode="last_agent"`** | แต่ละผู้ดำเนินการจะเห็นได้เพียงผลลัพธ์ของผู้ดำเนินการก่อนหน้าโดยตรงเท่านั้น |
| **เวิร์กโฟลว์ Foundry Toolkit** | ตัวช่วย Scaffold, Agent Inspector, Workflow Visualizer, การนำไปใช้ด้วยคลิกเดียว |

### ไอเดียในการขยายเวิร์กโฟลว์นี้

- **เพิ่มเอเย่นต์ที่ 5** - โค้ชมสัมภาษณ์ที่สร้างคำถามสัมภาษณ์ที่น่าจะเป็นไปได้ตามรายงานช่องว่าง
- **เพิ่มเครื่องมือ Bing เพื่อเสริมฐานความรู้** - ให้ JD Agent ค้นหาประกาศงานที่คล้ายกันเพื่อเสริมข้อกำหนด
- **เชื่อมต่อกับฐานข้อมูลประวัติย่อ** - ดึงโปรไฟล์ผู้สมัครจากฐานข้อมูลผ่าน `@tool` แบบกำหนดเอง
- **ลองใช้โมเดลต่าง ๆ** - เปรียบเทียบคุณภาพและความหน่วงเวลาเอาต์พุตระหว่าง `gpt-4.1` กับ `gpt-4.1-mini`
- **ประเมินด้วย Foundry** - ใช้ฟีเจอร์ Evaluations ให้คะแนนรายงานความเหมาะสมกับชุดข้อมูลทองคำ

### สำหรับผู้ใช้เส้นทาง B: อัปเกรดเป็นการนำไปใช้บนคลาวด์

เมื่อคุณพร้อมนำไปใช้บนคลาวด์:
1. สมัครสมาชิก Azure ([azure.microsoft.com/free](https://azure.microsoft.com/free/))
2. ทำ [Lab 01, โมดูล 01](../../lab01-single-agent/docs/01-setup.md) ให้เสร็จ (สร้างโครงการ, นำโมเดลไปใช้, กำหนด RBAC)
3. อัปเดต `.env` ของคุณด้วยจุดสิ้นสุดโครงการ Foundry และชื่อการนำโมเดลไปใช้
4. ดำเนินการต่อจาก [โมดูล 06 - นำไปใช้กับ Foundry](06-deploy-to-foundry.md)

## ล้างทรัพยากร (ถ้าต้องการ)

หากคุณต้องการลบทรัพยากร Azure ที่สร้างในระหว่างเวิร์กช็อปนี้:

### ตัวเลือก 1: ลบกลุ่มทรัพยากร (ลบทุกอย่าง)

```powershell
az group delete --name rg-hosted-agents-workshop --yes --no-wait
```

### ตัวเลือก 2: ลบเฉพาะ Hosted agent

1. เปิด [ai.azure.com](https://ai.azure.com) → โครงการของคุณ → **Build** → **Agents**
2. หา **PersonalCareerCopilot** → คลิก **Delete**

### ตัวเลือก 3: ลบการนำโมเดลไปใช้

1. ในแถบ Foundry ขยายโครงการของคุณ → **Models**
2. คลิกขวาที่การนำโมเดลไปใช้ → **Delete**

> **หมายเหตุค่าใช้จ่าย:** Hosted agents มีค่าใช้จ่ายเฉพาะเมื่อกำลังทำงานอยู่ หากคุณหยุดหรือลบ agent จะไม่มีการเรียกเก็บเงินต่อเนื่อง การนำโมเดลไปใช้อาจมีค่าใช้จ่ายเล็กน้อยสำหรับความจุที่จองไว้ - ให้ลบถ้าคุณทำงานเสร็จแล้ว
