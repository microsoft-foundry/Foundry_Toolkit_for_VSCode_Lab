# Ενότητα 7 - Επαλήθευση στο Playground

⏱️ ~10 λεπτά

Σε αυτήν την ενότητα, δοκιμάζετε τη λειτουργία πολλαπλών πρακτόρων που αναπτύξατε στο VS Code και στο Foundry Portal, επιβεβαιώνοντας ότι ο πράκτορας συμπεριφέρεται με τον ίδιο τρόπο όπως κατά τις τοπικές δοκιμές.

---

## Γιατί να ελέγξουμε ξανά μετά την ανάπτυξη;

Το περιβάλλον φιλοξενίας διαφέρει από τοπικό σε λίγους σημαντικούς τομείς:

| | Τοπικό | Φιλοξενούμενο |
|--|-------|--------|
| **Ταυτότητα** | Η προσωπική σας σύνδεση (`DefaultAzureCredential`) | Αφιερωμένη ταυτότητα Entra ανά πράκτορα (αυτόματα παραχωρημένη κατά την ανάπτυξη) |
| **Τελικό Σημείο** | `http://localhost:8088/responses` | URL διαχειριζόμενο από Foundry Agent Service |
| **Δίκτυο** | Η συσκευή σας → Azure OpenAI + MCP | Πλάτη Azure (χαμηλότερη καθυστέρηση) |

Μια λανθασμένη ρύθμιση περιβάλλοντος, πρόβλημα RBAC ή αποκλεισμένη εξερχόμενη κλήση MCP θα εμφανιστεί πρώτα εδώ.

---

## Επιλογή Α: Δοκιμή στο VS Code Playground (προτείνεται πρώτα)

### Βήμα 1: Πλοηγηθείτε στον φιλοξενούμενο πράκτορά σας

1. Κάντε κλικ στο εικονίδιο **Foundry Toolkit** στη Γραμμή Δραστηριότητας.
2. Αναπτύξτε το έργο σας → **Hosted Agents (Preview)** → βρείτε τον πράκτορά σας.

![Foundry Toolkit sidebar showing Hosted Agents (Preview) with resume-job-fit-evaluator and its deployed versions](../../../../../translated_images/el/06-foundry-sidebar-agent-status.a45994bfb5c21284.webp)

### Βήμα 2: Επιλέξτε μια έκδοση

1. Κάντε κλικ στον πράκτορα για να αναπτύξετε τις εκδόσεις του.
2. Κάντε κλικ στο `v1` → επιβεβαιώστε ότι η κατάσταση είναι **ενεργή** (η πλευρική μπάρα μπορεί να εμφανίζει "Running" ή "Started" - και τα δύο υποδεικνύουν την ίδια κατάσταση ετοιμότητας).

### Βήμα 3: Ανοίξτε το Playground

1. Κάντε κλικ στο **Playground** (ή δεξί κλικ στην έκδοση → **Άνοιγμα στο Playground**).
2. Ανοίγει παράθυρο συνομιλίας σε καρτέλα του VS Code.

### Βήμα 4: Εκτελέστε τις βασικές δοκιμές

Χρησιμοποιήστε τις ίδιες 3 δοκιμές από την [Ενότητα 5](05-test-locally.md). Πληκτρολογήστε κάθε μήνυμα στο πεδίο εισαγωγής του Playground και πατήστε **Αποστολή** (ή **Enter**).

#### Δοκιμή 1 - Πλήρες βιογραφικό + JD (τυπική ροή)

Επικολλήστε το πλήρες βιογραφικό + prompt JD από την Ενότητα 5, Δοκιμή 1 (Jane Doe + Senior Cloud Engineer στην Contoso Ltd).

**Αναμενόμενο:**
- Βαθμολογία καταλληλότητας με αναλυτικό μαθηματικό υπολογισμό (κλίμακα 100 σημείων)
- Ενότητα "Matched Skills"
- Ενότητα "Missing Skills"
- **Μία κάρτα κενών ανά δεξιότητα που λείπει** με URLs από Microsoft Learn
- Οδικός χάρτης εκμάθησης με χρονοδιάγραμμα

#### Δοκιμή 2 - Γρήγορη σύντομη δοκιμή (ελάχιστη είσοδος)

```
RESUME: 3 years Python developer, knows Django and PostgreSQL, no cloud experience.

JOB: Cloud DevOps Engineer requiring AWS, Kubernetes, Terraform, CI/CD. 5 years needed.
```

**Αναμενόμενο:**
- Χαμηλότερη βαθμολογία καταλληλότητας (< 40)
- Ειλικρινής αξιολόγηση με σταδιακό μονοπάτι μάθησης
- Πολλαπλές κάρτες κενών (AWS, Kubernetes, Terraform, CI/CD, κενό εμπειρίας)

#### Δοκιμή 3 - Υποψήφιος υψηλής καταλληλότητας

```
RESUME:
10 years Azure Cloud Architect. AZ-305 certified. Expert in AKS, Terraform, Azure DevOps, 
Azure Functions, Helm, Prometheus, Grafana, Python, Go. Led platform team of 8.

JOB:
Senior Cloud Engineer. Required: AKS, Terraform, Azure DevOps, Python. Preferred: Helm, Go.
5+ years experience. AZ-305 preferred.
```

**Αναμενόμενο:**
- Υψηλή βαθμολογία καταλληλότητας (≥ 80)
- Εστίαση στην ετοιμότητα για συνέντευξη και βελτίωση
- Λίγες ή καθόλου κάρτες κενών
- Σύντομο χρονοδιάγραμμα επικεντρωμένο στην προετοιμασία

### Βήμα 5: Σύγκριση με τοπικά αποτελέσματα

Ανοίξτε τις σημειώσεις σας ή την καρτέλα του προγράμματος περιήγησης από την Ενότητα 5 όπου αποθηκεύσατε τις τοπικές απαντήσεις. Για κάθε δοκιμή:

- Η απάντηση έχει την **ίδια δομή** (βαθμολογία καταλληλότητας, κάρτες κενών, οδικός χάρτης);
- Ακολουθεί την **ίδια μεθοδολογία βαθμολόγησης** (ανάλυση σε κλίμακα 100 σημείων);
- Είναι παρόντα τα **Microsoft Learn URLs** στις κάρτες κενών;
- Υπάρχει **μία κάρτα κενών ανά δεξιότητα που λείπει** (όχι περικομμένη);

> **Μικρές διαφορές στον λόγο είναι φυσιολογικές** - το μοντέλο είναι μη ντετερμινιστικό. Εστιάστε στη δομή, συνέπεια βαθμολόγησης και στη χρήση του εργαλείου MCP.

## Επιλογή Β: Δοκιμή στο Foundry Portal

Το [Foundry Portal](https://ai.azure.com) προσφέρει ένα διαδικτυακό playground χρήσιμο για κοινή χρήση με συναδέλφους ή ενδιαφερόμενους.

### Βήμα 1: Ανοίξτε το Foundry Portal

1. Ανοίξτε το πρόγραμμα περιήγησής σας και μεταβείτε στο [https://ai.azure.com](https://ai.azure.com).
2. Συνδεθείτε με τον ίδιο λογαριασμό Azure που χρησιμοποιείτε καθ’ όλη τη διάρκεια του εργαστηρίου.

### Βήμα 2: Πλοηγηθείτε στο έργο σας

1. Στην αρχική σελίδα, κοιτάξτε το **Recent projects** στην αριστερή πλευρική γραμμή.
2. Κάντε κλικ στο όνομα του έργου σας (π.χ. `workshop-agents`).
3. Αν δεν το βλέπετε, κάντε κλικ στο **All projects** και αναζητήστε το.

### Βήμα 3: Βρείτε τον αναπτυγμένο πράκτορά σας

1. Στην αριστερή πλοήγηση του έργου, κάντε κλικ στο **Build** → **Agents** (ή βρείτε την ενότητα **Agents**).
2. Θα δείτε λίστα με τους πράκτορες. Βρείτε τον αναπτυγμένο πράκτορά σας (π.χ. `resume-job-fit-evaluator`).
3. Κάντε κλικ στο όνομα του πράκτορα για να ανοίξετε τη σελίδα λεπτομερειών του.

### Βήμα 4: Ανοίξτε το Playground

1. Στη σελίδα λεπτομερειών του πράκτορα, κοιτάξτε τη γραμμή εργαλείων στο επάνω μέρος.
2. Κάντε κλικ στο **Open in playground** (ή **Try in playground**).
3. Ανοίγει διεπαφή συνομιλίας.

### Βήμα 5: Εκτελέστε τις ίδιες βασικές δοκιμές

Επαναλάβετε και τις 3 δοκιμές από την ενότητα VS Code Playground παραπάνω. Συγκρίνετε κάθε απάντηση με τα τοπικά αποτελέσματα (Ενότητα 5) και τα αποτελέσματα VS Code Playground (Επιλογή Α παραπάνω).

## Επαλήθευση ειδική για πολλαπλούς πράκτορες

Πέρα από τη βασική ορθότητα, επαληθεύστε τις εξής συμπεριφορές ειδικές για πολλαπλούς πράκτορες:

### Εκτέλεση εργαλείων MCP

| Έλεγχος | Πώς να επαληθεύσετε | Προϋπόθεση επιτυχίας |
|-------|---------------|----------------|
| Η κλήση MCP πετυχαίνει | Οι κάρτες κενών περιέχουν URLs `learn.microsoft.com` | Πραγματικά URLs, όχι μηνύματα εφεδρείας |
| Πολλαπλές κλήσεις MCP | Κάθε κενό υψηλής/μεσαίας προτεραιότητας έχει πόρους | Όχι μόνο η πρώτη κάρτα κενών |
| Λειτουργία εφεδρείας MCP | Αν λείπουν URLs, ελέγξτε για κείμενο εφεδρείας | Ο πράκτορας παράγει ακόμα κάρτες κενών (με ή χωρίς URLs) |

### Συντονισμός πρακτόρων

| Έλεγχος | Πώς να επαληθεύσετε | Προϋπόθεση επιτυχίας |
|-------|---------------|----------------|
| Και οι 4 πράκτορες εκτελέστηκαν | Η έξοδος περιέχει βαθμολογία καταλληλότητας ΚΑΙ κάρτες κενών | Η βαθμολογία προέρχεται από τον MatchingAgent, οι κάρτες από τον GapAnalyzer |
| Διαδοχική εκτέλεση | Ο χρόνος απόκρισης είναι λογικός (< 2 λεπτά) | Αν > 3 λεπτά, ελέγξτε για σφάλματα στο τερματικό |
| Ακεραιότητα ροής δεδομένων | Οι κάρτες κενών αναφέρονται σε δεξιότητες από την αναφορά αντιστοίχισης | Δεν υπάρχουν φανταστικές δεξιότητες που δεν υπάρχουν στο JD |

## Κριτήρια επικύρωσης

Χρησιμοποιήστε αυτό το πλαίσιο για να αξιολογήσετε τη συμπεριφορά της ροής πολλαπλών πρακτόρων που φιλοξενείται:

| # | Κριτήριο | Προϋπόθεση επιτυχίας | Επιτυχία; |
|---|----------|---------------|-------|
| 1 | **Λειτουργική ορθότητα** | Ο πράκτορας απαντά σε βιογραφικό + JD με βαθμολογία καταλληλότητας και ανάλυση κενών | |
| 2 | **Συνέπεια στη βαθμολόγηση** | Η βαθμολογία καταλληλότητας χρησιμοποιεί κλίμακα 100 σημείων με αναλυτικό μαθηματικό υπολογισμό | |
| 3 | **Πληρότητα καρτών κενών** | Μία κάρτα ανά δεξιότητα που λείπει (χωρίς περικοπή ή συνένωση) | |
| 4 | **Ενσωμάτωση εργαλείων MCP** | Οι κάρτες κενών περιλαμβάνουν πραγματικά Microsoft Learn URLs | |
| 5 | **Δομική συνέπεια** | Η δομή της εξόδου ταιριάζει μεταξύ τοπικών και φιλοξενούμενων εκτελέσεων | |
| 6 | **Χρόνος απόκρισης** | Ο φιλοξενούμενος πράκτορας απαντά μέσα σε 2 λεπτά για πλήρη αξιολόγηση | |
| 7 | **Χωρίς σφάλματα** | Δεν υπάρχουν σφάλματα HTTP 500, χρονικά όρια ή κενές απαντήσεις | |

> "Επιτυχία" σημαίνει ότι πληρούνται και τα 7 κριτήρια και στις 3 βασικές δοκιμές σε τουλάχιστον ένα playground (VS Code ή Portal).

## Αντιμετώπιση προβλημάτων playground

| Σύμπτωμα | Πιθανή αιτία | Διόρθωση |
|---------|-------------|-----|
| Το playground δεν φορτώνει | Το κοντέινερ δεν είναι σε κατάσταση `active` | Επιστρέψτε στην [Ενότητα 6](06-deploy-to-foundry.md), επιβεβαιώστε την κατάσταση ανάπτυξης. Περιμένετε αν είναι `creating` |
| Ο πράκτορας επιστρέφει κενή απάντηση | Διαφορά στο όνομα ανάπτυξης μοντέλου | Ελέγξτε το `agent.yaml` → `environment_variables` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` να ταιριάζει με το αναπτυγμένο μοντέλο |
| Ο πράκτορας επιστρέφει μήνυμα σφάλματος | Λαμβάνεται άδεια [RBAC](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry) | Αναθέστε **[Foundry User](https://aka.ms/foundry-ext-project-role)** (προηγουμένως Azure AI User) στο επίπεδο έργου |
| Δεν υπάρχουν Microsoft Learn URLs στις κάρτες κενών | Αποκλεισμένη εξερχόμενη κλήση MCP ή μη διαθέσιμος MCP server | Ελέγξτε αν το κοντέινερ μπορεί να φτάσει στο `learn.microsoft.com`. Δείτε [Ενότητα 8](08-troubleshooting.md) |
| Μόνο 1 κάρτα κενών (περικομμένη) | Στιγμές οδηγίες GapAnalyzer λείπει το μπλοκ "CRITICAL" | Ανασκοπήστε την [Ενότητα 3, Βήμα 2.4](03-configure-agents.md) |
| Βαθμολογία καταλληλότητας πολύ διαφορετική από τοπική | Αναπτυγμένο διαφορετικό μοντέλο ή διαφορετικές οδηγίες | Συγκρίνετε τις μεταβλητές περιβάλλοντος στο `agent.yaml` με το τοπικό `.env`. Αναπτύξτε ξανά αν χρειάζεται |
| "Agent not found" στο Portal | Η ανάπτυξη εξακολουθεί να διαδίδεται ή απέτυχε | Περιμένετε 2 λεπτά, ανανεώστε. Αν λείπει ακόμη, αναπτύξτε ξανά από την [Ενότητα 6](06-deploy-to-foundry.md) |
