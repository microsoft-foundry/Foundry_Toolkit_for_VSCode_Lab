# Ενότητα 8 - Αντιμετώπιση προβλημάτων

Αυτή η ενότητα είναι ένας οδηγός αναφοράς για κοινά προβλήματα. Αποθηκεύστε τη σελιδοδείκτη και επιστρέψτε όταν κάτι πάει στραβά.

---

## 1. Σφάλματα αδειών

### 1.1 Άρνηση άδειας `agents/write`

```
Error: lacks the required data action 
Microsoft.CognitiveServices/accounts/AIServices/agents/write
```

**Αιτία:** Έλλειψη ρόλου `Azure AI User` στο επίπεδο **έργου**. Αυτό είναι το σφάλμα #1 στα εργαστήρια.

**Επισκευή:**
1. Ανοίξτε το [portal.azure.com](https://portal.azure.com).
2. Αναζητήστε το όνομα του **έργου** Foundry → κάντε κλικ στο αποτέλεσμα τύπου **"Microsoft Foundry project"** (ΟΧΙ ο γονικός λογαριασμός).
3. **Έλεγχος πρόσβασης (IAM)** → **+ Προσθήκη** → **Προσθήκη ανάθεσης ρόλου**.
4. Ρόλος: **Azure AI User** → Επόμενο.
5. Μέλη: Επιλέξτε τον εαυτό σας → Αναθεώρηση + ανάθεση → Αναθεώρηση + ανάθεση.
6. **Περιμένετε 1–2 λεπτά** → επαναλάβετε.

> **Γιατί ο Owner/Contributor δεν αρκεί:** Αυτοί οι ρόλοι δίνουν *ενέργειες διαχείρισης* μόνο. Οι λειτουργίες agent απαιτούν την *ενέργεια δεδομένων* `agents/write`, η οποία υπάρχει μόνο στους `Azure AI User`, `Azure AI Developer` ή `Azure AI Owner`. Δείτε τα [Foundry RBAC docs](https://learn.microsoft.com/azure/foundry/concepts/rbac-foundry).

### 1.2 `AuthorizationFailed` κατά τη δημιουργία

**Επισκευή:** Ζητήστε από τον διαχειριστή σας να αναθέσει **Contributor** στην ομάδα πόρων, ή να δημιουργήσει το έργο για εσάς και να σας παραχωρήσει **Azure AI User** σε αυτό.

### 1.3 `SubscriptionNotRegistered`

```bash
az provider register --namespace Microsoft.CognitiveServices
az provider show --namespace Microsoft.CognitiveServices --query "registrationState"
# Περίμενε μέχρι: "Εγγεγραμμένος"
```

## 2. Σφάλματα Docker

> Το Docker είναι **προαιρετικό**. Αυτά ισχύουν μόνο αν το Docker Desktop είναι εγκατεστημένο και η επέκταση προσπαθεί τοπική κατασκευή.

### 2.1 Ο daemon του Docker δεν εκτελείται

**Επισκευή:** Ξεκινήστε το Docker Desktop → περιμένετε την κατάσταση "τρέχει" → επαληθεύστε με `docker info` → δοκιμάστε ξανά.

### 2.2 Αποτυχία κατασκευής με σφάλματα εξαρτήσεων

**Επισκευή:** Ελέγξτε την ορθογραφία του `requirements.txt`, δοκιμάστε το τοπικά πρώτα: `pip install -r requirements.txt`.

### 2.3 Ασυμφωνία πλατφόρμας (Apple Silicon)

```bash
docker build --platform linux/amd64 -t myagent:v1 .
```

## 3. Σφάλματα πιστοποίησης

### 3.1 Αποτυχία `DefaultAzureCredential`

**Επισκευή (δοκιμάστε με τη σειρά):**
1. `az login` (επανεγγραφή)
2. `az account set --subscription "<id>"` (σωστή συνδρομή)
3. VS Code → Λογαριασμοί → Αποσύνδεση → Είσοδος ξανά
4. Επαληθεύστε: `az account get-access-token --resource https://cognitiveservices.azure.com`

### 3.2 Το token λειτουργεί τοπικά αλλά όχι φιλοξενούμενο

**Αναμενόμενο:** Οι φιλοξενούμενοι agents χρησιμοποιούν ταυτότητα που διαχειρίζεται το σύστημα, όχι τα διαπιστευτήριά σας. Εάν ο φιλοξενούμενος agent λαμβάνει σφάλματα πιστοποίησης:
- Επαληθεύστε το `AZURE_AI_PROJECT_ENDPOINT` στο `agent.yaml` είναι σωστό
- Ελέγξτε ότι η διαχειριζόμενη ταυτότητα του έργου έχει πρόσβαση στο μοντέλο

## 4. Σφάλματα μοντέλου

### 4.1 Δεν βρέθηκε ανάθεση μοντέλου

**Επισκευή:** Το όνομα είναι **ευαίσθητο σε πεζά-κεφαλαία**. Συγκρίνετε `.env` → `AZURE_AI_MODEL_DEPLOYMENT_NAME` με το ακριβές όνομα στην πλαϊνή μπάρα Foundry → Models.

### 4.2 Απρόσμενη έξοδος μοντέλου

**Επισκευή:** Επανεξετάστε το `AGENT_INSTRUCTIONS` στο `main.py` (μην είναι κομμένο;). Δοκιμάστε άλλο μοντέλο (`gpt-4.1` έναντι `gpt-4.1-mini`).

## 5. Σφάλματα ανάπτυξης

### 5.1 Μη εξουσιοδοτημένο pull από ACR

**Επισκευή:** Azure Portal → Container Registry → Έλεγχος πρόσβασης (IAM) → Προσθήκη ρόλου **AcrPull** στη διαχειριζόμενη ταυτότητα του έργου Foundry.

### 5.2 Ο agent αποτυγχάνει να ξεκινήσει (παραμένει "Pending" ή "Failed")

Ελέγξτε τα αρχεία καταγραφής container στην πλαϊνή μπάρα. Κοινές αιτίες:

| Μήνυμα καταγραφής | Επισκευή |
|-------------|-----|
| `ModuleNotFoundError` | Προσθέστε το λείπον πακέτο στο `requirements.txt`, πραγματοποιήστε ξανά ανάπτυξη |
| `KeyError: 'AZURE_AI_PROJECT_ENDPOINT'` | Προσθέστε μεταβλητή περιβάλλοντος στο `agent.yaml` κάτω από `environment_variables` |
| `Address already in use` | Βεβαιωθείτε ότι μόνο μία διεργασία δεσμεύει τη θύρα 8088 |

### 5.3 Η ανάπτυξη λήγει χρόνος αναμονής

**Επισκευή:** Ελέγξτε τη σύνδεση στο διαδίκτυο. Η πρώτη ανάπτυξη στέλνει >100MB. Είστε πίσω από proxy; Ρυθμίστε τις ρυθμίσεις proxy του Docker Desktop.

## 6. Διαδρομή Β - Foundry Local

### 6.1 Το Foundry Local δεν ξεκινά

| Πρόβλημα | Επισκευή |
|-------|-----|
| `foundry: command not found` | Επανεγκαταστήστε: `winget install Microsoft.FoundryLocal` |
| Ανεπαρκείς πόροι | Το Foundry Local χρειάζεται ~4GB ελεύθερη μνήμη RAM. Κλείστε άλλες εφαρμογές. |
| Αποτυχία λήψης μοντέλου | Ελέγξτε τον χώρο στο δίσκο (τα μοντέλα είναι 2–8 GB). Επαναλάβετε: `foundry local models pull <name>` |

### 6.2 Σφάλματα μοντέλου Foundry Local

| Πρόβλημα | Επισκευή |
|-------|-----|
| Αργές απαντήσεις | Αναμενόμενο - τα τοπικά μοντέλα τρέχουν σε CPU εκτός αν έχετε GPU. Να είστε υπομονετικοί. |
| Κακή ποιότητα εξόδου | Δοκιμάστε μεγαλύτερο μοντέλο αν το υλικό σας το υποστηρίζει. Το `phi-4-mini` είναι καλή ισορροπία. |
| Απορρίπτεται η σύνδεση | Επαληθεύστε ότι το Foundry Local τρέχει: `foundry local status`. Επανεκκινήστε αν χρειάζεται. |

## 7. Γρήγορη αναφορά: ρόλοι RBAC

| Ρόλος | Πεδίο εφαρμογής | Παρέχει |
|------|-------|--------|
| **Azure AI User** | Έργο | Ενέργειες δεδομένων: `agents/write`, `agents/read` |
| **Azure AI Developer** | Έργο/Λογαριασμός | Ενέργειες δεδομένων + δημιουργία έργου |
| **Azure AI Owner** | Λογαριασμός | Πλήρης πρόσβαση + διαχείριση ρόλων |
| **Contributor** | Συνδρομή/ΟΜ | Μόνο ενέργειες διαχείρισης (**όχι** ενέργειες δεδομένων) |
| **Owner** | Συνδρομή/ΟΜ | Διαχείριση + ανάθεση ρόλων (**όχι** ενέργειες δεδομένων) |
